## 💡 一、异步校验函数

用户名和手机号需要异步查重。我们写两个独立的校验函数：

```js
// utils/validators.js

// 用户名查重（模拟）
export async function checkUsername(username) {
  // 模拟接口延迟
  await new Promise(resolve => setTimeout(resolve, 800))

  // 模拟：'admin' 和 'test' 已被占用
  const takenNames = ['admin', 'test', 'root', 'user']
  return !takenNames.includes(username.toLowerCase())
}

// 手机号查重（模拟）
export async function checkPhone(phone) {
  await new Promise(resolve => setTimeout(resolve, 800))

  // 模拟：13800000000 已被注册
  const takenPhones = ['13800000000', '13900000000']
  return !takenPhones.includes(phone)
}
```

在实际项目中，这里应该是真实的 API 调用：

```js
// 真实写法
export async function checkUsername(username) {
  const res = await fetch(`/api/users/check-username?name=${username}`)
  const { available } = await res.json()
  return available
}
```

## 🔑 二、主表单逻辑（RegisterForm.vue 的 script 部分）

这是整个实战的核心。先看 `<script setup>` 部分——它负责所有状态与逻辑：

```vue
<!-- views/RegisterForm.vue（逻辑部分） -->
<script setup>
import { useForm } from 'vee-validate'
import { ref, watch } from 'vue'
import { useDebounceFn } from '@vueuse/core'
import PasswordStrength from '../components/PasswordStrength.vue'
import { checkUsername, checkPhone } from '../utils/validators'

// ==================== 表单 ====================
const { handleSubmit, errors, values, resetForm } = useForm({
  validationSchema: {
    username: {
      required: true,
      min: 3
    },
    phone: {
      required: true,
      phone: true
    },
    email: {
      required: true,
      email: true
    },
    password: {
      required: true,
      passwordStrength: true
    },
    confirmPassword: {
      required: true,
      confirmed: '@password'
    },
    agreed: {
      // 自定义规则：必须勾选
      required: true
    }
  }
})

// ==================== 状态 ====================
const submitting = ref(false)
const submitSuccess = ref(false)
const agreed = ref(false)

// 异步校验状态
const checkingUsername = ref(false)
const usernameAvailable = ref(null)  // null=未检查, true=可用, false=不可用
const checkingPhone = ref(false)
const phoneAvailable = ref(null)

// 密码可见切换
const showPassword = ref(false)

// ==================== 异步校验 ====================
// 用 useDebounceFn 给异步校验加 500ms 防抖
const debouncedCheckUsername = useDebounceFn(async () => {
  const name = values.username
  if (!name || name.length < 3) {
    usernameAvailable.value = null
    return
  }

  checkingUsername.value = true
  usernameAvailable.value = null

  try {
    const available = await checkUsername(name)
    usernameAvailable.value = available
  } catch {
    usernameAvailable.value = null
  } finally {
    checkingUsername.value = false
  }
}, 500)

const debouncedCheckPhone = useDebounceFn(async () => {
  const phone = values.phone
  if (!phone || !/^1[3-9]\d{9}$/.test(phone)) {
    phoneAvailable.value = null
    return
  }

  checkingPhone.value = true
  phoneAvailable.value = null

  try {
    const available = await checkPhone(phone)
    phoneAvailable.value = available
  } catch {
    phoneAvailable.value = null
  } finally {
    checkingPhone.value = false
  }
}, 500)

// 监听字段变化，触发异步校验
watch(() => values.username, () => {
  usernameAvailable.value = null  // 用户改了就先清掉上次结果
  debouncedCheckUsername()
})

watch(() => values.phone, () => {
  phoneAvailable.value = null
  debouncedCheckPhone()
})

// ==================== 提交 ====================
const onSubmit = handleSubmit(async (formValues, { errors: formErrors }) => {
  // 异步校验未通过，拦截提交
  if (usernameAvailable.value === false) {
    alert('用户名已被占用，请更换')
    return
  }
  if (phoneAvailable.value === false) {
    alert('手机号已被注册，请更换')
    return
  }

  if (submitting.value) return
  submitting.value = true
  submitSuccess.value = false

  try {
    // 模拟提交
    await new Promise(resolve => setTimeout(resolve, 1500))
    console.log('✅ 注册成功，提交数据：', formValues)

    submitSuccess.value = true
    resetForm()
    agreed.value = false

    setTimeout(() => { submitSuccess.value = false }, 5000)
  } catch (err) {
    alert('注册失败：' + err.message)
  } finally {
    submitting.value = false
  }
})
</script>
```

> 💬 **老师备注**：script 部分的核心思路——**同步规则交给 VeeValidate，异步规则自己管**。`validationSchema` 只管格式（必填、长度、手机号格式），查重这种需要发请求的判断放在 `watch` + 防抖函数里，提交时再统一检查。

## 💡 三、关键代码解读

### 3.1 为什么用 `values.xxx` 而不是单独的 ref？

VeeValidate 的 `useForm` 返回的 `values` 是一个响应式对象，表单里用 `v-model="values.username"` 绑定。这比每个字段单独 `const username = ref('')` 更集中，一次性 `resetForm()` 就能清空全部。

### 3.2 异步校验为什么需要防抖？

用户每敲一个字就发一次请求 → 一秒敲 5 个字 = 5 次请求。用 `useDebounceFn(fn, 500)` 后，用户停止输入 500ms 后才发请求，减少不必要的网络开销。

### 3.3 提交前为什么要检查异步校验结果？

VeeValidate 只跑同步规则。`usernameAvailable === false` 是异步校验的结果，不算在 VeeValidate 的 `validationSchema` 里。所以 `onSubmit` 回调里要手动检查：

```js
if (usernameAvailable.value === false) {
  alert('用户名已被占用，请更换')
  return
}
```

## ⚠️ 四、常见陷阱

### 陷阱 1：异步校验结果的延时问题

用户输入 "admin"，失焦 → 500ms 防抖 → 800ms 接口延迟 = 总共 1.3 秒后才有结果。在结果出来之前如果用户点了"提交"，`usernameAvailable` 还是 `null`，这时代码里 `usernameAvailable.value === false` 不会拦截，可能把已占用的用户名提交上去。

**解决**：提交时如果 `usernameAvailable === null`（结果还没出来），也应该拦截或显示提示。

```js
if (usernameAvailable.value === null) {
  alert('正在校验用户名，请稍候...')
  return
}
```

### 陷阱 2：`watch` 触发时机

`watch(() => values.username, ...)` 在组件初始化时不会执行（默认 `immediate: false`）。如果初始值不为空，异步校验不会触发。需要的话加 `{ immediate: true }`。

### 陷阱 3：异步校验状态与 UI 的同步

异步校验是异步的，UI 上要同时反馈"校验中（⏳）/ 可用（✅）/ 不可用（❌）"三种状态。用一个 `usernameAvailable` 的 `null / true / false` 三态变量来管理，比单纯存布尔值更清晰。

## 🧠 本节小结

- **同步/异步分工**：格式类同步规则交给 VeeValidate 的 `validationSchema`；查重类异步规则用 `watch` + `useDebounceFn` 自己管，提交前统一检查
- **values 集中管理**：用 `useForm` 返回的响应式 `values` 绑定表单，`resetForm()` 一次清空，比每个字段单独 `ref` 更省心
- **三态状态机**：查重结果用 `null`（未检查/校验中）/ `true`（可用）/ `false`（不可用）管理，UI 与提交逻辑都靠它
- **提交二次拦截**：`usernameAvailable === false` 和 `=== null`（结果没出来）都要拦截，不能只防"不可用"漏掉"还在校验中"
- **防抖的必要性**：每敲一个字发一次请求不可接受，`useDebounceFn(fn, 500)` 让请求在停止输入 500ms 后才发出
- **watch 细节**：默认 `immediate: false`，初始值非空时不会触发异步校验，必要时加 `{ immediate: true }`
