## 🤔 一、v-model 的本质——它到底做了什么？

你肯定用过 `v-model`，它写起来太方便了：

```vue
<input v-model="username" />
```

但你知道 Vue 在背后帮你做了什么吗？上面这行代码，等价于：

```
<input
  :value="username"
  @input="username = $event.target.value"
/>
```

三件事合为一行：
1. 把 `username` 的值**绑定**到 `input.value`
2. 监听 `input` 事件
3. 事件触发时，把 `$event.target.value` **写回** `username`

这就是 `v-model` 的全部秘密——**一个属性绑定 + 一个事件监听**的语法糖。

### 不同表单元素的"本质拆解"

| 表单元素 | v-model 写法 | 等价写法 |
|---|---|---|
| `<input type="text">` | `v-model="val"` | `:value="val"` + `@input` |
| `<input type="checkbox">` | `v-model="checked"` | `:checked="checked"` + `@change` |
| `<input type="radio">` | `v-model="picked"` | `:checked="picked === val"` + `@change` |
| `<select>` | `v-model="selected"` | `:value="selected"` + `@change` |
| `<textarea>` | `v-model="text"` | `:value="text"` + `@input` |

> 💬 **老师备注**：理解这个本质很重要——因为你迟早会遇到"v-model 不够用"的场景。比如你需要对输入做格式处理（只允许数字、手机号自动加空格），这时你就得把 `v-model` 拆成 `:value` + `@input` 手动控制。

## 💡 二、三个修饰符：.lazy / .number / .trim

### 2.1 `.lazy` —— "别急，失焦再更新"

默认情况下，`v-model` 在每次 `input` 事件时同步数据（也就是每敲一个字符就更新）。加上 `.lazy` 后，改为 `change` 事件触发（输入框失焦时才更新）。

```vue
<!-- 默认：每敲一个字就更新 -->
<input v-model="keyword" />
<p>实时：{{ keyword }}</p>

<!-- .lazy：失焦后才更新 -->
<input v-model.lazy="keyword" />
<p>懒更新：{{ keyword }}</p>
```

**适用场景**：搜索框不需要每敲一个字就触发搜索，等用户打完再搜。或者表单字段特别多，希望减少更新频率时。

### 2.2 `.number` —— "用户输入的是数字"

`input` 的值默认是字符串。用 `.number` 后，Vue 会用 `parseFloat` 尝试转成数字。如果用户输入的不是合法数字（比如 "abc"），则保持原样。

```
<input v-model.number="age" type="number" />
<p>年龄：{{ age }}，类型：{{ typeof age }}</p>
<!-- 用户输入 18，输出：年龄：18，类型：number -->
```

> 💬 **老师备注**：`type="number"` 和 `.number` 要一起用。单用 `type="number"`，`v-model` 绑定的值仍然是字符串（在部分浏览器上），加上 `.number` 修饰符才确保拿到的是数字类型。

### 2.3 `.trim` —— "去掉首尾空格"

```vue
<input v-model.trim="username" />
<!-- 用户输入 "  张三  " → username 值为 "张三" -->
```

这个很简单，但经常被忽略。用户在输入框里无意中打的前后空格，可能导致后端接口校验失败（"张三" ≠ "张三 "）。

### 2.4 修饰符可以链式使用

```
<input v-model.lazy.number.trim="price" />
<!-- 依次：失焦更新 → 转数字 → 去空格 -->
```

三个修饰符的执行顺序就是写法的顺序，建议按 "事件 → 转换 → 清理" 排列（`.lazy.number.trim`）。

## 🛠 三、组件上的 v-model

### 3.1 传统写法（Vue 3.0 - 3.3）

`v-model` 用在组件上时，默认展开为：

```vue
<!-- 使用 -->
<MyInput v-model="username" />

<!-- 等价于 -->
<MyInput
  :modelValue="username"
  @update:modelValue="username = $event"
/>
```

子组件需要接收 `modelValue` prop 并 emit `update:modelValue`：

```
<!-- MyInput.vue -->
<script setup>
defineProps(['modelValue'])
defineEmits(['update:modelValue'])
</script>

<template>
  <input
    :value="modelValue"
    @input="$emit('update:modelValue', $event.target.value)"
  />
</template>
```

### 3.2 Vue 3.4+ 推荐写法：`defineModel()`

Vue 3.4 引入了 `defineModel()` 宏，把这个模式简化成了一行：

```vue
<!-- MyInput.vue（Vue 3.4+） -->
<script setup>
const model = defineModel()
</script>

<template>
  <input v-model="model" />
</template>
```

`defineModel()` 返回一个 ref，它的 `.value` 和父组件的 `v-model` 双向同步。你在子组件里 `model.value = '新值'`，父组件也会自动更新。

**带默认值**：

```js
const model = defineModel({ default: '' })
```

**带类型**：

```js
const model = defineModel<string>({ default: '' })
```

### 3.3 带参数的 v-model

一个组件可以绑定多个 `v-model`：

```
<!-- 使用 -->
<UserForm
  v-model:firstName="first"
  v-model:lastName="last"
/>
```

子组件：

```vue
<!-- UserForm.vue -->
<script setup>
const firstName = defineModel('firstName', { default: '' })
const lastName = defineModel('lastName', { default: '' })
</script>

<template>
  <input v-model="firstName" placeholder="姓" />
  <input v-model="lastName" placeholder="名" />
</template>
```

`v-model:xxx` → `defineModel('xxx')`，每个参数对应一个独立的双向绑定通道。

### 3.4 自定义修饰符

你也可以给组件的 `v-model` 加自定义修饰符：

```
<!-- 使用 -->
<MyInput v-model.capitalize="text" />
```

子组件通过 `defineModel` 的第二个参数拿到修饰符：

```vue
<script setup>
const [model, modifiers] = defineModel({
  set(value) {
    if (modifiers.capitalize) {
      return value.charAt(0).toUpperCase() + value.slice(1)
    }
    return value
  }
})
</script>
```

`modifiers` 对象里会有 `{ capitalize: true }`，你可以在 `set` 回调里自定义处理逻辑。

## ⚠️ 四、常见陷阱

### 陷阱 1：v-model 绑定的是字符串

```
<input type="number" v-model="age" />
<!-- age 仍然是字符串！ -->
```

前面说过，必须加 `.number` 修饰符才能拿到数字类型。`type="number"` 只是限制了用户输入的键盘，不改变 JS 类型。

### 陷阱 2：v-model 和 :value 同时使用

```vue
<!-- ❌ 报错 -->
<input v-model="text" :value="text" />
```

`v-model` 已经绑定了 `:value`，你再加一个就是冲突。要么用 `v-model`，要么用 `:value` + `@input`，不能混用。

### 陷阱 3：`defineModel` 需要 Vue 3.4+

`defineModel` 是一个编译宏，需要 Vue 3.4+。老项目（Vue 3.0 - 3.3）只能用 `defineProps` + `defineEmits` 的方式。如果你的项目是 Vite，还需要确保 `vite.config.js` 里的 `@vitejs/plugin-vue` 升级到支持 Vue 3.4 编译宏的版本。

### 陷阱 4：组件内直接改 prop

即便用了 `v-model`，子组件也不应该直接改 prop（传统写法里 `modelValue` 是 prop）。正确做法是 emit 事件让父组件改。`defineModel` 帮你在内部做了一个本地 ref 的代理，所以你直接改 `model.value` 是安全的。

## 🧠 本节小结

- **本质是语法糖**：原生元素 = `:value + @input`（checkbox 用 `:checked + @change`）；组件上默认展开为 prop `modelValue` + 事件 `update:modelValue`
- **三个修饰符**：`.lazy` 改 change 事件、失焦才更新；`.number` 自动 `parseFloat` 转数字；`.trim` 去首尾空格；可链式 `.lazy.number.trim`
- **defineModel()（Vue 3.4+）**：返回一个与父组件双向同步的 ref，`v-model:xxx` 对应 `defineModel('xxx')`，支持 `default` / 类型参数 / 自定义 `set`
- **自定义修饰符**：`defineModel` 第二个返回值 `modifiers` 拿修饰符对象，在 `set` 里实现 `capitalize` 这类处理
- **老项目替代**：Vue 3.0-3.3 用 `defineProps(['modelValue'])` + `defineEmits(['update:modelValue'])` 手写；Vite 项目需升级 `@vitejs/plugin-vue` 到支持 3.4 编译宏的版本
