## 🤔 一、为什么需要自定义规则？

VeeValidate 内置了 30+ 条规则（`required`、`email`、`min`、`max`、`confirmed` 等），但实际项目中你一定会遇到内置规则覆盖不到的场景：

- 手机号格式（11 位、1 开头、第二位 3-9）
- 身份证号校验
- 用户名不能包含特殊字符
- 两个字段的大小关系（结束时间 > 开始时间）
- **异步校验**：用户名是否已被注册（需要调接口）

自定义规则就是来填这些坑的。

---

## 💡 二、方式一：defineRule 全局注册

这是最推荐的方式——定义一次，整个项目都能用。

### 2.1 基础语法

```js
import { defineRule } from 'vee-validate'

defineRule('phone', (value) => {
  if (!value) return '手机号不能为空'
  if (!/^1[3-9]\d{9}$/.test(value)) return '手机号格式不正确'
  return true  // 通过验证
})
```

规则函数接收当前字段的值，返回：
- `true`：通过
- 字符串：错误信息
- `false`：不通过（VeeValidate 会用默认错误信息）

### 2.2 带参数的自定义规则

很多规则需要参数——比如"长度在 3 到 20 之间"、"金额大于 100"。

```js
defineRule('between', (value, [min, max]) => {
  const num = Number(value)
  if (isNaN(num)) return '请输入数字'
  if (num < min || num > max) return `必须在 ${min} 到 ${max} 之间`
  return true
})
```

使用时：

```js
validationSchema: {
  age: 'required|between:0,150',   // 字符串写法
  score: { required: true, between: [0, 100] }  // 对象写法
}
```

`[min, max]` 就是 `defineRule` 第二个参数接收到的参数数组，和你在 schema 里写的 `0,150` 一一对应。

### 2.3 实战：手机号 + 身份证号 + 金额

```js
// rules.js —— 建议集中管理
import { defineRule } from 'vee-validate'

// 手机号
defineRule('phone', (value) => {
  if (!value) return true  // 非必填项，空值不校验（配合 required 使用）
  if (!/^1[3-9]\d{9}$/.test(value)) return '手机号格式不正确（11 位，1 开头）'
  return true
})

// 身份证号（18 位）
defineRule('idCard', (value) => {
  if (!value) return true
  if (!/^\d{17}[\dX]$/.test(value)) return '身份证号格式不正确'
  return true
})

// 金额（两位小数）
defineRule('money', (value) => {
  if (!value) return true
  if (!/^\d+(\.\d{1,2})?$/.test(value)) return '金额格式不正确（最多两位小数）'
  return true
})
```

## 💡 三、方式二：schema 内联函数

如果你的规则只在一个地方用，不想全局注册，直接在 schema 里写函数：

```js
const { handleSubmit } = useForm({
  validationSchema: {
    // 内联函数，不需要 defineRule
    nickname: (value) => {
      if (!value) return '昵称不能为空'
      if (/[!@#$%^&*]/.test(value)) return '昵称不能包含特殊字符'
      if (value.length > 12) return '昵称最长 12 个字符'
      return true
    }
  }
})
```

> 💬 **老师备注**：全局规则和内联函数没有优劣之分。原则是：**一个规则在 3 个以上的地方用到，就全局注册；只在一个表单里用到，就内联**。

## 🛠 四、异步规则（重点）

这是实战中最常见的需求——比如注册时检查"用户名是否已被占用"。

### 4.1 基本写法

```js
defineRule('usernameUnique', async (value) => {
  if (!value) return true  // 空值不去查接口
  try {
    const res = await fetch(`/api/check-username?name=${value}`)
    const data = await res.json()
    if (data.exists) return '该用户名已被注册'
    return true
  } catch {
    return '网络错误，请稍后重试'
  }
})
```

异步规则的核心就是**返回一个 Promise**，VeeValidate 会等待 Promise resolve 后再决定是否通过。

### 4.2 实战：检查手机号是否已注册

```js
defineRule('phoneUnique', async (value) => {
  if (!value || !/^1[3-9]\d{9}$/.test(value)) return true  // 格式都不对，不去查接口

  // 模拟后端接口
  const res = await fetch(`/api/check-phone?phone=${value}`)
  const { exists } = await res.json()
  return exists ? '该手机号已被注册' : true
})
```

然后在 schema 里使用：

```js
validationSchema: {
  phone: 'required|phone|phoneUnique'
  // 先检查必填 → 再检查格式 → 最后检查唯一性
}
```

### 4.3 异步规则的注意事项

1. **防抖**：用户每敲一个字就发一次接口请求？太浪费了。建议配合 `@vueuse/core` 的 `useDebounceFn` 或手写防抖逻辑。
2. **loading 状态**：异步校验期间，字段可能处于"pending"状态，`useField` 返回的 `meta` 对象里有 `pending` 字段可以展示加载动画。
3. **错误处理**：接口挂了怎么办？一定要 try-catch，返回友好的错误提示而不是让页面崩溃。

## 🛠 五、跨字段规则

有些验证逻辑涉及两个字段之间的关系，比如"结束日期不能早于开始日期"。

```js
const { handleSubmit } = useForm({
  validationSchema: {
    startDate: 'required',
    // endDate 的验证依赖 startDate 的值
    endDate: (value, { form }) => {
      if (!value) return '结束日期不能为空'
      if (form.startDate && new Date(value) <= new Date(form.startDate)) {
        return '结束日期必须晚于开始日期'
      }
      return true
    }
  }
})
```

内联函数可以接收第二个参数 `{ form }`，通过 `form.xxx` 访问其他字段的值。

如果用 `defineRule`，需要额外传递 `params`：

```js
defineRule('after', (value, [targetField], { form }) => {
  if (!value || !form[targetField]) return true
  if (new Date(value) <= new Date(form[targetField])) {
    return '结束日期必须晚于开始日期'
  }
  return true
})

// 使用：endDate: 'required|after:startDate'
```

## ⚠️ 六、常见陷阱

### 陷阱 1：异步规则没有考虑空值

```js
// ❌ 字段为空时也会发接口请求
defineRule('checkUsername', async (value) => {
  const res = await fetch(`/api/check?name=${value}`)
  // ...
})

// ✅ 先判断空值
defineRule('checkUsername', async (value) => {
  if (!value) return true  // 空值跳过
  // ...
})
```

### 陷阱 2：自定义规则名和内置规则冲突

```js
// ❌ 'email' 是内置规则名，覆盖了可能导致奇怪行为
defineRule('email', myCustomEmailRule)
```

定义规则前确认名字不和内置规则重名。建议用前缀，如 `my-email` 或 `customEmail`。

### 陷阱 3：跨字段规则没有重新验证

当你改了 `startDate`，`endDate` 的错误状态不会自动更新——因为 VeeValidate 不会自动追踪字段间的依赖关系。解决方案：

```js
// 在 useForm 的配置里开启跨字段验证
const { handleSubmit } = useForm({
  validationSchema: { ... },
  // 表单级别验证（每次任何字段变化时重新跑所有规则）
  validateOnMount: false
})
```

或者手动在 `startDate` 变化后触发 `endDate` 的重新验证（用 `useField` 的 `handleChange` + `validate`）。

## 🧠 本节小结

- **三种自定义方式**：`defineRule('name', fn)` 全局注册（多处复用）、schema 内联函数（单处使用）、第三方规则按需引入
- **返回值约定**：规则函数返回 `true` 通过 / 字符串当错误信息 / `false` 用默认文案；带参数规则第二参收 `[min, max]` 参数数组，与 `between:0,150` 对应
- **异步规则**：返回 Promise 即可，VeeValidate 会等待结果；典型场景是查重——但空值先 `return true` 别发无谓请求，且必须 try-catch 防接口挂掉
- **异步性能**：查重要配防抖（如 VueUse `useDebounceFn`）；pending 期间可用 `meta.pending` 展示加载态
- **跨字段规则**：内联函数第二参 `{ form }` 取其他字段值；`defineRule` 版需声明目标字段参数并用 `{ form }` 读取
- **两个坑**：空值也发请求浪费接口；自定义规则名与内置规则重名会覆盖（用 `myEmail` 这类前缀）
