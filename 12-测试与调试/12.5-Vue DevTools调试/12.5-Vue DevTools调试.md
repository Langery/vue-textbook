## 🤔 一、为什么要用 DevTools？

你写代码的时候，有没有过这种经历：

- "这个 prop 到底传进来了没有？值是什么？"
- "这个 computed 算出来的结果到底对不对？"
- "为什么这个组件一直在重新渲染？"
- "Pinia store 里的值啥时候被改的？"

如果你只会 `console.log`，你需要在代码里到处加日志，改了还要刷新页面——效率很低。

**Vue DevTools 让你在浏览器里直接"看到"组件内部的一切**，不用改代码、不用刷新，所见即所得。

## 💡 二、安装与打开

### 2.1 安装

去 Chrome 应用商店（或 Edge 扩展商店）搜索 **"Vue.js devtools"**，认准图标和作者 `vuejs`，点击安装。

> 💬 **老师备注**：注意不要装成"Vue.js devtools 6"老版本。装好之后，打开你自己的 Vue 开发页面，F12 → 看到顶部多了"Vue"标签，就说明装对了。

### 2.2 不显示 Vue 标签？

如果打开了一个 Vue 页面，F12 里却看不到 Vue 标签，检查：

1. 确认页面确实在用 Vue 3（F12 → Console 输入 `window.__VUE__` 回车，看有没有输出）
2. 如果是生产环境（`vite build` 后的页面），默认不开启 DevTools
3. 右键扩展图标 → "管理扩展" → 确保"允许访问文件 URL"已开启
4. 试试关掉 F12 再重新打开

## 🔑 三、Components 面板 —— 最常用

打开你的 Vue 项目，F12，切换到 **Components** 标签页：

### 3.1 组件树

左侧会显示整个页面的组件层级结构：

```text
App
├── Header
│   ├── Logo
│   └── NavMenu
├── MainContent
│   ├── Sidebar
│   └── ArticleList
│       └── ArticleCard (×5)   ← v-for 渲染了 5 个
└── Footer
```

### 3.2 查看组件数据

点一下左侧的 `ArticleCard`，右侧面板显示：

```text
Props:
  title: "Vue 3 入门教程"
  author: "张三"
  likes: 42

Data (setup):
  isBookmarked: false
  expanded: true

Computed:
  displayDate: "2026-07-03"
```

**你可以在右侧直接点击属性值来修改**！比如把 `isBookmarked` 改成 `true`，页面立刻更新——不用刷新、不用改代码。

### 3.3 "瞄准"定位

DevTools 右上角有个瞄准图标（🔍），点一下它，然后在页面上点某个元素，DevTools 会自动在组件树中选中对应的组件。非常适合"这个按钮是哪个组件渲染的？"

### 3.4 "Open in editor"

如果你用的是 VS Code / WebStorm，Components 面板中组件名后面有个小小的 `<>` 图标。点一下，**直接在你的编辑器里打开这个组件的源文件**。比你在文件系统里翻快十倍。

## 🛠 四、Timeline 面板 —— 性能排查

当你发现页面"怎么这么卡"，Timeline 可以帮你定位问题：

1. 切换到 **Timeline** 标签
2. 点击左上角**录制按钮**（红点）
3. 在页面上做卡顿的操作（比如疯狂输入、滚动大列表）
4. 点击**停止录制**

你会看到每个组件的渲染时间条：

```text
App              ████
Header           ██
MainContent      ████████████   ← 这个渲染太久了！
  Sidebar        ██
  ArticleList    ██████████     ← 子组件也跟着重渲染
```

如果某个操作导致大量组件不必要地重新渲染，Timeline 一眼就能看出来。

## 🔑 五、Pinia 面板

用了 Pinia 管理状态？Pinia 面板专门为你服务：

### 5.1 查看 Store 状态

左侧列出所有 store，点击查看完整 state：

```text
useUserStore:
  user: { id: 1, name: "小明", vip: true }
  token: "eyJhbGciOi..."

useCartStore:
  items: [{ id: 1, name: "Vue 3 实战", price: 59 }]
  totalCount: 1
```

### 5.2 时间线追踪

Pinia 面板可以记录每次 state 变化：

```text
14:23:01.123  items.push({ id: 2, name: "React 入门" })
14:23:01.124  totalCount → 2
14:23:05.567  items[0].quantity → 3
```

当你疑惑"这个值什么时候被改的？被谁改的？"——看时间线就行。

### 5.3 手动修改 State

跟 Components 面板一样，你可以直接在 Pinia 面板里改 state 值，页面会立刻响应。

## 🛠 六、Console 里的调试技巧

在 Components 面板选中一个组件后，打开 Console 标签，输入 `$vm0` 就可以直接访问这个组件实例：

```js
// 控制台中
$vm0                     // 当前选中的组件实例
$vm0.count               // 读取内部数据
$vm0.count = 10          // 手动修改
$vm0.handleClick()       // 调用组件方法
```

选中不同组件，`$vm0` 指向不同实例。非常灵活。

## ⚠️ 七、使用注意事项

### 注意 1：生产环境不启用 DevTools

默认情况下，`vite build` 构建的生产版本不包含 DevTools 检测代码。这是为了安全和包体积。**DevTools 只在开发环境用。**

### 注意 2：Pinia DevTools 需要显式开启

如果你用了 Pinia，确保在创建 Pinia 实例时开启了 DevTools（默认是开启的）：

```js
// main.js
import { createPinia } from 'pinia'
const pinia = createPinia()
// devtools 默认开启，无需额外配置
app.use(pinia)
```

### 注意 3：不是所有数据都能看到

DevTools 只展示"响应式"数据。如果你在 `<script setup>` 里定义了一个普通变量（没用 ref/reactive），它在 Components 面板里是看不到的。

## 🧠 本节小结

- **安装验证**：商店认准作者 `vuejs`；装好打开开发环境页面，F12 顶部多出 "Vue" 标签即成功；生产构建默认不启用
- **Components 面板**：左侧组件树看层级，右侧实时查看 props / data / computed；可直接改属性值验证效果；瞄准图标从页面元素反查所属组件；`<>` 图标一键在编辑器打开源文件
- **Timeline 面板**：录制操作 → 查看各组件渲染时长条，一眼定位"谁在过度重渲染"
- **Pinia 面板**：查看各 store 完整 state、追踪每次 state 变化的时间线（谁在何时改的）、手动改值做即时调试
- **Console 技巧**：选中组件后 `$vm0` 直接访问实例——读数据、改值、调方法都行
- **两个认知**：普通（非响应式）变量在面板里看不到；DevTools 是开发环境工具，别拿它调试生产页面
