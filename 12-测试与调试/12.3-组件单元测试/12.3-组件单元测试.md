## 🤔 一、组件测试的核心三问

当你面对一个 Vue 组件，你该测什么？记住三个问题：

1. **输入 → 渲染**：给它某些 Props，它渲染出正确的内容吗？
2. **交互 → 输出**：用户点击/输入后，它触发正确的事件吗？
3. **状态 → 视图**：内部状态变化后，视图正确更新了吗？

这一节我们逐一击破。

## 💡 二、测试 Props

### 2.1 测试组件

```vue
<!-- src/components/UserCard.vue -->
<script setup>
defineProps({
  name: { type: String, required: true },
  age: { type: Number, default: 18 },
  vip: { type: Boolean, default: false }
})
</script>

<template>
  <div class="user-card">
    <h2 data-test="name">{{ name }}</h2>
    <span data-test="age">{{ age }} 岁</span>
    <span v-if="vip" data-test="vip-badge" class="badge">VIP</span>
  </div>
</template>
```

### 2.2 测试代码

```js
// src/components/__tests__/UserCard.test.js
import { mount } from '@vue/test-utils'
import UserCard from '../UserCard.vue'

describe('UserCard 组件', () => {
  test('传入 name 和 age 后正确渲染', () => {
    const wrapper = mount(UserCard, {
      props: { name: '小明', age: 20 }
    })
    expect(wrapper.find('[data-test="name"]').text()).toBe('小明')
    expect(wrapper.find('[data-test="age"]').text()).toBe('20 岁')
  })

  test('age 默认值为 18', () => {
    const wrapper = mount(UserCard, {
      props: { name: '小红' }  // 不传 age
    })
    expect(wrapper.find('[data-test="age"]').text()).toBe('18 岁')
  })

  test('vip 为 true 时显示 VIP 徽章', () => {
    const wrapper = mount(UserCard, {
      props: { name: '小王', vip: true }
    })
    expect(wrapper.find('[data-test="vip-badge"]').exists()).toBe(true)
  })

  test('vip 为 false 时不显示徽章', () => {
    const wrapper = mount(UserCard, {
      props: { name: '小张' }
    })
    expect(wrapper.find('[data-test="vip-badge"]').exists()).toBe(false)
  })
})
```

> 💬 **老师备注**：为什么同时测 `vip=true` 和 `vip=false`？因为只测"显示"不测"不显示"是常见的漏测——你永远不知道哪天有人把 `v-if` 写成了 `v-show` 或者删掉了条件。

## 🔑 三、测试事件（emit）

### 3.1 被测组件

```
<!-- src/components/Counter.vue -->
<script setup>
import { ref } from 'vue'

const count = ref(0)
const emit = defineEmits(['update', 'reset'])

function increment() {
  count.value++
  emit('update', count.value)
}

function reset() {
  count.value = 0
  emit('reset')
}
</script>

<template>
  <div>
    <span data-test="count">{{ count }}</span>
    <button data-test="inc-btn" @click="increment">+1</button>
    <button data-test="reset-btn" @click="reset">重置</button>
  </div>
</template>
```

### 3.2 测试 emit

```js
// src/components/__tests__/Counter.test.js
import { mount } from '@vue/test-utils'
import Counter from '../Counter.vue'

describe('Counter 事件', () => {
  test('点击 +1 触发 update 事件', async () => {
    const wrapper = mount(Counter)

    await wrapper.find('[data-test="inc-btn"]').trigger('click')
    await wrapper.find('[data-test="inc-btn"]').trigger('click')

    // emitted() 返回所有事件记录
    const updateEvents = wrapper.emitted('update')
    expect(updateEvents).toHaveLength(2)       // 触发了 2 次
    expect(updateEvents[0]).toEqual([1])        // 第一次参数是 1
    expect(updateEvents[1]).toEqual([2])        // 第二次参数是 2
  })

  test('点击重置触发 reset 事件', async () => {
    const wrapper = mount(Counter)

    await wrapper.find('[data-test="inc-btn"]').trigger('click')
    await wrapper.find('[data-test="reset-btn"]').trigger('click')

    expect(wrapper.emitted('reset')).toHaveLength(1)
  })

  test('重置后计数归零', async () => {
    const wrapper = mount(Counter)

    await wrapper.find('[data-test="inc-btn"]').trigger('click')
    await wrapper.find('[data-test="inc-btn"]').trigger('click')
    await wrapper.find('[data-test="reset-btn"]').trigger('click')

    expect(wrapper.find('[data-test="count"]').text()).toBe('0')
  })
})
```

### 3.3 emitted() 的数据结构

```js
wrapper.emitted()
// {
//   'update': [[1], [2], [3]],   // 3 次 update，每次参数数组
//   'reset': [[]]                 // 1 次 reset，无参数
// }

wrapper.emitted('update')
// [[1], [2], [3]]
```

> 💬 **老师备注**：注意 `emitted('update')[0]` 返回的是 `[1]` 而不是 `1`。因为一个事件可以带多个参数 `emit('update', arg1, arg2)`，所以每次事件的参数都包在一个数组里。

## 🛠 四、测试 v-model 双向绑定

### 4.1 被测组件

```vue
<!-- src/components/SearchInput.vue -->
<script setup>
defineProps({ modelValue: String })
const emit = defineEmits(['update:modelValue'])
</script>

<template>
  <input
    data-test="input"
    :value="modelValue"
    @input="emit('update:modelValue', ($event.target).value)"
  />
</template>
```

### 4.2 测试代码

```js
import { mount } from '@vue/test-utils'
import SearchInput from '../SearchInput.vue'

test('输入文字后触发 update:modelValue', async () => {
  const wrapper = mount(SearchInput, {
    props: { modelValue: '' }
  })

  const input = wrapper.find('[data-test="input"]')
  await input.setValue('Vue 3')

  // 验证 emit
  expect(wrapper.emitted('update:modelValue')).toHaveLength(1)
  expect(wrapper.emitted('update:modelValue')[0]).toEqual(['Vue 3'])
})
```

`setValue()` 会依次触发 `input`、`change` 等事件，模拟真实用户输入。

> 💬 **老师备注**：从 Vue 3.4 开始可以用 `defineModel()` 简化 v-model，测试方式不变——`emitted('update:modelValue')` 一样用。

## 🔑 五、测试插槽（slot）

### 5.1 被测组件

```
<!-- src/components/Card.vue -->
<script setup>
defineProps({ title: String })
</script>

<template>
  <div class="card">
    <div class="card-header">{{ title }}</div>
    <div class="card-body">
      <slot />
    </div>
    <div class="card-footer">
      <slot name="footer" />
    </div>
  </div>
</template>
```

### 5.2 测试代码

```js
import { mount } from '@vue/test-utils'
import Card from '../Card.vue'

test('默认插槽渲染内容', () => {
  const wrapper = mount(Card, {
    props: { title: '公告' },
    slots: {
      default: '<p>这是卡片内容</p>'
    }
  })

  expect(wrapper.find('.card-body').text()).toContain('这是卡片内容')
})

test('命名插槽渲染 footer 内容', () => {
  const wrapper = mount(Card, {
    props: { title: '公告' },
    slots: {
      footer: '<button>确定</button>'
    }
  })

  expect(wrapper.find('.card-footer').text()).toContain('确定')
})
```

## ⚠️ 六、常见陷阱

### 陷阱 1：trigger 之后忘了 await

```js
// ❌ 没有 await，Vue 还没更新 DOM
wrapper.find('button').trigger('click')
expect(wrapper.text()).toContain('1')  // 可能失败

// ✅ 加 await
await wrapper.find('button').trigger('click')
expect(wrapper.text()).toContain('1')  // 稳定通过
```

### 陷阱 2：测试组件但不测边界情况

只测"正常传入"不测"不传/传错"，上线后用户一搞特殊操作就崩：

```js
// ✅ 好的测试覆盖
test('正常传入 name', () => { /* ... */ })
test('不传 name 时的默认值', () => { /* ... */ })
test('name 为空字符串', () => { /* ... */ })
test('name 特别长', () => { /* ... */ })
```

### 陷阱 3：用 wrapper.vm 直接改数据而不是模拟用户操作

```js
// ❌ 绕过了组件逻辑
wrapper.vm.count = 5

// ✅ 模拟真实用户操作
await wrapper.find('[data-test="inc-btn"]').trigger('click')
```

## 🧠 本节小结

- **核心三问**：输入 → 渲染（Props 给对，内容出对）、交互 → 输出（点击/输入触发正确事件）、状态 → 视图（内部状态变化驱动 UI 更新）
- **测 Props 双向**：既测"传入值正确渲染"，也测"不传时默认值生效"；`v-if` 控制的条件块要同时测显示与不显示两种分支
- **测 emit**：`wrapper.emitted('事件名')` 返回二维数组，`[0]` 取第一次事件的参数数组；事件多次触发用 `toHaveLength(2)` 验证次数
- **测 v-model**：`setValue('Vue 3')` 模拟输入 → 断言 `emitted('update:modelValue')` 参数；Vue 3.4+ 用 `defineModel` 后测试写法不变
- **测插槽**：`mount(Comp, { slots: { default: '...', footer: '...' } })` 传入插槽内容后验证渲染
- **三条红线**：trigger 后必须 `await`；别只测正常路径不测边界（默认值/空串/超长）；别用 `wrapper.vm` 直接改数据绕过组件逻辑
