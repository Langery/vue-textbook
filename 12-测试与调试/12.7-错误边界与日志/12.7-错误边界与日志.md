## 🤔 一、先讲一个事故

你做了一个电商 App。某天产品经理说："商品详情页要加一个推荐算法模块。"

你在商品详情页里加了一个 `<RecommendSection>` 组件，调用了一个新接口。一切看起来都正常，上线了。

结果第 2 天，运营冲过来："商品详情页全白了！什么都没有！"

排查后发现：推荐接口偶尔超时，`<RecommendSection>` 里一个未处理的异常导致**整个商品详情页**崩溃——连正常的商品图片、价格、购买按钮都跟着没了。

如果当时你给 `<RecommendSection>` 套了一层错误边界：它崩了，显示一行"推荐加载失败"——但商品信息、价格、购买按钮一切正常。损失会小得多。

**这就是错误边界的价值：局部组件出错，不影响整个页面。**

## 💡 二、onErrorCaptured：组件级错误边界

Vue 3 提供了 `onErrorCaptured` 生命周期钩子。父组件通过它捕获子组件抛出的错误。

### 2.1 基本用法

```vue
<!-- 父组件：ErrorBoundary.vue -->
<script setup>
import { ref, onErrorCaptured } from 'vue'

const hasError = ref(false)
const errorMessage = ref('')

onErrorCaptured((err, instance, info) => {
  hasError.value = true
  errorMessage.value = err.message

  // 日志上报（后面讲）
  console.error('捕获到子组件错误：', err.message, info)

  // return false → 阻止错误继续向上传播
  return false
})
</script>

<template>
  <div v-if="hasError" class="error-fallback">
    <p>😵 该模块加载失败</p>
    <p class="error-detail">{{ errorMessage }}</p>
    <button @click="hasError = false">重试</button>
  </div>
  <slot v-else />
</template>
```

`onErrorCaptured` 有三个参数：

| 参数 | 含义 | 示例 |
|------|------|------|
| `err` | 错误对象 | `new Error('网络请求失败')` |
| `instance` | 抛出错误的组件实例 | — |
| `info` | 描述错误来源的字符串 | `"setup function"`、`"render function"` |

**关键**：`return false` 阻止错误继续向上冒泡。如果不返回 false，错误会继续传到更上层的 `onErrorCaptured` 或全局错误处理器。

### 2.2 使用 ErrorBoundary 包装

```
<!-- 商品详情页 -->
<template>
  <div class="product-page">
    <ProductInfo :product="product" />
    <BuyButton :price="product.price" />

    <!-- 用 ErrorBoundary 包裹不稳定模块 -->
    <ErrorBoundary>
      <RecommendSection :product-id="product.id" />
    </ErrorBoundary>

    <ProductReviews :product-id="product.id" />
  </div>
</template>
```

现在 `<RecommendSection>` 崩了，只有它自己显示降级 UI，`ProductInfo`、`BuyButton`、`ProductReviews` 都正常工作。

> 💬 **老师备注**：`onErrorCaptured` 只能捕获**子组件**的错误。组件自身的错误它捕获不到。所以 ErrorBoundary 必须是"包装者"，不能给自己用。

### 2.3 完整的 ErrorBoundary 组件

```vue
<script setup>
import { ref, onErrorCaptured } from 'vue'

const hasError = ref(false)
const error = ref(null)

onErrorCaptured((err, instance, info) => {
  hasError.value = true
  error.value = err
  console.error(`[ErrorBoundary] ${info}:`, err)
  // 上报到日志服务
  reportError({ message: err.message, info, time: Date.now() })
  return false
})

function retry() {
  hasError.value = false
}

// 假装有日志上报函数
function reportError(data) {
  // 实际项目中，这里是调 Sentry 或自己的日志接口
  if (import.meta.env.PROD) {
    // fetch('/api/log', { method: 'POST', body: JSON.stringify(data) })
  }
}
</script>

<template>
  <div v-if="hasError" class="error-boundary">
    <p>模块加载失败，请重试</p>
    <button @click="retry">重试</button>
  </div>
  <slot v-else />
</template>
```

## 🔑 三、全局错误处理

### 3.1 app.config.errorHandler

当错误没有被子组件的 `onErrorCaptured` 捕获，它会一路冒泡到全局：

```js
// main.js
import { createApp } from 'vue'
import App from './App.vue'

const app = createApp(App)

app.config.errorHandler = (err, instance, info) => {
  console.error('全局错误:', err)

  // 生产环境上报
  if (import.meta.env.PROD) {
    sendToLogService({
      message: err.message,
      stack: err.stack,
      component: instance?.$.type?.name,
      info,
      time: new Date().toISOString()
    })
  }
}

app.mount('#app')
```

> 💬 **老师备注**：`errorHandler` 捕获错误后，Vue 依然会打印默认的错误日志。如果你不想在控制台看到红色报错，可以在开发环境判断后不打印。但建议开发环境让它报——方便调试。

### 3.2 window.onerror：最后的防线

有些错误（比如第三方脚本、图片加载失败）不会被 Vue 捕获。用浏览器原生的 `window.onerror` 兜底：

```js
window.onerror = (message, source, line, column, error) => {
  console.error('未捕获的全局错误:', message, source, line)
  // 上报...
}
```

## 🛠 四、生产环境的日志体系

### 4.1 开发 vs 生产

| | 开发环境 | 生产环境 |
|------|----------|----------|
| 错误展示 | 控制台红色报错 + 浏览器弹窗 | 静默上报，用户看不到 |
| 调试信息 | 完整的 stack trace | 脱敏后的关键信息 |
| 用户感知 | 应该让开发者立刻看到 | 降级 UI + 友好提示 |

### 4.2 日志该记什么

每条错误日志至少包含：

```js
const logEntry = {
  message: err.message,       // 错误信息
  stack: err.stack,           // 调用栈
  component: 'RecommendSection', // 哪个组件
  info: 'setup function',     // 在哪个阶段
  time: Date.now(),           // 时间戳
  user: 'userId-xxx',         // 用户标识（可选）
  url: window.location.href,  // 当前页面
}
```

### 4.3 主流日志服务

| 服务 | 特点 |
|------|------|
| **Sentry** | 开源、功能全、有免费额度 |
| **LogRocket** | 带录屏回放，可以看到用户操作 |
| **自建** | Node.js + Elasticsearch + Kibana |

对于课程项目，可以先不用第三方服务，自己在 `errorHandler` 里调用一个后端日志接口即可。重点在于"错误发生时你知道"——而不是靠用户截图来反馈。

## ⚠️ 五、常见陷阱

### 陷阱 1：ErrorBoundary 包裹了异步组件但没处理异步错误

```
<script setup>
// ❌ 异步组件自身的 Promise reject 不会被 onErrorCaptured 捕获
import { defineAsyncComponent } from 'vue'

const AsyncComp = defineAsyncComponent(() =>
  import('./HeavyComp.vue')
)
</script>
```

`defineAsyncComponent` 的加载错误有自己的一套处理机制（`onError` 选项），不走 `onErrorCaptured`。

### 陷阱 2：return false 用错了

```js
onErrorCaptured((err) => {
  console.error(err)
  // ❌ 忘了 return false，错误继续向上传播！
})

onErrorCaptured((err) => {
  console.error(err)
  return false  // ✅ 阻止传播
})
```

### 陷阱 3：生产环境把错误"藏"得太深

```js
// ❌ 生产环境静默吞掉所有错误，线上出 bug 完全不知道
app.config.errorHandler = () => {}

// ✅ 静默用户侧 + 上报开发侧
app.config.errorHandler = (err) => {
  sendToLogService(err)  // 上报
  // 不打印到控制台，用户看不到红字
}
```

## 🧠 本节小结

- **错误边界的价值**：局部组件出错只影响它自己——`ErrorBoundary` 包裹不稳定模块（如推荐位），崩了显示降级 UI，页面主体不受牵连
- **onErrorCaptured**：父组件捕获子组件错误，三个参数 `err / instance / info`；`return false` 阻止错误继续向上传播；注意它捕获不到组件自身错误，所以 ErrorBoundary 只能是"包装者"
- **三层防线**：组件级 `onErrorCaptured` → 全局 `app.config.errorHandler`（兜底 + 生产上报）→ `window.onerror`（第三方脚本等非 Vue 错误）
- **错误日志要素**：message、stack、component、info（阶段）、time、url，可选 user；开发环境让错误"炸"出来，生产环境静默上报 + 友好降级
- **上报方案**：Sentry（开源功能全）/ LogRocket（带录屏）/ 自建日志接口；课程项目先在 `errorHandler` 里打一个后端日志接口即可
- **三个陷阱**：`defineAsyncComponent` 加载失败走自己的 `onError` 不走 `onErrorCaptured`；忘 `return false` 会继续冒泡；生产别把错误"藏"死——静默用户侧但必须上报开发侧
