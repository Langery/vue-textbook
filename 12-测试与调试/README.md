## 🤔 这章讲什么、为什么、学完能干什么

**这章讲什么？**

前 11 章教你怎么把功能"写出来"，本章教你怎么把功能"写对、写稳"。内容包括两条线：**测试**（Vitest + Vue Test Utils 单元测试）和**调试**（DevTools、断点、Bug 排查、错误边界与日志）。

**为什么必须有这章？**

项目越大，改一处崩三处。没有测试，回归全靠肉眼；没有调试技巧，一个 Bug 查半天。测试与调试是区分"会写代码"和"专业工程师"的分水岭，也是第 13 章综合项目交付前的质量保障。

**学完能干什么？**

- 给组件写单元测试，改代码后一键回归
- 用 DevTools 快速定位数据不对、组件不渲染的问题
- 给应用加全局错误处理，单点崩溃不至于白屏
- 排查 Vue 特有的高频 Bug（key 问题、响应式丢失等）

> 🧑 **小白**：代码能跑就行，为什么要写测试？感觉是浪费时间啊。

> 🤖 **Vue 君**：等你的项目有 50 个组件，改一个按钮结果三个页面一起崩的时候，你会哭着回来补测试的……

> 👨🏫 **老湿**：测试与调试是"会写代码"和"专业工程师"的分水岭。第 13 章项目交付前，用这章的技巧过一遍，质量完全不一样。

> 💬 **老师备注**：本章不求你写出 100% 覆盖率的测试，但求建立"写完功能顺手测一下"的习惯——第 13 章项目做完，用本章的调试技巧过一遍，交付质量完全不同。

## 🛠 本章实战

1. 给一个计数器组件写 5 个测试（渲染 / 点击 / props / emit / v-model）
2. 用 `vi.mock` 模拟接口模块，测试异步数据组件
3. 用 Vue DevTools 的 Components 面板查看组件树并定位数据问题
4. 用 Network 面板排查一次"接口 500"的问题
5. 给应用注册全局错误处理器，崩溃时提示而不是白屏

---

## ⚠️ 学习提示

- **先跑通再深入**：先让 `npm run test` 跑起来，再学复杂断言和 mock。
- **测试不用求全**：优先测"用户最常走、最容易坏"的路径。
- **调试先看 Network**：90% 的"页面没数据"问题，在 Network 面板一眼就能看出来。
