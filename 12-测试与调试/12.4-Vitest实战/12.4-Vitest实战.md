## 🤔 一、Vitest 是什么？

Vitest 是一个基于 Vite 的测试框架，它跟 Vite 共用同一套配置和转换管道，所以速度极快，天然支持 TypeScript 和 ESM。

你用过的 `describe`、`test`、`expect` 这些 API 跟 Jest 几乎一样——如果你以前学过 Jest，切到 Vitest 基本零成本。

## 💡 二、测试套件的结构

一个标准的测试文件长这样：

```js
// src/utils/__tests__/math.test.js
import { describe, test, expect, beforeEach } from 'vitest'

// 1. 分组：把相关测试包在一起
describe('math 工具函数', () => {
  // 2. 钩子：每个测试前都会执行
  beforeEach(() => {
    // 初始化测试数据
  })

  // 3. 单个测试
  test('add(1,2) 应该返回 3', () => {
    expect(1 + 2).toBe(3)
  })

  test('空数组 length 为 0', () => {
    expect([].length).toBe(0)
  })
})
```

> 💬 **老师备注**：如果你配了 `globals: true`，`describe`、`test`、`expect` 不需要 import 直接用。但为了显式清晰，推荐保留 import。

### 2.1 describe：测试分组

```js
describe('UserStore', () => {
  describe('登录', () => {
    test('正确的账号密码 → 登录成功', () => {})
    test('错误的密码 → 返回错误提示', () => {})
  })

  describe('退出', () => {
    test('退出后清空 token', () => {})
  })
})
```

`describe` 可以嵌套，形成一个清晰的测试树。

### 2.2 四个生命周期钩子

```js
describe('示例', () => {
  beforeAll(() => console.log('所有测试开始前，执行 1 次'))
  beforeEach(() => console.log('每个测试开始前，都执行'))
  afterEach(() => console.log('每个测试结束后，都执行'))
  afterAll(() => console.log('所有测试结束后，执行 1 次'))
})
```

常用的是 `beforeEach`——每个测试前重置状态，避免测试之间互相污染。

## 🔑 三、常用断言速查

### 3.1 值比较

```js
// 基本类型用 toBe（严格相等 ===）
expect(2 + 2).toBe(4)
expect('hello').toBe('hello')

// 对象/数组用 toEqual（深度比较）
expect({ a: 1 }).toEqual({ a: 1 })
expect([1, 2, 3]).toEqual([1, 2, 3])

// toStrictEqual：更严格，undefined 的 key 也算
expect({ a: 1, b: undefined }).not.toStrictEqual({ a: 1 })
```

### 3.2 字符串和数组

```js
expect('Hello Vue 3').toContain('Vue')        // 包含子串
expect([1, 2, 3]).toContain(2)                // 包含元素
expect([1, 2, 3]).toHaveLength(3)             // 长度
expect('').toBeFalsy()                         // 假值
expect('有内容').toBeTruthy()                  // 真值
```

### 3.3 异常测试

```js
function throwError() {
  throw new Error('出错了！')
}

test('应该抛异常', () => {
  expect(() => throwError()).toThrow('出错了！')
})
```

### 3.4 数字比较

```js
expect(0.1 + 0.2).toBeCloseTo(0.3)  // 浮点数比较
expect(5).toBeGreaterThan(3)        // > 3
expect(5).toBeLessThan(10)          // < 10
```

## 🛠 四、异步测试

### 4.1 async/await

```js
// 被测函数
function fetchUser(id) {
  return new Promise((resolve) => {
    setTimeout(() => resolve({ id, name: '小明' }), 100)
  })
}

test('fetchUser 返回用户数据', async () => {
  const user = await fetchUser(1)
  expect(user).toEqual({ id: 1, name: '小明' })
})
```

> 💬 **老师备注**：如果你的测试函数用了 `async`，Vitest 会自动等待它完成。如果 `await` 后面的 Promise 被 `reject`，测试也会自动失败。

### 4.2 模拟定时器

真实等 100ms 太慢了，用 `vi.useFakeTimers()` 接管时间：

```js
import { vi } from 'vitest'

test('fetchUser 在 100ms 后返回', async () => {
  vi.useFakeTimers()          // 接管定时器

  const promise = fetchUser(1)

  vi.advanceTimersByTime(100) // 快进 100ms
  const user = await promise

  expect(user.name).toBe('小明')

  vi.useRealTimers()          // 恢复真实定时器
})
```

`vi.advanceTimersByTime(100)` 让所有定时器瞬间跳过 100ms，测试不用真的等。

## 🔑 五、Mock 技术

### 5.1 vi.fn()：创建 Mock 函数

Mock 函数可以记录它被调用了多少次、传了什么参数、返回了什么：

```js
test('mock 函数的基本用法', () => {
  const fn = vi.fn()

  fn('hello', 123)
  fn('world')

  expect(fn).toHaveBeenCalledTimes(2)           // 调用了 2 次
  expect(fn).toHaveBeenCalledWith('hello', 123)  // 某次调用参数
  expect(fn.mock.calls[0]).toEqual(['hello', 123]) // 第 1 次调用参数
})
```

你还可以控制 mock 函数的返回值：

```js
const fn = vi.fn()
fn.mockReturnValue('AAA')       // 每次调用都返回 'AAA'
fn.mockReturnValueOnce('BBB')   // 第一次返回 'BBB'

expect(fn()).toBe('BBB')  // 第一次
expect(fn()).toBe('AAA')  // 之后
```

### 5.2 vi.mock()：Mock 整个模块

当你想隔离测试、不让组件真的发 HTTP 请求时：

```js
// 假设 api.js 里有一个 fetchUsers 函数
import { fetchUsers } from '@/api/users'

// Mock 整个模块
vi.mock('@/api/users', () => ({
  fetchUsers: vi.fn(() =>
    Promise.resolve([{ id: 1, name: '小明' }])
  )
}))

test('mock 后调用 fetchUsers 返回假数据', async () => {
  const users = await fetchUsers()
  expect(users).toEqual([{ id: 1, name: '小明' }])
  expect(fetchUsers).toHaveBeenCalledTimes(1)
})
```

> 💬 **老师备注**：`vi.mock()` 必须放在文件最顶层（import 之后、测试之前）。Vitest 会自动把它提升到文件最前面执行。

### 5.3 实战：Mock API 测试组件

```vue
<!-- src/components/UserList.vue -->
<script setup>
import { ref, onMounted } from 'vue'
import { fetchUsers } from '@/api/users'

const users = ref([])
const loading = ref(true)

onMounted(async () => {
  users.value = await fetchUsers()
  loading.value = false
})
</script>

<template>
  <div>
    <p v-if="loading" data-test="loading">加载中...</p>
    <ul v-else>
      <li v-for="user in users" :key="user.id" data-test="user-item">
        {{ user.name }}
      </li>
    </ul>
  </div>
</template>
```

```js
// 测试
import { mount } from '@vue/test-utils'
import { vi } from 'vitest'
import UserList from '../UserList.vue'

vi.mock('@/api/users', () => ({
  fetchUsers: vi.fn(() => Promise.resolve([
    { id: 1, name: '张三' },
    { id: 2, name: '李四' }
  ]))
}))

test('加载完成后显示用户列表', async () => {
  const wrapper = mount(UserList)
  
  // 初始状态：显示加载中
  expect(wrapper.find('[data-test="loading"]').exists()).toBe(true)

  // 等异步完成
  await new Promise(resolve => setTimeout(resolve, 0))
  // 或者用：await wrapper.vm.$nextTick()（但更推荐上面的写法）

  // 加载完成后
  expect(wrapper.find('[data-test="loading"]').exists()).toBe(false)
  expect(wrapper.findAll('[data-test="user-item"]')).toHaveLength(2)
  expect(wrapper.text()).toContain('张三')
})
```

## 🛠 六、测试覆盖率

覆盖率告诉你"哪些代码被测试跑到了"：

```bash
npx vitest run --coverage
```

会生成一个 `coverage/` 目录，打开 `coverage/index.html` 看到：

| 指标 | 含义 |
|------|------|
| **Lines** | 代码行覆盖率 |
| **Functions** | 函数覆盖率 |
| **Branches** | 分支覆盖率（if/else、三元表达式） |
| **Statements** | 语句覆盖率 |

> 💬 **老师备注**：Branches 是最容易被忽略但最重要的指标。比如你测了 `if (vip)` 为 true 的情况，但忘了测 false——Branches 就会标出来。所以如果你的 Lines 很高但 Branches 很低，说明边界情况没测到。

## ⚠️ 七、常见陷阱

### 陷阱 1：Mock 之后忘记验证调用

```js
// ❌ Mock 了但没验证，mock 失效了你也不知道
vi.mock('@/api/users', () => ({ fetchUsers: vi.fn() }))
// 测试里没写 expect(fetchUsers).toHaveBeenCalled()

// ✅ Mock 后至少要验证是否被调用了
expect(fetchUsers).toHaveBeenCalled()
```

### 陷阱 2：异步测试没 return 或 await

```js
// ❌ 测试直接结束，Promise 还没 resolve
test('bad test', () => {
  fetchUser().then(user => {
    expect(user.name).toBe('小明')
  })
})

// ✅ 方案 1：return Promise
test('good test 1', () => {
  return fetchUser().then(user => {
    expect(user.name).toBe('小明')
  })
})

// ✅ 方案 2：async/await
test('good test 2', async () => {
  const user = await fetchUser()
  expect(user.name).toBe('小明')
})
```

### 陷阱 3：假定时器用完后没恢复

```js
test('用假定时器', () => {
  vi.useFakeTimers()
  // ...测试...
  // ❌ 忘了恢复！后续测试的 setTimeout 都坏了
})

// ✅ 方案 1：在 afterEach 中恢复
afterEach(() => {
  vi.useRealTimers()
})

// ✅ 方案 2：用 vi.useFakeTimers() 返回的 scope 自动恢复
```

## 🧠 本节小结

- **套件组织**：`describe` 可嵌套成测试树；`beforeEach` 最常用——每个用例前重置状态防互相污染；配了 `globals: true` 可不 import 直接用
- **断言速查**：基本类型 `toBe`、对象数组 `toEqual` / `toStrictEqual`、浮点 `toBeCloseTo`；`toContain` / `toHaveLength` / `toBeTruthy` / `toThrow` 覆盖常见场景
- **异步测试**：async 函数 Vitest 自动等待；`vi.useFakeTimers()` + `vi.advanceTimersByTime(100)` 快进时间，测完务必 `vi.useRealTimers()` 或放 `afterEach`
- **vi.fn()**：记录调用次数与参数（`toHaveBeenCalledTimes` / `mock.calls`），可用 `mockReturnValueOnce` 控制首次返回值
- **vi.mock()**：放文件顶层，把真实模块（如 `@/api/users`）换成假实现，让组件测试不依赖网络；Mock 后记得验证"确实被调用了"
- **覆盖率**：`npx vitest run --coverage` 生成 `coverage/index.html`，关注 Lines 之外的 **Branches**——它专抓 `if` 只测了 true 没测 false 的漏网情况
