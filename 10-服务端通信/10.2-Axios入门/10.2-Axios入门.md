## 🤔 一、为什么要用 Axios？

浏览器原生提供了 `fetch` API，可以发 HTTP 请求，那为什么还要装 Axios？

```js
// 原生 fetch：能跑，但写起来啰嗦
fetch('/api/products')
  .then(res => res.json())   // 多一步：手动转 JSON
  .then(data => console.log(data))
  .catch(err => console.error(err))
```

Axios 帮我们做了很多"脏活"：

| 功能 | fetch | Axios |
|---|---|---|
| 自动转 JSON | ❌ 手动 `res.json()` | ✅ 自动 |
| 请求 / 响应拦截 | ❌ 自己封装 | ✅ 内置 |
| 取消请求 | ❌ 较麻烦 | ✅ 内置 |
| 超时设置 | ❌ 较麻烦 | ✅ 一行配置 |
| 上传进度 | ❌ 较麻烦 | ✅ 内置 |

Vue 生态里 Axios 是事实标准，几乎所有教程和实战项目都用它。

## 💡 二、安装和第一次发请求

### 2.1 安装

```bash
npm install axios
```

### 2.2 在组件里引入并发请求

```vue
<script setup>
import axios from 'axios'
import { ref, onMounted } from 'vue'

const products = ref([])

// 组件挂载后自动发请求
onMounted(async () => {
  const response = await axios.get('https://jsonplaceholder.typicode.com/posts')
  products.value = response.data
})
</script>

<template>
  <ul>
    <li v-for="item in products" :key="item.id">{{ item.title }}</li>
  </ul>
</template>
```

> 💬 **老师备注**：`onMounted` 里发请求是常见做法——组件渲染完再拿数据，避免阻塞首屏。后面会讲更多发请求的时机。

## 🔑 三、Axios 的四种基本请求

RESTful API 对应四种操作，Axios 提供了对应的方法：

```js
// 获取列表
axios.get('/api/products')

// 获取详情（URL 里带 ID）
axios.get('/api/products/1')

// 新增
axios.post('/api/products', {
  name: 'iPhone 15',
  price: 5999
})

// 修改（完整更新）
axios.put('/api/products/1', {
  name: 'iPhone 15 Pro',
  price: 6999
})

// 删除
axios.delete('/api/products/1')
```

### 响应对象的结构

Axios 的响应不是一个纯 JSON，而是一个包装对象：

```js
const response = await axios.get('/api/products')
console.log(response)
// {
//   data: {...},      // ← 后端返回的数据（最常用，可以是任意 JSON：对象/数组/字符串）
//   status: 200,      // HTTP 状态码
//   statusText: 'OK',
//   headers: {...},   // 响应头
//   config: {...}     // 这次请求的配置
// }

// 实际拿数据：response.data
const products = response.data
```

## 🛠 四、async / await 完整写法

`async / await` 让异步代码写起来像同步代码，是配合 Axios 最推荐的写法。

### 4.1 基本套路

```
<script setup>
import axios from 'axios'
import { ref } from 'vue'

const user = ref(null)
const loading = ref(false)
const error = ref('')

const fetchUser = async () => {
  loading.value = true
  error.value = ''

  try {
    const res = await axios.get('https://jsonplaceholder.typicode.com/users/1')
    user.value = res.data
  } catch (err) {
    // 请求失败进这里：网络错误、404、500 都会触发
    error.value = '获取用户信息失败，请稍后重试'
    console.error(err)
  } finally {
    loading.value = false
  }
}
</script>

<template>
  <button @click="fetchUser" :disabled="loading">
    {{ loading ? '加载中...' : '获取用户信息' }}
  </button>

  <p v-if="error" style="color: red;">{{ error }}</p>

  <div v-if="user">
    <p>姓名：{{ user.name }}</p>
    <p>邮箱：{{ user.email }}</p>
  </div>
</template>
```

### 4.2 try / catch / finally 各自负责什么

| 部分 | 作用 |
|---|---|
| `try` | 放可能出错的代码（发请求） |
| `catch` | 请求失败时执行（网络断了、后端崩了） |
| `finally` | 无论成功失败都执行（通常用来关闭 loading） |

> 💬 **老师备注**：很多同学习惯只写 `try`，不写 `catch`——生产环境一定要写！否则网络一断，用户看到的就是空白页面，没有任何提示。

## ⚠️ 五、常见陷阱

### 陷阱 1：忘记 `.value`（Vue 新手经典错误）

```js
const products = ref([])

// ❌ 错误：直接改 products，不是 products.value
products = await axios.get('/api/products')   // 报错！ref 不能重新赋值

// ❌ 错误：忘记 .value
products = response.data                       // products 还是 ref 对象

// ✅ 正确
products.value = response.data
```

### 陷阱 2：await 外面拿数据，拿到 undefined

```js
const fetchData = async () => {
  const res = await axios.get('/api/products')
  return res.data
}

// ❌ 错误：fetchData 是 async 函数，返回的是 Promise
const data = fetchData()     // data 是一个 Promise，不是数据本身

// ✅ 正确：在 async 函数里 await
const data = await fetchData()
```

### 陷阱 3：并发请求写串行，慢

```js
// ❌ 慢：两个请求没有依赖，却一个等一个
const user = await axios.get('/api/user')
const orders = await axios.get('/api/orders')

// ✅ 快：同时发，等两个都完成
const [userRes, ordersRes] = await Promise.all([
  axios.get('/api/user'),
  axios.get('/api/orders')
])
```

## 🧠 本节小结

- **为什么要用 Axios**：自动转 JSON、拦截器、取消请求、超时配置，比原生 fetch 省心，是 Vue 社区事实标准
- **安装引入**：`npm install axios` + `import axios from 'axios'`
- **基本请求**：`get / post / put / delete` 对应增删改查，真正拿到的数据在 `response.data`
- **推荐写法**：`async / await` + `try / catch / finally`，千万别漏 catch
- **三个高频坑**：忘了 `.value`、直接拿 async 函数的返回值、无依赖的请求写成串行
