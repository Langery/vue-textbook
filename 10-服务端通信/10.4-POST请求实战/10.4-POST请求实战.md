## 🤔 一、POST 请求是干嘛的？

GET 是"拿数据"，POST 是"交数据"——比如发布一篇文章、提交一个订单、注册一个新用户。

```text
POST /api/posts
请求体（JSON）：
{
  "title": "我的第一篇博客",
  "body": "今天学了 Vue，真开心！",
  "userId": 1
}

→ 响应（201 Created）：
{
  "id": 101,           ← 后端生成的新 ID
  "title": "我的第一篇博客",
  "body": "今天学了 Vue，真开心！",
  "userId": 1
}
```

和 GET 的最大区别：**POST 有请求体（Body）**，数据不是拼在 URL 里，而是放在请求体里发给后端。

GET 和 POST 是 HTTP 里最常出双入对的一对，把区别摊开看：

| 对比维度 | GET | POST |
|---|---|---|
| 用途 | 获取数据（查） | 新增数据（增） |
| 请求体 | 无（数据拼在 URL） | 有（JSON 等放在 body） |
| 数据位置 | URL 查询字符串（`?userId=1`） | 请求体（`{ title, body }`） |
| 安全性 | 低（URL 可见、会被记录） | 相对高（body 不暴露在 URL） |
| 幂等性 | 幂等（重复请求结果一样） | 不幂等（重复提交会创建多条） |
| 成功状态码 | 200 | 201 Created |
| 典型场景 | 列表、详情、搜索 | 发布文章、提交订单、注册 |

## 💡 二、实战：发布新文章

做一个"写文章"的表单，提交后把文章加到列表里。

### 2.1 表单页面

```vue
<script setup>
import axios from 'axios'
import { ref } from 'vue'

const title = ref('')
const body = ref('')
const submitting = ref(false)

const submit = async () => {
  // 前端验证：提交前先检查
  if (!title.value.trim()) {
    alert('标题不能为空')
    return
  }
  if (!body.value.trim()) {
    alert('内容不能为空')
    return
  }

  submitting.value = true

  try {
    const res = await axios.post(
      'https://jsonplaceholder.typicode.com/posts',
      {
        title: title.value,
        body: body.value,
        userId: 1
      }
    )

    // 成功：清空表单，提示用户
    alert('发布成功！新文章 ID：' + res.data.id)
    title.value = ''
    body.value = ''
  } catch (err) {
    alert('发布失败，请稍后重试')
    console.error(err)
  } finally {
    submitting.value = false
  }
}
</script>

<template>
  <h1>发布新文章</h1>

  <div>
    <label>标题：</label>
    <input v-model="title" placeholder="输入文章标题" style="width: 300px;" />
  </div>

  <div style="margin-top: 12px;">
    <label>内容：</label><br />
    <textarea
      v-model="body"
      rows="6"
      placeholder="输入文章内容"
      style="width: 300px;"
    ></textarea>
  </div>

  <button @click="submit" :disabled="submitting" style="margin-top: 12px;">
    {{ submitting ? '发布中...' : '发布' }}
  </button>
</template>
```

> 💬 **老师备注**：JSONPlaceholder 是模拟 API，POST 请求并不会真的把数据存到服务器——它返回的是模拟的成功响应（每次返回的 `id` 都是 101）。但这不影响我们学习 POST 的用法，因为真实后端的行为是一样的。

## 🔑 三、新增成功后更新列表（不刷新页面）

实际场景中，发布文章后通常会跳回列表页，并且新文章要出现在列表里。有两种做法：

**做法 1**：提交成功后重新发 GET 请求拉列表（简单，但多一次请求）

```js
const submit = async () => {
  await axios.post('/api/posts', { title: title.value, body: body.value })
  // 重新拉列表
  const res = await axios.get('/api/posts')
  posts.value = res.data
}
```

**做法 2**：把后端返回的新数据直接塞进列表（推荐，无刷新、无额外请求）

```
<script setup>
import axios from 'axios'
import { ref, onMounted } from 'vue'

const posts = ref([])
const title = ref('')
const body = ref('')

// 页面加载时拉列表
onMounted(async () => {
  const res = await axios.get('https://jsonplaceholder.typicode.com/posts?_limit=5')
  posts.value = res.data
})

// 提交文章
const submit = async () => {
  try {
    const res = await axios.post(
      'https://jsonplaceholder.typicode.com/posts',
      { title: title.value, body: body.value, userId: 1 }
    )
    // 把新文章塞到列表最前面
    posts.value.unshift(res.data)
    title.value = ''
    body.value = ''
    alert('发布成功！')
  } catch (err) {
    alert('发布失败')
  }
}
</script>

<template>
  <h1>发布文章</h1>

  <div>
    <input v-model="title" placeholder="标题" />
    <textarea v-model="body" placeholder="内容"></textarea>
    <button @click="submit">发布</button>
  </div>

  <h2>文章列表</h2>
  <ul>
    <li v-for="post in posts" :key="post.id">
      {{ post.title }}
    </li>
  </ul>
</template>
```

> 💬 **老师备注**：`unshift` 把新元素加到数组最前面，这样新文章会出现在列表顶部。如果用 `push`，新文章会出现在列表底部。

## 🛠 四、POST 请求的响应处理

后端对 POST 请求的成功响应通常是 **201 Created**（而不是 200），并且响应体里会返回**新创建的资源**，包含后端生成的 ID。

```js
const res = await axios.post('/api/posts', newPost)

// res.status === 201  ← 表示创建成功
// res.data            ← 新创建的文章对象，包含后端生成的 id

console.log('新文章 ID：', res.data.id)
```

**不要信任前端自己生成的 ID**。比如你前端临时给新文章一个 `id: Date.now()`，但后端返回的才是真实 ID，后续操作（编辑、删除）必须用后端的 ID。

```js
// ❌ 错误：用前端自己生成的 ID
const fakeId = Date.now()
posts.value.unshift({ id: fakeId, ...newPost })

// ✅ 正确：用后端返回的 ID
posts.value.unshift(res.data)   // res.data 里包含后端生成的真实 id
```

## ⚠️ 五、常见陷阱

### 陷阱 1：POST 的数据格式不对

Axios 默认把请求体序列化成 JSON，并自动设置 `Content-Type: application/json`。但如果你直接传 FormData，Axios 也会自动处理：

```js
// 发送 JSON（最常见，Axios 自动设置 Content-Type）
axios.post('/api/posts', {
  title: 'Hello',
  body: 'World'
})

// 发送 FormData（上传文件时用）
const formData = new FormData()
formData.append('title', 'Hello')
formData.append('file', fileInput.files[0])
axios.post('/api/posts', formData)
// Axios 会自动设置 Content-Type: multipart/form-data
```

### 陷阱 2：提交按钮放在 `<form>` 里，点按钮页面刷新

```vue
<!-- ❌ 错误：button 在 form 里，默认 type="submit"，会刷新页面 -->
<form>
  <input v-model="title" />
  <button @click="submit">发布</button>   ← 一点就刷新！
</form>
```

解决办法：用 `@click.prevent`，或者把 `button` 的 `type` 设为 `button`：

```
<!-- ✅ 解决 1：阻止默认行为 -->
<button @click.prevent="submit">发布</button>

<!-- ✅ 解决 2：显式声明 type -->
<button type="button" @click="submit">发布</button>
```

### 陷阱 3：重复提交（用户狂点按钮）

用户点一次"发布"，请求还没回来，又点了一下——导致发了两次 POST，后端创建了两条一样的数据。

```js
const submit = async () => {
  if (submitting.value) return   // ← 正在提交时，直接返回，不重复发
  submitting.value = true
  // ...
}
```

## 🧠 本节小结

- **GET vs POST**：GET 拿数据没请求体，POST 交数据有请求体（JSON）；POST 成功通常是 201 Created
- **发 POST**：`axios.post(url, 数据对象)`，Axios 自动序列化 JSON 并设置 `Content-Type: application/json`；传 FormData 会自动转 `multipart/form-data`
- **成功后更新列表**：推荐把后端返回的新对象 `unshift` 进数组（无刷新、无额外请求），而不是重新拉一次列表
- **ID 以后端为准**：不要信任前端 `Date.now()` 之类自造的 ID，编辑/删除要用后端返回的真实 ID
- **三大坑**：`<form>` 里按钮默认 submit 会刷新页面（用 `@click.prevent` 或 `type="button"`）；`submitting` 标志位防止重复提交；前端验证后仍需后端验证兜底
