## 🤔 一、问题：每个组件都在写重复代码

回顾前面几节的例子，每个组件发请求都是这样的：

```js
const res = await axios.get('https://jsonplaceholder.typicode.com/posts')
```

项目小了还好。等你有 30 个组件、后端地址换了一次、每个请求都要带 token 的时候，麻烦就来了：

```js
// 组件 A
axios.get('https://api.mysite.com/v1/products', {
  headers: { Authorization: `Bearer ${localStorage.getItem('token')}` }
})

// 组件 B
axios.get('https://api.mysite.com/v1/orders', {
  headers: { Authorization: `Bearer ${localStorage.getItem('token')}` }
})

// 组件 C ... 30 个组件，每个都写一遍
```

后端地址一换（比如加了 `/v2`），你得改 30 个文件。

**解决办法**：把公共逻辑抽到一个地方。这就是 Axios 实例 + 拦截器要做的事。

## 💡 二、Axios 实例：把公共配置抽出来

### 2.1 创建实例文件

实战中，项目里通常会有一个 `utils/request.js`（或 `api/axios.js`），专门创建 Axios 实例并导出：

```js
// src/utils/request.js
import axios from 'axios'

// 创建一个"定制版"的 axios
const request = axios.create({
  baseURL: 'https://api.mysite.com/v1',   // 所有请求共用这个前缀
  timeout: 10000,                          // 10 秒超时，超了自动报错
  headers: {
    'Content-Type': 'application/json'     // 默认请求头
  }
})

export default request
```

### 2.2 组件里用它

```js
// 组件里——URL 只写后半段就行
import request from '@/utils/request'

const res = await request.get('/posts')       // 实际请求：https://api.mysite.com/v1/posts
const res = await request.post('/orders', {}) // 实际请求：https://api.mysite.com/v1/orders
```

改后端地址？只改 `request.js` 里一行 `baseURL`，所有组件自动生效。

> 💬 **老师备注**：`@` 是 Vite 项目里的路径别名，指向 `src` 目录。没配置的话用相对路径 `../utils/request` 也行。

## 🔑 三、拦截器：在请求/响应的路上"插一脚"

拦截器是 Axios 最强大的功能，分两种：

- **请求拦截器**：请求发出去之前执行（比如加 token）
- **响应拦截器**：响应回来之后、组件拿到之前执行（比如统一弹错误提示）

### 3.1 请求拦截器：自动带 token

后端接口通常要求登录后每个请求带上 token，放在请求头的 `Authorization` 字段里。与其每个组件手动加，不如在拦截器里统一加：

```js
// src/utils/request.js
import axios from 'axios'

const request = axios.create({
  baseURL: 'https://api.mysite.com/v1',
  timeout: 10000
})

// ─── 请求拦截器 ───
request.interceptors.request.use(
  (config) => {
    // 发请求之前，从 localStorage 拿 token 塞进去
    const token = localStorage.getItem('token')
    if (token) {
      config.headers.Authorization = `Bearer ${token}`
    }
    return config   // ⚠️ 必须 return config，否则请求发不出去
  },
  (error) => {
    // 请求配置出错时进这里
    return Promise.reject(error)
  }
)

export default request
```

以后任何组件用 `request` 发请求，都会自动带 token——不需要组件操一点心。

### 3.2 响应拦截器：统一处理错误

```js
// ─── 响应拦截器 ───
request.interceptors.response.use(
  (response) => {
    // 2xx 状态码进这里
    // 可以直接返回 response.data，省得组件里每次都 .data
    return response.data
  },
  (error) => {
    // 非 2xx 状态码进这里
    if (error.response) {
      const status = error.response.status

      switch (status) {
        case 401:
          // token 过期或未登录 → 跳登录页
          localStorage.removeItem('token')
          window.location.href = '/login'
          break
        case 403:
          alert('没有权限访问')
          break
        case 500:
          alert('服务器繁忙，请稍后重试')
          break
        default:
          alert(`请求失败（${status}）`)
      }
    } else {
      // 根本没有收到响应（网络断了、超时等）
      alert('网络异常，请检查网络连接')
    }

    return Promise.reject(error)   // 继续抛出，让组件里的 catch 也能拿到
  }
)
```

> 💬 **老师备注**：如果响应拦截器里返回了 `response.data`（解包），那组件里 `await request.get(...)` 拿到的就直接是数据，不用再 `.data`。但有些团队不喜欢这样——因为组件里看不出是 Axios 响应还是纯数据。两种写法都可以，保持团队统一就行。

## 🛠 四、完整示例：从配置到组件

### 4.1 `request.js` 完整版

```js
// src/utils/request.js
import axios from 'axios'

const request = axios.create({
  baseURL: import.meta.env.VITE_API_BASE_URL || '/api',   // 用环境变量，方便切换环境
  timeout: 10000
})

// 请求拦截器
request.interceptors.request.use(
  (config) => {
    const token = localStorage.getItem('token')
    if (token) {
      config.headers.Authorization = `Bearer ${token}`
    }
    return config
  },
  (error) => Promise.reject(error)
)

// 响应拦截器
request.interceptors.response.use(
  (response) => response.data,
  (error) => {
    if (error.response) {
      const { status, data } = error.response
      if (status === 401) {
        localStorage.removeItem('token')
        window.location.href = '/login'
      } else {
        alert(data?.message || `请求失败（${status}）`)
      }
    } else {
      alert('网络异常，请检查网络连接')
    }
    return Promise.reject(error)
  }
)

export default request
```

### 4.2 组件里用起来

```vue
<script setup>
import request from '@/utils/request'
import { ref, onMounted } from 'vue'

const posts = ref([])

onMounted(async () => {
  // 不用写完整 URL，不用手动加 token，不用手动 .data（如果拦截器解包了）
  posts.value = await request.get('/posts')
})
</script>
```

对比一下改造前后：

| | 改造前 | 改造后 |
|---|---|---|
| **URL** | `https://api.xxx.com/v1/posts` | `/posts` |
| **token** | 每个组件手动加 | 拦截器自动加 |
| **错误处理** | 每个组件 try-catch | 拦截器统一弹提示 |
| **超时** | 手动设 | `create` 时一行搞定 |

## ⚠️ 五、常见陷阱

### 陷阱 1：拦截器里忘了 `return config`

```js
// ❌ 错误：没有 return config，请求发不出去，也不报错
request.interceptors.request.use((config) => {
  config.headers.Authorization = `Bearer ${token}`
  // 忘了 return config
})

// ✅ 正确
request.interceptors.request.use((config) => {
  config.headers.Authorization = `Bearer ${token}`
  return config
})
```

### 陷阱 2：在 `main.js` 里直接改全局 `axios.defaults`

```js
// ❌ 不推荐：改动全局 axios，影响范围太大
axios.defaults.baseURL = 'https://api.xxx.com'
axios.defaults.headers.common['Authorization'] = 'Bearer xxx'
```

虽然能用，但如果你项目里有多个后端（比如订单服务和用户服务是不同的 baseURL），全局配置就不好使了。**建议统一用 `axios.create` 创建实例**。

### 陷阱 3：响应拦截器里重复弹 alert

如果响应拦截器已经弹了 `alert('服务器繁忙')`，组件里又 `catch` 再弹一次，用户会被弹两次。

```js
// 组件里
try {
  await request.get('/posts')
} catch (err) {
  alert('加载失败')   // ← 这行和拦截器里的 alert 会一起弹！
}
```

**解决办法**：拦截器负责通用提示（比如 500、网络异常），组件只处理业务相关的错误（比如"该订单已取消"）。

## 🧠 本节小结

- **为什么要封装**：几十个组件重复写完整 URL / token / 错误处理，改一处要动全盘；用 `axios.create` 建实例，`baseURL` / `timeout` 只写一次
- **请求拦截器**：请求发出前执行，典型用途是自动注入 `Authorization: Bearer <token>`；⚠️ 必须 `return config`，否则请求发不出去
- **响应拦截器**：响应回来、组件拿到之前执行，统一处理 401 跳登录、403/500 弹提示；可按团队约定直接 `return response.data` 解包
- **别动全局 `axios.defaults`**：多后端场景会互相污染，统一用 `axios.create` 创建独立实例
- **提示别重复**：拦截器已统一弹错时，组件 `catch` 只处理业务相关错误，避免用户被 alert 轰炸
