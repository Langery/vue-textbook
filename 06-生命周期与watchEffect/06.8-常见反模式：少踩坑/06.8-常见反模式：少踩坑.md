## 🤔 什么是"反模式"？

**反模式（Anti-Pattern）= 看起来能用、实际上会坑你的写法。**

这些写法在简单场景下可能没事，但一旦数据复杂、用户操作频繁、组件嵌套深，就会暴露 bug。下面列出本章知识点最常踩的 6 个坑。

---

## 💡 反模式 1：watch + ref 赋值 → 该用 computed

### 症状

```javascript
// ❌ 反模式
const price = ref(100)
const quantity = ref(2)
const total = ref(0)

watch(
  [price, quantity],
  ([p, q]) => {
    total.value = p * q  // 纯计算！不需要 watch
  }
)
```

### 问题
- `total` 只是一个"根据 `price` 和 `quantity` 算出来的值"，不需要副作用
- 用 `watch` 多写了 4 行代码，还丢了 `computed` 的缓存

### 修复

```javascript
// ✅ 正确：用 computed
const total = computed(() => price.value * quantity.value)
```

---

## 💡 反模式 2：忘记 `deep: true`

### 症状

```javascript
// ❌ 反模式
const list = ref([1, 2, 3])

watch(list, (newList) => {
  console.log('列表变了', newList)
})

// 用户点"添加"
function addItem() {
  list.value.push(4)  // ❌ watch 没触发！list.value 引用没变
}
```

### 问题
`ref([])` 包装的数组，`.push()` 不会改变引用，`watch` 默认只比较引用。

### 修复

```javascript
// ✅ 方案 1：加 deep: true
watch(list, (newList) => {
  console.log('列表变了', newList)
}, { deep: true })

// ✅ 方案 2：用 reactive
const list = reactive([1, 2, 3])
watch(list, () => { /* 自动 deep */ })

// ✅ 方案 3：用 getter 监听长度
watch(() => list.value.length, () => { /* 精准监听 */ })
```

---

## 💡 反模式 3：`deep: true` 滥用

### 症状

```javascript
// ❌ 反模式
const bigData = ref({
  // 假设这是一个 10 万行的表格数据
  rows: [/* ... 大量数据 ... */],
  config: { /* ... */ }
})

// deep: true → Vue 递归遍历所有属性 → 性能灾难
watch(bigData, () => {
  updateChart()
}, { deep: true })
```

### 问题
`deep: true` 让 Vue 递归遍历整个对象/数组的每一层。数据越大，性能越差。

### 修复

```javascript
// ✅ 精准监听：只监听需要关心的字段
watch(
  () => bigData.value.rows.length,
  (newLen) => {
    console.log(`行数变为 ${newLen}`)
  }
)

// ✅ 或者只监听某个配置
watch(
  () => bigData.value.config.theme,
  (newTheme) => {
    applyTheme(newTheme)
  }
)
```

## 💡 反模式 4：watchEffect 依赖追踪盲区

### 症状

```javascript
// ❌ 反模式
const count = ref(0)

watchEffect(() => {
  if (count.value > 10) {
    console.log('大于 10！')  // count 从 0 到 5：没触发（条件没进）
  }
})
// 期望：count 任何变化都触发
// 实际：只有 count 从 ≤10 变到 >10 的那一次才触发
```

### 问题
`watchEffect` 只在**实际执行到的代码路径**中追踪依赖。`count.value` 在 `if` 分支里，条件不满足时根本不会读到 `count.value` → 没追踪。

### 修复

```javascript
// ✅ 方案 1：把依赖读到分支外
watchEffect(() => {
  const c = count.value  // 先读，保证被追踪
  if (c > 10) {
    console.log('大于 10！')
  }
})

// ✅ 方案 2：如果只需要">10 才触发"，用 watch
watch(count, (newVal) => {
  if (newVal > 10) {
    console.log('大于 10！')
  }
})
```

## 💡 反模式 5：忘记清理副作用

### 症状

```javascript
// ❌ 反模式
const roomId = ref('room-1')

watch(roomId, (newId) => {
  // 每次 roomId 变化，创建一个新的 WebSocket
  const ws = new WebSocket(`wss://chat.example.com/${newId}`)
  ws.onmessage = (e) => { /* 处理消息 */ }
  // ❌ 没有关闭旧的 WebSocket！房间切了 5 次 → 5 个连接并存！
})
```

### 问题
- 旧连接没断开 → 内存泄漏 + 网络资源浪费
- 组件卸载后连接还在 → 幽灵连接

### 修复

```javascript
// ✅ 正确：用 onWatcherCleanup 清理
import { watch, onWatcherCleanup } from 'vue'

watch(roomId, (newId) => {
  const ws = new WebSocket(`wss://chat.example.com/${newId}`)
  ws.onmessage = (e) => { /* 处理消息 */ }

  onWatcherCleanup(() => {
    ws.close()  // 清理旧连接！
  })
})
```

## 💡 反模式 6：watch 监听 props 未处理 undefined

### 症状

```javascript
// ❌ 反模式
const props = defineProps({
  userId: Number
})

// props.userId 初始可能是 undefined（父组件还没传）
watch(() => props.userId, (newId) => {
  fetchUserData(newId)  // newId 可能是 undefined → 请求 /api/user/undefined
})
```

### 问题
父组件异步加载数据时，子组件的 props 初始值为 `undefined`，watch 的 `immediate: true` 或首次触发时会用 `undefined` 调用回调。

### 修复

```javascript
// ✅ 加空值判断
watch(() => props.userId, (newId) => {
  if (newId == null) return  // 跳过 undefined / null
  fetchUserData(newId)
})

// ✅ 或者用 computed 提供默认值
const safeUserId = computed(() => props.userId ?? 0)
watch(safeUserId, (newId) => {
  if (newId > 0) fetchUserData(newId)
})
```

## 📋 反模式速查总表

| # | 反模式 | 快速诊断 | 修复 |
|---|---|---|---|
| 1 | watch 里只做赋值 | 回调里只有 `ref.value = ...` | 改 `computed` |
| 2 | 忘加 `deep: true` | `.push()` / `.splice()` 不触发 | 加 `deep: true` 或用 `reactive` |
| 3 | `deep: true` 滥用 | 监听大对象，表格卡顿 | 改用 getter 精准监听 |
| 4 | 依赖追踪盲区 | `if` 分支里的数据不追踪 | 把依赖读操作提到分支外 |
| 5 | 忘记清理副作用 | 定时器/WebSocket 一直在跑 | `onWatcherCleanup` |
| 6 | props 未处理 undefined | `undefined` 触发请求 | 加空值守卫 |

---

## 🧠 本节小结

- **反模式 1**：watch 回调里只做 `ref.value = ...` → 改用 computed
- **反模式 2**：监听 ref 数组忘 `deep: true`，`.push()` 不触发 → 加 deep 或用 reactive
- **反模式 3**：`deep: true` 滥用监听大对象 → 用 getter 精准监听
- **反模式 4**：watchEffect 里依赖写在 `if` 分支内不被追踪 → 依赖读操作提到分支外
- **反模式 5**：忘记清理副作用 → `onWatcherCleanup` 或 `onUnmounted`
- **反模式 6**：watch props 没处理 undefined → 空值守卫或用 computed 默认值
- **排查方法**：症状（现象）→ 原因 → 修复三列自查，先看"该不该用 watch"再看"写法对不对"
