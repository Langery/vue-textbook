```text
│   └── 与 onMounted 成对出现
└── 模板引用（template ref）

```

不少新手把"在 setup 里直接发请求"和"在 onMounted 里发请求"混着写，结果时好时坏：有时能拿 DOM、有时拿不到，图表时渲染时空白。原因很简单——setup 执行时组件还没挂到页面上。`onMounted` 系列钩子就是给"时机敏感"操作兜底的，本节讲清各钩子触发时机与成对清理套路。

## 🤔 一、`onMounted`——最常用的生命周期钩子

`onMounted` 是 Vue 组件开发里用得最多的钩子。一句话：**"等组件渲染好了，再做事"**。

### 典型场景

| 场景 | 为什么放在 onMounted |
|---|---|
| 发请求获取数据 | DOM 渲染完了再展示数据，体验好 |
| 初始化 ECharts / 地图 | 需要拿到真实的 DOM 容器 |
| `element.focus()` | 需要元素已经在页面上 |
| 获取元素宽高 | 需要 DOM 渲染完毕才有尺寸 |
| 第三方库初始化 | 大部分第三方库需要真实 DOM |

## 🛠 二、完整可运行示例

### 示例 1：模板引用 + onMounted

```vue
<script setup>
import { ref, onMounted } from 'vue'

// 模板引用：type ref="inputRef" 绑定到下面 input 元素
const inputRef = ref(null)

onMounted(() => {
  // ✅ onMounted 中可以安全访问 DOM
  console.log(inputRef.value)  // <input> 元素
  inputRef.value?.focus()      // 自动聚焦
})
</script>

<template>
  <div>
    <label>用户名：</label>
    <!-- ref 绑定 Vue 模板引用 -->
    <input ref="inputRef" placeholder="输入用户名" />
    <p>页面一打开，输入框自动聚焦</p>
  </div>
</template>
```

### 示例 2：初始化 ECharts 图表

```
<script setup>
import { ref, onMounted, onUnmounted, watch } from 'vue'
import * as echarts from 'echarts'

const chartRef = ref(null)
let chart = null
const data = ref([120, 200, 150, 80, 70, 110, 130])

onMounted(() => {
  // 1. 初始化图表（需要真实 DOM 容器）
  chart = echarts.init(chartRef.value)

  // 2. 设置配置项和数据
  chart.setOption({
    xAxis: { data: ['周一','周二','周三','周四','周五','周六','周日'] },
    yAxis: {},
    series: [{ type: 'bar', data: data.value }]
  })
})

// 监听数据变化，更新图表
watch(data, (newData) => {
  chart?.setOption({ series: [{ data: newData }] })
}, { deep: true })

onUnmounted(() => {
  // 3. 组件卸载时销毁图表实例
  chart?.dispose()
  chart = null
})
</script>

<template>
  <div>
    <div ref="chartRef" style="width: 100%; height: 300px"></div>
    <button @click="data.push(Math.floor(Math.random() * 300))">添加数据</button>
  </div>
</template>
```

### 示例 3：页面停留时长统计

```vue
<script setup>
import { onMounted, onUnmounted } from 'vue'

let enterTime = null

onMounted(() => {
  // 记录进入时间
  enterTime = Date.now()
  console.log('进入页面')
})

onUnmounted(() => {
  // 计算停留时长
  const duration = Math.floor((Date.now() - enterTime) / 1000)
  console.log(`离开页面，停留了 ${duration} 秒`)
  // 实际上可以发送一个埋点请求
  // navigator.sendBeacon('/api/stay', JSON.stringify({ duration }))
})
</script>

<template>
  <p>留一会儿，然后切到别的页面。打开控制台看日志。</p>
</template>
```

## 🔍 三、`onUpdated`——能用但尽量不用

`onUpdated` 在 DOM 更新后触发。听起来很有用，但**很容易踩坑**。

```
<script setup>
import { ref, onUpdated } from 'vue'

const count = ref(0)

// ⚠️ 危险！count 变了 → onUpdated → 又改 count → 死循环
onUpdated(() => {
  count.value++  // 找死！
})
</script>
```

### 什么时候该用？

```vue
<script setup>
import { ref, onUpdated, nextTick } from 'vue'

const list = ref([])
const listRef = ref(null)

// 添加新项后，自动滚动到底部
async function addItem() {
  list.value.push(`项目 ${list.value.length + 1}`)
  // 等 DOM 更新完成
  await nextTick()
  listRef.value?.lastElementChild?.scrollIntoView({ behavior: 'smooth' })
}
</script>
```

> 💬 **老师备注**：`nextTick` 比 `onUpdated` 更安全——它是"一次性"的等待，不会造成循环。大多数"等 DOM 更新后做某事"的场景，`nextTick` 是最好的选择。

## ⚠️ 四、`onMounted` / `onUnmounted` 的配对原则

**只要在 `onMounted` 里创建了"持续存在"的东西，必须在 `onUnmounted` 里清理**：

| onMounted 里创建 | onUnmounted 里清理 |
|---|---|
| `setInterval(...)` | `clearInterval(...)` |
| `setTimeout(...)` | `clearTimeout(...)` |
| `new WebSocket(...)` | `socket.close()` |
| `document.addEventListener(...)` | `document.removeEventListener(...)` |
| `echarts.init(...)` | `chart.dispose()` |
| `new IntersectionObserver(...)` | `observer.disconnect()` |
| `const controller = new AbortController()` | `controller.abort()` |

### 配对示例

```
<script setup>
import { onMounted, onUnmounted } from 'vue'

let timer = null
let socket = null

onMounted(() => {
  // 创建副作用
  timer = setInterval(() => console.log('tick'), 1000)
  socket = new WebSocket('wss://example.com/ws')
})

onUnmounted(() => {
  // ✅ 全部清理干净
  if (timer) clearInterval(timer)
  if (socket) socket.close()
})
</script>
```

## ⚠️ 五、常见陷阱

### 陷阱 1：在 `setup` 顶层访问 `template ref` ❌

```vue
<script setup>
import { ref } from 'vue'

const boxRef = ref(null)

// ❌ setup 阶段 DOM 还没渲染
console.log(boxRef.value)  // null
</script>

<template>
  <div ref="boxRef">Hello</div>
</template>
```

**修复**：放到 `onMounted` 中。

### 陷阱 2：只清理了 `onMounted` 里的一部分 ❌

```
<script setup>
import { onMounted, onUnmounted } from 'vue'

let timerA = null
let timerB = null

onMounted(() => {
  timerA = setInterval(() => {}, 1000)
  timerB = setInterval(() => {}, 2000)
})

onUnmounted(() => {
  clearInterval(timerA)
  // ❌ 忘了 timerB！还剩一个在跑
})
</script>
```

**修复**：写完 `onUnmounted` 后对照 `onMounted` 逐一检查。

### 陷阱 3：`onMounted` 在子组件先于父组件执行 ❌

**真相**：Vue 的挂载顺序是**父 `onMounted` 在所有子组件挂载完成后才执行**。如果你需要"父组件等所有子组件都好了再做某事"，`onMounted` 自动满足。

## 🧠 本节小结

- **onMounted 最常用**：DOM 挂载后触发，适合发请求、初始化图表、拿模板引用
- **setup 里别操作 DOM**：执行时组件还没挂载，`document.querySelector` 拿不到自家元素
- **onUpdated 慎用**：DOM 更新后触发，易无限循环；要响应数据变化优先 watch/nextTick
- **onUnmounted 做清理**：关定时器、断 WebSocket、解绑事件、调 AbortController
- **成对检查法**：写了 onMounted 就检查有没有配套 onUnmounted，防资源泄漏
- **执行顺序**：子组件的 onMounted 先于父组件 onMounted（父等全部子完成）
