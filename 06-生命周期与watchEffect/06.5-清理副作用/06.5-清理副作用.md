## 🤔 一、为什么需要"清理"副作用？

先看一段**有问题的代码**：

```vue
<script setup>
import { ref, watch } from 'vue'

const keyword = ref('')

watch(keyword, () => {
  // 每次 keyword 变化，都创建一个新的定时器
  setInterval(() => {
    console.log('查询中...', keyword.value)
  }, 1000)
  // ❌ 问题：旧的定时器没有被清除！
  // 用户输入 5 个字 → 创建了 5 个定时器 → 全部在跑！
})
</script>
```

**后果**：
- 输入 3 个字 → 3 个定时器同时跑 → 控制台刷屏
- 组件卸载了 → 定时器还在跑 → **内存泄漏**
- 用户切到别的页面 → 浏览器越来越卡

> 💬 **老师备注**：就像你去饭店吃饭，每次点菜老板都给你一个新杯子，但从没收走过旧杯子。吃 5 道菜桌上堆了 5 个杯子，走的时候杯子还留在桌上——这就是"没清理副作用"。

**Vue 提供的解决方案**：**清理函数**——在下一次副作用执行前或组件卸载时，先执行清理逻辑。

## 💡 二、`onWatcherCleanup`（Vue 3.5+，推荐）

Vue 3.5 引入了 `onWatcherCleanup`，专门在 `watch` / `watchEffect` 中注册清理函数。

### 基本语法

```javascript
import { watch, watchEffect, onWatcherCleanup } from 'vue'

watch(source, (newVal, oldVal) => {
  // ... 副作用逻辑 ...

  // 注册清理函数：下次 watcher 重新执行前，先调用它
  onWatcherCleanup(() => {
    // 清理逻辑：清定时器、取消请求、解绑事件...
    console.log('清理上一次的副作用')
  })
})

// watchEffect 同理
watchEffect(() => {
  // ... 副作用逻辑 ...

  onWatcherCleanup(() => {
    // 清理逻辑
  })
})
```

### 执行时机

```
第 1 次执行：watchEffect 回调运行，注册 onWatcherCleanup
    ↓ （依赖变化）
先执行：onWatcherCleanup 注册的清理函数（清理旧副作用）
再执行：watchEffect 回调重新运行（执行新副作用）
    ↓ （依赖再次变化 or 组件卸载）
先执行：onWatcherCleanup 清理
```

简单记：**"新副作用执行前，先把旧的收拾干净"**。

## 🛠 三、完整可运行示例

### 场景 1：定时器清理（防抖实操）

```
<script setup>
import { ref, watch, onWatcherCleanup } from 'vue'

const keyword = ref('')
const result = ref('')

watch(keyword, (newVal) => {
  if (newVal.trim() === '') {
    result.value = ''
    return
  }

  // 1. 创建定时器（副作用）
  const timer = setTimeout(() => {
    result.value = `搜索「${newVal}」的结果...`
  }, 500)

  // 2. 注册清理函数
  onWatcherCleanup(() => {
    console.log(`清理旧定时器（关键词：${newVal}）`)
    clearTimeout(timer)  // 清除上一次的定时器
  })
})
</script>

<template>
  <div>
    <input v-model="keyword" placeholder="输入搜索关键词" />
    <p v-if="keyword">正在搜：{{ keyword }}</p>
    <p v-if="result" style="color: green">{{ result }}</p>
  </div>
</template>
```

**效果**：快速输入 "hello"，只有最后一次 `setTimeout` 会真正执行，前面的全被清理了——这就是"防抖"的底层原理。

### 场景 2：竞态请求（Race Condition）

```vue
<script setup>
import { ref, watch, onWatcherCleanup } from 'vue'

const userId = ref(1)
const userData = ref(null)
const loading = ref(false)

watch(userId, async (newId) => {
  loading.value = true

  // 1. 创建 AbortController（可以取消请求）
  const controller = new AbortController()

  // 2. 注册清理：下次 userId 变了，取消上一次请求
  onWatcherCleanup(() => {
    console.log(`取消用户 ${newId} 的请求`)
    controller.abort()
  })

  try {
    const res = await fetch(`/api/user/${newId}`, {
      signal: controller.signal  // 绑定取消信号
    })
    userData.value = await res.json()
  } catch (err) {
    // 如果是因为 abort 取消的，不报错
    if (err.name !== 'AbortError') {
      console.error('请求失败', err)
    }
  } finally {
    loading.value = false
  }
})
</script>

<template>
  <div>
    <button @click="userId--">上一个</button>
    <span>用户 ID：{{ userId }}</span>
    <button @click="userId++">下一个</button>
    <div v-if="loading">加载中...</div>
    <pre v-else>{{ userData }}</pre>
  </div>
</template>
```

> 💬 **老师备注**：这个例子解决了"竞态条件"——用户快速点"下一个"3 次，发出 3 个请求。由于网络延迟，第 1 个请求可能最后返回，覆盖第 3 个的结果。`AbortController` + `onWatcherCleanup` 确保**只有最新请求的结果才会显示**。

### 场景 3：WebSocket 清理

```
<script setup>
import { ref, watchEffect, onWatcherCleanup } from 'vue'

const roomId = ref('room-1')
const messages = ref([])

watchEffect(() => {
  // 1. 建立 WebSocket 连接（副作用）
  const ws = new WebSocket(`wss://chat.example.com/${roomId.value}`)

  ws.onmessage = (event) => {
    messages.value.push(JSON.parse(event.data))
  }

  ws.onopen = () => {
    console.log(`已加入房间 ${roomId.value}`)
  }

  // 2. 注册清理：断开连接
  onWatcherCleanup(() => {
    console.log(`离开房间 ${roomId.value}`)
    ws.close()  // 断开旧连接
  })
})
</script>
```

当 `roomId` 变化时：
1. 先执行上一次的清理函数 → 断开旧房间的 WebSocket
2. 再创建新房间的 WebSocket
3. 完美衔接，不会出现"同时连着两个房间"的混乱

## 🆚 四、`onWatcherCleanup` vs `onCleanup`

Vue 3.5 之前，清理函数是通过 `watchEffect` 回调的参数传入的：

```javascript
// Vue 3.2 - 3.4 写法（onCleanup）
watchEffect((onCleanup) => {
  const timer = setInterval(() => { /* ... */ }, 1000)
  onCleanup(() => clearInterval(timer))
})

// Vue 3.5+ 写法（onWatcherCleanup）—— 推荐
import { onWatcherCleanup } from 'vue'

watchEffect(() => {
  const timer = setInterval(() => { /* ... */ }, 1000)
  onWatcherCleanup(() => clearInterval(timer))
})
```

| 特性 | `onCleanup`（旧） | `onWatcherCleanup`（新） |
|---|---|---|
| **引入方式** | 回调参数隐式传入 | 显式 import 导入 |
| **适用 API** | 仅 `watchEffect` | `watch` + `watchEffect` |
| **Vue 版本** | 3.2+ | 3.5+ |
| **TypeScript** | 类型略麻烦 | 类型友好 |
| **推荐** | 老项目维护 | ✅ **新项目使用** |

> 💬 **老师备注**：Vue 3.5 把清理能力统一到了 `onWatcherCleanup`，`watch` 和 `watchEffect` 都能用。老 `onCleanup` 写法仍然兼容，但新项目建议直接用 `onWatcherCleanup`。

## 🔍 五、深入理解：清理的本质

很多同学会问："为什么 Vue 不自动帮我清理？"

答案：Vue **不知道你的副作用是什么**。`setTimeout`、`fetch`、`WebSocket`、`addEventListener`……这些都是浏览器 API，Vue 不知道你创建了什么，自然无法帮你清理。

`onWatcherCleanup` 就是你**告诉 Vue**："我创建了这些东西，如果下次要重新执行或组件卸载了，请先帮我执行这个清理函数。"

类比一下：

```javascript
// 就像租房子
watchEffect(() => {
  // 副作用 = 你搬进去住
  rentHouse(roomId.value)

  // onWatcherCleanup = 跟房东说"我要搬走时，先退房打扫"
  onWatcherCleanup(() => {
    cleanUpHouse()  // 退房清扫
  })
})
// 换房间时：先退房打扫旧房间，再搬进新房间
// 退租（组件卸载）：最后退房打扫
```

## ⚠️ 六、常见陷阱

### 陷阱 1：忘了清理导致内存泄漏 ❌

```vue
<script setup>
import { ref, watchEffect } from 'vue'

const isRunning = ref(true)

// ❌ 错误：定时器永远在跑，即使组件卸载了
watchEffect(() => {
  if (isRunning.value) {
    setInterval(() => {
      console.log('tick')  // 组件没了还在打印！
    }, 1000)
  }
})
</script>
```

**修复**：

```
<script setup>
import { ref, watchEffect, onWatcherCleanup } from 'vue'

const isRunning = ref(true)

// ✅ 正确：注册清理函数
watchEffect(() => {
  let timer = null
  if (isRunning.value) {
    timer = setInterval(() => {
      console.log('tick')
    }, 1000)
  }

  onWatcherCleanup(() => {
    if (timer) clearInterval(timer)  // 清！
  })
})
</script>
```

### 陷阱 2：清理函数里引用了过时的变量 ❌

```javascript
watchEffect(() => {
  const data = fetchData(id.value)

  // ❌ 清理函数引用了外层的 data，但此时 data 可能已经变了
  onWatcherCleanup(() => {
    cancelRequest(data)  // data 是闭包捕获的旧值
  })
})
```

**解决**：在清理函数中捕获"副作用本身"，而不是"副作用的结果"。

```javascript
watchEffect(() => {
  const controller = new AbortController()

  // ✅ 捕获 controller 本身（稳定引用）
  onWatcherCleanup(() => {
    controller.abort()
  })

  fetch(`/api/data/${id.value}`, { signal: controller.signal })
})
```

### 陷阱 3：在 `onMounted` 中创建副作用，忘在 `onUnmounted` 清理 ❌

```vue
<script setup>
import { onMounted } from 'vue'

// ❌ 定时器在 onMounted 里创建，但没在 onUnmounted 里清
onMounted(() => {
  setInterval(() => {
    console.log('轮询中...')
  }, 5000)
})
</script>
```

**修复**：

```
<script setup>
import { onMounted, onUnmounted } from 'vue'

let timer = null

onMounted(() => {
  timer = setInterval(() => {
    console.log('轮询中...')
  }, 5000)
})

// ✅ 组件卸载时清理
onUnmounted(() => {
  if (timer) clearInterval(timer)
})
</script>
```

> 💬 **老师备注**：`onMounted` + `onUnmounted` 是一对，`watchEffect` + `onWatcherCleanup` 是另一对。前者管组件级生命周期，后者管 watcher 级生命周期。不要混用。

## 🧠 本节小结

- **为什么要清理**：定时器不关、旧请求覆盖新请求、事件监听重复绑定，都会造成内存泄漏或竞态
- **onWatcherCleanup（Vue 3.5+）**：在 watch/watchEffect 回调内注册清理函数
- **清理时机**：依赖再次变化时先执行上次清理再跑新回调；组件卸载时执行最后一次清理
- **竞态修复**：`AbortController` 取消旧请求 + onWatcherCleanup 兜底
- **版本注意**：Vue 3.2-3.4 用回调第二参数 `onCleanup`，3.5+ 推荐独立 `onWatcherCleanup`
- **别混用**：组件级资源用 onMounted/onUnmounted，watcher 级资源用 onWatcherCleanup
