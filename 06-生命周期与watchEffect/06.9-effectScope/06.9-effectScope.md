## 🤔 一、痛点：一个个 stop 太累了

先回顾一下，每个 `watch` / `watchEffect` 都返回一个 `stop` 函数：

```javascript
const stop1 = watchEffect(() => { /* ... */ })
const stop2 = watch(count, () => { /* ... */ })
const stop3 = watchEffect(() => { /* ... */ })

// 要全部停掉？
stop1()
stop2()
stop3()
// 10 个呢？50 个呢？
```

这在**自定义 composable** 里尤其麻烦：

```javascript
// ❌ composable 内部创建了多个 watcher
// 调用者不知道怎么停掉它们
function useMouseTracker() {
  const x = ref(0)
  const y = ref(0)

  watchEffect(() => { /* 监听鼠标移动 */ })
  watchEffect(() => { /* 监听触摸事件 */ })
  // ... 还有 3 个 watcher

  // 问题：调用者怎么一次性停掉所有？
  return { x, y }
}
```

> 💬 **老师备注**：组件内创建的 watcher，Vue 在组件卸载时会自动停掉。但 composable 不属于任何组件——如果 composable 是在组件外创建的，它的 watcher 就会"泄漏"。这就是 `effectScope` 要解决的问题。

---

## 💡 二、`effectScope` 基本概念

**一句话**：`effectScope` 就是一个"副作用袋子"——把多个 watcher 装进去，然后**一次性全部停掉**。

### 基本语法

```javascript
import { effectScope, ref, watchEffect } from 'vue'

// 1. 创建一个"副作用作用域"
const scope = effectScope()

// 2. 在作用域内执行代码（创建 watcher 等）
scope.run(() => {
  const count = ref(0)

  // 这个 watchEffect 自动注册到 scope 下
  watchEffect(() => {
    console.log(`count = ${count.value}`)
  })

  // 这个也注册到 scope 下
  watch(count, () => { /* ... */ })
})

// 3. 一次性停掉作用域内的所有副作用！
scope.stop()
// 上面两个 watcher 全部停止！
```

### 关键理解

| 概念 | 说明 |
|---|---|
| **作用域（scope）** | 一个"容器"，管理一组副作用 |
| **`scope.run(fn)`** | 在域内执行 fn，fn 中创建的所有 watcher 自动归属该域 |
| **`scope.stop()`** | 停止域内所有 watcher，并触发 `onScopeDispose` 回调 |
| **停止后** | scope 进入"stopped"状态，无法再 `run` |

## 🛠 三、完整可运行示例

### 示例 1：自定义 composable 中的批量管理

```javascript
// composables/useMouseTracker.js
import { ref, effectScope, onScopeDispose } from 'vue'

export function useMouseTracker() {
  const x = ref(0)
  const y = ref(0)
  let scope = null  // 保存作用域引用

  function onMouseMove(e) {
    x.value = e.clientX
    y.value = e.clientY
  }

  // start：创建作用域，开始追踪
  function start() {
    // 如果已有作用域，先停掉
    if (scope) scope.stop()

    // 创建新作用域
    scope = effectScope()

    scope.run(() => {
      window.addEventListener('mousemove', onMouseMove)

      // 注册清理：作用域停止时，移除事件监听
      onScopeDispose(() => {
        window.removeEventListener('mousemove', onMouseMove)
        console.log('鼠标追踪已停止')
      })
    })
  }

  // stop：停止追踪
  function stop() {
    scope?.stop()
    scope = null
  }

  return { x, y, start, stop }
}
```

### 使用

```vue
<script setup>
import { useMouseTracker } from './composables/useMouseTracker'

const { x, y, start, stop } = useMouseTracker()

// 组件挂载时开始追踪
start()
// 在 onUnmounted 中停止也行
import { onUnmounted } from 'vue'
onUnmounted(() => stop())
</script>

<template>
  <p>鼠标位置：x = {{ x }}, y = {{ y }}</p>
  <button @click="stop">停止追踪</button>
  <button @click="start">开始追踪</button>
</template>
```

### 示例 2：表单页面的"重置所有监听"

```
<script setup>
import { ref, effectScope, watchEffect, onScopeDispose } from 'vue'

const form = ref({ name: '', email: '', age: 0 })
const isDirty = ref(false)
const autoSaveEnabled = ref(true)
let autoSaveScope = null

// 自动保存功能（独立的作用域）
function startAutoSave() {
  if (autoSaveScope) autoSaveScope.stop()

  autoSaveScope = effectScope()

  autoSaveScope.run(() => {
    // 监听表单任何变化
    watchEffect(() => {
      // 只要读了 form.value 的任何属性，任何变化都触发
      const snapshot = JSON.stringify(form.value)
      isDirty.value = true

      // 注册清理（作用域停止时触发）
      onScopeDispose(() => {
        console.log('自动保存已停用')
        isDirty.value = false
      })
    })
  })
}

function stopAutoSave() {
  autoSaveScope?.stop()
  autoSaveScope = null
}

// 重置表单：停掉自动保存，清空数据，再重新启用
function resetForm() {
  stopAutoSave()
  form.value = { name: '', email: '', age: 0 }
  startAutoSave()
}

// 启动
startAutoSave()
</script>

<template>
  <div>
    <input v-model="form.name" placeholder="姓名" />
    <input v-model="form.email" placeholder="邮箱" />
    <input v-model.number="form.age" placeholder="年龄" type="number" />
    <p v-if="isDirty" style="color: orange">表单已修改</p>
    <button @click="resetForm">重置表单</button>
  </div>
</template>
```

> 💬 **老师备注**：这个例子展示了 `effectScope` 的典型用途——**条件式副作用管理**。自动保存只在需要时运行，重置时完全停掉再重新开始，干净利落。没有 `effectScope` 的话，你需要手动记录每个 `stop` 函数，很容易漏。

### 示例 3：组件级"可暂停的轮询"

```vue
<script setup>
import { ref, effectScope, watchEffect, onScopeDispose } from 'vue'

const isPolling = ref(false)
const data = ref(null)
let pollScope = null

function startPolling() {
  if (pollScope) pollScope.stop()

  pollScope = effectScope()

  pollScope.run(() => {
    isPolling.value = true

    // 创建一个周期性副作用
    watchEffect(() => {
      const timer = setInterval(async () => {
        const res = await fetch('/api/status')
        data.value = await res.json()
        console.log('轮询中...', data.value)
      }, 3000)

      // 关键：作用域停止时清除定时器
      onScopeDispose(() => {
        clearInterval(timer)
        console.log('轮询已停止')
      })
    })
  })
}

function stopPolling() {
  pollScope?.stop()
  pollScope = null
  isPolling.value = false
}
</script>

<template>
  <div>
    <button @click="startPolling" :disabled="isPolling">开始轮询</button>
    <button @click="stopPolling" :disabled="!isPolling">停止轮询</button>
    <pre v-if="data">{{ data }}</pre>
  </div>
</template>
```

## 🔍 四、`onScopeDispose` —— 作用域级清理

`onScopeDispose` 和 `onWatcherCleanup` 的区别：

| API | 触发时机 | 适用范围 |
|---|---|---|
| **`onWatcherCleanup`** | 下一次 watcher 执行前 / watcher 停止时 | 单个 watcher 内部 |
| **`onScopeDispose`** | `scope.stop()` 被调用时 | 整个作用域 |
| **`onUnmounted`** | 组件卸载时 | 整个组件 |

### 使用示例

```javascript
const scope = effectScope()

scope.run(() => {
  // 创建副作用
  const ws = new WebSocket('wss://...')

  // 注册作用域级清理
  onScopeDispose(() => {
    ws.close()           // 关闭 WebSocket
    console.log('作用域已销毁')
  })
})

// 一行代码全部清理
scope.stop()
// → ws.close() 执行
// → "作用域已销毁" 打印
```

## 🔍 五、`getCurrentScope` —— 检测当前作用域

```javascript
import { effectScope, getCurrentScope, onScopeDispose } from 'vue'

const scope = effectScope()

scope.run(() => {
  const current = getCurrentScope()
  console.log(current === scope)  // true

  // 没有 run 在 scope 里时
  const outside = getCurrentScope()
  console.log(outside)  // 组件内 → 组件级 scope；组件外 → undefined
})
```

> 💬 **老师备注**：`getCurrentScope` 在写通用工具函数时有用——比如你想判断"当前是否在某个 scope 内"，来决定副作用注册到哪里。

## 🔍 六、`detached: true` —— 分离作用域

默认情况下，子作用域会跟随父作用域停止：

```javascript
const parentScope = effectScope()
let childScope

parentScope.run(() => {
  childScope = effectScope()  // 默认：嵌套在 parentScope 内
})

parentScope.stop()
// childScope 也被停止了！
```

用 `detached: true` 可以让子作用域独立：

```javascript
const parentScope = effectScope()

parentScope.run(() => {
  // detached: true → 子作用域不受父作用域影响
  childScope = effectScope(true)

  childScope.run(() => {
    watchEffect(() => { /* ... */ })
  })
})

parentScope.stop()
// parentScope 停了，但 childScope 还在！
childScope.stop()  // 需要手动停
```

实用场景：

```javascript
// useSharedState：需要独立于组件生命周期
function useSharedState() {
  // 用 detached scope，确保不会随着调用组件卸载而停止
  const scope = effectScope(true)

  scope.run(() => {
    watchEffect(() => {
      // 全局共享的状态监听，不应该随组件卸载而停
    })
  })

  return scope
}
```

## 📋 API 速查总表

| API | 用途 | 关键参数 |
|---|---|---|
| `effectScope(detached?)` | 创建作用域 | `detached: true` 独立运行 |
| `scope.run(fn)` | 在域内执行 fn | 返回 fn 的返回值 |
| `scope.stop()` | 停止域内所有副作用 | 不可逆，scope 变为 stopped |
| `onScopeDispose(fn)` | 注册域销毁回调 | 在 `scope.run()` 内调用 |
| `getCurrentScope()` | 获取当前活跃作用域 | 返回 `EffectScope` 或 `undefined` |

## ⚠️ 七、常见陷阱

### 陷阱 1：scope 停止后无法再 run ❌

```javascript
const scope = effectScope()
scope.run(() => { /* ... */ })
scope.stop()

// ❌ 报错！scope 已停止
scope.run(() => { /* ... */ })
```

**解决**：需要重新创建 scope。

### 陷阱 2：在 scope.run 外部创建的 watcher 不归 scope 管 ❌

```javascript
const scope = effectScope()
const count = ref(0)

// ❌ 这行在 scope.run 外面，不归 scope 管
watchEffect(() => console.log(count.value))

scope.run(() => {
  // ✅ 这个归 scope 管
  watch(count, () => { /* ... */ })
})

scope.stop()
// 外面的 watchEffect 还在跑！
```

**原则**：只有 `scope.run(fn)` 回调内部创建的 watcher 才归属该 scope。

### 陷阱 3：忘记在组件卸载时 stop scope ❌

```
<script setup>
const scope = effectScope()
scope.run(() => { /* ... */ })

// ❌ 组件卸载了，scope 没停 → 泄漏！
// ✅ 修复：
import { onUnmounted } from 'vue'
onUnmounted(() => scope.stop())
</script>
```

> 💬 **老师备注**：组件内部创建的 watcher 会自动随组件卸载而停止。但手动创建的 `effectScope` 不会——你需要手动在 `onUnmounted` 中 `scope.stop()`。

## 🧠 本节小结

- **痛点**：多个 watcher 要手动逐个 `stop()`，composable 里调用者不知道停哪些
- **effectScope 是什么**：把副作用装进一个"作用域容器"，`scope.stop()` 一次全停
- **核心 API**：`effectScope()` 创建、`scope.run(fn)` 执行、`scope.stop()` 停止、`onScopeDispose` 注册清理、`getCurrentScope` 取当前域
- **detached: true**：创建脱离父作用域的独立域，生命周期自己管
- **实战场景**：自定义 composable 批量管理、表单重置、条件式副作用组（v-if 式启停）
- **组件与 scope 的关系**：组件自带 scope，卸载自动 stop；手动 scope 必须自己调 stop，别忘
