学编程时都夸"纯函数"好：同样的输入永远同样的输出。可到了 Vue 里，发请求、改 DOM、存 localStorage 这些"不纯"的操作天天都要做——它们有个正式名字叫**副作用**。你会发现 `computed` 里不能发请求、`watch` 天生就是管副作用的，搞不清这条分界线，代码迟早出乱子。本节把"副作用"这个词讲透。

## 🤔 一、什么是"副作用"？

"副作用"这个词听起来很吓人，其实换个说法就好理解了：

> **副作用 = 除了"算出一个结果"之外，还干了别的事。**

用代码来说：

```javascript
// ✅ 纯函数：只根据输入计算输出，不碰外界
function add(a, b) {
  return a + b    // 输入什么就输出什么
}

// ❌ 有副作用：除了算结果，还改了别的东西
let total = 0
function addWithSideEffect(a, b) {
  total += 1       // 改了外部变量 total ⚠️ 副作用
  return a + b
}
```

第二个函数跟第一个的区别：它改了 `total` 这个外部变量——这就叫"副作用"。

> 💬 **老师备注**：不要一听到"副作用"就觉得是坏东西。在 Vue 中，**副作用是必须的**——你总要发请求、总要改 DOM、总要存 localStorage，这些都是副作用。关键是**管理好它**。

## 💡 二、Vue 组件中哪些是副作用？

回顾一下一个典型的 Vue 组件都干了什么：

```vue
<script setup>
import { ref, computed } from 'vue'

const keyword = ref('')
const list = ref([])

// ✅ 纯计算：依赖 keyword，结果是过滤后的数组
const filtered = computed(() => {
  return list.value.filter(item => item.includes(keyword.value))
})

// ❌ 这是副作用：改变了"世界"（发了网络请求）
async function search() {
  const res = await fetch(`/api/search?q=${keyword.value}`)
  list.value = await res.json()   // 改了 list 的值
}

// ❌ 这也是副作用：改了页面标题
document.title = '搜索页面'

// ❌ 这也是副作用：存了 localStorage
localStorage.setItem('lastKeyword', keyword.value)
</script>
```

总结一下，Vue 组件中常见的副作用：

| 操作 | 为什么是副作用 |
|---|---|
| `fetch()` / `axios.get()` | 发网络请求——"网络"是函数外的世界 |
| `document.title = '...'` | 改了浏览器标签页标题——函数外的世界 |
| `localStorage.setItem(...)` | 改了浏览器存储——函数外的世界 |
| `setInterval(...)` | 创建了定时器——浏览器全局资源 |
| `element.focus()` | 改了 DOM 的状态——函数外的世界 |
| `websocket.send(...)` | 发了消息——到了另一台电脑 |
| `console.log(...)` | 打印到控制台——也算副作用（尽管无害） |

> 💬 **老师备注**：`computed` 是纯计算——同样输入永远同样输出，Vue 还能缓存它。`watch` 和 `watchEffect` 就是 Vue 给副作用"安排的位置"，告诉 Vue："数据变了，请帮我干这些事"。

## 🔍 三、为什么需要专门的 API 管理副作用？

如果不用 watch，你会怎么写"数据变了就发请求"？

```javascript
// ❌ 原始办法：手动在每个地方调
function changeKeyword(newVal) {
  keyword.value = newVal
  search()  // 每次改 keyword 都得记得调 search
}
// 忘了调？bug！
```

有了 Vue 的响应式系统，你可以这样：

```
<script setup>
import { ref, watch } from 'vue'

const keyword = ref('')

// ✅ Vue 帮你盯着 keyword，变了就自动调 fetchResults
watch(keyword, (newVal) => {
  fetchResults(newVal)   // 副作用：发请求
})
</script>
```

三个好处：
1. **自动触发**：`keyword` 变了，副作用自动执行，不用手动调
2. **自动追踪**：不用指定"哪些数据变了要干啥"，Vue 自己知道
3. **自动清理**：组件卸载时 Vue 会自动停掉 watch（配合 `onWatcherCleanup` 更安全）

## 🛠 四、完整示例：副作用 vs 纯计算

```vue
<script setup>
import { ref, computed, watch } from 'vue'

const keyword = ref('')
const results = ref([])

// ✅ 纯计算：同样的 keyword 永远得到同样的过滤结果
// computed 没有副作用，Vue 可以缓存
const filteredResults = computed(() => {
  return results.value.filter(item =>
    item.toLowerCase().includes(keyword.value.toLowerCase())
  )
})

// ✅ 副作用：发网络请求
// watch 专门干这件事——数据变了，做额外的事
watch(keyword, async (newKeyword) => {
  if (newKeyword.trim() === '') {
    results.value = []
    return
  }
  // 这是副作用：fetch 改变了"世界"
  const res = await fetch(`/api/search?q=${newKeyword}`)
  results.value = await res.json()
})
</script>

<template>
  <div>
    <!-- v-model 自动更新 keyword.value -->
    <input v-model="keyword" placeholder="输入搜索关键词" />
    <p>匹配数量：{{ filteredResults.length }}</p>
    <ul>
      <li v-for="item in filteredResults" :key="item.id">
        {{ item.name }}
      </li>
    </ul>
  </div>
</template>
```

这个例子展示了清晰的分工：
- **`computed`** 负责纯计算（从已有数据算出新数据，无副作用）
- **`watch`** 负责副作用（数据变了 → 请求接口）

## ⚠️ 五、常见误区

### 误区 1：所有函数都叫"副作用" ❌

**真相**：`computed`、纯工具函数（如 `formatDate()`）就没有副作用。只有"改变了函数外世界的状态"才算副作用。

### 误区 2：副作用就是坏的，要避免 ❌

**真相**：**Web 应用天生充满副作用**——你不发请求怎么拿到数据？你不改 DOM 用户看什么？关键是**管理好副作用**，而不是消灭它。

### 误区 3：事件处理（`@click`）也是副作用 ❌

**半对半错**。`@click` 里可能包含副作用（如发请求），但它属于"用户手动触发"，不是"响应式数据变了自动触发"。Vue 用 watch 管理的是后者。

---

## 🧠 本节小结

- **副作用定义**：函数做了"计算以外"的事——改外部变量、发请求、写 DOM、订阅事件
- **Vue 组件常见副作用**：数据请求、DOM 操作、定时器、WebSocket/事件订阅、写 localStorage
- **computed 必须纯**：只做计算、不产生副作用，否则推导逻辑不可控
- **watch/watchEffect 专管副作用**：响应式数据变了自动触发，组件卸载自动清理
- **事件处理器不算"响应式副作用"**：`@click` 是用户主动触发，别用 watch 替代
