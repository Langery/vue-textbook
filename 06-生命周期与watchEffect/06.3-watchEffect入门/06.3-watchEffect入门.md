上节说副作用要"管理"，可手动管理很烦：数据一变，你总得记得去调那个函数。`watchEffect` 的卖点就是"自动"——你只需写"数据变了之后要干什么"，它自己盯着回调里读了哪些响应式数据，一变就重新执行。首次执行、停止监听、和 `watch` 怎么取舍，本节一次讲清。

## 🤔 一、为什么需要 `watchEffect`？

回顾 6.2 节：副作用 = "数据变了，干额外的事"。`watchEffect` 就是做这件事最直白的 API。

**用一个生活类比**：

> 💬 **老师备注**：`watchEffect` 就像一个"自动监控摄像头"——你不用告诉它"盯着哪个门"，它自己会分析画面里有哪些东西在动，任何一个动了就报警。`watch` 则像"指定一个探头"——你明确说"盯着 3 号门"，别的不看。

## 💡 二、基本语法

```javascript
import { watchEffect } from 'vue'

// 最简单的用法
watchEffect(() => {
  // 这个回调里的所有响应式数据，Vue 自动追踪
  // 任何一个发生变化 → 回调重新执行
})
```

**关键点**：
1. `watchEffect` 接收一个**回调函数**作为参数
2. 回调里**读过的所有响应式数据**自动成为"依赖"
3. 任何依赖变了，回调重新执行
4. `watchEffect` 创建时**立刻执行一次**（不像 `watch` 默认不执行）

## 🛠 三、完整可运行示例

### 示例 1：自动追踪

```vue
<script setup>
import { ref, watchEffect } from 'vue'

const firstName = ref('张')
const lastName = ref('三')
const fullName = ref('')

// watchEffect 自动追踪 firstName 和 lastName
// 任一个变了，回调重新执行
watchEffect(() => {
  // 回调里读了 firstName.value 和 lastName.value
  // Vue 自动把它们标记为"依赖"
  fullName.value = `${firstName.value} ${lastName.value}`
  console.log(`全名更新：${fullName.value}`)
})
</script>

<template>
  <div>
    <input v-model="firstName" placeholder="姓" />
    <input v-model="lastName" placeholder="名" />
    <p>全名：{{ fullName }}</p>
  </div>
</template>
```

运行效果：
- 页面一打开，控制台输出 `全名更新：张 三`
- 修改"姓"或"名"，`fullName` 自动更新
- 你**不需要**手动指定"监听 firstName"，Vue 自己发现了

### 示例 2：停止监听

```
<script setup>
import { ref, watchEffect } from 'vue'

const count = ref(0)
const isRunning = ref(true)

// watchEffect 返回一个"停止函数"
const stop = watchEffect(() => {
  if (isRunning.value) {
    console.log(`count = ${count.value}`)
  } else {
    console.log('监听已停止')
  }
})

// 5 秒后停止监听
setTimeout(() => {
  isRunning.value = false
  stop()  // 手动停掉 watchEffect
}, 5000)
</script>

<template>
  <button @click="count++">+1（{{ count }}）</button>
  <p>5 秒后自动停止监听</p>
</template>
```

> 💬 **老师备注**：正常情况下你不需要手动 `stop()`——组件卸载时 Vue 会自动停掉。但如果你的 `watchEffect` 是在 `setup` 外创建的（比如在可复用的 composable 中），手动 `stop` 就需要了。

## 🔍 四、`watchEffect` 的执行时机

`watchEffect` 默认在**组件渲染前**执行。但可以用 `flush` 选项控制：

```javascript
import { watchEffect } from 'vue'

// 默认：组件渲染前执行（flush: 'pre'）
watchEffect(() => { /* ... */ })

// 组件渲染后执行（可以安全操作 DOM）
watchEffect(() => {
  // 这里可以访问最新的 DOM
}, { flush: 'post' })

// 同步执行（慎用，性能较差）
watchEffect(() => { /* ... */ }, { flush: 'sync' })
```

| flush 值 | 执行时机 | 使用场景 |
|---|---|---|
| `'pre'`（默认） | DOM 更新前 | 大多数情况 |
| `'post'` | DOM 更新后 | 需要访问 DOM、做滚动定位 |
| `'sync'` | 数据变化时立刻同步执行 | 极少数需要"立刻生效"的场景 |

> 💬 **老师备注**：99% 的情况用默认的 `flush: 'pre'` 就行。如果你需要在 `watchEffect` 里操作 DOM（比如获取元素宽高），用 `flush: 'post'`。

## 🆚 五、`watchEffect` vs `watch`

| 特性 | `watchEffect` | `watch` |
|---|---|---|
| **依赖指定** | 自动追踪（回调里读到谁就监听谁） | 明确指定（第 1 个参数指定"源"） |
| **首次执行** | ✅ 默认立即执行 | ❌ 默认不执行，需 `{ immediate: true }` |
| **新旧值** | ❌ 拿不到旧值 | ✅ 可以拿到 `(newVal, oldVal)` |
| **精准控制** | ❌ 依赖由 Vue 自动判断 | ✅ 可配 `deep` / `immediate` |
| **适用场景** | "数据变了就干某个事"（简单粗暴） | "我知道要监听谁，需要新旧值"（精准控制） |

### 场景速查

```javascript
// ✅ watchEffect：简单场景
// "只要这些数据任何一个变了，就重新算全名"
watchEffect(() => {
  fullName.value = `${firstName.value} ${lastName.value}`
})

// ✅ watch：精准场景
// "我知道要监听 userId，还需要拿到新旧值做对比"
watch(userId, (newId, oldId) => {
  console.log(`从 ${oldId} 切到 ${newId}`)
  fetchUserData(newId)
})
```

## ⚠️ 六、常见陷阱

### 陷阱 1：依赖追踪的"盲区"

```javascript
const count = ref(0)

// ❌ count.value 在条件分支里，初始为 0 时不会读到
watchEffect(() => {
  if (count.value > 10) {
    console.log('大于 10 了')  // count 从 0→5 时没触发
  }
})
// count 从 0→5→11：前两次 count.value 根本没被读（条件没进）
// 只有从 10→11 那次才读到了 count.value，此前没追踪！
```

**原因**：`watchEffect` 只在**实际执行到的代码路径**中追踪依赖。条件分支里没走到，就不会追踪那里的数据。

> 💬 **老师备注**：绝大部分时候这不是问题——正常需求就是要 `count > 10` 才触发。但如果你期望"count 任何变化都触发"，就要把 `count.value` 放到分支外面先读一次。

### 陷阱 2：在 `watchEffect` 里修改依赖导致无限循环

```javascript
// ❌ 死循环！改了 count → 触发 watchEffect → 又改 count → ...
watchEffect(() => {
  count.value++  // 无限循环！
})
```

**解决**：如果想"有条件地修改依赖"，加个判断：

```javascript
watchEffect(() => {
  if (count.value < 100) {
    count.value++  // 安全，到了 100 就停
  }
})
```

## 🧠 本节小结

- **watchEffect 用法**：`watchEffect(() => { ... })`，回调里访问的响应式数据自动成为依赖
- **自动追踪**：不用手动指定监听谁，数据一变回调自动重跑
- **默认立即执行一次**：创建即跑，不像 `watch` 需要 `immediate: true`
- **停止监听**：`const stop = watchEffect(...)`，`stop()` 手动停；组件卸载自动停
- **vs watch**：watchEffect 简单自动、"干了就好"；watch 精准指定源、拿新旧值、可配选项
- **改数据要设出口**：回调里改被监听数据要加条件（如计数上限），否则死循环
