新手最容易问的一句话是："请求到底该放在哪？数据初始化放哪？组件关了之后谁负责收拾残局？"随便放确实也能跑，但页面一旦复杂就会遇到：定时器越攒越多、请求重复发、DOM 还没好就去操作。Vue 给组件规定了从"出生"到"销毁"的固定流程，每个阶段都留好了钩子位。本节先把生命周期全景图讲清楚。

## 🤔 一、什么是"生命周期"？

我们先想一个问题：你在淘宝上点开一个商品详情页会发生什么？

1. **页面刚打开**：空的，壳子先出来，数据还没加载
2. **数据到了**：图片、价格、标题显示出来
3. **用户操作**：选了不同颜色，价格跟着变
4. **关掉页面**：切到其他页面，这个组件就不见了

这就是一个 Vue 组件从"出生"到"销毁"的完整过程——**生命周期**。

> 💬 **老师备注**：可以把组件想象成一个人：
> - 出生（setup）→ 长大站稳（onMounted）→ 经历变化（onUpdated）→ 退休离世（onUnmounted）
> - 生命周期钩子就是"在每个关键节点，你可以插一脚做点事"

---

## 💡 二、四个阶段 & 八个钩子

Vue 3 组合式 API 提供了以下生命周期钩子（生命周期函数）：

```vue
<script setup>
import {
  onBeforeMount,    // 挂载前
  onMounted,        // 挂载后 ✅ 最常用
  onBeforeUpdate,   // 更新前
  onUpdated,        // 更新后
  onBeforeUnmount,  // 卸载前 ✅ 清理资源
  onUnmounted,      // 卸载后
  onErrorCaptured,  // 捕获子组件错误
} from 'vue'

// 这些钩子可以直接在 <script setup> 中调用
onMounted(() => {
  console.log('组件挂载好了，可以操作 DOM 了')
})
</script>
```

### 关键钩子速查表

| 钩子 | 触发时机 | 能干啥 |
|---|---|---|
| `setup()` / `<script setup>` | 组件创建时，`data` 和 `computed` 初始化前 | 声明响应式数据、computed、methods |
| `onBeforeMount` | DOM 渲染前一刻 | 很少用，一般不需要 |
| **`onMounted`** | DOM 渲染完毕，可以操作 DOM | **发请求、初始化图表、获取元素引用** |
| `onBeforeUpdate` | 数据变了，DOM 重新渲染前 | 获取更新前的 DOM 状态 |
| `onUpdated` | DOM 重新渲染后 | 更新后的 DOM 操作（谨慎使用） |
| `onBeforeUnmount` | 组件要卸载前一刻 | 清定时器、取消订阅、解绑事件 |
| **`onUnmounted`** | 组件已卸载 | **最终清理（定时器、WebSocket、AbortController）** |
| `onErrorCaptured` | 子组件抛出错误时 | 错误兜底（ErrorBoundary） |

> 💬 **老师备注**：日常开发 90% 的钩子场景只需要两个：**`onMounted`**（初始化）和 **`onUnmounted`**（清资源）。其他钩子见到认识就行，不用死记。

## 🛠 三、完整可运行示例：追踪组件一生

```
<script setup>
import { ref, onMounted, onBeforeUnmount, onUpdated } from 'vue'

// 响应式数据
const count = ref(0)
const logs = ref([])

// 记录日志的辅助函数
function addLog(msg) {
  const now = new Date().toLocaleTimeString()
  logs.value.push(`[${now}] ${msg}`)
}

// ===== 生命周期钩子 =====

// 1. <script setup> 本身 = setup() 阶段
addLog('🔵 setup：组件正在创建，数据和方法已初始化')

// 2. 挂载后
onMounted(() => {
  addLog('🟢 onMounted：DOM 已挂载，可以操作页面元素了')
  // 例如：可以在这里发请求
  // fetchUserData()
})

// 3. 更新后
onUpdated(() => {
  addLog(`🟡 onUpdated：数据变了，DOM 已重绘（count = ${count.value}）`)
})

// 4. 卸载前
onBeforeUnmount(() => {
  addLog('🟠 onBeforeUnmount：即将卸载，准备清理资源...')
})

// 点击 +1
function increment() {
  count.value++
}
</script>

<template>
  <div>
    <h2>组件生命周期演示</h2>
    <p>当前计数：<strong>{{ count }}</strong></p>
    <button @click="increment">+1（触发更新）</button>
    <hr />
    <h3>生命周期日志：</h3>
    <ul>
      <li v-for="(log, i) in logs" :key="i">{{ log }}</li>
    </ul>
  </div>
</template>
```

运行后你会看到：
- 首次渲染：`setup` → `onMounted` 依次触发
- 每次点击 +1：`onUpdated` 触发
- 如果这个组件被 `v-if` 移除：`onBeforeUnmount` 触发

## 🆚 四、选项式 API vs 组合式 API 对照

如果你看到老项目（Vue 2 风格）用的选项式写法，对应关系如下：

| 选项式 API | 组合式 API（本书） | 说明 |
|---|---|---|
| `created` | `setup()` / `<script setup>` | Vue 3 中 `setup` 替代了 `created` |
| `mounted` | `onMounted` | DOM 挂载后 |
| `updated` | `onUpdated` | DOM 更新后 |
| `destroyed` | `onUnmounted` | 组件销毁后（Vue 3 改名） |
| `beforeDestroy` | `onBeforeUnmount` | 销毁前（Vue 3 改名） |

> 💬 **老师备注**：选项式 API 里钩子名都是**不带 on**（`mounted`、`created`），组合式 API 统一加了 **on 前缀**（`onMounted`）。这是最简单的记忆方法。

## ⚠️ 五、常见陷阱

### 陷阱 1：在 `setup` 阶段操作 DOM ❌

```vue
<script setup>
import { onMounted } from 'vue'

// ❌ 错误：setup 阶段还没渲染，document.querySelector 找不到
const box = document.querySelector('.box')  // null！

// ✅ 正确：放到 onMounted 里
onMounted(() => {
  const box = document.querySelector('.box')  // 有值！
})
</script>
```

**原因**：`setup` 阶段只在 JS 中执行，HTML 还没渲染到页面上。**任何 DOM 操作必须放在 `onMounted` 或之后**。

### 陷阱 2：忘记 `onUnmounted` 清理 ❌

```
<script setup>
import { onMounted } from 'vue'

// ❌ 错误：设了定时器但组件卸载时没清
onMounted(() => {
  setInterval(() => {
    console.log('还在跑...')  // 组件都没了还在跑！
  }, 1000)
})
</script>
```

**后果**：内存泄漏，定时器一直运行，越积越多。**只要在 `onMounted` 里创建了"持续的"东西（定时器、WebSocket、事件监听），必须在 `onUnmounted` 里清理**。6.5 节专门讲清理。

### 陷阱 3：`onUpdated` 里改数据导致死循环 ❌

```vue
<script setup>
import { ref, onUpdated } from 'vue'

const count = ref(0)

// ❌ 危险：onUpdated 里改数据 → 触发更新 → 又触发 onUpdated → 无限循环
onUpdated(() => {
  count.value++  // 找死！
})
</script>
```

> 💬 **老师备注**：`onUpdated` 极少数场景才用，99% 的情况你应该用 `watch` 或 `computed` 来响应数据变化，而不是靠 `onUpdated`。

## 🧠 本节小结

- **生命周期 = 四个阶段**：创建（setup）→ 挂载（onMounted）→ 更新（onUpdated）→ 卸载（onUnmounted）
- **8 个组合式钩子**：before/after 成对出现，加 `onErrorCaptured` 兜底错误
- **最常用三个**：`setup` 初始化数据、`onMounted` 发请求/操作 DOM、`onUnmounted` 清理资源
- **选项式对照**：`created → setup()`、`mounted → onMounted()`、`destroyed → onUnmounted()`
- **别乱用 onUpdated**：99% 的"数据变了要干活"用 `watch`/`computed` 更合适
