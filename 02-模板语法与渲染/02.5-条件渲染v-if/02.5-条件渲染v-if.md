想想你每天打开的各种页面：登录前显示"请登录"，登录后变成"欢迎回来"；购物车空荡荡时显示引导文案，有商品时才出现结算按钮；页面滚动到底部，"加载更多"才会冒出来。这些"根据条件决定显不显示"的需求，几乎是每个前端项目都会遇到的。上一节我们搞懂了模板的规矩，这一节就来解决这个最常见的场景——用 `v-if` 做条件渲染。

---

## 🤔 一、条件渲染是什么？

回想一下你用过哪些"根据情况显示不同内容"的功能：

- 登录前显示"请登录"，登录后显示"欢迎回来"；
- 购物车为空显示"空空如也"，有商品显示结算按钮；
- 成绩 >= 60 显示"及格"，否则显示"不及格"。

在 Vue 里，这些都是靠一组叫 **`v-if`** 的指令来实现的。你可以把它理解成 JS 里的 `if...else`，只不过它控制的是 **HTML 的显示和隐藏**。

---

## 💡 二、四种写法详解

### 写法一：`v-if` 单独使用（最常用）

```vue
<script setup>
import { ref } from 'vue'

const showBanner = ref(true)
</script>

<template>
  <div v-if="showBanner" class="banner">
    🎉 限时优惠！全场 8 折！
  </div>

  <button @click="showBanner = !showBanner">
    {{ showBanner ? '关闭' : '显示' }}横幅
  </button>
</template>
```

`v-if="表达式"` — 表达式为 `true` 时元素出现在 DOM 中，为 `false` 时**元素直接从 DOM 中移除（不是隐藏，是真没了）**。打开开发者工具的 Elements 面板，点按钮切换，你会看到 `<div class="banner">` 整行没了又回来。

---

### 写法二：`v-if` + `v-else`（二选一）

很多场景就两个状态互斥：

```
<script setup>
import { ref } from 'vue'

const isLoggedIn = ref(false)

function toggleLogin() {
  isLoggedIn.value = !isLoggedIn.value
}
</script>

<template>
  <div v-if="isLoggedIn">
    <p>👤 欢迎回来，张三！</p>
    <button @click="toggleLogin">退出登录</button>
  </div>
  <div v-else>
    <p>🔒 请先登录</p>
    <button @click="toggleLogin">立即登录</button>
  </div>
</template>
```

两个元素**必须紧挨着**，中间不能插入其他标签。`v-else` 不需要写条件表达式——它自动取反前面的 `v-if`。

---

### 写法三：`v-if` + `v-else-if` + `v-else`（多分支）

需要多个条件分支时用这个：

```vue
<script setup>
import { ref } from 'vue'

const score = ref(85)
</script>

<template>
  <p>你的成绩：{{ score }} 分</p>

  <p v-if="score >= 90">🏆 优秀</p>
  <p v-else-if="score >= 80">👍 良好</p>
  <p v-else-if="score >= 60">✅ 及格</p>
  <p v-else>❌ 不及格</p>

  <input type="range" min="0" max="100" v-model.number="score" />
</template>
```

就和 JS 的 `if / else if / else` 一样，从上到下依次匹配，命中一个就停，后面的不执行。

---

### 写法四：`<template v-if>`（分组条件 — 不产生额外 DOM）

有时候你想让**多个元素**共用一个条件，但又不想在外面套一层 `<div>`（会破坏布局）：

```
<template>
  <template v-if="hasPermission">
    <h3>管理面板</h3>
    <p>这里是管理员才能看到的内容</p>
    <button>删除用户</button>
  </template>
</template>
```

`<template>` 本身**不会被渲染到页面上**——它在 Vue 编译阶段就被"消掉"了，只留下里面的子元素。这是条件分组的**最佳实践**，HTML 结构干净，不会出现多余的包裹层。

> 💬 **老师备注**：如果你发现自己在写 `<div v-if>` 只是图分组方便，马上换成 `<template v-if>`，保持 DOM 清爽。

---

## 🆚 三、`v-if` vs `v-show`

很多初学者分不清这两个，记住一句话就够了：

| | `v-if` | `v-show` |
|---|---|---|
| 原理 | 条件为 false 时，元素**不存在**于 DOM | 始终在 DOM，只是 `display: none` |
| 切换开销 | 高（创建/销毁 DOM + 触发生命周期） | 低（只改 CSS） |
| 初始渲染 | 低（false 时不渲染） | 高（始终渲染） |
| 适用场景 | 切换频率低（如登录状态、权限判断） | 切换频率高（如标签页、弹窗开关） |

```vue
<!-- 频繁切换 → 用 v-show -->
<div v-show="activeTab === 'home'">首页内容</div>

<!-- 几乎不变 → 用 v-if -->
<div v-if="user.role === 'admin'">管理员菜单</div>
```

> 💬 **记忆口诀**：切得勤用 `v-show`，很少动用 `v-if`。

## ⚠️ 四、常见陷阱

### 陷阱 1：`v-if` 和 `v-for` 写在同一元素上 ❌

```
<!-- ❌ 错误写法 -->
<li v-for="item in list" v-if="item.active">{{ item.name }}</li>
```

Vue 3 里 `v-if` 优先级高于 `v-for`，这会导致 `v-if` 先执行时拿不到 `item` 变量，直接报错。**永远不要把它们放在同一个标签上**。正确做法见 2.8 节。

### 陷阱 2：`v-else` 和 `v-if` 之间插入了其他元素 ❌

```vue
<!-- ❌ 错误：中间有个 <hr> 打断了兄弟关系 -->
<div v-if="flag">A</div>
<hr />
<div v-else>B</div>  <!-- 这个 v-else 不生效！ -->
```

`v-if` 和 `v-else` / `v-else-if` **必须是相邻的兄弟元素**，中间不能插入任何标签。

---

## 🧠 本节小结

- **`v-if` 家族**：`v-if` / `v-else-if` / `v-else` 是"真条件渲染"，不满足直接不渲染，适合低频切换
- **`v-show`**：只是 `display: none`，元素始终在 DOM 中，适合高频切换
- **`<template v-if>`**：一次控制多个相邻元素且不产生多余 DOM 包裹
- **两条陷阱**：`v-if` 别和 `v-for` 同元素；`v-else` 必须紧跟前一个兄弟元素
