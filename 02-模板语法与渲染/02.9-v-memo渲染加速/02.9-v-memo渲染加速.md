一个表格页面有 5000 行数据，你只想切换某一列的显示模式，结果页面卡了半秒——明明只有一小块区域需要重绘，Vue 却把整张表重新 Diff 了一遍。上一节我们学会了如何正确组合 `v-for` 和 `v-if`，但列表一上规模，性能问题又会冒出来。这一节要讲的 `v-memo`，就是 Vue 3 专门为"大列表局部更新"准备的渲染加速武器。

## 🤔 一、先看一个场景

假设你做了一个大型数据表格，展示 5000 条学生的各科成绩。每行的结构复杂度不低：有进度条、有颜色标记、有格式化文本。页面上还有一个"全部展开/收起"按钮，切换某列的显示模式。

点了按钮，你会发现页面**卡了半秒**。但仔细一想：5000 条里，真正受影响需要重绘的只有"展开文本"那个区域，其余 4999 条压根没变啊！Vue 为什么要把它们全部 Diff 一遍？

这就是 `v-memo` 要解决的问题。

---

## 💡 二、v-memo 是什么？

`v-memo` 是 Vue 3.2 引入的模板级缓存指令。它的作用很简单：

> **"如果这些依赖项都没变，这棵子树直接复用上一次的 VNode，跳过 Diff。"**

```vue
<div v-memo="[name, age]">
  <!-- 只有当 name 或 age 变化时，才重新渲染这个 div 及其子节点 -->
  <ExpensiveComponent :name="name" :age="age" />
</div>
```

把它放在 `v-for` 上：

```
<div v-for="item in hugeList" :key="item.id" v-memo="[item.selected]">
  <!-- 只有 item.selected 变了，这一行才重新渲染 -->
  {{ item.name }} - {{ item.score }}
</div>
```

`v-memo="[item.selected]"` 的含义：**这行只在 `item.selected` 发生变化时才更新**。如果只改了其他行的 `selected`，当前行直接复用缓存。

---

## 🛠 三、语法详解

### 3.1 基本语法

```
v-memo="[表达式1, 表达式2, ...]"
```

- 接收一个**数组**，元素为任意 JS 表达式
- 数组中**所有**值都与上一次渲染时**全等（`===`）**比较
- 全部相等 → 缓存命中，跳过渲染
- 任意一个不等 → 缓存失效，正常渲染

### 3.2 空数组 = 永不更新

```vue
<span v-memo="[]">{{ Date.now() }}</span>
<!-- 永远显示第一次渲染的时间戳，不会更新 -->
```

这等价于 `v-once`，但语义上更明确。

### 3.3 与 `v-for` 配合

```
<template v-for="item in list" :key="item.id">
  <tr v-memo="[item.score, item.selected]">
    <td>{{ item.name }}</td>
    <td>{{ item.score }}</td>
    <td>{{ item.selected ? '★' : '☆' }}</td>
  </tr>
</template>
```

当 `item.score` 和 `item.selected` 都没变时，整行 `<tr>` 的 VNode 直接复用，不走 Vue 的 Diff 算法。

## 🔬 四、实战对比：普通 v-for vs v-memo

### 场景：1000 行表格 + 单选高亮

做一个学生成绩表：1000 条数据，点击某行高亮该行，其余 999 行不变。

```vue
<script setup>
import { ref, reactive } from 'vue'

// 生成 1000 条模拟数据
const students = ref(
  Array.from({ length: 1000 }, (_, i) => ({
    id: i + 1,
    name: `学生${String(i + 1).padStart(4, '0')}`,
    score: Math.floor(Math.random() * 60) + 40,
    selected: false,
  }))
)

// 模拟"繁重"的渲染（每行生成复杂 DOM）
function getScoreColor(score) {
  if (score >= 90) return '#27ae60'
  if (score >= 60) return '#2980b9'
  return '#e74c3c'
}

// 点击某行 → 切换选中状态
function toggleSelect(id) {
  students.value = students.value.map(s => ({
    ...s,
    selected: s.id === id ? !s.selected : s.selected,
  }))
}

// 用于性能测量
let startTime = 0
function markStart() {
  startTime = performance.now()
}
function logEnd(label) {
  // 用 nextTick 确保 DOM 更新完成后再计时
  requestAnimationFrame(() => {
    const elapsed = (performance.now() - startTime).toFixed(2)
    console.log(`[${label}] 渲染耗时: ${elapsed}ms`)
  })
}
</script>

<template>
  <h2>📊 学生成绩大表（1000 行）</h2>

  <button @click="markStart(); toggleSelect(500); logEnd('v-memo 版本')">
    选中第 500 行
  </button>

  <table border="1" cellpadding="4" cellspacing="0">
    <thead>
      <tr>
        <th>编号</th>
        <th>姓名</th>
        <th>成绩</th>
        <th>等级</th>
        <th>操作</th>
      </tr>
    </thead>
    <tbody>
      <tr
        v-for="s in students"
        :key="s.id"
        v-memo="[s.selected, s.score]"
        :style="{ background: s.selected ? '#fff3cd' : '' }"
      >
        <td>{{ s.id }}</td>
        <td>{{ s.name }}</td>
        <td :style="{ color: getScoreColor(s.score), fontWeight: 'bold' }">
          {{ s.score }}
        </td>
        <td>
          <span v-if="s.score >= 90">🏆 优秀</span>
          <span v-else-if="s.score >= 60">✅ 及格</span>
          <span v-else>❌ 不及格</span>
        </td>
        <td>
          <button @click="toggleSelect(s.id)">
            {{ s.selected ? '取消' : '选中' }}
          </button>
        </td>
      </tr>
    </tbody>
  </table>
</template>
```

### 对比实验

| | 无 `v-memo` | 有 `v-memo="[s.selected, s.score]"` |
|---|---|---|
| 点了"选中第 500 行"后 | Vue 遍历比对全部 1000 行 | Vue 只重绘 `selected` 变化的 1~2 行 |
| Diff 节点数 | ~1000 | ~2 |
| 渲染耗时（参考） | 15~60ms | 1~5ms |
| 用户体感 | 可能微卡 | 完全无感 |

### 场景二：定时更新某一列

```
<script setup>
import { ref } from 'vue'

const items = ref(
  Array.from({ length: 500 }, (_, i) => ({
    id: i,
    name: `商品${i}`,
    price: Math.floor(Math.random() * 1000) + 100,
    stock: Math.floor(Math.random() * 200),     // 时常变
    description: `描述内容很长很长...`.repeat(10), // 基本不变
  }))
)

// 模拟库存实时更新（每秒随机改几行的库存）
setInterval(() => {
  const randomId = Math.floor(Math.random() * 500)
  items.value[randomId] = {
    ...items.value[randomId],
    stock: Math.floor(Math.random() * 200),
  }
}, 1000)
</script>

<template>
  <div
    v-for="item in items"
    :key="item.id"
    v-memo="[item.stock]"
  >
    <span>{{ item.name }}</span>
    <span>¥{{ item.price }}</span>
    <span :class="{ low: item.stock < 20 }">库存: {{ item.stock }}</span>
    <p>{{ item.description }}</p>
  </div>
</template>
```

在这个场景里，`v-memo="[item.stock]"` 的价值非常大：`description` 是长文本（渲染成本高），但 99% 的时候它不变——因此缓存命中后完全不重新渲染长文本部分。

## 🆚 五、v-memo 与 key 的关系

很多人第一次看到 `v-memo` 会想："这和 `:key` 有什么区别？我加了 `:key` 还不够吗？"

| | `:key` | `v-memo` |
|---|---|---|
| 作用阶段 | Diff 匹配阶段 | Diff 跳过阶段 |
| 功能 | 告诉 Vue "这个节点是谁" | 告诉 Vue "这个节点不用查" |
| 粒度 | 整个节点的身份标识 | 子树级的缓存控制 |
| 类比 | 身份证 | 快速通道卡 |

**`key` 确保正确性，`v-memo` 确保性能。两者各司其职，可以一起用。**

## ⚠️ 六、什么时候不应该用 v-memo

### 反模式一：小列表滥用

```vue
<!-- ❌ 3 条数据，加 memo 的开销比收益大 -->
<li v-for="item in 3items" :key="item.id" v-memo="[item]">
```

100 条以内没必要，Vue 的默认 Diff 已经足够快。

### 反模式二：依赖项太多

```
<!-- ❌ 写了 5 个依赖项，每次都要全等比较 5 次 -->
<tr v-memo="[item.name, item.score, item.grade, item.selected, item.time]">
```

依赖项越多，每次比对的成本越高。如果每行数据本来就会频繁变化，缓存基本不命中，`v-memo` 就成了纯开销。

### 反模式三：v-memo 替代 computed

```vue
<!-- ❌ 想用 v-memo 来缓存计算结果？方向错了 -->
<span v-memo="[items]">{{ items.filter(...).map(...).join(...) }}</span>
```

`v-memo` 缓存的是 **VNode（模板渲染结果）**，不是 JS 计算结果。要缓存计算结果请用 `computed`。

## 📊 七、性能优化的决策框架

```
你的列表有多长？
├── < 100 条 → 不需要 v-memo，默认 Diff 够快
├── 100 ~ 1000 条 → 看场景：频繁更新某几列 vs 全量更新
└── > 1000 条 → 强烈建议用 v-memo，配合虚拟滚动更佳

你的列表更新模式？
├── 只改个别几行 → v-memo 收益最大
├── 每行都在高频变化 → 缓存基本不命中，别用
└── 不变列表 → 直接用 v-once（或 v-memo="[]"）
```

## 🧠 本节小结

- **作用**：依赖数组不变时直接复用上次的 VNode，跳过 diff 与重新渲染
- **典型场景**：1000 行大列表只改个别行、表格高亮切换、局部列刷新
- **与 `v-for` 搭配**：`:key` 管"身份"，`v-memo` 管"要不要重新渲染"，职责不同
- **空数组 `v-memo="[]"`** 约等于 `v-once`（永不更新）
- **别滥用**：小列表、依赖项太多、想替代 computed 的场景都不适合
- **决策框架**：先问"每行变化多吗"→ 再决定用不用 v-memo
