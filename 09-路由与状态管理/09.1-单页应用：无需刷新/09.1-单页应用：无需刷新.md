## 🤔 一、传统多页应用怎么跳转？

回想一下传统网站：你点一个链接 → 浏览器向服务器发请求 → 服务器返回一整个新页面的 HTML → 页面白一下 → 渲染出新页面。

```text
点击"关于我们"链接:
浏览器 → GET /about.html → 服务器 → 返回完整 HTML → 浏览器重新渲染
```

每次跳转都走"请求 → 响应 → 渲染"的完整流程。哪怕新页面和旧页面 90% 的布局一样（导航栏、侧边栏、页脚），也得全部重新下载和渲染。

这在网速好的台式机上不明显，但在移动端弱网环境下，白屏时间会很痛苦。

---

## 💡 二、SPA 怎么跳转？

SPA（Single Page Application，单页应用）换个思路：**整个应用只有一个 HTML 页面**。用户看到的"页面切换"实际上是 JS 在同一个页面里**卸载旧组件、挂载新组件**。

```text
点击"关于我们"链接:
浏览器 → 不请求服务器 → JS 把 <Home /> 换成 <About /> → 瞬间切换
```

URL 会变、浏览器历史记录会更新、用户可以前进后退——但页面不会刷新。这就是 SPA 的核心体验。

---

## 🔑 三、SPA 是怎么做到的？—— 前端路由

实现"URL 变了但不刷新页面"，浏览器提供了两种方式：

### 3.1 Hash 模式

URL 中 `#` 后面的部分叫 hash。hash 变化不会触发页面刷新，但可以触发 `hashchange` 事件：

```js
// hash 模式
window.addEventListener('hashchange', () => {
  console.log('当前 hash：', window.location.hash)
  // 根据 hash 切换组件
})
```

URL 示例：`https://app.com/#/about`、`https://app.com/#/user/123`

### 3.2 History 模式

HTML5 的 History API 允许 JS 直接操作浏览器地址栏，`pushState` 改 URL 不刷新页面：

```js
// History 模式
// 跳转到 /about，不刷新
history.pushState(null, '', '/about')

// 监听浏览器的前进 / 后退
window.addEventListener('popstate', () => {
  console.log('当前路径：', window.location.pathname)
})
```

URL 示例：`https://app.com/about`、`https://app.com/user/123`（干净，没有 `#`）

Vue Router 同时支持两种模式，默认推荐 History 模式。

> 💬 **老师备注**：History 模式的 URL 更干净，但需要服务器配置——所有路径都返回同一个 `index.html`，否则用户刷新 `/about` 时服务器会返回 404。Hash 模式不需要服务器配合，开箱即用。

## 🛠 四、SPA 的实际体验

用 Vue Router 构建的 SPA，你看到的页面结构大概长这样：

```vue
<!-- App.vue -->
<template>
  <nav>
    <router-link to="/">首页</router-link>
    <router-link to="/about">关于</router-link>
  </nav>

  <!-- 这里就是"页面切换"的插槽，根据 URL 动态渲染不同组件 -->
  <router-view />
</template>
```

`<router-view>` 就像一个占位符。当 URL 是 `/`，它渲染 `Home` 组件；当 URL 是 `/about`，它渲染 `About` 组件。整个过程中 `<nav>` 导航栏始终不变。

## ⚠️ 五、SPA 的优缺点

| 优点 | 说明 |
|---|---|
| **快** | 首次加载后，页面切换几乎瞬间完成 |
| **流畅** | 无白屏、无闪烁，体验接近原生 App |
| **前后端分离** | 前端专注 UI，后端只提供 API，各自独立开发和部署 |
| **状态保持** | 页面切换不丢失内存中的状态（表单数据、滚动位置等） |

| 缺点 | 说明 |
|---|---|
| **首屏加载慢** | 要下载整个 JS 包才能渲染（代码分割 / 懒加载可缓解） |
| **SEO 不友好** | 搜索引擎爬虫可能抓不到 JS 渲染的内容（SSR / SSG 可解决） |
| **浏览器后退需处理** | 需要手动管理滚动位置、状态恢复等细节 |

> 💬 **老师备注**：SPA 的缺点都有成熟的解决方案——懒加载解决首屏、SSR 解决 SEO。Vue 生态提供了 Nuxt.js 这样的框架来一站式解决这些问题。但作为初学者，先理解 SPA 本身就够了。

## 🧠 本节小结

- **传统 MPA 痛点**：每次跳转都整页刷新、白屏等待，公共状态（如登录态）留不住
- **SPA 定义**：一个 HTML + JS 驱动所有视图切换，数据不丢、交互流畅，体验接近原生 App
- **SPA 优点**：切换快、前后端分离、状态可跨页保持；**缺点**：首屏加载慢、SEO 不友好
- **本质机制**：SPA 也要"路由"来管理视图，只是切换发生在浏览器内存里，不再向服务器要新页面
- **选型认知**：博客/内容站仍可 MPA；后台、工具类应用 SPA 是真香
