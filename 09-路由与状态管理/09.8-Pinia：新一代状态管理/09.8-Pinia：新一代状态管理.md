## 🤔 一、Pinia 是什么？

Pinia 是 Vue 3 官方推荐的状态管理库，由 Vuex 的核心开发者 Eduardo（也是 Vue Router 的作者）打造。你可以把它看作 Vuex 5——吸取了 Vuex 3/4 的所有教训，API 更简洁、类型更安全。

Vue 官方文档已经明确表示：**Pinia is the recommended choice for new projects**。

```bash
npm install pinia
```

```js
// src/main.js
import { createApp } from 'vue'
import { createPinia } from 'pinia'
import App from './App.vue'

const app = createApp(App)
const pinia = createPinia()

app.use(pinia)       // ← 安装 Pinia
app.mount('#app')
```

## 🔑 三、两种 Store 写法

Pinia 提供了两种定义 store 的方式：

### 3.1 Option Store（熟悉 Vuex 的人友好）

```js
// stores/counter.js
import { defineStore } from 'pinia'

export const useCounterStore = defineStore('counter', {
  state: () => ({
    count: 0,
    name: 'Counter'
  }),
  getters: {
    doubleCount: (state) => state.count * 2,
    doubleCountPlusOne() {
      // getter 里可以通过 this 访问其他 getter
      return this.doubleCount + 1
    }
  },
  actions: {
    increment() {
      this.count++
    },
    async incrementAsync() {
      await new Promise(r => setTimeout(r, 1000))
      this.count++
    }
  }
})
```

### 3.2 Setup Store（推荐，最像组合式 API）

```js
// stores/counter.js
import { ref, computed } from 'vue'
import { defineStore } from 'pinia'

export const useCounterStore = defineStore('counter', () => {
  // state → ref
  const count = ref(0)

  // getters → computed
  const doubleCount = computed(() => count.value * 2)

  // actions → 普通函数
  function increment() {
    count.value++
  }

  async function incrementAsync() {
    await new Promise(r => setTimeout(r, 1000))
    count.value++
  }

  // 返回需要暴露的所有内容
  return { count, doubleCount, increment, incrementAsync }
})
```

Setup Store 的优势很明显：

- 你**不需要学新概念**——`ref` 就是 state，`computed` 就是 getters，函数就是 actions
- TypeScript 类型推断**完全自动**，不需要额外声明
- 可以直接使用所有 Vue Composition API（`watch`、`onMounted` 等）
- 逻辑可以像 composable 一样提取和复用

> 💬 **老师备注**：全书推荐使用 **Setup Store** 风格。Option Store 只是兼容写法，新项目无需用它。

## 🛠 四、在组件中使用 Pinia store

```vue
<script setup>
import { useCounterStore } from '../stores/counter'

// 获取 store 实例
const counter = useCounterStore()

// 读取 state 和 getters（直接访问属性）
// 模板里：{{ counter.count }}、{{ counter.doubleCount }}

// 调用 action（直接调函数，不需要 dispatch / commit）
function handleClick() {
  counter.increment()
  // counter.incrementAsync()
}
</script>

<template>
  <div>
    <p>当前计数：{{ counter.count }}</p>
    <p>两倍：{{ counter.doubleCount }}</p>
    <button @click="handleClick">+1</button>
  </div>
</template>
```

对比 Vuex 的写法：

```js
// Vuex（繁琐）
store.state.count              // 读 state
store.getters.doubleCount      // 读 getter
store.dispatch('increment')    // 调 action
store.commit('increment')      // 调 mutation

// Pinia（简洁）
counter.count                  // 读 state
counter.doubleCount            // 读 getter
counter.increment()            // 调 action（没有 mutation）
```

Pinia 为什么能取代 Vuex？核心差异一目了然：

| 对比维度 | Vuex | Pinia |
|---|---|---|
| Mutation | 必须（state 只能通过 commit mutation 改） | 不需要，action 直接改 state |
| 调用方式 | `dispatch('action')` / `commit('mutation')` | 直接调函数 `store.increment()` |
| TypeScript | 类型推断困难，需大量手写类型 | 天然完美推断 |
| 模块化 | 嵌套 module，层层注册 | 每个 store 独立文件，天然模块化 |
| DevTools | 支持 | 支持，且更友好（`$patch` 记录为一条） |
| 学习成本 | 概念多（state / getters / mutations / actions / modules） | 概念少（state / getters / actions） |
| 官方态度 | Vue 3 新项目不再推荐 | Vue 官方推荐 |

## 🛠 五、解构 store 时保持响应式

如果你想解构 store 的值，必须用 `storeToRefs`：

```js
import { storeToRefs } from 'pinia'

const counter = useCounterStore()

// ❌ 直接解构会丢失响应式
const { count, doubleCount } = counter

// ✅ 用 storeToRefs 保持响应式
const { count, doubleCount } = storeToRefs(counter)

// actions 可以直接解构（actions 是函数，不需要响应式）
const { increment } = counter
```

`storeToRefs` 只会提取 state 和 getters，actions 和 `$patch` 等方法不会被提取（这正是我们需要的）。

## 🛠 六、$patch 批量修改

有时候一次要改多个 state 属性，用 `$patch` 可以一次性搞定：

```js
const store = useUserStore()

// 逐个改（会触发多次响应式更新）
store.name = '张三'
store.age = 25
store.email = 'zhangsan@example.com'

// 批量改（只触发一次响应式更新，Devtools 也只记录一条）
store.$patch({
  name: '张三',
  age: 25,
  email: 'zhangsan@example.com'
})

// 甚至可以用函数
store.$patch((state) => {
  state.name = '张三'
  state.age = 25
})
```

## ⚠️ 七、常见陷阱

### 陷阱 1：store 必须用函数形式调用

```js
// ❌
const store = useCounterStore

// ✅
const store = useCounterStore()
```

`defineStore` 返回的是一个 composable 函数，必须调用它才能拿到 store 实例。

### 陷阱 2：在 setup 之外调用 store

```js
// ❌ 在全局作用域调用
const store = useCounterStore()  // 可能还没初始化

// ✅ 在 setup / 生命周期函数中调用
<script setup>
const store = useCounterStore()
</script>
```

Pinia store 依赖 Vue 的 `pinia` 插件初始化，必须在应用挂载之后才能用。

### 陷阱 3：忘记了 `storeToRefs`

直接解构 store 会丢失响应式。任何时候要解构 state 或 getter，记得用 `storeToRefs`。

## 🧠 本节小结

- **Pinia 定位**：Vue 官方推荐的状态管理库（可看作 Vuex 5），没有 mutation、不用 dispatch
- **两种写法**：Option Store（选项式仓库，`state/getters/actions` 字段风格）与 Setup Store（组合式仓库，ref/computed/function 风格，官方推荐）
- **使用套路**：`defineStore('id', 定义)` 创建 → 组件里 `useXxxStore()` 拿实例 → 直接读写、调 action
- **保持响应式**：解构 state 会丢响应，取 `storeToRefs(store)`；actions 不需要
- **对比 Vuex**：TypeScript 友好、模块扁平化、改 state 像调普通函数——老项目才纠结 mutation
- **选型结论**：新项目直接 Pinia；9.7 的 Vuex 知识用来读懂老项目即可
