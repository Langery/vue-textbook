## 🤔 一、什么时候需要编程式导航？

`<router-link>` 只能用在模板里，并且必须是用户"点击"触发。但很多场景需要在 JS 逻辑中导航：

- 登录成功 → 跳首页
- 表单提交完 → 跳结果页
- 检测到权限不足 → 跳 403 页面
- 倒计时结束 → 自动跳转

这些场景不能靠用户"点"链接，必须用 JS 驱动导航——这就是编程式导航。

## 💡 二、`router.push`：最常用的导航

### 2.1 基本用法

```vue
<script setup>
import { useRouter } from 'vue-router'

const router = useRouter()

async function handleLogin() {
  const success = await login(username.value, password.value)
  if (success) {
    router.push('/dashboard')  // 登录成功，跳转到控制台
  }
}
</script>

<template>
  <form @submit.prevent="handleLogin">
    <input v-model="username" />
    <input v-model="password" type="password" />
    <button type="submit">登录</button>
  </form>
</template>
```

### 2.2 多种参数形式

```js
// 字符串路径（最简单）
router.push('/about')

// 路径对象 + query
router.push({ path: '/search', query: { keyword: 'vue', page: 2 } })
// → /search?keyword=vue&page=2

// 命名路由 + params
router.push({ name: 'user', params: { id: 123 } })
// → /user/123

// 带 hash
router.push({ path: '/about', hash: '#team' })
// → /about#team
```

> 💬 **老师备注**：`params` 必须和 `name` 搭配，不能和 `path` 搭配。`router.push({ path: '/user', params: { id: 1 } })` 会导致 `params` 被忽略，这是新手高频错误。

## 🔑 三、`router.replace`：替换而不是追加

`router.push` 的行为是：在浏览器历史记录栈中**追加**一条新记录。用户点"后退"可以回到之前的页面。

`router.replace` 的行为是：**替换**当前历史记录。用户点"后退"不会回到被替换的页面。

```js
// 登录页 → 跳首页，用 replace
// 这样用户登录后在首页点"后退"不会回到登录页
router.replace('/dashboard')
```

适用场景：

| 场景 | 应该用 |
|---|---|
| 登录成功后跳转 | `replace`（不让用户退回登录页） |
| 从 A 页跳到 B 页 | `push`（让用户可以退回 A） |
| 表单提交后跳结果页 | `replace`（避免重复提交） |
| 重定向 | `replace` |

## 🛠 四、`router.go`：前进后退

```js
// 后退一页
router.go(-1)

// 前进一页
router.go(1)

// 后退三页
router.go(-3)
```

本质上就是 `window.history.go()` 的封装。大多数情况下用浏览器的前进后退按钮就够了，但有时你需要在代码里控制——比如移动端的手势滑动返回。

## 🛠 五、实战：完整的登录跳转流程

```
<script setup>
import { ref } from 'vue'
import { useRouter, useRoute } from 'vue-router'

const router = useRouter()
const route = useRoute()

const username = ref('')
const password = ref('')
const error = ref('')

async function handleLogin() {
  error.value = ''

  try {
    const result = await fakeLogin(username.value, password.value)

    if (result.success) {
      // 检查是否有"来源页面"（比如用户直接访问 /dashboard 被拦截到登录页）
      const redirect = route.query.redirect || '/dashboard'
      // 用 replace 防止回到登录页
      router.replace(redirect)
    } else {
      error.value = '用户名或密码错误'
    }
  } catch (e) {
    error.value = '网络错误，请稍后再试'
  }
}
</script>

<template>
  <form @submit.prevent="handleLogin">
    <h2>登录</h2>
    <input v-model="username" placeholder="用户名" />
    <input v-model="password" type="password" placeholder="密码" />
    <p v-if="error" class="error">{{ error }}</p>
    <button type="submit">登录</button>
  </form>
</template>
```

> 💬 **老师备注**：`route.query.redirect` 这个模式非常实用。用户在未登录状态下访问 `/dashboard`，被导航守卫踢到 `/login?redirect=/dashboard`，登录成功后读取 `redirect` 参数跳回去，用户体验很丝滑。

## ⚠️ 六、常见陷阱

### 陷阱 1：`params` 和 `path` 混用

```js
// ❌ params 会被忽略
router.push({ path: '/user', params: { id: 1 } })
// 实际跳转：/user（id 丢了）

// ✅ 用命名路由
router.push({ name: 'user', params: { id: 1 } })
```

### 陷阱 2：重复导航到同一路由

```js
// 当前已经在 /about，再次 push('/about')
// Vue Router 会抛出一个 Uncaught (in promise) NavigationDuplicated 错误
router.push('/about')
```

这个错误通常无害，但如果你在测试中看到它，用 `.catch(() => {})` 处理即可。Vue Router 4 的 `push` 返回 Promise。

### 陷阱 3：导航后立即读取路由参数

```js
// ❌ router.push 是异步的，但这里没有 await
router.push('/dashboard')
console.log(route.path)  // 可能还是旧路径

// ✅ 等待导航完成
await router.push('/dashboard')
console.log(route.path)  // '/dashboard'
```

## 🧠 本节小结

- **核心 API**：`router.push(location)` 跳转并入栈；`replace` 替换当前记录；`back / forward` 前进后退
- **对象写法**：`router.push({ name: 'user', params: { id } })` 比拼字符串路径更稳、更好维护
- **返回值是 Promise**：可 `await`、可 `.catch`，用来处理重复导航等错误，别放任未捕获的 Promise
- **与声明式对比**：模板静态链接用 `<router-link>`；表单提交、登录成功、定时跳转等逻辑场景用编程式
- **踩坑**：用 `params` 时必须配合 `name`（单独 path 下 params 会失效）
