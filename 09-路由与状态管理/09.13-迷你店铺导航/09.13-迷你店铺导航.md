# 9.13 章末实战：迷你店铺导航（P9）

> 章节：第 9 章 路由与状态管理
> 课时：1 课时
> 类型：章末实战 · 独立小项目 P9

---

第九章给了你做"正经多页面应用"的两块骨架：Vue Router 管页面跳转（9.2~9.6），Pinia 管跨页面共享数据（9.8~9.10），最后 9.11 把两者接起来——守卫里读 Store 做权限。这一节我们用它们搭一个**「迷你店铺导航」**：商品列表 → 商品详情 → 购物车 → 结算登录拦截，串起一次完整的浏览-加购-结算动线。它和大项目 Campus2Hand 的关系几乎是一比一：大项目的"前台浏览 / 后台管理"路由分层、`user / cart / goods` 三 Store，就是这套"路由 + 状态管理"思路的放大版。

## 🎯 项目需求（一句话）

做一个"迷你二手店铺"：首页商品列表 → 点进商品详情（动态路由）→ 加购进购物车（Pinia，刷新后购物车还在）→ 结算时未登录先跳登录页（路由守卫 + Store）——全程只用第 9 章已学的 Router 与 Pinia 能力，不引入新库。

### ✅ 验收标准（能跑、能展示）

- [ ] 项目能 `npm run dev` 启动，导航栏能切换"商品列表 / 购物车 / 登录"三个页面
- [ ] 列表页点某件商品，URL 变成 `/goods/:id` 且详情页展示对应商品
- [ ] 商品详情页点"加入购物车"，购物车角标数字 +1；商品可再次加购、可删除
- [ ] 购物车数据用 Pinia 管理并持久化到 `localStorage`：**刷新页面购物车不丢**
- [ ] 未登录时直接访问 `/cart`（或结算按钮）会被守卫拦下并跳到登录页；"登录"后能回到原目标页
- [ ] 能向同学讲清：为什么"购物车"放 Pinia 而不是每个页面自己 `ref`？守卫为什么要在 `beforeEach` 里读 Store？

## 🛠 分步提示（3~5 步，含关键代码锚点）

> 以下只给路线和关键锚点，**不贴全量答案**。卡住时回头翻 9.2 / 9.3 / 9.6 / 9.9 / 9.10 / 9.11 对应小节。

### Step 1：搭路由骨架（回顾 9.2）

建 `router/index.js`：三条一级路由 `/`（列表）、`/goods/:id`（详情，动态路由回顾 9.3）、`/cart`（购物车），App 顶部用 `router-link` 做导航、页面出口放 `<RouterView />`。商品数据先写死在页面里，先把"三个页面能互相跳"跑通。

### Step 2：商品数据进 Store（回顾 9.9 的 product store）

仿照课堂 `stores/product.js` 建 `stores/product.js`：`defineStore` + Setup Store 风格，state 放 6~8 件二手商品（名称、价格、图片可用 emoji/色块占位、描述），提供"按 id 取商品"的 getter。列表页用 `storeToRefs` 解出商品数组渲染成卡片。

### Step 3：详情页走动态路由（回顾 9.3）

详情页用 `useRoute()` 拿 `route.params.id`，再调 product store 的 getter 取商品。可选把 `:id` 声明为 props 后直接用 `defineProps` 接收（9.3 的 Props 传参模式）。卡片上"加入购物车"按钮先留空壳。

### Step 4：购物车 Store + 持久化（回顾 9.8 / 9.9 / 9.10）

建 `stores/cart.js`：state 存 `items`（商品 id + 数量）、actions 提供 `add(itemId)` / `remove(itemId)` / `clear()`，`totalAmount` 用 `computed` 在 store 内实时汇总（回顾 9.9 跨 Store 协作：需要商品单价时在 cart 里 import `useProductStore` 查价格）。按 9.10 教的 localStorage 持久化姿势，让 `items` 刷新不丢。购物车页展示行明细 + 总价 + "去结算"按钮（暂时跳 `/cart` 自己或占位）。

### Step 5：登录守卫 + Store 权限（回顾 9.6 / 9.11）

建 `stores/user.js`（或 `auth.js`）：`isLoggedIn` + `login()` + `logout()`。用 9.11 的姿势在 `router.beforeEach` 里拦截未登录访问 `/cart`：

```js
router.beforeEach((to) => {
  const user = useUserStore()   // 9.11 强调：在守卫里调用 Pinia 是安全的
  if (to.path === '/cart' && !user.isLoggedIn) {
    return { path: '/login', query: { redirect: to.fullPath } }
  }
})
```

登录页点"模拟登录"后调 `user.login()` 并 `router.push(route.query.redirect || '/')` 回跳（回顾 9.5 编程式导航）。此时再验证：未登录访问 `/cart` 被拦、登录后能回到购物车。

## 🚀 延伸挑战（1~2 个加分项）

1. **嵌套路由**：把"商品中心"做成父路由 `/goods`，下面 `children` 里挂列表与详情，体会 9.4 的双层 `RouterView` 布局。
2. **浏览足迹**：详情页每次进入时把"最近看的 5 个商品"写进 `localStorage`，列表页底部展示"最近浏览"——试试把这段逻辑放进一个 composable（8 章技能 + 9.11 的"URL ↔ Store"思路结合）。

## 🔮 它在最后的大项目里长成什么

这一节的"迷你店铺导航"，就是大项目 **Campus2Hand 校园二手集市**的**前台动线骨架**：商品列表/详情 = 这里的 `/goods` 与 `/goods/:id`；购物车 = 这里的 cart store；登录后才能下单 = 这里的守卫拦截。到了第 13 章，这套骨架会放大成"前台 + 后台"两套路由分层、`user / cart / goods` 三个正式 Store，路由守卫里还要做"管理员才能进后台"的权限判断——你在本实战练过的每一步都会原样复用。
