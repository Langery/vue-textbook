## 🧠 思维导图

```text
9.4 嵌套路由
├── 问题：页面内还有页面
│   ├── /user/1/profile 和 /user/1/posts 共享 UserLayout
│   └── 无法用平级路由优雅表达
├── children 子路由
│   ├── 父路由：path: '/user/:id'
│   ├── 子路由：children: [{ path: 'profile' }, { path: 'posts' }]
│   └── 子路由 path 不需要写完整的 '/user/:id/profile'
├── 双层 <router-view>
│   ├── App.vue 的 router-view：渲染 UserLayout
│   ├── UserLayout.vue 的 router-view：渲染 Profile 或 Posts
│   └── 每一层路由各有一个出口
├── 命名路由
│   ├── name: 'user-posts'
│   ├── router.push({ name: 'user-posts' }) 替代路径字符串
│   └── 路径改了也不用改跳转代码
└── 默认子路由
    └── path: '' → 进入 /user/1 时默认渲染哪个子组件
```

动态路由解决了「不同 id、同一套页面」。可后台项目还有个新麻烦：顶栏、侧边菜单、内容区，结构永远是那套壳，只有最里面那块内容在换。如果每个页面都重画一遍壳，改个菜单名得全站动。这节讲嵌套路由，把「壳」和「内容」分层管理。

---

## 🤔 一、场景：用户后台布局

看这个 URL 结构：

```text
/user/1/profile    → 用户 1 的个人资料
/user/1/posts      → 用户 1 的文章列表
/user/1/settings   → 用户 1 的设置
```

这三个页面的布局是一样的：左侧用户头像 + 信息卡，右侧三个 Tab 切换内容。如果写成三个平级路由，每个页面都要复制一份左侧布局——太蠢了。

---

## 💡 二、嵌套路由：`children`

解决方案是**嵌套路由**：父路由负责布局，子路由负责切换内容。

```js
// router/index.js
import UserLayout from '../views/UserLayout.vue'
import UserProfile from '../views/UserProfile.vue'
import UserPosts from '../views/UserPosts.vue'
import UserSettings from '../views/UserSettings.vue'

const routes = [
  {
    path: '/user/:id',
    component: UserLayout,      // 父组件 = 布局框架
    children: [
      // 子路由的 path 不要写 /user/:id 前缀，写相对路径即可
      { path: 'profile', component: UserProfile },
      { path: 'posts', component: UserPosts },
      { path: 'settings', component: UserSettings },
    ]
  }
]
```

---

## 🔑 三、父组件里再放一个 `<router-view>`

`UserLayout.vue` 需要有自己的 `<router-view>` 来渲染子组件：

```vue
<!-- src/views/UserLayout.vue -->
<script setup>
import { useRoute } from 'vue-router'
const route = useRoute()
</script>

<template>
  <div class="user-layout">
    <!-- 左侧：公共信息 -->
    <aside class="sidebar">
      <h2>用户 {{ route.params.id }}</h2>
      <nav>
        <router-link :to="`/user/${route.params.id}/profile`">资料</router-link>
        <router-link :to="`/user/${route.params.id}/posts`">文章</router-link>
        <router-link :to="`/user/${route.params.id}/settings`">设置</router-link>
      </nav>
    </aside>

    <!-- 右侧：子路由渲染位置 -->
    <main class="content">
      <router-view />
    </main>
  </div>
</template>
```

渲染流程：

```text
App.vue 的 <router-view>
  └─ UserLayout.vue（父组件）
      ├── <aside> 侧边栏（始终存在）
      └── UserLayout 的 <router-view>
          ├── /user/1/profile → 渲染 UserProfile.vue
          ├── /user/1/posts → 渲染 UserPosts.vue
          └── /user/1/settings → 渲染 UserSettings.vue
```

> 💬 **老师备注**：`<router-view>` 可以嵌套多层，理论上无限。但一般项目最多三层（根布局 → 页面布局 → 详情/编辑）。

## 🛠 四、默认子路由

进入 `/user/1` 时，如果不指定子路由，右侧 `<router-view>` 是空的。可以设置一个默认子路由：

```js
{
  path: '/user/:id',
  component: UserLayout,
  children: [
    { path: '', component: UserProfile },   // 默认显示资料
    { path: 'profile', component: UserProfile },
    { path: 'posts', component: UserPosts },
    { path: 'settings', component: UserSettings },
  ]
}
```

`path: ''` 表示当 URL 精确匹配父路径（`/user/1`）时自动渲染 `UserProfile`。

## 🛠 五、命名路由

写路径字符串容易出错（比如路径改了要改很多地方），可以给路由起个名字：

```js
const routes = [
  {
    path: '/user/:id',
    name: 'user',         // ← 命名
    component: UserLayout,
    children: [
      { path: 'profile', name: 'user-profile', component: UserProfile },
      { path: 'posts', name: 'user-posts', component: UserPosts },
    ]
  }
]
```

现在跳转可以用名字代替路径：

```
<!-- 模板里 -->
<router-link :to="{ name: 'user-posts', params: { id: 123 } }">
  用户 123 的文章
</router-link>
```

```js
// JS 里
router.push({ name: 'user-posts', params: { id: 123 } })
```

命名路由的优势：如果将来把路径从 `/user/:id/posts` 改成 `/u/:id/posts`，跳转代码一行都不用改——`name` 不变就行。

## ⚠️ 六、常见陷阱

### 陷阱 1：子路由 path 写了 `/` 开头

```js
children: [
  { path: '/profile', component: UserProfile },  // ❌ 会被当成绝对路径 /profile
  { path: 'profile', component: UserProfile },   // ✅ 相对于父路径 /user/:id/profile
]
```

子路由的 `path` 如果以 `/` 开头，会被 Vue Router 视为绝对路径，脱离父路由。

### 陷阱 2：父路由组件忘记写 `<router-view>`

```vue
<!-- UserLayout.vue -->
<template>
  <aside>侧边栏</aside>
  <!-- ❌ 没有 <router-view>，子路由组件无处渲染 -->
</template>
```

忘记写子 `<router-view>` 是嵌套路由最常见的坑。

### 陷阱 3：嵌套过深

三层以上的嵌套路由会让代码难读难调。如果发现自己在写祖孙路由，考虑是不是可以用组件组合代替路由嵌套。

## 🧠 本节小结

- **场景**：后台「顶栏 + 侧边栏 + 内容区」这类固定壳，只有最内层内容随 URL 变
- **写法**：父路由加 `children: []`，子路由 `path` 不带 `/` 表示相对拼接；组件里放子 `<router-view>`
- **默认子路由**：`path: ''` 让父路径直接渲染默认子组件，或用 `redirect` 指过去
- **嵌套层级**：壳组件可以再套壳（如再嵌一层 tabs），每层一个 `<router-view>` 对应渲染
- **注意**：嵌套不代表组件树唯一，按 URL 层级组织即可，别把无父子关系的页面硬塞进 children
