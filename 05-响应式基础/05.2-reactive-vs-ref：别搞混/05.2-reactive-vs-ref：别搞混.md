5.1 的 `ref` 能包单值，可一遇到对象就纠结：`const user = ref({ name: '张三' })` 访问还要多写一层 `.value`。于是有人转头用 `reactive`——省了 `.value`，可把它传出去、解构出来，响应式又悄悄没了。到底什么时候用哪个？本节从类型、访问方式、解构、类型推导几个维度把两者差异摆清楚。

## 🤔 一、为什么会有两个 API？

Vue 3 同时保留了 `ref` 和 `reactive`，很多同学一开始就懵了："两个都能做响应式，到底用哪个？"

答案很简单：**它们解决的是同一个问题（让数据变响应式），但适合不同的场景**。

| | ref | reactive |
|---|---|---|
| **能包什么** | 任何类型（数字、字符串、对象...） | **只能**包对象/数组 |
| **读写方式** | `.value` | 直接读写属性 |
| **底层原理** | `RefImpl` 类 + getter/setter | `Proxy` 拦截 |
| **解构** | 解构会丢响应式（除非 `toRefs`） | 解构会丢响应式（必须 `toRefs`） |
| **模板里** | 自动解包，不用 `.value` | 直接用属性名 |

## 💡 二、reactive 基本用法

```vue
<script setup>
import { reactive } from 'vue'

// reactive() 接收一个对象
const state = reactive({
  name: '张三',
  age: 20,
  hobbies: ['篮球', '游戏']
})

function birthday() {
  state.age++  // ✅ 不用 .value！
}

function addHobby(h) {
  state.hobbies.push(h)  // ✅ 数组操作也响应式
}
</script>

<template>
  <p>{{ state.name }}，{{ state.age }} 岁</p>
  <p>爱好：{{ state.hobbies.join('、') }}</p>
  <button @click="birthday">过生日 +1 岁</button>
</template>
```

`reactive` 的好处：**不用 `.value`**，像操作普通 JS 对象一样读写属性。但代价是**只能包对象**。

---

## 🔬 三、ref 包对象：内部转了 reactive

有意思的是：当你用 `ref` 包一个对象时，**Vue 内部会自动调用 `reactive` 处理深层属性**：

```js
import { ref } from 'vue'

const user = ref({ name: '张三', age: 20 })

// 等价于：ref 内部对 { name: '张三', age: 20 } 调了 reactive
// 所以你改深层属性也是响应式的：
user.value.age++  // ✅ 页面会更新
```

也就是说 `ref({...})` ≈ `ref(reactive({...}))`。**两者都能让深层属性响应式**，区别只是顶层要不要 `.value`。

## 🔑 四、toRefs：解构 reactive 不丢响应式

`reactive` 最大的坑：**解构会丢失响应式**。

```js
const state = reactive({ count: 0, name: 'Vue' })

// ❌ 解构后 count 是普通数字，不是响应式
const { count, name } = state
// count = 1 → 页面不变
```

解决方案：`toRefs()` 把 `reactive` 对象的每个属性转成独立的 `ref`：

```
<script setup>
import { reactive, toRefs } from 'vue'

const state = reactive({ count: 0, name: 'Vue' })

// ✅ 解构后每个属性都是 ref
const { count, name } = toRefs(state)

function add() {
  count.value++   // 页面会更新
}
</script>

<template>
  <p>{{ count }} - {{ name }}</p>    <!-- 模板里不用 .value -->
  <button @click="add">+1</button>
</template>
```

> 💬 **老师备注**：`toRefs` 就是把一个 `{ a: ..., b: ... }` 的 reactive 对象展开成 `{ a: ref(...), b: ref(...) }`，让你可以安全地解构使用。Composables（组合式函数）里特别常用。

## 🛠 五、完整对比示例：表单组件

### reactive 版

```vue
<script setup>
import { reactive } from 'vue'

const form = reactive({
  username: '',
  password: '',
  rememberMe: false
})

function submit() {
  console.log('提交表单：', form)
}
</script>

<template>
  <form @submit.prevent="submit">
    <input v-model="form.username" placeholder="用户名" />
    <input v-model="form.password" type="password" placeholder="密码" />
    <label><input type="checkbox" v-model="form.rememberMe" /> 记住我</label>
    <button type="submit">登录</button>
  </form>
</template>
```

### ref 版（等价写法）

```
<script setup>
import { ref } from 'vue'

const form = ref({
  username: '',
  password: '',
  rememberMe: false
})

function submit() {
  console.log('提交表单：', form.value)  // 注意 .value
}
</script>

<template>
  <!-- 模板里 v-model 会自动解包 ref，所以写 form.username 就行 -->
  <form @submit.prevent="submit">
    <input v-model="form.username" placeholder="用户名" />
    <input v-model="form.password" type="password" placeholder="密码" />
    <label><input type="checkbox" v-model="form.rememberMe" /> 记住我</label>
    <button type="submit">登录</button>
  </form>
</template>
```

两者都能跑。`reactive` 版 JS 代码里不用 `.value`，爽一点；`ref` 版更通用（能包基本类型）。

## ⚠️ 六、常见陷阱

### 陷阱 1：reactive 整体替换会丢响应式

```js
const state = reactive({ count: 0 })

// ❌ state 被整个换成新对象，响应式丢了！
state = { count: 1 }

// ✅ 正确方式：用 Object.assign 合并
Object.assign(state, { count: 1, name: 'new' })
```

### 陷阱 2：reactive 包基本类型（无效）

```js
const count = reactive(0)  // ❌ 不会报错但也不会响应式
```

`reactive` 只能包对象！基本类型乖乖用 `ref`。

### 陷阱 3：ref 模板解包只对顶层属性生效

```vue
<script setup>
const obj = { count: ref(0) }  // 普通对象里包了一个 ref
</script>

<template>
  {{ obj.count + 1 }}  <!-- ❌ 不会自动解包，显示 [object Object]1 -->
</template>
```

模板自动解包**只对 setup 里顶层 ref 变量生效**，嵌套在普通对象里的 ref 不会解包。解决办法：用 `reactive` 包整个对象，或者直接声明为顶层 ref。

## 📝 选型建议

| 场景 | 推荐 |
|---|---|
| 单个数字、字符串、布尔值 | `ref` |
| 表单对象（一组相关字段） | `reactive` |
| 需要解构传给子组件 | `ref` + 直接解构，或 `reactive` + `toRefs` |
| 组合式函数（composable）返回值 | `ref`（更好解构） |
| Vue 3.4+ 新项目 | 统一用 `ref`（官方趋势） |

---

## 🧠 本节小结

- **ref 包任何值**：基础类型、对象、数组都能包；脚本里访问要 `.value`，模板里自动解包
- **reactive 只收对象**：访问属性不用 `.value`，但直接替换整个对象、解构裸属性都会丢响应式
- **传参/解构场景**：`reactive` 对象传出去别丢引用，要解构用 `toRefs`；`ref` 天生好解构
- **类型推导**：`reactive` 推导出的类型更"干净"，但组合式函数返回建议用 `ref`
- **选型口诀**：单个值、要传递 → ref；局部大对象不想老写 `.value` → reactive；Vue 3.4+ 新项目官方趋势是统一 `ref`
