5.5 说"改了不立即变"，可总有些场景你得"等它变了再干活"：数据更新后立刻测量元素高度、滚动到指定位置、拿输入框新宽度。你写 `value++` 后马上读 DOM 还是旧值——很多人加个 `setTimeout` 碰运气，其实 Vue 备好了正经工具。本节主角 `nextTick` 就是"DOM 更新完成"的信号灯。

---

## 🤔 一、什么时候需要 nextTick？

回顾 5.5 节的核心结论：**Vue 异步更新 DOM**。你改了数据，DOM 不是立刻变。

`nextTick` 就是给你一个"DOM 更新完成"的信号：**你想在 DOM 更新后做点事？用 `nextTick` 等着。**

三个经典场景：

| 场景 | 问题 | 解决 |
|---|---|---|
| 改了数据立刻读 DOM | 读到旧值 | `await nextTick()` 后再读 |
| `v-if` 显示输入框后 focus | 输入框还没渲染 | `await nextTick()` 后 `.focus()` |
| 列表新增后滚动到底部 | 滚动高度还是旧的 | `await nextTick()` 后 `.scrollTo()` |

## 💡 二、核心用法

### 2.1 基础语法

```vue
<script setup>
import { ref, nextTick } from 'vue'

const count = ref(0)

async function addAndRead() {
  count.value++
  
  // ❌ 此时 DOM 还是旧的
  console.log(document.getElementById('num').textContent) // "0"
  
  // ✅ 等 DOM 更新完
  await nextTick()
  console.log(document.getElementById('num').textContent) // "1"
}
</script>

<template>
  <p id="num">{{ count }}</p>
  <button @click="addAndRead">+1 并读取</button>
</template>
```

### 2.2 回调写法（兼容旧习惯）

```js
nextTick(() => {
  console.log('DOM 更新完了')
})
// 等价于
await nextTick()
console.log('DOM 更新完了')
```

推荐用 `await` 写法，更现代、代码更平（不用嵌套）。

## 🛠 三、3 个典型应用场景

### 场景 1：改了数据后读 DOM 属性

```
<script setup>
import { ref, nextTick } from 'vue'

const msg = ref('Hello')
const width = ref(0)

async function measure() {
  msg.value = 'Hello, Vue 3!'
  await nextTick()
  // 拿到更新后的元素宽度
  const el = document.getElementById('msg')
  width.value = el.offsetWidth
}
</script>

<template>
  <p id="msg">{{ msg }}</p>
  <p>宽度：{{ width }}px</p>
  <button @click="measure">测量宽度</button>
</template>
```

### 场景 2：v-if 显示输入框后自动 focus

```vue
<script setup>
import { ref, nextTick } from 'vue'

const showInput = ref(false)
const inputRef = ref(null)

async function openInput() {
  showInput.value = true
  await nextTick()
  // v-if 渲染完成后，DOM 才存在
  inputRef.value?.focus()
}
</script>

<template>
  <button @click="openInput">编辑</button>
  <input v-if="showInput" ref="inputRef" placeholder="请输入..." />
</template>
```

### 场景 3：列表新增后滚动到底部

```
<script setup>
import { ref, nextTick } from 'vue'

const list = ref(['消息1', '消息2', '消息3'])
const listContainer = ref(null)

async function addMessage(msg) {
  list.value.push(msg)
  await nextTick()
  // 滚动到最新消息
  const el = listContainer.value
  el.scrollTop = el.scrollHeight
}
</script>

<template>
  <div ref="listContainer" class="msg-list">
    <p v-for="(item, i) in list" :key="i">{{ item }}</p>
  </div>
  <button @click="addMessage('新消息 ' + (list.length + 1))">发送</button>
</template>

<style scoped>
.msg-list {
  height: 200px;
  overflow-y: auto;
  border: 1px solid #ccc;
  padding: 8px;
}
</style>
```

## 🔬 四、nextTick vs setTimeout 时序对比

```js
console.log('1. 同步代码')

count.value = 100                     // 修改数据

nextTick(() => {
  console.log('2. nextTick — DOM 已更新')
})

setTimeout(() => {
  console.log('3. setTimeout 0 — 宏任务')
}, 0)

console.log('4. 同步代码结束')

/*
输出顺序：
1. 同步代码
4. 同步代码结束
2. nextTick — DOM 已更新     ← 微任务，先执行
3. setTimeout 0 — 宏任务     ← 宏任务，后执行
*/
```

如果要在 DOM 更新后立刻操作 DOM，用 `nextTick`（微任务），不要用 `setTimeout`（宏任务，晚一步）。

## ⚠️ 五、常见陷阱

### 陷阱 1：忘了 await

```js
async function buggy() {
  count.value++
  nextTick()                     // ❌ 没有 await，Promise 没有被等待
  console.log(el.textContent)    // 还是旧值
}
```

### 陷阱 2：嵌套 nextTick

```js
await nextTick()
await nextTick()  // ❌ 第二个通常没必要
```

一次 `nextTick` 就是一次 DOM 更新完成后。如果数据只改了一轮，一个 `await nextTick()` 就够了。

### 陷阱 3：在 nextTick 回调里又改数据

```js
await nextTick()
count.value++     // 又改了！这次 DOM 又没更新
// 需要再 await nextTick()
```

如果在 `nextTick` 回调里又改响应式数据，DOM 又进入了"待更新"状态——得再 `await nextTick()` 一次才能读到最新的。

## 🧠 本节小结

- **nextTick 是什么**：返回一个 Promise，在"本次数据变更引起的 DOM 更新完成"后 resolve
- **用法**：`await nextTick()` 或 `nextTick(() => { ... })`，回调里读到的 DOM 是最新的
- **忘记 await 的坑**：不等待直接读 DOM，还是旧值——nextTick 只是排队，不是立即执行
- **vs setTimeout**：nextTick 走微任务、DOM 更新后立刻执行；setTimeout 走宏任务、时机更晚，别拿它替代
- **嵌套不必要**：回调里别再包一层 nextTick，除非又改了数据需要再等一轮
