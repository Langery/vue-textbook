## 🤔 一、为什么购物车必须用 Pinia，而不是组件里的 `ref`

假设你把购物车数据写在 `CartView.vue` 里：

```js
// ❌ 写在页面组件里，别的组件拿不到
const items = ref([])
```

立刻会遇到三个问题：

1. **详情页加购，购物车页不知道**——两个页面各自的 `items` 是两份独立数据；
2. **顶栏角标没法更新**——顶栏是 `AppHeader.vue`，它读不到 `CartView` 里的 `ref`；
3. **刷新页面购物车清空**——组件被销毁，数据跟着走。

购物车是典型的"**多个页面/组件共享 + 需要持久化**"的状态，属于 Pinia 的使用场景。这和第 9 章讲"什么时候该用 store"的判断标准完全一致：**数据要被多个不相关组件读写，就该放进 store。**

> 💬 **老师备注**：判断标准一句话——"这份数据，脱离某个组件之后还有意义吗？"购物车、用户信息、主题设置，都有；某个弹窗的开闭状态，没有。

## 💡 二、`stores/cart.js`：state / getters / actions 三件套

```js
// src/stores/cart.js
import { defineStore } from 'pinia'

export const useCartStore = defineStore('cart', {
  state: () => ({
    // 每一项：{ id, title, price, cover, qty }
    items: []
  }),

  getters: {
    // 总件数：所有条目数量之和（顶栏角标用）
    totalCount: (state) => state.items.reduce((sum, it) => sum + it.qty, 0),

    // 总金额：单价 × 数量再累加
    totalPrice: (state) =>
      state.items.reduce((sum, it) => sum + it.price * it.qty, 0),

    isEmpty: (state) => state.items.length === 0
  },

  actions: {
    // 加购：已在车里就数量 +1，否则新增一条
    addToCart(goods) {
      const found = this.items.find(it => it.id === goods.id)
      if (found) {
        found.qty++
      } else {
        this.items.push({
          id: goods.id,
          title: goods.title,
          price: goods.price,
          cover: goods.cover,
          qty: 1
        })
      }
    },

    // 改数量：0 或负数时直接删掉
    changeQty(id, qty) {
      const found = this.items.find(it => it.id === id)
      if (!found) return
      if (qty <= 0) {
        this.removeItem(id)
        return
      }
      found.qty = qty
    },

    removeItem(id) {
      this.items = this.items.filter(it => it.id !== id)
    },

    clearCart() {
      this.items = []
    }
  }
})
```

三处要讲清楚：

- **`getters` 只做派生，不写副作用**。`totalPrice` 每次依赖变化自动重算，不在里面调接口、不改 `state`。
- **`actions` 里改 `state` 用 `this`**，别解构。`const { items } = this` 之后的修改不会同步回 store（第 9 章的经典陷阱）。
- **`changeQty` 里"减到 0 就移除"**是产品细节：没人想让购物车里躺着一件数量为 0 的商品。

### 2.1 加个持久化，刷新不丢车

第 9 章讲过 Pinia 持久化的思路，这里用最朴素的一版——`watch` 存、初始化读：

```js
// 接上面的 defineStore，补一段初始化与监听
state: () => ({
  items: JSON.parse(localStorage.getItem('c2h-cart') || '[]')
}),
// ...
// 在 main.js 里（或封装成插件）：
// watch 到 items 变化就写回 localStorage
```

```js
// main.js 片段
import { useCartStore } from '@/stores/cart'

const cart = useCartStore()
watch(
  () => cart.items,
  (val) => localStorage.setItem('c2h-cart', JSON.stringify(val)),
  { deep: true }
)
```

> 💬 **老师备注**：`localStorage` 只认字符串，所以进出都要 `JSON.stringify / parse`——这个坑 13.8 刚踩过。生产项目更推荐 `pinia-plugin-persistedstate`，原理就是这段 `watch`。

## 🛠 三、购物车页面：列表 + 合计 + 空态

```vue
<!-- src/views/front/CartView.vue -->
<script setup>
import { useRouter } from 'vue-router'
import { ElMessage, ElMessageBox } from 'element-plus'
import { useCartStore } from '@/stores/cart'

const router = useRouter()
const cart = useCartStore()

function handleCheckout() {
  // 1. 登录校验（13.3 的守卫也会拦，这里显式兜底 + 带 redirect）
  if (!localStorage.getItem('token')) {
    ElMessage.warning('请先登录再下单')
    router.push({ path: '/login', query: { redirect: '/cart' } })
    return
  }

  // 2. 二次确认，防手滑
  ElMessageBox.confirm(
    `共 ${cart.totalCount} 件，合计 ¥${cart.totalPrice.toFixed(2)}，确认下单？`,
    '确认下单',
    { type: 'info' }
  ).then(() => {
    // 3. 本站无真实后端：生成本地订单号，清空购物车
    const orderNo = 'C2H' + Date.now()
    cart.clearCart()
    ElMessage.success(`下单成功！订单号 ${orderNo}，请与卖家线下交易`)
    router.push('/orders')
  }).catch(() => {})   // 用户取消，什么都不做
}
</script>
```

```vue
<template>
  <div class="cart-page">
    <h2>我的购物车</h2>

    <!-- 空态：给用户一条出路 -->
    <el-empty v-if="cart.isEmpty" description="购物车还是空的">
      <el-button type="primary" @click="router.push('/')">去逛逛</el-button>
    </el-empty>

    <template v-else>
      <el-table :data="cart.items">
        <el-table-column label="商品">
          <template #default="{ row }">
            <img :src="row.cover" class="thumb" />
            <span>{{ row.title }}</span>
          </template>
        </el-table-column>
        <el-table-column label="单价" width="120">
          <template #default="{ row }">¥{{ row.price.toFixed(2) }}</template>
        </el-table-column>
        <el-table-column label="数量" width="180">
          <template #default="{ row }">
            <el-input-number
              :model-value="row.qty"
              :min="0"
              size="small"
              @update:model-value="(val) => cart.changeQty(row.id, val)"
            />
          </template>
        </el-table-column>
        <el-table-column label="小计" width="120">
          <template #default="{ row }">¥{{ (row.price * row.qty).toFixed(2) }}</template>
        </el-table-column>
        <el-table-column label="操作" width="90">
          <template #default="{ row }">
            <el-button text type="danger" @click="cart.removeItem(row.id)">删除</el-button>
          </template>
        </el-table-column>
      </el-table>

      <div class="cart-footer">
        <span>共 {{ cart.totalCount }} 件</span>
        <span class="total">合计：¥{{ cart.totalPrice.toFixed(2) }}</span>
        <el-button type="primary" size="large" @click="handleCheckout">结算</el-button>
      </div>
    </template>
  </div>
</template>
```

注意 `el-input-number` 上用的是 `:model-value` + `@update:model-value`，**而不是 `v-model="row.qty"`**。原因：`v-model` 会直接改到 `row.qty`（store 里的 state），绕过了 `changeQty` 里"减到 0 要删除"和未来可能加的校验。**所有对 store 的写操作都应该走 action**，这是 Pinia 的使用纪律。

### 3.1 顶栏角标：另一处"共享"的证明

```vue
<!-- src/components/AppHeader.vue 片段 -->
<script setup>
import { useCartStore } from '@/stores/cart'
const cart = useCartStore()
</script>

<template>
  <el-badge :value="cart.totalCount" :hidden="cart.totalCount === 0">
    <el-button @click="$router.push('/cart')">购物车</el-button>
  </el-badge>
</template>
```

详情页只要 `cart.addToCart(goods)`，顶栏角标立刻 +1、购物车页立刻多一行——**这就是 store 的价值：一份数据，处处同步。**

## ⚠️ 五、常见陷阱

### 陷阱 1：直接改 state，绕过 action

```js
// ❌ 组件里直接改，逻辑散落各处
cart.items.push(goods)

// ✅ 永远走 action
cart.addToCart(goods)
```

### 陷阱 2：`getters` 里做副作用

```js
// ❌ getters 里调接口 / 改数据，会导致重复请求与死循环
totalPrice: (state) => { api.log(); return ... }

// ✅ getters 只做纯计算
totalPrice: (state) => state.items.reduce((sum, it) => sum + it.price * it.qty, 0)
```

### 陷阱 3：金额直接相加后显示成一长串小数

```js
// ❌ 0.1 + 0.2 = 0.30000000000000004
{{ cart.totalPrice }}

// ✅ 展示层统一 toFixed(2)；真要精确计算应把金额存成"分"
{{ cart.totalPrice.toFixed(2) }}
```

### 陷阱 4：刷新后购物车空了

没做持久化，Pinia 的 `state` 只活在内存里。补上第二节那段 `watch` + `localStorage` 即可。

> 💬 **老师备注**：面试高频题"购物车数据怎么存的？"标准答案分两层——**状态层用 Pinia 管理，持久层落 localStorage（或后端购物车接口）**，并说清"以服务端为准、本地只做缓存"的取舍。

## 🧠 本节小结

- **购物车 = 跨页面共享状态**，判断依据是"数据脱离组件后是否还有意义"，该进 Pinia 就别犹豫
- **三件套各司其职**：`state` 存数据、`getters` 纯派生（总件数 / 总金额）、`actions` 改数据（加购 / 改量 / 删除 / 清空）
- **写操作一律走 action**，组件里不要直接改 `state`；`v-model` 换成 `:model-value + @update:model-value` 就是为了这个
- **金额显示统一 `toFixed(2)`**，真要精确计算应改为"以分为单位存整数"
- **模拟下单讲清前端职责**：登录校验 → 二次确认 → 生成订单号 → 清空购物车 → 提示与跳转；没后端不代表可以省略流程设计
- **持久化一句话**：`watch` 深监听 + `localStorage` 存取，刷新不丢车
