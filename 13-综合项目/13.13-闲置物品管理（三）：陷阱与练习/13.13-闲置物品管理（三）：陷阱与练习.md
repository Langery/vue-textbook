## ⚠️ 一、常见陷阱

闲置物品管理是 Campus2Hand 管理后台里最典型的 CRUD 页面，坑也最集中。下面 4 个陷阱每个都按「错误代码 → 正确代码 → 原因与排查要点」三件套讲清楚，对照你手头的 `GoodsList.vue` / `GoodsForm.vue` 就能改。

### 陷阱 1：删除后列表没刷新

```js
// ❌ 错误：删除成功但列表还是原来的
const handleDelete = async (row) => {
  await deleteGoods(row.id)      // 删了
  // 完事？没完！列表数据还是旧数组，被删的行还挂在页面上
}
```

```js
// ✅ 正确：删除后重新拉取列表，并处理"删掉当前页最后一条"的边界
const handleDelete = async (row) => {
  await deleteGoods(row.id)
  ElMessage.success('删除成功')

  // ① 如果当前页只剩这一条，且不是第一页，页码先减 1
  if (goodsList.value.length === 1 && pageNum.value > 1) {
    pageNum.value -= 1
  }

  // ② 重新拉数据
  await fetchList()
}
```

**原因**：删除接口只改了数据库，**页面上的 `goodsList` 是前端内存里的副本**，不会自己更新。必须重新调 `fetchList()` 拉取最新数据（或者至少 `goodsList.splice(index, 1)` 本地删掉一行）。

**排查要点**：
1. `handleDelete` 里有没有调用 `fetchList()`？没有就是没刷新；
2. 删除的是当前页最后一条时，`pageNum` 不减 1，后端会返回"空页"——表现为"删完列表空了"；
3. 删除接口返回后有没有 `ElMessage.success` 提示？没有的话用户以为没删成功，会反复点；
4. 顺手检查：删除按钮有没有做二次确认（`ElMessageBox.confirm`），防止误删。

### 陷阱 2：编辑页数据未回填就直接提交

```js
// ❌ 错误：用户刚进编辑页，接口还没返回，表单是空的，直接点提交
const handleSubmit = async () => {
  // goodsForm 此时还是初始值：name=''、price=0、stock=0
  // 直接把空数据 PUT 到后端，把闲置物品改没了
  await updateGoods(route.params.id, goodsForm)
}
```

```js
// ✅ 正确：提交按钮加 loading，回填完成前禁止提交
const isEdit = ref(!!route.params.id)
const loading = ref(false)        // ① 回填 / 提交共用的 loading

onMounted(async () => {
  if (isEdit.value) {
    loading.value = true          // ② 回填期间锁住按钮
    try {
      const res = await getGoodsDetail(route.params.id)
      Object.assign(goodsForm, res.data)
    } finally {
      loading.value = false
    }
  }
})

const handleSubmit = async () => {
  if (loading.value) return       // ③ 双保险：loading 时直接忽略点击
  loading.value = true
  try {
    if (isEdit.value) {
      await updateGoods(route.params.id, goodsForm)
    } else {
      await createGoods(goodsForm)
    }
    ElMessage.success(isEdit.value ? '修改成功' : '新增成功')
    router.back()
  } finally {
    loading.value = false
  }
}
```

```vue
<!-- 按钮绑定 loading：回填/提交期间自动禁用 -->
<el-button type="primary" :loading="loading" @click="handleSubmit">
  {{ isEdit ? '保存修改' : '新增闲置物品' }}
</el-button>
```

**原因**：`goodsForm` 是初始值（空字符串/0），编辑模式下 `getGoodsDetail` 还没返回就提交，等于用空数据覆盖了闲置物品。用户感知是"我没改啥，闲置物品怎么没了"。

**排查要点**：
1. 提交前判断 `isEdit.value && !goodsForm.name` 时阻止提交（兜底方案）；
2. 更规范的是提交按钮加 `loading`，回填完成前天然禁用；
3. 检查 `onMounted` 里回填失败时有没有 `finally { loading = false }`——否则按钮会一直转圈；
4. 回填用 `Object.assign(goodsForm, res.data)` 比逐个赋值更简洁，也避免漏字段。

### 陷阱 3：图片上传不带 token

```js
// ❌ 错误：el-upload 默认不带 Authorization 头
<el-upload
  action="/api/goods/upload"
  :on-success="handleUploadSuccess"
/>
<!-- 后端：401！你的 token 呢？ -->
```

```js
// ✅ 正确：在 :headers 里手动加 token
// el-upload 发的是原生 XMLHttpRequest，不经过 Axios 拦截器
// 所以拦截器里的"统一加 token"对上传请求无效，必须手动加
const uploadHeaders = {
  Authorization: `Bearer ${localStorage.getItem('token')}`
}
```

```vue
<el-upload
  action="/api/goods/upload"
  :headers="uploadHeaders"
  :on-success="handleUploadSuccess"
>
  <el-button type="primary">上传图片</el-button>
</el-upload>
```

**原因**：Axios 拦截器只对**通过 Axios 发出去的请求**生效。`el-upload` 内部用的是浏览器原生 `XMLHttpRequest` 直接打 `action` 地址，绕过了你的拦截器——所以请求头里没有 token，后端直接 401。

**排查要点**：
1. 上传接口报 401，先看 Network → 上传请求的 Request Headers 里有没有 `Authorization`；
2. 确认是 `localStorage` 还是 Pinia 存 token——`:headers` 里只能取同步可读的值；
3. 如果 token 会过期，`:headers` 里的旧 token 会一直生效到刷新页面（`uploadHeaders` 是常量）；进阶做法是用 `:before-upload` 动态组装 headers 或直接走自定义 `http-request`；
4. 别忘了设置 `name="file"`，和后端约定的字段名一致。

### 陷阱 4：数字输入用了 `el-input`

```js
// ❌ 错误：价格/库存用 el-input + v-model.number
<el-input v-model.number="goodsForm.price" placeholder="价格" />
<el-input v-model.number="goodsForm.stock" placeholder="库存" />

// 三个隐藏问题：
// ① 用户能输入 "abc"，v-model.number 转换失败时值是原始字符串 "abc"
// ② 没有上下限，价格能输 -999，库存能输 3.7
// ③ 没有增减按钮，体验也差一截
```

```vue
<!-- ✅ 正确：用 el-input-number，自带范围限制和增减按钮 -->
<el-input-number
  v-model="goodsForm.price"
  :min="0.01"
  :precision="2"        <!-- 保留两位小数 -->
  :step="1"
  controls-position="right"
/>
<el-input-number
  v-model="goodsForm.stock"
  :min="0"
  :precision="0"        <!-- 库存只能是整数 -->
/>
```

**原因**：`v-model.number` 只是个"尽力转换"的修饰符——输入合法数字时转成 number，输入不合法内容（如 `abc`）时**原样保留字符串**。价格 `"abc"` 提交到后端，轻则校验失败，重则 `NaN` 入库。`el-input-number` 从组件层面杜绝了非法输入，还自带范围校验。

**排查要点**：
1. 表单里凡是"数字语义"的字段（价格/库存/数量），统一用 `el-input-number`；
2. `precision` 记得设：价格 `2` 位小数、库存 `0` 位（整数）；
3. 后端字段是整数时，`min` 和 `precision` 一起设，别让用户输入负数库存；
4. 提交前再配合 `rules` 里的 `type: 'number'` 校验双保险（见 13.12 的 `GoodsForm.vue`）。

## 📝 二、即时练习

3 个练习层层递进：先会"选中批量操作"，再管"上传并发状态"，最后做"筛选联动"。每个都附「需求拆解 → 参考骨架 → 验收清单」。

### 练习 1：批量删除

**需求拆解**：
1. 在 `el-table` 上增加复选框列：`<el-table-column type="selection" />`，并用 `@selection-change` 收集选中的行到 `selectedRows`；
2. 顶栏加"批量删除"按钮，`disabled` 绑定"没有选中任何行"；
3. 点击后弹二次确认（`ElMessageBox.confirm`），确认后并行（或串行）调用删除接口；
4. 全部删除成功后清空选中、刷新列表。

**参考实现骨架**：

```vue
<template>
  <div class="goods-toolbar">
    <el-button
      type="danger"
      :disabled="selectedRows.length === 0"
      :loading="deleting"
      @click="handleBatchDelete"
    >
      批量删除（{{ selectedRows.length }}）
    </el-button>
  </div>

  <el-table
    :data="goodsList"
    @selection-change="handleSelectionChange"
  >
    <el-table-column type="selection" width="55" />
    <el-table-column prop="name" label="闲置物品名称" />
    <!-- 其他列... -->
  </el-table>
</template>
```

```js
import { deleteGoods } from '@/api/goods'
import { ElMessage, ElMessageBox } from 'element-plus'

const selectedRows = ref([])
const deleting = ref(false)

const handleSelectionChange = (rows) => {
  selectedRows.value = rows
}

const handleBatchDelete = async () => {
  try {
    await ElMessageBox.confirm(
      `确定删除选中的 ${selectedRows.value.length} 个闲置物品吗？`,
      '批量删除',
      { type: 'warning' }
    )
  } catch {
    return   // 用户取消
  }

  deleting.value = true
  try {
    // 并行删除（也可以用 Promise.all 统一处理错误）
    await Promise.all(selectedRows.value.map((row) => deleteGoods(row.id)))
    ElMessage.success('批量删除成功')
    selectedRows.value = []
    await fetchList()   // 别忘了刷新（陷阱 1 的教训！）
  } finally {
    deleting.value = false
  }
}
```

**验收清单**：

- [ ] 表格左侧出现复选框列，能勾选多行
- [ ] 未选中任何行时"批量删除"按钮是禁用态
- [ ] 点击后弹出二次确认，取消不会删除
- [ ] 确认后调用删除接口，按钮有 loading 状态防重复点击
- [ ] 删除成功后选中清空、列表刷新，被删闲置物品不再出现
- [ ] 删除的是当前页全部行时，页码能正确回退（参考陷阱 1）

### 练习 2：上传未完成禁止提交

**需求拆解**：
1. 用 `ref` 维护一个 `uploading` 状态（默认 `false`）；
2. 用 `el-upload` 的 `on-change` 钩子：有文件在上传时 `uploading = true`，`status === 'success'` 时置回 `false`；
3. 提交按钮：`uploading` 为 `true` 时禁用并提示"图片上传中，请稍候"；
4. 额外兜底：`on-remove` 也更新一下状态，防止删掉上传中的文件后状态卡死。

**参考实现骨架**：

```vue
<el-upload
  action="/api/goods/upload"
  :headers="uploadHeaders"
  :on-change="handleUploadChange"
  :on-remove="handleUploadRemove"
  list-type="picture-card"
>
  <el-icon><Plus /></el-icon>
</el-upload>

<el-button
  type="primary"
  :loading="submitting || uploading"
  @click="handleSubmit"
>
  {{ uploading ? '图片上传中...' : '提交' }}
</el-button>
```

```js
const uploading = ref(false)

// on-change 在文件状态变化时触发（选中/上传中/成功/失败都会触发）
const handleUploadChange = (file) => {
  if (file.status === 'uploading') {
    uploading.value = true
  } else if (['success', 'error', 'removed'].includes(file.status)) {
    // 所有文件都不在传了，才解除锁定
    uploading.value = fileList.value.some((f) => f.status === 'uploading')
  }
}

const handleUploadRemove = () => {
  // 删除文件后重新计算：还有没有在上传的
  uploading.value = fileList.value.some((f) => f.status === 'uploading')
}
```

**验收清单**：

- [ ] 上传图片期间，提交按钮显示"图片上传中..."且不可点击
- [ ] 上传完成后按钮恢复可点击
- [ ] 上传失败时按钮也能恢复（不会永远锁死）
- [ ] 上传过程中删除该文件，状态能正确解除
- [ ] 提交成功后表单重置，上传列表也清空（`fileList` 置空）

### 练习 3：按分类筛选联动

**需求拆解**：
1. 顶栏加一个 `el-select`，选项来自分类接口（或 13.11 定义的 `GOODS_CATEGORIES` 常量）；
2. `v-model` 绑定 `queryForm.categoryId`，`change` 时重置 `pageNum = 1` 并调用 `fetchList()`；
3. 把 `categoryId` 和搜索关键词一起放进请求参数——支持"按名称搜索 + 按分类筛选"同时生效；
4. 清空分类（选"全部"）时传 `undefined`，不要传 `''` 给后端（很多后端空串会参与过滤）。

**参考实现骨架**：

```vue
<div class="filter-bar">
  <el-input
    v-model="queryForm.keyword"
    placeholder="搜索闲置物品名称"
    clearable
    @keyup.enter="handleSearch"
  />
  <el-select
    v-model="queryForm.categoryId"
    placeholder="全部分类"
    clearable
    @change="handleCategoryChange"
  >
    <el-option
      v-for="cat in categories"
      :key="cat.id"
      :label="cat.name"
      :value="cat.id"
    />
  </el-select>
  <el-button type="primary" @click="handleSearch">查询</el-button>
</div>
```

```js
const queryForm = reactive({
  keyword: '',
  categoryId: undefined
})

const handleCategoryChange = () => {
  pageNum.value = 1          // 筛选条件变了，回到第一页
  fetchList()
}

const handleSearch = () => {
  pageNum.value = 1
  fetchList()
}

// fetchList 组装参数：空值不传给后端
const fetchList = async () => {
  const params = {
    pageNum: pageNum.value,
    pageSize: pageSize.value,
  }
  if (queryForm.keyword) params.keyword = queryForm.keyword
  if (queryForm.categoryId) params.categoryId = queryForm.categoryId

  const res = await getGoodsList(params)
  goodsList.value = res.data.list
  total.value = res.data.total
}
```

**验收清单**：

- [ ] 下拉框能展示分类列表，默认"全部分类"
- [ ] 选择分类后列表按该分类过滤，且页码重置为 1
- [ ] 输入关键词 + 选择分类同时生效（交集筛选）
- [ ] 清空分类选择后能恢复全部闲置物品
- [ ] 空值（keyword/categoryId）不会以空字符串形式传给后端
- [ ] 翻页、搜索、筛选三者状态互不干扰

## 🚀 三、进阶挑战

**挑战 1：删除二次确认 + 加载态**

把单行删除也做成"确认 → loading → 刷新"的完整闭环，并区分"删除中"和"删除成功"两种状态：

```js
const deletingId = ref(null)   // 正在删除的闲置物品 id

const handleDelete = async (row) => {
  try {
    await ElMessageBox.confirm(`确定删除闲置物品「${row.name}」吗？`, '删除确认', {
      type: 'warning'
    })
  } catch {
    return
  }
  deletingId.value = row.id
  try {
    await deleteGoods(row.id)
    ElMessage.success('删除成功')
    if (goodsList.value.length === 1 && pageNum.value > 1) pageNum.value -= 1
    await fetchList()
  } finally {
    deletingId.value = null
  }
}
```

验收：删除按钮在请求期间显示 loading（`:loading="deletingId === row.id"`），用户无法连点；删除当前页最后一条时页码正确回退；取消确认不触发任何请求。

**挑战 2：价格区间筛选**

在练习 3 的基础上，加 `minPrice` / `maxPrice` 两个数字输入框，后端接口支持 `minPrice`/`maxPrice` 参数。要求：`minPrice > maxPrice` 时前端直接提示"最小价格不能大于最大价格"，不发请求；只填一个时只传一个参数。验收：价格区间与分类、关键词三者可同时组合筛选，参数干净无空值。

## 🧠 本节小结

- **陷阱 1 删完要刷新**：删除只改后端，前端列表要 `fetchList()` 重拉；删的是当前页最后一条时先把 `pageNum` 减 1，避免空页
- **陷阱 2 回填未完禁提交**：编辑模式用 `loading` 锁住提交按钮（`onMounted` 回填 `finally` 里解锁），回填可用 `Object.assign(goodsForm, res.data)`；兜底判断 `isEdit && !name` 阻止空提交
- **陷阱 3 上传要手动带 token**：`el-upload` 走原生 XHR 绕过 Axios 拦截器，必须用 `:headers="{ Authorization: Bearer ... }"`；token 过期场景可用 `:before-upload` 动态组装或自定义 `http-request`
- **陷阱 4 数字字段用 el-input-number**：`v-model.number` 遇非法输入会原样保留字符串；`el-input-number` 设 `:min` / `:precision`（价格 2 位、库存 0 位）从组件层杜绝脏数据
- **练习要点**：批量删除用 `type="selection"` 列 + `@selection-change` 收集 + `Promise.all` 并发 + 删除后刷新；上传中 `on-change` 维护 `uploading` 状态锁提交按钮；分类筛选与关键词可叠加，空值不传给后端
- **进阶挑战**：单行删除用 `deletingId` 粒度 loading；价格区间筛选在 `min > max` 时前端拦截不发请求
