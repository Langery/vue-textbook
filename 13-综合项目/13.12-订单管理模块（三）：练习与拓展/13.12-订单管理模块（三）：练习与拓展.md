## 📝 一、即时练习

3 个练习覆盖了订单模块最常用的三个能力：**文件下载、状态变更、条件查询**。每个都附「需求拆解 → 参考骨架 → 验收清单」。

### 练习 1：导出订单 Excel

**需求拆解**：
1. 在订单列表页顶栏加"导出"按钮，点击后调用后端接口 `/orders/export`；
2. Axios 请求设置 `responseType: 'blob'`——后端返回的是二进制流，不是 JSON，不设置会得到一堆乱码文本；
3. 拿到 blob 后用 `URL.createObjectURL` 创建临时链接、`a.click()` 触发下载、最后 `URL.revokeObjectURL` 释放内存；
4. 处理好"导出当前筛选条件"和"导出为空"两种场景。

**参考实现骨架**：

```js
// src/api/order.js
export const exportOrders = (params) => {
  return request({
    url: '/orders/export',
    method: 'get',
    params,
    responseType: 'blob'   // ✅ 关键：告诉 Axios 按二进制流接收
  })
}
```

```js
// OrderList.vue 中的导出逻辑
import { exportOrders } from '@/api/order'

const handleExport = async () => {
  const res = await exportOrders(currentQuery)   // 带上当前筛选条件

  // ① 从响应头里尝试拿后端给的文件名（拿不到就用默认名）
  const disposition = res.headers['content-disposition'] || ''
  const match = disposition.match(/filename\*?=(?:UTF-8'')?"?([^";]+)"?/i)
  const filename = match ? decodeURIComponent(match[1]) : '订单导出.xlsx'

  // ② 创建临时链接触发下载
  const url = URL.createObjectURL(new Blob([res.data]))
  const link = document.createElement('a')
  link.href = url
  link.download = filename
  link.click()

  // ③ 释放内存（不释放会累积内存泄漏）
  URL.revokeObjectURL(url)
}
```

**验收清单**：

- [ ] 点击"导出"能下载到一份 Excel 文件，且内容与当前列表一致
- [ ] 文件能正常打开，不是乱码（说明 `responseType: 'blob'` 设置成功）
- [ ] 文件名来自后端 `content-disposition`（拿不到时回退到默认名）
- [ ] 筛选了日期/状态后导出，导出内容也按相同条件过滤
- [ ] 导出为空数据时不报错，能给用户"暂无数据可导出"的提示（进阶）
- [ ] 导出按钮有 loading 状态，防止重复点击

### 练习 2：详情弹窗内修改状态

**需求拆解**：
1. 在 `OrderDetailDialog.vue` 的状态展示处，把只读的 `el-tag` 换成 `el-select`（或保留 Tag、另加一个下拉框）；
2. 选项来自 13.10 定义的 `ORDER_STATUS_OPTIONS`（如 待付款/已付款/已发货/已完成/已取消）；
3. 选中新状态后调用 `updateOrderStatus(id, status)`；
4. 成功后：更新本地状态、`ElMessage.success` 提示、`emit` 事件通知父组件刷新列表。

**参考实现骨架**：

```vue
<!-- OrderDetailDialog.vue -->
<el-descriptions-item label="订单状态">
  <el-select
    :model-value="orderDetail.status"
    placeholder="请选择状态"
    @change="handleStatusChange"
  >
    <el-option
      v-for="opt in ORDER_STATUS_OPTIONS"
      :key="opt.value"
      :label="opt.label"
      :value="opt.value"
    />
  </el-select>
</el-descriptions-item>
```

```js
import { updateOrderStatus } from '@/api/order'
import { ORDER_STATUS_OPTIONS } from '@/constants/orderStatus'

const emit = defineEmits(['refresh'])

const handleStatusChange = async (newStatus) => {
  const oldStatus = orderDetail.value.status
  try {
    await updateOrderStatus(orderDetail.value.id, newStatus)
    orderDetail.value.status = newStatus      // 本地立即更新
    ElMessage.success(`状态已从「${getStatusLabel(oldStatus)}」改为「${getStatusLabel(newStatus)}」`)
    emit('refresh')                            // 通知父组件刷新列表
  } catch {
    // 失败：保持原状态，el-select 通过 model-value 自动回显
    ElMessage.error('状态修改失败')
  }
}
```

**验收清单**：

- [ ] 详情弹窗里能打开状态下拉框，选项与 13.10 定义一致
- [ ] 选择新状态后调用接口，成功才更新本地状态
- [ ] 成功后弹提示，并通知父组件刷新列表（列表里的状态同步变化）
- [ ] 接口失败时下拉框回显原状态，不产生"前端改了、后端没改"的假象
- [ ] 修改状态期间按钮/下拉框有防重复提交处理（loading 或禁用）

### 练习 3：按日期范围筛选

**需求拆解**：
1. 在订单列表筛选区加 `el-date-picker`，类型 `daterange`，绑定 `dateRange` 数组；
2. 选择范围后，拆成 `startDate` / `endDate` 传给后端（或直接传 `startDate`/`endDate` 两个参数）；
3. 参考 13.10 的筛选逻辑：**日期变化时重置 `pageNum` 为 1**；
4. 值为空时不传参数给后端（后端拿 `''` 做过滤会查不出数据）。

**参考实现骨架**：

```vue
<el-date-picker
  v-model="dateRange"
  type="daterange"
  range-separator="至"
  start-placeholder="开始日期"
  end-placeholder="结束日期"
  value-format="YYYY-MM-DD"
  @change="handleDateChange"
/>
```

```js
const dateRange = ref([])

const handleDateChange = () => {
  pageNum.value = 1          // 筛选条件变化 → 回到第一页
  fetchList()
}

// fetchList 组装参数：空值不传
const fetchList = async () => {
  const params = { pageNum: pageNum.value, pageSize: pageSize.value }
  if (dateRange.value?.length === 2) {
    params.startDate = dateRange.value[0]
    params.endDate = dateRange.value[1]
  }
  // 其他筛选条件（keyword / status）同理...
  const res = await getOrderList(params)
  orderList.value = res.data.list
  total.value = res.data.total
}
```

**验收清单**：

- [ ] 能选择起止日期，选择后列表按日期范围过滤
- [ ] 选择日期后页码重置为 1（从第 5 页筛选后不会停留在空页）
- [ ] 清空日期范围后恢复全部订单
- [ ] 参数以 `YYYY-MM-DD` 格式传给后端，空值不传
- [ ] 与状态筛选、关键词搜索能组合使用

## 🚀 二、进阶挑战

**挑战 1：导出文件名带日期 + 空数据拦截**

升级练习 1：导出时自动把导出日期拼进文件名（如 `订单导出_2026-08-28.xlsx`）；后端返回的 blob 为空时，用 `res.data.size === 0` 拦截并提示"暂无数据可导出"，避免下载一个打不开的空文件。

提示：`new Blob([res.data]).size` 可以判断 blob 是否为空；文件名里不要带 `:` 等非法字符。

**挑战 2：状态流转合法性校验**

订单状态不是随便改的——"已发货"不能改回"已付款"，"已完成"不能改回"已发货"。请为 13.11 的 `handleShip` 和练习 2 的下拉框加一层**状态机校验**：定义每个状态允许流转到哪些状态（如 `已付款 → [已发货, 已取消]`），不允许的流转直接提示"当前状态不能直接变更为 X"。

提示：在 `orderStatus.js` 里维护一张 `ORDER_STATUS_TRANSITIONS` 映射表；前端校验拦截后，后端接口最好也做同样的校验（前端校验是体验，后端校验才是安全）。

验收：从"已发货"尝试改回"已付款"会被拦截并给出明确提示；合法流转（已付款→已发货）正常通过。

### 4.2 回顾对照：13.10 / 13.11 / 13.12 知识串讲

三个小节表面上是"接口 → 组件 → 练习"的递进，本质上是**同一条数据链路的三次打磨**。对照着看会更清楚：

| 环节 | 13.10 打下的基础 | 13.11 的进阶 | 13.12 你的产出 |
|---|---|---|---|
| 数据获取 | `getOrderList(params)` 封装分页查询 | 详情弹窗 `getOrderDetail(id)` 单独拉详情 | 导出复用同一份查询参数（`currentQuery`） |
| 状态展示 | `orderStatus.js` 定义 `status → label/tagType` 映射 | 详情弹窗用映射渲染 `el-tag` | 下拉框直接复用 `ORDER_STATUS_OPTIONS` 改状态 |
| 状态变更 | 只读列表，无变更能力 | `handleShip` 单点发货（写死逻辑） | 通用 `updateOrderStatus(id, status)` + 状态机校验 |
| 条件筛选 | 关键词搜索 + 状态筛选 | — | 日期范围筛选，与既有筛选统一走 `pageNum=1` 重置 |
| 用户反馈 | `ElMessage` 提示 | `ElMessageBox.confirm` 二次确认 | loading / 防重复提交 / 失败回显 |

**一个关键认知**：13.10 的 `orderStatus.js` 是 13.11 和 13.12 的"公共字典"——展示用它的映射，修改用它的选项，进阶校验也基于它扩展。写业务代码前先定义好这类**常量与映射**，后面每个功能都会受益。

### 4.3 模块横向对比

订单模块和商品模块（13.7~13.9）合起来，你已经掌握了后台管理系统最常见的两种页面形态：

| 对比维度 | 商品模块（CRUD 表单型） | 订单模块（只读展示型） |
|---|---|---|
| 核心操作 | 增删改查全都要 | 查询 + 详情 + 状态流转 |
| 主要组件 | `el-form` + `el-upload` | `el-table` + `el-dialog` + `el-descriptions` |
| 数据特点 | 用户可编辑、需校验 | 系统生成、只读为主 |
| 常见陷阱 | 回填 / 上传 token / 数字输入 | blob 下载 / 状态机约束 |
