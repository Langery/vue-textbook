## 🤔 一、为什么需要做一个综合项目？

前 12 章你学了大量知识点：组件、Props、事件、响应式、组合式 API、路由、状态管理、Axios……

但**知识点 ≠ 能力**。

就像你背了所有菜谱，不代表你能做一桌宴席。综合项目就是那桌宴席——把你学过的所有知识**串起来**，在一个真实场景里用一遍。

> 💬 **老师备注**：很多企业面试官不会问你"Vue 3 的 reactive 和 ref 有什么区别"，而是直接让你"用 Vue 3 做一个后台管理系统"。这一章就是帮你准备好这个答案。

---

## 💡 二、项目定位：电商后台管理系统

我们做的不是面向消费者的购物网站（那是前端 + 后端 + 支付 + 物流的大工程），而是**电商后台管理系统**——电商运营人员用来管理商品、订单、用户的内部工具。

这类系统在真实工作中非常常见，几乎所有互联网公司都有自己的后台管理系统。学会做这个，你就能应对 80% 的 Vue 3 岗位需求。

### 2.1 为什么选"电商"而不是"博客"或"待办"？

| 项目类型 | 功能丰富度 | 适合学习 |
|---|---|---|
| 待办清单 | ⭐ | 太简单，覆盖不了核心技术点 |
| 个人博客 | ⭐⭐ | 缺少权限控制、图片上传等实战点 |
| 电商后台 | ⭐⭐⭐⭐ | 覆盖登录、CRUD、图片上传、图表、权限 |
| ERP/CRM | ⭐⭐⭐⭐⭐ | 太复杂，课设时间不够 |

电商后台的复杂度刚好——既有足够的实战价值，又能在 2 周内完成。

## 🛠 三、功能模块详解

### 3.1 登录注册模块

这是所有后台系统的入口。功能包括：

- 用户登录（账号 + 密码 → 后端返回 JWT token）
- Token 存储到 Pinia + localStorage
- 路由守卫：未登录强制跳转到 `/login`
- 登录后跳转到 `/dashboard`

**涉及技术点**：Vue Router 路由守卫、Pinia 持久化、Axios 请求拦截器、JWT 基础概念。

### 3.2 数据看板（Dashboard）

登录后的首页，展示核心数据：

- 销售额折线图（近 7 天）
- 订单量柱状图
- 商品总数、订单总数、用户总数（卡片展示）

**涉及技术点**：ECharts 集成、Axios 并发请求（`Promise.all`）、响应式数据展示。

### 3.3 商品管理模块

这是最核心的 CRUD 模块，功能包括：

- 商品列表（分页、搜索）
- 新增商品（表单 + 图片上传）
- 编辑商品（数据回填）
- 删除商品（确认弹窗）
- 商品状态切换（上架/下架）

**涉及技术点**：组件通信、表单验证、Element Plus 表格/分页/弹窗/上传组件、图片转 Base64。

### 3.4 订单管理模块

- 订单列表（分页）
- 按状态筛选（待付款/已付款/已发货/已完成/已取消）
- 订单详情弹窗（展示商品明细）

**涉及技术点**：动态路由参数、计算属性过滤、弹窗组件复用。

### 3.5 用户管理（可选扩展）

- 用户列表
- 角色分配（管理员/普通用户）

## 🔑 四、技术选型——为什么是这六个？

### 4.1 Vue 3（核心框架）

选择 Vue 3 而不是 Vue 2，原因：

- 组合式 API 更适合中大型项目
- `<script setup>` 语法更简洁
- 更好的 TypeScript 支持
- 官方已宣布 Vue 2 进入维护模式

### 4.2 Vite（构建工具）

替代 Webpack 的新一代构建工具：

- 开发服务器启动秒级（Webpack 要等几十秒）
- 热更新（HMR）极快
- 生产构建基于 Rollup，输出优化

```bash
# 创建项目只需一行
npm create vite@latest my-admin -- --template vue
```

### 4.3 Pinia（状态管理）

替代 Vuex 的新一代状态管理：

- API 更简洁（没有 `mutations`）
- 完美支持组合式 API
- TypeScript 类型推断友好
- 官方推荐

```js
// Pinia store 长这样（对比 Vuex 的繁琐）
export const useUserStore = defineStore('user', () => {
  const token = ref('')
  const setToken = (t) => { token.value = t }
  return { token, setToken }
})
```

### 4.4 Vue Router 4（路由）

Vue 3 配套的路由库，功能：

- 路由守卫（登录拦截）
- 动态路由（权限控制）
- 懒加载（代码分割）

### 4.5 Axios（HTTP 请求）

浏览器原生 `fetch` 也能发请求，但 Axios 提供了：

- 请求/响应拦截器（统一加 token、统一处理错误）
- 请求取消
- 自动转换 JSON

### 4.6 Element Plus（UI 组件库）

Vue 3 生态最成熟的 UI 库：

- 提供表格、表单、弹窗、分页、上传等后台必备组件
- 中文文档完善
- 社区活跃

> 💬 **老师备注**：技术选型没有"唯一正确答案"。React + Ant Design 也能做同样的事。但我们学的是 Vue 3，所以选 Vue 3 生态。面试时，重要的是你能说清楚"为什么选这个"，而不是"选了什么"。

## ⚠️ 五、常见陷阱

### 陷阱 1：一开始就追求"完美"

很多同学拿到项目，第一件事是选最好的 UI 库、配最好的 ESLint、研究最优雅的代码结构……然后一周过去了，登录页面还没做完。

**正确做法**：先跑起来，再迭代。第一版能用就行，功能完整比代码优雅更重要。

### 陷阱 2：不做需求分析，直接写代码

"登录页面"听起来很简单，但如果不先想清楚：token 存哪里？过期了怎么办？记住登录状态吗？——写到一半就会发现到处要改。

**正确做法**：先画流程图（哪怕在纸上画），再写代码。这节的目的就是帮你把需求想清楚。

### 陷阱 3：技术选型"追新"不考虑稳定性

Vue 3 很新，但如果你选了一个昨天刚发布、GitHub 只有 50 个 star 的 UI 库，项目做到一半发现文档不全、bug 没人修，就悲剧了。

**正确做法**：选生态成熟、社区活跃的库。Element Plus 虽然不算最新，但胜在稳定、文档全。

## 🧠 本节小结

- **项目定位**：电商后台管理系统——电商运营管理商品/订单的内部工具，SPA 单页应用，课设级别而非生产级
- **功能模块**：登录注册（JWT + Pinia + 路由守卫）、数据看板（ECharts）、商品管理（CRUD + 上传）、订单管理（筛选 + 详情），用户管理可选
- **技术选型六件套**：Vue 3 + Vite + Pinia + Vue Router 4 + Axios + Element Plus；选型理由比"选了什么"更重要——面试官爱问"为什么"
- **三个陷阱**：别一开始追求"完美"（先跑起来再迭代）；别跳过需求分析直接写码（token 存哪、过期怎么办先想清楚）；别"追新"选生态不稳的库
- **验收标准**：功能完整（登录 + 商品 + 订单 + 看板）+ 代码规范（ESLint + 目录规范）+ `vite build` 可运行部署
