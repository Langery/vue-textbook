## 🤔 一、`npm run dev` 跑得好好的，为什么要 build？

`npm run dev` 是开发模式（Development Mode）：Vite 启动一个本地服务器，文件修改后热更新，代码**不压缩、不优化**，方便调试。

但**浏览器不认识 `.vue` 文件**，也不认识 `import { ref } from 'vue'` 这种 ESM 裸导入。把这些"开发代码"变成"浏览器能直接运行的代码"的过程，就是**打包（Build）**。

打个比方：
- 开发模式 = 你在厨房里炒菜，边尝边调
- 打包 = 装盘上桌，摆盘、装饰、切掉不好看的部分，端给客人

## 💡 二、Vite 打包实战

### 2.1 执行打包

```bash
npm run build
```

Vite 会在项目根目录下生成 `dist/` 文件夹，结构如下：

```text
dist/
├── index.html          ← 入口 HTML
├── assets/
│   ├── index-DqM3rXh2.js    ← 主 JS（业务代码）
│   ├── index-BTx9HGpC.css   ← 全局 CSS
│   ├── LoginView-CqK8z5nL.js   ← 懒加载路由 JS
│   └── GoodsList-CvN3mT2w.js   ← 懒加载路由 JS
└── favicon.ico
```

关键特征：
- 文件名带有随机 Hash（`DqM3rXh2`），每次构建变化，用于**浏览器缓存更新**
- 每个懒加载的路由组件被拆成独立的 JS 文件（**代码分割**）
- 所有文件体积远小于源码（压缩 + Tree Shaking）

### 2.2 关键配置项（vite.config.js）

```js
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'

export default defineConfig({
  plugins: [vue()],
  base: '/admin/',   // ⚠️ 关键：部署路径。部署到根目录用 '/'，子目录用 '/子目录名/'
  build: {
    outDir: 'dist',
    rollupOptions: {
      output: {
        // 手动代码分割：把 node_modules 打成一个独立 chunk
        manualChunks(id) {
          if (id.includes('node_modules')) return 'vendor'
        }
      }
    }
  }
})
```

**`base` 是最容易踩的坑**：如果你的项目部署在 `https://example.com/admin/` 而不是根路径，但 `base` 配置为 `/`，那么所有 JS/CSS 都会 404。

### 2.3 环境变量

Vite 使用 `.env` 文件管理不同环境的配置：

```bash
# .env.development
VITE_API_BASE=http://localhost:3000/api

# .env.production
VITE_API_BASE=https://api.your-domain.com/api
```

在代码中通过 `import.meta.env.VITE_API_BASE` 读取。**注意**：只有 `VITE_` 前缀的变量才会暴露给客户端代码。

## 🔑 三、Nginx 部署详解

### 3.1 为什么用 Nginx？

`dist/` 文件夹可以用任何静态文件服务器托管，但 Nginx 是生产环境最常用的选择——性能极高、配置灵活、生态成熟。

### 3.2 部署步骤

**第一步：上传 dist/ 到服务器**

```bash
scp -r dist/* root@your-server:/var/www/admin/
```

**第二步：配置 Nginx**

```nginx
server {
    listen       80;
    server_name  admin.your-domain.com;
    root         /var/www/admin;
    index        index.html;

    # SPA 核心配置：所有路径都指向 index.html
    location / {
        try_files $uri $uri/ /index.html;
    }

    # Gzip 压缩（可选但推荐）
    gzip on;
    gzip_types text/css application/javascript image/svg+xml;
}
```

**第三步：重载 Nginx**

```bash
nginx -t              # 测试配置文件语法
nginx -s reload       # 重载配置
```

### 3.3 `try_files` 的原理（SPA 路由的关键）

Vue Router 使用 History 模式时，URL 如 `/goods/list` 实际上没有对应的物理文件。用户直接访问或刷新时，Nginx 找不到 `/goods/list` 这个文件，就会返回 404。

`try_files $uri $uri/ /index.html` 的含义：

```text
1. 先尝试找 $uri（如 /goods/list）→ 找不到
2. 再尝试找 $uri/（目录）→ 找不到
3. 最终回退到 /index.html → Vue Router 接管，正确渲染 /goods/list 页面
```

**如果没配这一行，刷新页面直接白屏 404**——这是 SPA 部署最常见的故障。

## 🛠 四、免费一键部署（课程推荐）

如果暂时没有服务器，可以用 Vercel 或 Netlify 免费部署。

### 4.1 Vercel 部署（推荐）

1. 把项目上传到 GitHub
2. 打开 [vercel.com](https://vercel.com)，用 GitHub 登录
3. 点击 "New Project" → 导入你的仓库
4. 框架自动识别 Vite，无需修改配置
5. 点击 "Deploy" → 1 分钟后获得 `https://xxx.vercel.app` 域名

Vercel 自动处理 SPA 路由（无需配 `try_files`），还支持自定义域名 + 免费 HTTPS。

### 4.2 Netlify 部署

与 Vercel 类似。额外需要在项目根目录添加 `_redirects` 文件（或 `netlify.toml`）：

```text
/*    /index.html   200
```

这行的作用等价于 Nginx 的 `try_files`。

## ⚠️ 五、常见陷阱

### 陷阱 1：`base` 配错导致资源 404

部署在子路径（如 `/admin/`）但 `base: '/'`，浏览器会去 `https://example.com/assets/index.js` 找资源，而实际在 `https://example.com/admin/assets/index.js`。

**检查方法**：打开浏览器 DevTools → Network 面板，看 JS/CSS 请求的 URL 是否正确。

### 陷阱 2：History 模式路由刷新 404

配了 Vue Router 的 `history: createWebHistory()` 但没有配 Nginx 的 `try_files`。

**临时方案**：改用 Hash 模式 `createWebHashHistory()`（URL 带 `#`），不用改 Nginx 配置。

### 陷阱 3：环境变量不生效

变量名不是 `VITE_` 开头，或者改完 `.env` 后没有重新 `npm run dev` / `npm run build`（Vite 只在启动/构建时读取环境变量）。

### 陷阱 4：打包后文件体积过大

检查 `dist/assets/` 目录，如果某个 JS 超过 500KB，考虑：
- 是否有未 Tree Shaking 的库（如全量引入 ECharts 而非按需引入）
- 路由是否都做了懒加载（`() => import()`）
- 是否可以用 CDN 外链替代 npm 包

## 🧠 本节小结

- **为什么要 build**：浏览器不认 `.vue` 和 ESM 裸导入，`npm run build` 把它们编译压缩成 `dist/`（入口 index.html + 带 Hash 的 assets），文件名 Hash 用于缓存更新
- **三个关键配置**：`base`（部署路径，子目录部署不配会全部 404）、`rollupOptions.manualChunks`（把 node_modules 打成独立 vendor chunk 做代码分割）、`.env.*` + `VITE_` 前缀环境变量
- **Nginx 部署三步**：上传 `dist/` → 配 `root` + `location /` 的 `try_files $uri $uri/ /index.html` → `nginx -t` 后 `nginx -s reload`
- **`try_files` 是 SPA 命门**：History 路由刷新时没有对应物理文件，回退到 `/index.html` 让 Vue Router 接管；没配这行会白屏 404
- **常见四坑**：base 配错资源 404、History 刷新 404（临时可用 Hash 模式）、环境变量没重跑 build、产物过大（按需引入 ECharts + 路由懒加载 + CDN）
- **没服务器也能上线**：Vercel 自动识别 Vite 并处理 SPA 路由；Netlify 需 `_redirects`（`/* /index.html 200`），等价于 Nginx 的 `try_files`
