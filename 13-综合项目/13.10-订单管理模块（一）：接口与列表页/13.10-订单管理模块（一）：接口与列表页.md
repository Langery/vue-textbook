商品模块把 CRUD 打满了，但后台还有一类典型页面跟它不一样：订单管理——订单由前台用户产生，管理员只读、筛选、改状态。这节带你做"只读数据展示页"：三个接口函数 + 用常量枚举统一管状态（告别硬编码 0/1/2）+ `el-radio-group` 状态筛选列表页，最后预告两个只有这类页面才有的坑。

## 🤔 一、订单模块和商品模块有什么不同？

订单模块是**只读为主**的模块——后台管理员通常不需要"新增订单"（订单是用户在前台下的），主要工作是：

- 查看所有订单
- 按状态筛选（待发货的订单要优先处理）
- 查看订单详情（确认商品、收货地址）
- 修改订单状态（标记已发货）

所以订单模块的页面结构比商品模块简单——**没有新增/编辑表单**，只有列表 + 详情弹窗。

## 💡 二、api/order.js —— 接口函数封装

```js
// src/api/order.js
import request from './index'

// 获取订单列表（分页 + 状态筛选）
export const getOrderList = (params) => {
  return request({
    url: '/orders',
    method: 'get',
    params   // { pageNum, pageSize, status }
  })
}

// 获取订单详情
export const getOrderDetail = (id) => {
  return request({
    url: `/orders/${id}`,
    method: 'get'
  })
}

// 更新订单状态（如：标记已发货）
export const updateOrderStatus = (id, status) => {
  return request({
    url: `/orders/${id}/status`,
    method: 'put',
    data: { status }
  })
}
```

## 🔑 三、订单状态——用枚举统一管理

订单状态在列表、详情、筛选多处用到，用**常量对象**统一管理，避免硬编码数字：

```js
// src/utils/orderStatus.js
export const ORDER_STATUS = {
  0: { label: '待付款', type: 'warning' },
  1: { label: '已付款', type: 'primary' },
  2: { label: '已发货', type: '' },
  3: { label: '已完成', type: 'success' },
  4: { label: '已取消', type: 'info' }
}

// 转为 el-select 的选项格式
export const ORDER_STATUS_OPTIONS = Object.entries(ORDER_STATUS).map(
  ([value, { label }]) => ({ label, value: Number(value) })
)
```

> 💬 **老师备注**：`ORDER_STATUS` 里的 `type` 对应 Element Plus 的 `el-tag` 的 `type` 属性（`success` / `warning` / `danger` / `info` / `primary`），这样状态标签的颜色就能自动对应。

## 🛠 四、订单列表页（OrderList.vue）——完整代码

```vue
<!-- src/views/order/OrderList.vue -->
<script setup>
import { ref, reactive, onMounted } from 'vue'
import { getOrderList } from '@/api/order'
import { ORDER_STATUS } from '@/utils/orderStatus'
import { ElMessage } from 'element-plus'

// ==================== 列表数据 ====================
const tableData = ref([])
const loading = ref(false)

// ==================== 分页 ====================
const pagination = reactive({
  pageNum: 1,
  pageSize: 10,
  total: 0
})

// ==================== 状态筛选 ====================
const currentStatus = ref(-1)  // -1 表示全部

// ==================== 获取列表 ====================
const fetchList = async () => {
  loading.value = true
  try {
    const params = {
      pageNum: pagination.pageNum,
      pageSize: pagination.pageSize
    }
    // 只有选择了具体状态才传 status 参数
    if (currentStatus.value !== -1) {
      params.status = currentStatus.value
    }

    const res = await getOrderList(params)
    tableData.value = res.data.list
    pagination.total = res.data.total
  } catch (error) {
    ElMessage.error('获取订单列表失败')
  } finally {
    loading.value = false
  }
}

// ==================== 状态筛选切换 ====================
const handleStatusChange = (status) => {
  currentStatus.value = status
  pagination.pageNum = 1
  fetchList()
}

// ==================== 分页 ====================
const handlePageChange = (page) => {
  pagination.pageNum = page
  fetchList()
}

// ==================== 查看详情 ====================
const detailDialogVisible = ref(false)
const currentOrder = ref(null)

const showDetail = async (row) => {
  try {
    const res = await getOrderDetail(row.id)
    currentOrder.value = res.data
    detailDialogVisible.value = true
  } catch (error) {
    ElMessage.error('获取订单详情失败')
  }
}

// ==================== 标记发货 ====================
const handleShip = async (row) => {
  try {
    await updateOrderStatus(row.id, 2)
    ElMessage.success('已标记为已发货')
    fetchList()
  } catch (error) {
    ElMessage.error('操作失败')
  }
}

onMounted(() => {
  fetchList()
})
</script>

<template>
  <div class="order-list">
    <h2>订单管理</h2>

    <!-- 状态筛选 -->
    <div class="filter-bar">
      <el-radio-group v-model="currentStatus" @change="handleStatusChange">
        <el-radio-button :label="-1">全部</el-radio-button>
        <el-radio-button :label="0">待付款</el-radio-button>
        <el-radio-button :label="1">已付款</el-radio-button>
        <el-radio-button :label="2">已发货</el-radio-button>
        <el-radio-button :label="3">已完成</el-radio-button>
        <el-radio-button :label="4">已取消</el-radio-button>
      </el-radio-group>
    </div>

    <!-- 订单表格 -->
    <el-table :data="tableData" v-loading="loading" stripe border>
      <el-table-column prop="id" label="订单号" width="100" align="center" />
      <el-table-column prop="buyerName" label="买家" width="120" />
      <el-table-column label="商品数量" width="100" align="center">
        <template #default="{ row }">
          {{ row.items?.length || 0 }} 件
        </template>
      </el-table-column>
      <el-table-column label="订单金额" width="120" align="center">
        <template #default="{ row }">
          ¥{{ row.totalAmount.toFixed(2) }}
        </template>
      </el-table-column>
      <el-table-column label="状态" width="100" align="center">
        <template #default="{ row }">
          <el-tag :type="ORDER_STATUS[row.status]?.type">
            {{ ORDER_STATUS[row.status]?.label }}
          </el-tag>
        </template>
      </el-table-column>
      <el-table-column prop="createTime" label="下单时间" width="180" />
      <el-table-column label="操作" width="200" align="center" fixed="right">
        <template #default="{ row }">
          <el-button size="small" @click="showDetail(row)">详情</el-button>
          <el-button
            v-if="row.status === 1"
            size="small"
            type="primary"
            @click="handleShip(row)"
          >
            标记发货
          </el-button>
        </template>
      </el-table-column>
    </el-table>

    <!-- 分页 -->
    <div class="pagination-wrapper">
      <el-pagination
        v-model:current-page="pagination.pageNum"
        v-model:page-size="pagination.pageSize"
        :total="pagination.total"
        :page-sizes="[10, 20, 50]"
        layout="total, sizes, prev, pager, next, jumper"
        @current-change="handlePageChange"
      />
    </div>

    <!-- 详情弹窗 -->
    <OrderDetailDialog
      v-if="detailDialogVisible"
      :visible="detailDialogVisible"
      :order="currentOrder"
      @close="detailDialogVisible = false"
    />
  </div>
</template>

<style scoped>
.order-list { padding: 20px; }
.order-list h2 { margin-bottom: 20px; }
.filter-bar { margin-bottom: 20px; }
.pagination-wrapper { display: flex; justify-content: flex-end; margin-top: 20px; }
</style>
```

## ⚠️ 五、常见陷阱

### 陷阱 1：切换筛选或分页时，必须回到第一页

```js
// ❌ 只改 status，不重置 pageNum，可能停留在越界的页码
const handleStatusChange = (status) => {
  currentStatus.value = status
  fetchList()   // pageNum 还是原来的值
}
```

**解决**：任何筛选 / 搜索 / 切换每页条数的操作，都必须先把 `pageNum` 重置为 1 再请求：

```js
const handleStatusChange = (status) => {
  currentStatus.value = status
  pagination.pageNum = 1   // ✅ 回到第一页
  fetchList()
}
```

### 陷阱 2：状态筛选 `-1` 代表"全部"的边界处理

后端接口通常不接收 `status=-1` 这个参数（因为 -1 不是合法状态），所以发请求前要判断：

```js
if (currentStatus.value !== -1) {
  params.status = currentStatus.value
}
```

> 💬 **老师备注**：这个 `-1` 只是前端 UI 的"全部"占位值，**不应该**传到后端。类似的边界值还有："全部日期"用空字符串、`el-select` 的 `clearable` 清空后值为 `undefined` 等，都需要在组装参数时过滤。

## 🧠 本节小结

- **订单模块是只读为主的 CRUD 变体**：无新增/编辑表单，页面 = 列表 + 状态筛选 + 详情弹窗 + 状态流转，比商品模块结构简单
- **接口只要三个**：`getOrderList(params)`（分页+status）、`getOrderDetail(id)`、`updateOrderStatus(id, status)`，URL 走 RESTful `/orders/:id/status`
- **状态用枚举统一管理**：`ORDER_STATUS` 常量把 0/1/2/3/4 映射成 `{ label, type }`，模板里 `ORDER_STATUS[row.status]?.label/.type` 一处取用，杜绝散落的魔法数字
- **筛选要重置页码**：任何状态切换都必须 `pageNum = 1` 再请求，否则可能停在越界页
- **`-1` 是 UI 占位不传给后端**：组装 params 时 `!== -1` 才加入 `status`；空串、`undefined` 等边界值同理需要过滤
- **只读页套路**：`el-radio-button` 筛选 + `el-tag` 上色 + 详情按钮预埋弹窗（下节实现）+ 标记发货按钮按 `status === 1` 条件显示
