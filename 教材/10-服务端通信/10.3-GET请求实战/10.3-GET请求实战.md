## 🤔 一、GET 请求的两种典型场景

和后端打交道，GET 请求主要干两件事：

**场景 1：获取列表**——比如文章列表、用户列表、商品列表

```text
GET /api/posts
→ 返回：[ { id: 1, title: "..." }, { id: 2, title: "..." } ]
```

**场景 2：获取详情**——比如某篇文章的内容、某个用户的资料

```text
GET /api/posts/1
→ 返回：{ id: 1, title: "...", body: "...", userId: 1 }
```

这两种场景在 Vue 组件里的写法几乎一样，区别只在于：列表用 `v-for` 渲染数组，详情直接渲染对象的属性。

列表和详情是 GET 请求的两大主角，差别只有"一打"和"一个"：

| 对比维度 | 获取列表 | 获取详情 |
|---|---|---|
| 请求地址 | `GET /api/posts` | `GET /api/posts/1` |
| 返回数据 | 数组（`[ {...}, {...} ]`） | 单个对象（`{ id, title, body }`） |
| 渲染方式 | `v-for` 循环渲染 | 直接访问对象属性 |
| 常见带参 | 分页、搜索、筛选（`params`） | 路由参数 `:id` |
| 空状态 | 列表为空要提示"暂无数据" | 对象为 `null` 要提示"不存在" |

## 💡 二、实战：文章列表页

用 JSONPlaceholder 的 `/posts` 接口，做一个文章列表。这个接口返回一个 100 篇文章的数组。

### 2.1 基础版本：拿到数据就渲染

```vue
<script setup>
import axios from 'axios'
import { ref, onMounted } from 'vue'

const posts = ref([])

onMounted(async () => {
  const res = await axios.get('https://jsonplaceholder.typicode.com/posts')
  posts.value = res.data
})
</script>

<template>
  <h1>文章列表</h1>
  <ul>
    <li v-for="post in posts" :key="post.id">
      {{ post.title }}
    </li>
  </ul>
</template>
```

打开页面，你会看到 100 个文章标题。但这样写有个问题：网络慢的时候，用户看到的是空白——不知道是正在加载，还是根本没有数据。

### 2.2 完整版本：加上 loading 和错误处理

```
<script setup>
import axios from 'axios'
import { ref, onMounted } from 'vue'

const posts = ref([])
const loading = ref(false)
const error = ref('')

const fetchPosts = async () => {
  loading.value = true
  error.value = ''

  try {
    const res = await axios.get('https://jsonplaceholder.typicode.com/posts')
    posts.value = res.data
  } catch (err) {
    error.value = '加载失败，请稍后重试'
    console.error(err)
  } finally {
    loading.value = false
  }
}

onMounted(() => {
  fetchPosts()
})
</script>

<template>
  <h1>文章列表</h1>

  <p v-if="loading">加载中...</p>
  <p v-else-if="error" style="color: red;">{{ error }}</p>
  <p v-else-if="posts.length === 0">暂无文章</p>
  <ul v-else>
    <li v-for="post in posts" :key="post.id">
      {{ post.title }}
    </li>
  </ul>
</template>
```

> 💬 **老师备注**：`v-if / v-else-if / v-else` 的顺序很重要——先判断 loading，再判断 error，最后判断空数据。这个顺序对应请求的三个阶段：进行中 → 失败了 → 成功了但没数据 → 有数据。

## 🔑 三、实战：文章详情页

详情页需要从 URL 里拿到文章 ID，再拼进请求地址。假设你用的是 Vue Router，路由配置是这样的：

```js
// router/index.js
{
  path: '/posts/:id',
  component: PostDetail
}
```

### 3.1 拿到路由里的 ID

```vue
<script setup>
import axios from 'axios'
import { ref, onMounted } from 'vue'
import { useRoute } from 'vue-router'

const route = useRoute()
const post = ref(null)
const loading = ref(false)

onMounted(async () => {
  loading.value = true
  const id = route.params.id   // 从 URL 里拿 ID，比如 /posts/5 → id = "5"
  const res = await axios.get(`https://jsonplaceholder.typicode.com/posts/${id}`)
  post.value = res.data
  loading.value = false
})
</script>
```

### 3.2 渲染详情

```
<template>
  <div v-if="loading">加载中...</div>
  <div v-else-if="!post">文章不存在</div>
  <div v-else>
    <h1>{{ post.title }}</h1>
    <p style="color: #666;">作者 ID：{{ post.userId }}</p>
    <p>{{ post.body }}</p>
  </div>
</template>
```

> 💬 **老师备注**：JSONPlaceholder 的 `body` 字段是纯文本，没有 HTML 格式。实际项目的文章详情通常是富文本（包含 HTML 标签），渲染时要用 `v-html`（注意 XSS 安全风险）。

## 🛠 四、带查询参数的 GET 请求

很多列表接口支持查询参数：分页、搜索、筛选。Axios 的第二个参数可以传 `params` 对象，会自动拼成 URL 查询字符串。

```js
// 我要发这个请求：
// GET /api/posts?userId=1&_limit=5

const res = await axios.get('https://jsonplaceholder.typicode.com/posts', {
  params: {
    userId: 1,    // 只拿 userId=1 的文章
    _limit: 5     // 只拿前 5 条
  }
})
```

### 实战：带搜索的列表

```vue
<script setup>
import axios from 'axios'
import { ref } from 'vue'

const posts = ref([])
const keyword = ref('')
const loading = ref(false)

const search = async () => {
  loading.value = true

  try {
    const res = await axios.get('https://jsonplaceholder.typicode.com/posts', {
      params: {
        title_like: keyword.value   // JSONPlaceholder 支持模糊搜索（模拟）
      }
    })
    posts.value = res.data
  } catch (err) {
    console.error(err)
  } finally {
    loading.value = false
  }
}
</script>

<template>
  <input v-model="keyword" placeholder="搜索文章..." />
  <button @click="search">搜索</button>

  <ul>
    <li v-for="post in posts" :key="post.id">{{ post.title }}</li>
  </ul>
</template>
```

> 💬 **老师备注**：`title_like` 是 JSONPlaceholder 提供的模拟搜索参数，真实后端接口的搜索参数名需要看后端文档，可能是 `keyword`、`q`、`search` 等。

## ⚠️ 五、常见陷阱

### 陷阱 1：ID 是字符串，后端要数字

```js
// 路由里的 params 全是字符串
const id = route.params.id   // 类型是 string，比如 "5"

// 直接拼 URL 没问题
axios.get(`/api/posts/${id}`)   // → /api/posts/5（正确）

// 但如果要把 ID 当数字用（比如比较、计算），需要转换
const idNum = Number(route.params.id)   // 或 parseInt(route.params.id)
```

### 陷阱 2：onMounted 里直接 await，没有 loading 状态

```
<script setup>
// ❌ 数据没回来之前，用户看到空白，不知道在加载
onMounted(async () => {
  const res = await axios.get('/api/posts')
  posts.value = res.data
})
</script>
```

加上 `loading` 状态，用户体验好很多。

### 陷阱 3：详情页组件复用，ID 变了但数据没更新

用户从 `/posts/1` 跳转到 `/posts/2`，Vue 会复用同一个组件实例，`onMounted` **不会再次触发**，数据还是第一篇文章的。

解决办法：用 `watch` 监听路由参数变化（下一章会讲），或者用 `key` 强制重新创建组件。

---

## 🧠 本节小结

- **GET 两大场景**：列表返回数组 → `v-for` 渲染；详情返回单个对象 → 直接访问属性渲染
- **页面三态切换**：loading（进行中）/ error（失败）/ 空数据，`v-if / v-else-if / v-else` 顺序对应请求的三个阶段
- **详情页取参**：`route.params.id` 拿到的是字符串，拼 URL 没问题，做数字运算要先 `Number()` 转换
- **带查询参数**：`axios.get(url, { params: { ... } })` 会自动拼成查询字符串，常用于分页、搜索、筛选
- **组件复用陷阱**：同一个详情组件从 `/posts/1` 跳到 `/posts/2` 时 `onMounted` 不会重跑，要用 `watch` 监听路由参数或用 `key` 强制重建
