前面几节你每发一次请求，是不是都在重复写同一套代码：`loading` 先置 `true`、成功塞 `data`、失败记 `error`、结束 `finally` 里关掉 `loading`？三五个页面还能忍，页面一多就成了"复制粘贴大赛"——改一个细节得全局搜着改。这节不教新接口，专门解决"重复"：把这三件套抽成 `useRequest` 组合式函数，再顺手用 `AbortController` 治掉"人走了请求还在飞"的内存泄漏隐患。

## 🤔 一、痛点：每写一个请求，都要写一遍"三件套"

回忆一下，前面几节里每次发请求都是这个模式：

```js
const data = ref(null)
const loading = ref(false)
const error = ref('')

const fetchData = async () => {
  loading.value = true
  error.value = ''
  try {
    data.value = await request.get('/api/data')
  } catch (err) {
    error.value = err.message
  } finally {
    loading.value = false
  }
}
```

五个组件，这套代码要写五遍。实际项目中可能有几十个页面，每个页面都来一遍——这显然不科学。

**提炼一下，它们长得一样的地方是**：

1. 管理 `loading`（请求前 `true`，结束后 `false`）
2. 管理 `error`（失败时记录错误信息）
3. 管理 `data`（成功时存数据）

把它们抽成一个可复用的函数——在 Vue 3 里叫 **Composable**（组合式函数）。

## 💡 二、初版 useRequest：把三件套封起来

### 2.1 基础版本

```js
// src/composables/useRequest.js
import { ref } from 'vue'

export function useRequest(fetchFn) {
  const data = ref(null)
  const loading = ref(false)
  const error = ref('')

  const execute = async (...args) => {
    loading.value = true
    error.value = ''

    try {
      const result = await fetchFn(...args)
      data.value = result
      return result
    } catch (err) {
      error.value = err.message || '请求失败'
      throw err
    } finally {
      loading.value = false
    }
  }

  return { data, loading, error, execute }
}
```

### 2.2 组件里使用

```vue
<script setup>
import request from '@/utils/request'
import { useRequest } from '@/composables/useRequest'

const { data: posts, loading, error, execute: fetchPosts } = useRequest(
  () => request.get('/posts')
)

// 组件挂载时自动请求
fetchPosts()
</script>

<template>
  <p v-if="loading">加载中...</p>
  <p v-else-if="error" style="color: red;">{{ error }}</p>
  <ul v-else>
    <li v-for="post in posts" :key="post.id">{{ post.title }}</li>
  </ul>
</template>
```

对比一下：原来需要写 5 行的 `ref` 定义 + 10 行的 `fetchData` 函数，现在变成了一行 `useRequest(...)`。

同样的三态逻辑，手写和封装之后的差距有多大？看这张表：

| 对比维度 | 手写请求状态 | `useRequest` 封装 |
|---|---|---|
| 代码量 | 每个组件 15 行左右（ref × 3 + try-catch-finally） | 一行 `useRequest(...)` |
| loading 管理 | 手动 `true` / `finally` 里 `false` | 自动管理 |
| error 管理 | 手动 catch 赋值 | 自动捕获 |
| data 管理 | 手动赋值 | 自动存结果 |
| 复用性 | 零（每个组件复制粘贴） | 高（抽成 composable） |
| 取消请求 | 不支持（需另写 AbortController） | 可集成自动取消 |
| 维护成本 | 改一个细节要改 N 处 | 只改一处 |

### 2.3 带参数请求

```js
// 搜索场景：关键词变了再发请求
const { data, loading, execute: search } = useRequest(
  (keyword) => request.get('/posts', { params: { q: keyword } })
)

// 用户点搜索
const handleSearch = () => {
  search(keyword.value)
}
```

`execute` 的参数会透传给 `fetchFn`，所以你可以在调 `execute` 时传入搜索关键词、分页参数等。

## 🔑 三、取消请求：AbortController

### 3.1 为什么要取消请求

看一个常见场景：

```text
用户在「商品列表页」→ 点了「搜索」→ 请求 A 发出去了
    → 不等请求 A 回来，立刻点「手机」分类 → 请求 B 发出去了
    → 请求 A 回来了，更新了数据 → 页面展示的是旧数据！
    → 请求 B 也回来了 → 数据又被覆盖
```

更严重的情况：用户从商品页跳到了购物车页，但商品页的请求还没回来。等请求回来了，它试图更新一个已经销毁的组件——轻则内存泄漏，重则直接报错。

**解决办法**：在新请求发出前，把旧请求"取消"掉。

### 3.2 AbortController 基础用法

```js
// 1. 创建一个控制器
const controller = new AbortController()

// 2. 把它的 signal 传给 axios
axios.get('/api/data', {
  signal: controller.signal
})

// 3. 需要取消时调用 abort()
controller.abort()
// → axios 会抛出 CanceledError，请求停止
```

实际效果：`controller.abort()` 后，对应的请求会立刻中断，不会再回来更新组件。

### 3.3 集成到 useRequest

```js
// src/composables/useRequest.js（带取消能力）
import { ref, onUnmounted } from 'vue'

export function useRequest(fetchFn) {
  const data = ref(null)
  const loading = ref(false)
  const error = ref('')
  let controller = null    // 存当前请求的 AbortController

  const execute = async (...args) => {
    // 如果上一次请求还没完成，先取消它
    if (controller) {
      controller.abort()
    }

    // 创建新的控制器
    controller = new AbortController()

    loading.value = true
    error.value = ''

    try {
      // 把 signal 传给请求函数
      const result = await fetchFn(...args, controller.signal)
      data.value = result
      return result
    } catch (err) {
      // 被取消的请求不要写 error（不是真的错误）
      if (err.name === 'CanceledError' || err.code === 'ERR_CANCELED') return
      error.value = err.message || '请求失败'
      throw err
    } finally {
      loading.value = false
    }
  }

  // 组件卸载时取消请求
  onUnmounted(() => {
    controller?.abort()
  })

  return { data, loading, error, execute }
}
```

### 3.4 组件里配合使用

因为 `fetchFn` 现在会收到 `signal`，你在定义它的时候需要把 `signal` 传给 Axios：

```
<script setup>
import request from '@/utils/request'
import { useRequest } from '@/composables/useRequest'

// fetchFn 接收 signal 并传给 axios
const { data: posts, loading, execute: fetchPosts } = useRequest(
  (keyword, signal) => request.get('/posts', {
    params: { q: keyword },
    signal   // ← 关键：把 signal 传给 axios
  })
)

const keyword = ref('')
const handleSearch = () => fetchPosts(keyword.value)
</script>
```

现在连续点搜索按钮，旧的请求会被自动取消，只有最新一次的请求会更新数据。

> 💬 **老师备注**：`useRequest` 是 Vue 生态里非常常见的封装模式，社区也有成熟的库（如 `vue-request`、`@tanstack/vue-query`）。但自己写一遍能帮你理解它的原理，面试也经常问到。

## 🛠 四、扩展：onMounted 时自动请求

很多场景下，组件一加载就要发请求。可以在 `useRequest` 里加一个 `immediate` 参数：

```js
export function useRequest(fetchFn, options = {}) {
  const { immediate = false } = options
  // ... 前面的代码不变 ...

  if (immediate) {
    execute()
  }

  return { data, loading, error, execute }
}

// 使用
const { data, loading } = useRequest(
  (signal) => request.get('/posts', { signal }),
  { immediate: true }   // 组件挂载时自动请求
)
```

这样连 `fetchPosts()` 都不用写，页面一进来就自动加载。

## ⚠️ 五、常见陷阱

### 陷阱 1：忘记把 signal 传给 axios

```js
// ❌ useRequest 里传了 signal，但这里没接住——取消无效！
const { data } = useRequest((keyword, signal) => {
  return request.get('/posts', { params: { q: keyword } })   // 没传 signal！
})
```

每次都要检查：`signal` 有没有一路传到 Axios 的 `config` 里。

### 陷阱 2：被取消的请求当做错误提示

```js
// ❌ 用户切换页面，旧请求被取消 → 弹出"请求失败"
catch (err) {
  error.value = '请求失败'   // 取消也会进这里！
}
```

必须判断 `err.name === 'CanceledError'` 或 `err.code === 'ERR_CANCELED'`，取消不是错误，跳过就行。

### 陷阱 3：useRequest 返回的 data 是 ref，模板里直接用

```js
// setup 里
const { data } = useRequest(...)
// data 已经是 ref，模板里直接 {{ data }}，不要 {{ data.value }}
```

`useRequest` 返回的 `data`、`loading`、`error` 都是 `ref`，模板里会自动解包。

### 陷阱 4：composable 里用 `onUnmounted`，但忘记 import

```js
// ❌ onUnmounted is not defined
import { ref } from 'vue'
// 忘了 import onUnmounted

// ✅
import { ref, onUnmounted } from 'vue'
```

## 🧠 本节小结

- **Composable 封装**：`useRequest(fetchFn)` 把 data / loading / error 三态和 try-catch-finally 收进一个函数，组件里一行调用，`execute` 参数透传给 `fetchFn`
- **为什么取消请求**：用户快速切页/连点搜索时，旧请求回包会覆盖新数据，甚至更新已销毁组件——内存泄漏 + 报错
- **AbortController 用法**：`const c = new AbortController()` → 把 `c.signal` 传给 axios config → 需要时 `c.abort()` 中断请求
- **集成要点**：新请求发出前 abort 上一个；组件卸载 `onUnmounted` 里 abort；`signal` 必须一路传到 axios config，否则取消无效
- **取消不是错误**：catch 里先判断 `err.name === 'CanceledError'`（或 `ERR_CANCELED`）直接 return，别把它当失败弹提示
- **进阶**：加 `immediate` 参数实现挂载即请求；社区方案有 `vue-request`、`@tanstack/vue-query`，自己写一遍更好理解原理
