
# 2.12 章末实战：校园公告板（P2）

> 章节：第 2 章 模板语法与渲染
> 课时：1 课时
> 类型：章末实战 · 独立小项目 P2

---

一整章的语法学下来，插值、`v-if`、`v-for`、`key`、`v-memo` 都有了，但都是"点状"的。这一节我们干一件正经事：把它们拼成一个**能跑、能展示**的小应用——「校园公告板」，模拟校园二手集市首页的闲置列表。

---

## 🎯 项目需求（一句话）

做一个"校园二手闲置公告板"单页应用：页面展示若干条学生发布的闲置物品（教材、电动车、吉他……），顶部可切换分类，进入时有加载态、列表为空时有空态——全部只用第 2 章已学的模板语法实现，不引入任何新库。

### ✅ 验收标准（能跑、能展示）

- [ ] 项目能 `npm run dev` 启动，浏览器打开能看到页面（数据写在本地，不依赖后端）
- [ ] 默认展示全部闲置：每条含 emoji 占位封面、标题、价格、发布人、分类徽章
- [ ] 顶部有「全部 / 数码 / 学习资料 / 生活用品」筛选按钮，点击后列表实时切换
- [ ] 首次进入先看到"加载中"状态，约 1 秒后切换到列表（`v-if` 切换两个分支）
- [ ] 把源数据改成空数组时，页面显示"还没有人发布闲置"空态，而不是一片空白
- [ ] 能向同学讲清楚：这个列表用到了哪几个指令、`key` 为什么这么选

> 🎯 **类比一下**：这个公告板就像「校园公告栏」——墙上贴着一排告示（闲置列表），顶部有分类标签（全部/数码/学习资料/生活用品），有人来贴新告示（新增数据）时，管理员（Vue）照着模板自动排好版面。你学的 `v-if`（加载态/空态/列表三分支）、`v-for`（一排告示）、`:key`（每张告示的编号）就是管理员手里的三件套。

> 👨🏫 **老湿**：这节是第 2 章所有语法的"团建"——把它们放一个项目里协同作战。跑通之后你会发现：单个语法你都会，组合起来才是真本事。

<details>
<summary>🧊 深究一下：为什么公告板"只用数据不用 DOM 操作"？</summary>

整个公告板从头到尾没有一句 `document.getElementById`——你只改数据（新增、清空、切换分类），Vue 自动算出 DOM 该怎么变。这就是"数据驱动视图"：UI 是数据的函数，数据定了，界面自然定。以后写任何 Vue 项目，先问"我的数据长什么样"，再问"界面怎么把数据画出来"，思路就顺了。
</details>

## 🛠 分步提示（3~5 步，含关键代码锚点）

> 以下只给路线和关键锚点，**不贴全量答案**。卡住时回头翻 2.5 / 2.6 / 2.8 对应小节。

### Step 1：搭一个干净的页面

新建项目（或复用 01 章 P1 名片的 Vite 工程），把默认的计数器模板和样式清掉：

```bash
npm create vite@latest bulletin-board -- --template vue
cd bulletin-board && npm install && npm run dev
```

### Step 2：把"闲置数据"定义在 `<script setup>` 里

准备 6~8 条本地数据，字段固定为 `id / title / price / owner / category`，再准备分类数组和当前选中分类：

```js
const goods = ref([
  { id: 1, title: '九成新《高等数学》上下册', price: 15, owner: '计算机-小林', category: '学习资料' },
  // …… 自己再补 5~7 条：耳机、电动车、吉他、篮球……
])
const categories = ['全部', '数码', '学习资料', '生活用品']
const activeCategory = ref('全部')
const loading = ref(true)   // 初始为加载中
```

### Step 3：用 `computed` 做筛选（回顾 2.8 方案一）

`v-for` 不要直接遍历 `goods`，而是遍历一个"筛选后的数组"，这样切分类时模板不用改：

```js
const filteredGoods = computed(() =>
  activeCategory.value === '全部'
    ? goods.value
    : goods.value.filter((item) => item.category === activeCategory.value)
)
```

### Step 4：模板里写"加载中 / 空态 / 列表"三分支

分类按钮用 `v-for` 渲染并高亮当前项；列表主体用 `v-if / v-else-if / v-else` 三兄弟分工（回顾 2.5、2.6、2.8）：

```html
<p v-if="loading">⏳ 正在加载闲置列表…</p>
<p v-else-if="filteredGoods.length === 0">🌱 还没有人发布闲置，快来抢沙发</p>
<ul v-else>
  <li v-for="item in filteredGoods" :key="item.id">
    <!-- 标题 / 价格 / 发布人 / 分类徽章 -->
  </li>
</ul>
```

"加载中"不要一直手动改：在 `<script setup>` 顶层加一行 `setTimeout(() => (loading.value = false), 1000)` 模拟网络请求；选中分类时也可以顺手把 `loading` 置回 `true` 再切回来，感受"加载态 + 列表态"的真实切换。

### Step 5（进阶锚点）：给大列表加 `v-memo`（回顾 2.9）

把 `goods` 复制成 500 条后，在 `v-for` 的 `<li>` 上加 `v-memo="[item.sold]"`——只有 `sold` 变化的行才重新渲染，其余行跳过 diff：

```html
<li v-for="item in filteredGoods" :key="item.id" v-memo="[item.sold]">
```

| 验证动作 | 观察到什么 | 对应小节 |
|---|---|---|
| 刚打开页面 | 先是「⏳ 正在加载闲置列表…」，约 1 秒后自己变成列表——代码里没人手动改过 `loading` | 2.5 v-if |
| 点「数码」 | 按钮高亮跟着换，列表只剩 2 条，**模板一行都没改** | 2.2 `:class` / 2.8 过滤 |
| 点完分类后刷新 Elements 面板 | 底部提示条加载时被藏了，但节点还在，只是 CSS 上多了 `display: none` | 2.5 v-show |
| 把 `goods` 整个改成 `[]` | 列表消失、出现「🌱 还没有人发布闲置」——空态不是一片空白 | 2.6 v-else |
| 把列表的 `:key="item.id"` 改成 `:key="index"` | 切分类时标题和价格会「串行」——旧 DOM 被复用了 | 2.7 key |
| 把 `getFilteredGoods()` 整个删掉，直接 `v-for="item in goods"` | 切分类时列表纹丝不动——模板只认你给它的那个数组 | 2.8 过滤 |

<details>
<summary>💬 老师备注：为什么 <code>activeCategory</code> 没包 <code>ref</code>，而 <code>goods</code> 包了？</summary>

这是这份成品里最值得你琢磨 30 秒的一处设计。

- `goods` 和 `loading` 都用了 `ref`（2.2、2.5 就教过）——因为 Vue **只在响应式数据变化时**才重新渲染。
- `activeCategory` 是普通变量。改它**不会**触发重渲染；真正触发的，是 `switchCategory` 里那句 `loading.value = true`，以及 400ms 后的 `loading.value = false`。重渲染发生的那一刻，模板重新调用 `getFilteredGoods()`，读到的已经是新的 `activeCategory` 了。
- 换句话说：**这是一份"故意绕远路"的写法**。它让你亲眼看清"到底是谁触发了重渲染"这件事，而不是被 `ref` + `computed` 的自动魔法糊弄过去。

等第 3 章学了 `computed`，把 `activeCategory` 改成 `ref`、`getFilteredGoods()` 改成 `filteredGoods = computed(() => ...)`，页面行为**一模一样**——那时你就能说出这两版的区别了：**一个是手动触发 + 手动算，一个是数据变了自动触发 + 自动算（且有缓存）。**

顺带一提：本节 Step 3 给的 `computed` 版本才是"正式写法"，这一版是为了配合第 2 章的教学节奏。两种都对，理解差别比记住写法重要。
