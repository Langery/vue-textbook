
# 4.14 章末实战：小组件库（P3）

> 章节：第 4 章 组件化思想
> 课时：1 课时
> 类型：章末实战 · 独立小项目 P3

---

第四章最核心的一句话是"把界面拆成组件"。拆完组件怎么**组织、复用、拼装**？这一节我们直接照大项目的方式做一件正经事：沉淀一套**通用小组件库**——商品卡片、确认弹窗、上架徽章。这既是组件拆分 / props / slot 的集中练兵，也是大项目 Campus2Hand 通用组件层的第一块地基，第 12 章的商品卡片、确认弹窗、状态徽章直接复用这套设计。

> 🎯 **类比一下：小组件库 ≈ 自己的工具箱**
> 螺丝刀、扳手、卷尺各归各位，用的时候直接拿，不用每次现造。组件库就是前端的工具箱：商品卡片、确认弹窗、状态徽章沉淀一次，全项目复用——这就是"通用组件层"的意义。

> 🧑 **小白**：这不就是把代码复制来复制去吗？
> 🤖 **Vue 君**：不是复制，是"一份设计、多处引用"。改一处，所有用到的地方同步生效。
> 👨🏫 **老湿**：做完这一节你会发现：**复用不是把代码粘过来，是把职责收拢成一个组件**。第 12 章大项目直接捡现成。

## 🎯 项目需求（一句话）

做一个"小组件库展示页"：在 `src/components/` 下沉淀三个可复用组件——`GoodsCard`（商品卡片）、`AppModal`（确认弹窗）、`StatusBadge`（状态徽章），用一个展示页把它们拼起来看效果——全程只用第 4 章已学的组件拆分、props、slot、Teleport、受控思路，不引入任何新库。

### ✅ 验收标准（能跑、能展示）

- [ ] 项目能 `npm run dev` 启动，展示页能看到三个组件并排呈现
- [ ] `GoodsCard` 至少接收商品标题、价格两个 props，正文区域用默认 slot 放描述，底部可放扩展内容
- [ ] `StatusBadge` 接收"文案 + 类型"两个 props，不同类型显示不同配色（如 在售/已出/审核中）
- [ ] 同一个组件在展示页被复用了至少 3 次，且数据各不相同（证明"一份设计、多处使用"）
- [ ] `AppModal` 弹窗能受控打开/关闭（父组件管 `visible`），用 Teleport 渲染到 `<body>` 下，并预留 `#header` / `#footer` 具名插槽
- [ ] 能向同学讲清楚：这个弹窗是受控还是非受控？为什么这么设计？

## 🛠 分步提示（3~5 步，含关键代码锚点）

> 以下只给路线和关键锚点，**不贴全量答案**。卡住时回头翻 4.4 / 4.5 / 4.8 / 4.9 / 4.12 对应小节。

### Step 1：想清楚组件树（回顾 4.3 / 4.7）

展示页是根组件，往下挂三个"叶子组件"：`GoodsCard`、`StatusBadge`、`AppModal`。先在纸上画出层级，再动手建目录——推荐一个组件一个目录（`.vue` + 未来可扩展的配套文件），这就是组件文件组织的最小示范。

### Step 2：写 `GoodsCard`——props 声明 + slot 拼装（回顾 4.5 / 4.8）

```vue
<script setup>
defineProps({
  title: String,
  price: Number,
  cover: { type: String, default: '📦' }
})
</script>
<template>
  <div class="goods-card">
    <span class="cover">{{ cover }}</span>
    <h3>{{ title }}</h3>
    <p class="price">￥{{ price }}</p>
    <slot />              <!-- 描述等扩展内容 -->
  </div>
</template>
```

> 锚点检查：展示页里传不同 `title / price / cover` 就能得到不同卡片——这就是"父传子、一份设计多处用"。

### Step 3：写 `StatusBadge`——用 props 驱动样式

接收 `text`（展示文案）和 `type`（'onSale' / 'sold' / 'reviewing' 等），内部准备一个"类型 → class"映射，把动态 class 绑到根元素上（回顾 2.2 的 `:class` 思想，第 4 章继续沿用）：

```html
<span class="badge" :class="`badge--${type}`">{{ text }}</span>
```

### Step 4：写 `AppModal`——Teleport + 具名插槽 + 受控（回顾 4.9 / 4.12）

`visible` 由父组件传入（props），父组件改它，弹窗开合。内容区分成三个插槽：`#header`、默认、`#footer`。外层用 `<Teleport to="body">` 把弹窗移出当前层级，避免被父容器 `overflow` / `z-index` 挡住：

```html
<Teleport to="body">
  <div v-if="visible" class="modal-mask" @click.self="$emit('update:visible', false)">
    <div class="modal">
      <slot name="header" />
      <slot />
      <slot name="footer" />
    </div>
  </div>
</Teleport>
```

> 锚点检查：先做成 `visible` 由父组件写死的弹窗看样式，再用按钮切换父组件的 `ref` 数据控制开合——体会"受控组件值归父组件管"（回顾 4.12）。`$emit` 只是让父组件收到"想关弹窗"的请求，具体改不改、怎么改由父组件决定。

### Step 5：用展示页把它们拼起来

`App.vue` 里准备 3 条商品数据、1 个 `showModal` 开关，把三个组件各复用多次：

```html
<GoodsCard v-for="item in goods" :key="item.id" :title="item.title" :price="item.price">
  <StatusBadge :text="item.statusText" :type="item.status" />
</GoodsCard>
<button @click="showModal = true">打开确认弹窗</button>
<AppModal v-model:visible="showModal" title="确认删除这件闲置？">
  <template #footer>
    <button @click="showModal = false">取消</button>
    <button @click="showModal = false">确认</button>
  </template>
</AppModal>
```

**`src/components/StatusBadge.vue`** —— 徽章：文案 + 类型两个 props，类型驱动配色：

```vue
<script setup>
// ====== props：父组件传进来的"文案 + 类型" ======
defineProps({
  text: { type: String, default: '未分类' },
  // type 决定配色，class 名直接拼在后面：badge--onSale / badge--sold / badge--reviewing
  type: { type: String, default: 'onSale' }
})

// 未知类型兜底到 onSale 配色，避免徽章变成"没有样式"的白板
// 注意：这里必须写成「函数」而不是 const 变量 —— props 变了要能重新算
function badgeClass(t) {
  return ['onSale', 'sold', 'reviewing'].includes(t) ? t : 'onSale'
}
</script>

<template>
  <span class="badge" :class="`badge--${badgeClass(type)}`">{{ text }}</span>
</template>

<style scoped>
.badge {
  display: inline-block;
  padding: 2px 10px;
  border-radius: 999px;
  font-size: 12px;
  line-height: 18px;
}
/* 三种状态三种色：颜色跟着 props 变，模板不用写 if */
.badge--onSale { background: #e4f6ec; color: #2f9e63; }
.badge--sold { background: #f0f0ee; color: #999; }
.badge--reviewing { background: #fdf1dc; color: #c98a20; }
</style>
```

**`src/components/AppModal.vue`** —— 弹窗：受控 + Teleport + 具名插槽：

```vue
<script setup>
// ====== props：visible 完全由父组件掌控，弹窗自己不存状态 ======
const props = defineProps({
  visible: { type: Boolean, default: false },
  title: { type: String, default: '确认操作' },
  confirmText: { type: String, default: '确认' },
  cancelText: { type: String, default: '取消' }
})

// ====== emit：弹窗只发请求，由父组件决定改不改数据 ======
// update:visible 让父组件能用 v-model:visible 双向控制
const emit = defineEmits(['update:visible', 'confirm'])

function close() {
  emit('update:visible', false)
}

function confirmAndClose() {
  emit('confirm')
  close()
}
</script>

<template>
  <!-- Teleport：把弹窗移到 body 下，避开父容器的 overflow / z-index 干扰 -->
  <Teleport to="body">
    <div v-if="visible" class="modal-mask" @click.self="close">
      <div class="modal">
        <!-- header 具名插槽：父组件不传就用 title 兜底 -->
        <header class="modal-header">
          <slot name="header">
            <h3 class="modal-title">{{ title }}</h3>
          </slot>
          <button class="modal-close" title="关闭" @click="close">✕</button>
        </header>

        <!-- 默认插槽：弹窗正文 -->
        <div class="modal-body">
          <slot />
        </div>

        <!-- footer 具名插槽：底部按钮区 -->
        <footer v-if="$slots.footer" class="modal-footer">
          <slot name="footer" />
        </footer>
        <footer v-else class="modal-footer">
          <!-- 父组件没给 footer，就用内置的取消/确认，保证弹窗永远能关 -->
          <button class="btn cancel" @click="close">{{ cancelText }}</button>
          <button class="btn confirm" @click="confirmAndClose">{{ confirmText }}</button>
        </footer>
      </div>
    </div>
  </Teleport>
</template>
```

**`src/App.vue`** —— 展示页：三个组件各复用多次，再加一个动态组件 Tab：

```vue
<script setup>
import { ref, markRaw } from 'vue'
import GoodsCard from './components/GoodsCard.vue'
import AppModal from './components/AppModal.vue'
import StatusBadge from './components/StatusBadge.vue'

// ====== 数据：3 条商品，展示页喂给 GoodsCard ======
const goods = ref([
  { id: 1, title: '九成新《高等数学》上下册', price: 15, cover: '📚', owner: '小林', status: 'onSale', statusText: '在售', tags: ['九成新', '可小刀'], desc: '只翻过前两章，笔记干净，赠答案册。' },
  { id: 2, title: '降噪蓝牙耳机（小米）', price: 120, cover: '🎧', owner: '阿凯', status: 'reviewing', statusText: '审核中', tags: ['配件全'], desc: '电池健康度 92%，带充电盒和说明书。' },
  { id: 3, title: 'Switch 续航版（含卡带）', price: 850, cover: '🎮', owner: '大壮', status: 'sold', statusText: '已出', tags: ['已验机'], desc: '毕业清仓，含 3 张卡带，机器无维修记录。' }
])

// ====== 动态组件：同一块区域，按 tab 切显示哪个组件 ======
// markRaw 标记组件对象，避免 Vue 试图把它变成响应式代理（回顾 4.10）
// 每个 tab 自带 props：GoodsCard 认 title/price/...，StatusBadge 只认 text/type
// 多传的 props 会被组件直接忽略，所以这里 v-bind 一把梭也完全没问题
const demo = goods.value[2] // 演示区统一拿第 3 条商品当素材
const tabs = [
  {
    key: 'onSale',
    label: '在售卡片',
    comp: markRaw(GoodsCard),
    props: { title: demo.title, price: demo.price, cover: demo.cover, tags: demo.tags, status: 'onSale', statusText: '在售' }
  },
  {
    key: 'sold',
    label: '已出卡片',
    comp: markRaw(GoodsCard),
    props: { title: demo.title, price: demo.price, cover: demo.cover, tags: demo.tags, status: 'sold', statusText: '已出' }
  },
  {
    key: 'badge',
    label: '只看徽章',
    comp: markRaw(StatusBadge),
    props: { type: 'reviewing', text: '审核中' }
  }
]
const activeTab = ref('onSale')

// 切tab 时要重新 find 一遍，所以放在函数里而不是 const currentTab
// （写成 const 就成了"死值"，切 tab 时不会跟着变——这是初学者常踩的坑）
function getCurrentTab() {
  return tabs.find((t) => t.key === activeTab.value)
}

// ====== 弹窗：受控状态全在这 ======
const showModal = ref(false)
const detailTitle = ref('')

function openDetail(title) {
  detailTitle.value = title
  showModal.value = true
}

function onConfirm() {
  // 收到弹窗的确认事件后由父组件决定做什么（回顾 4.12 受控）
  showModal.value = false
}
</script>

<template>
  <div class="page">
    <header class="page-head">
      <h2 class="title">🧰 小组件库展示页</h2>
      <p class="subtitle">GoodsCard × 3 复用 · AppModal 受控开合 · StatusBadge 驱动配色</p>
    </header>

    <!-- ====== 动态组件区：tab 决定这块区域渲染哪个组件 ====== -->
    <section class="panel">
      <h3 class="panel-title">动态组件区（回顾 4.10）</h3>
      <div class="tabs">
        <button
          v-for="tab in tabs"
          :key="tab.key"
          class="tab"
          :class="{ active: activeTab === tab.key }"
          @click="activeTab = tab.key"
        >
          {{ tab.label }}
        </button>
      </div>

      <!-- :is 指向变量，而不是写死组件名 -->
      <!-- v-bind 把"要传什么"也交给数据决定：不同组件各认各的 props，多传的会被忽略 -->
      <component :is="getCurrentTab().comp" v-bind="getCurrentTab().props" @detail="openDetail">
        <p>{{ demo.desc }}</p>
      </component>
    </section>

    <!-- ====== 卡片列表：GoodsCard 被复用 3 次，每次数据都不同 ====== -->
    <section class="panel">
      <h3 class="panel-title">商品卡片区（回顾 4.5 / 4.8）</h3>
      <div class="grid">
        <GoodsCard
          v-for="item in goods"
          :key="item.id"
          :title="item.title"
          :price="item.price"
          :cover="item.cover"
          :status="item.status"
          :status-text="item.statusText"
          :tags="item.tags"
          @detail="openDetail"
        >
          <!-- 默认插槽：这张卡专属的描述 -->
          <p class="card-desc">{{ item.desc }}</p>

          <!-- footer 具名插槽：每张卡放不同的操作按钮 -->
          <template #footer>
            <button class="mini-btn">收藏</button>
            <button class="mini-btn primary">@{{ item.owner }} 聊聊</button>
          </template>
        </GoodsCard>
      </div>
    </section>

    <!-- ====== 徽章一览：StatusBadge 单独复用，证明它能脱离卡片独立用 ====== -->
    <section class="panel">
      <h3 class="panel-title">徽章一览（StatusBadge 独立复用）</h3>
      <div class="badge-row">
        <StatusBadge text="在售" type="onSale" />
        <StatusBadge text="已出" type="sold" />
        <StatusBadge text="审核中" type="reviewing" />
```

<summary>💬 老师备注：这个成品里有三处"故意的非标准写法"，值得你找出来</summary>

**① `StatusBadge` 里的 `badgeClass()` 兜底，以及为什么它不能写成 `const`。**
组件通常假设"外部会传对的值"。但真实项目里 `type` 可能来自后端接口——一旦传进来一个没定义过的类型，`badge--unknown` 这个 class 不存在，徽章就变成一块没背景没颜色的裸文字，看起来像"样式丢了"。

那为什么兜底逻辑要写成函数、而不是 `const safeType = ...`？因为 **`const` 只在组件创建时算一次**。这份展示页用动态组件复用同一个 `StatusBadge`，切tab 时 props 变了、文案跟着变，但那个 `const` 还攥着第一次的值——于是你会看到「文案写着在售、颜色却是已出」的鬼画面。**凡是"根据 props 算出来"的东西，都不能存成快照。**（第 3 章的 `computed` 正是解决这件事的正规工具。）

**教学取舍**：组件越"防御性"，调用越省心，但代码也会变长——真实项目里请按团队约定来定，别什么组件都套一层。

**② `GoodsCard` 里 `<slot>` 带兜底内容。**
`<slot>卖家很懒，什么都没写。</slot>` 中间那段，只有父组件**没传内容**时才会显示。如果父组件传了空字符串 `''`，兜底**不会**出现（空字符串算"传了"）。这是 slot 最容易被忽略的细节，值得动手试一次。

**③ `AppModal` 的 footer 写了两遍。**
`<footer v-if="$slots.footer">` 和 `<footer v-else>`——这是"插槽可覆盖 + 组件自带保底"的常见套路。好处是：调用方想改按钮就传 `#footer`，不想管就直接用内置的。坏处是模板重复。**如果只有一种选择，直接写死就够；想清楚了"为什么两种都要"再写这份重复。**

最后留个思考题：`showModal` 用的是 `ref`，而 `getCurrentTab()` 只是个普通函数——如果当初图省事写成 `const currentTab = tabs.find(...)`，切 tab 时会发生什么？（提示：去 ① 里那个 `const` 的坑找答案，同样的道理。）想清楚"为什么这里必须是函数、那里必须是 ref"，你就真的懂第 3 章的响应式了。

## 🔮 它在最后的大项目里长成什么

这一节沉淀的"小组件库"，就是大项目 **Campus2Hand 校园二手集市**的**通用组件层起点**——商品卡片、确认弹窗、上架徽章会原样搬进大项目并被所有页面复用；后续章节还会继续往里加分页、表单控件，第 12 章你会看到"这套组件库我亲手写过"。

> 🧊 **冷知识**：真实项目里"组件库"往往不止一种粒度——`基础组件`（按钮/输入框）、`业务组件`（商品卡片/状态徽章）、`页面组件`（整页）。你现在做的小组件库属于"业务组件"层，它依赖更底层的基础组件，也被更上层的页面引用。分层的意义就是：每层只操心自己那一亩三分地。

<details><summary>🔍 想深究再看：组件库目录结构为什么推荐"一个组件一个目录"？</summary>

`GoodsCard/`、`AppModal/`、`StatusBadge/` 每个组件独立成目录，好处有三个：一是组件主体 `.vue` 和它的配套文件（测试、文档、样式、类型声明）放一起，好找；二是将来要做"按需打包"（tree-shaking）时，目录就是天然边界；三是多人协作时各目录互不打架。早期为了省事全堆在 `components/` 平铺，组件一多就乱——这也是大项目里常见的重构场景。
