## 🎯 项目需求（一句话）

做一个"小组件库展示页"：在 `src/components/` 下沉淀三个可复用组件——`GoodsCard`（商品卡片）、`AppModal`（确认弹窗）、`StatusBadge`（状态徽章），用一个展示页把它们拼起来看效果——全程只用第 3 章已学的组件拆分、props、slot、Teleport、受控思路，不引入任何新库。

### ✅ 验收标准（能跑、能展示）

- [ ] 项目能 `npm run dev` 启动，展示页能看到三个组件并排呈现
- [ ] `GoodsCard` 至少接收商品标题、价格两个 props，正文区域用默认 slot 放描述，底部可放扩展内容
- [ ] `StatusBadge` 接收"文案 + 类型"两个 props，不同类型显示不同配色（如 在售/已出/审核中）
- [ ] 同一个组件在展示页被复用了至少 3 次，且数据各不相同（证明"一份设计、多处使用"）
- [ ] `AppModal` 弹窗能受控打开/关闭（父组件管 `visible`），用 Teleport 渲染到 `<body>` 下，并预留 `#header` / `#footer` 具名插槽
- [ ] 能向同学讲清楚：这个弹窗是受控还是非受控？为什么这么设计？

## 🛠 分步提示（3~5 步，含关键代码锚点）

> 以下只给路线和关键锚点，**不贴全量答案**。卡住时回头翻 3.4 / 3.5 / 3.8 / 3.9 / 3.12 对应小节。

### Step 1：想清楚组件树（回顾 3.3 / 3.7）

展示页是根组件，往下挂三个"叶子组件"：`GoodsCard`、`StatusBadge`、`AppModal`。先在纸上画出层级，再动手建目录——推荐一个组件一个目录（`.vue` + 未来可扩展的配套文件），这就是组件文件组织的最小示范。

### Step 2：写 `GoodsCard`——props 声明 + slot 拼装（回顾 3.5 / 3.8）

```vue
<script setup>
defineProps({
  title: String,
  price: Number,
  cover: { type: String, default: '📦' }
})
</script>
<template>
  <div class="goods-card">
    <span class="cover">{{ cover }}</span>
    <h3>{{ title }}</h3>
    <p class="price">￥{{ price }}</p>
    <slot />              <!-- 描述等扩展内容 -->
  </div>
</template>
```

> 锚点检查：展示页里传不同 `title / price / cover` 就能得到不同卡片——这就是"父传子、一份设计多处用"。

### Step 3：写 `StatusBadge`——用 props 驱动样式

接收 `text`（展示文案）和 `type`（'onSale' / 'sold' / 'reviewing' 等），内部准备一个"类型 → class"映射，把动态 class 绑到根元素上（回顾 2.2 的 `:class` 思想，第 3 章继续沿用）：

```html
<span class="badge" :class="`badge--${type}`">{{ text }}</span>
```

### Step 4：写 `AppModal`——Teleport + 具名插槽 + 受控（回顾 3.9 / 3.12）

`visible` 由父组件传入（props），父组件改它，弹窗开合。内容区分成三个插槽：`#header`、默认、`#footer`。外层用 `<Teleport to="body">` 把弹窗移出当前层级，避免被父容器 `overflow` / `z-index` 挡住：

```html
<Teleport to="body">
  <div v-if="visible" class="modal-mask" @click.self="$emit('update:visible', false)">
    <div class="modal">
      <slot name="header" />
      <slot />
      <slot name="footer" />
    </div>
  </div>
</Teleport>
```

> 锚点检查：先做成 `visible` 由父组件写死的弹窗看样式，再用按钮切换父组件的 `ref` 数据控制开合——体会"受控组件值归父组件管"（回顾 3.12）。`$emit` 只是让父组件收到"想关弹窗"的请求，具体改不改、怎么改由父组件决定。

### Step 5：用展示页把它们拼起来

`App.vue` 里准备 3 条商品数据、1 个 `showModal` 开关，把三个组件各复用多次：

```html
<GoodsCard v-for="item in goods" :key="item.id" :title="item.title" :price="item.price">
  <StatusBadge :text="item.statusText" :type="item.status" />
</GoodsCard>
<button @click="showModal = true">打开确认弹窗</button>
<AppModal v-model:visible="showModal" title="确认删除这件闲置？">
  <template #footer>
    <button @click="showModal = false">取消</button>
    <button @click="showModal = false">确认</button>
  </template>
</AppModal>
```

## 🚀 延伸挑战（1~2 个加分项）

1. **再加一个 `EmptyState`**：当商品列表为空时展示的"还没有闲置"空态组件（图 + 文案 + 引导按钮），用 slot 让调用方自定义引导按钮——这是大项目首页空态的原型。
2. **给 `AppModal` 加一个"确认中"状态**：弹窗里点"确认删除"后，让按钮短暂变成"处理中…（禁用）"，再自动关闭——这个"父组件收到事件后自己决定何时关弹窗"的节奏，正好把受控思路练到位。
