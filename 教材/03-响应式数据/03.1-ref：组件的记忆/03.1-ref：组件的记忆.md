## 🧠 思维导图

```text
3.1 ref：组件的记忆
├── 问题：普通变量为什么不更新
│   ├── JS 变量赋完值就"完事了"
│   ├── Vue 不知道你改了变量
│   └── 需要一个"能被 Vue 感知"的容器
├── ref 就是那个容器
│   ├── ref() 把值包成一个对象
│   ├── 读/写要通过 .value
│   └── Vue 能拦截 .value 的读写
├── 核心用法
│   ├── 创建：const count = ref(0)
│   ├── 读：count.value
│   ├── 改：count.value++
│   └── 模板里自动解包：直接用 count
└── 支持的类型
    ├── 基本类型：Number、String、Boolean
    ├── 对象/数组（ref 也能包对象！）
    └── null、undefined（虽然不常用）
```

学完模板语法后，你想让页面上的数字按钮"点一下加一"，顺手写了个普通变量 `let count = 0`。结果按钮点了，控制台明明打印出 1，页面上的数字却纹丝不动——这几乎是每个 Vue 新手遇到的第一个"灵异事件"。先别怀疑人生，真相很简单：**Vue 根本不知道你改了变量**。这节登场的 `ref()`，就是给数据套上一个"能被 Vue 感知"的壳。

> 🎯 **类比一下：便利贴 vs 显示屏**
>
> 普通变量，像把数字写在**便利贴上**——只有你自己看得见，Vue 不会一直凑过来看你的便利贴。
> `ref` 则像把数字接上了**显示屏**：你这边一改，屏幕上立刻跟着变。
> 不是数字本身变了性子，而是它被装进了一个"有人盯着"的容器里。

## 🤔 一、为什么普通变量不够用？

先看一段"翻车"代码：

```vue
<script setup>
let count = 0

function add() {
  count++           // JS 眼里：count 现在是 1 了
  console.log(count) // 控制台也打印了 1
}
</script>

<template>
  <p>当前计数：{{ count }}</p>   <!-- 永远是 0，不会变！ -->
  <button @click="add">+1</button>
</template>
```

你点了按钮，控制台明明显示 `count` 变成 1 了，为什么页面上还是 0？

因为 **Vue 不知道你改了变量**。`let count = 0` 就是一个普通 JS 变量——你改它，Vue 根本没收到通知。它不会自动重新渲染模板。

> 💬 **老师备注**：Vue 不是"每秒轮询检查所有变量有没有变"——那样性能会炸。它需要你**主动告诉它**："这个数据我可能要改，你帮我盯着。"

<details>
<summary>🔍 想深究再看：既然是"主动告诉"，Vue 具体是怎么被通知到的？</summary>

答案在 ES6 新增的 **`Proxy`（代理对象）** 身上。

`ref(0)` 返回的并不是数字 `0`，而是一个被 Proxy 包裹过的对象。这个 Proxy 在你**读** `.value` 时记下"谁在用这个数据"（收集依赖），在你**写** `.value` 时通知那些使用者"该重新渲染了"（派发更新）。

> 🧊 **冷知识：Vue 2 为什么没有 `Vue.set` 了？**
> Vue 2 用的是 `Object.defineProperty`，它只能劫持对象上**已经存在**的属性。所以那时候给对象**新增**一个属性，视图是不会更新的，必须调用 `Vue.set` 手动补救。
> Vue 3 换成 `Proxy` 后，新增、删除属性都能被感知——`Vue.set` 已无必要。

</details>

## 💡 二、ref：给数据套一个"能被追踪"的壳

### 2.1 ref 基本语法

```vue
<script setup>
import { ref } from 'vue'

// ref(初始值) 返回一个响应式引用对象
const count = ref(0)
</script>
```

> 📦 **ES6 小灶：上面那两行 `import` 和 `const`，其实都是 ES6 语法**
>
> ES6（ECMAScript 2015）是 JavaScript 在 2015 年发布的一次大版本升级，本书后面会反复用到它带来的新语法。先认识本节出现的两个：
>
> - `import { ref } from 'vue'` —— **模块导入**。把 `vue` 这个模块里的 `ref` 拿出来用。在此之前，浏览器里要靠一堆 `<script>` 标签按顺序引入，容易互相污染。
> - `const count = ref(0)` —— **常量声明**。块级作用域，且不允许再指向别的值。
>
> ⚠️ 翻车示例：
>
>     const count = ref(0)
>     count = ref(1)   // ❌ TypeError: Assignment to constant variable.
>     count.value = 1  // ✅ 合法——不能改指向，不等于不能改内容
>
> "不能重新赋值"管的是**变量指向谁**，不是**对象内部能不能变**。这是初学 `const` 时最大的误会。

`ref(0)` 做的事：把数字 `0` 包进一个对象里，这个对象有且只有一个属性叫 `.value`。

```js
console.log(count)        // RefImpl { value: 0 }  ← 不是 0，而是一个对象！
console.log(count.value)  // 0
```

**JS 代码里**读写必须用 `.value`：

```vue
<script setup>
import { ref } from 'vue'

const count = ref(0)

function add() {
  count.value++   // ✅ 这样 Vue 就知道了
}
</script>
```

### 2.2 模板里自动解包

在 `<template>` 中，Vue 帮你自动"剥壳"——不用写 `.value`：

```vue
<template>
  <p>当前计数：{{ count }}</p>   <!-- ✅ 直接写 count，不用 .value -->
  <button @click="add">+1</button>
</template>
```

> 💬 **老师备注**：这是 Vue 的贴心设计——模板里 `.value` 写多了又丑又容易忘，干脆自动帮你拆。

### 2.3 完整计数器示例

```vue
<script setup>
import { ref } from 'vue'

const count = ref(0)

function add()    { count.value++ }
function minus()  { count.value-- }
function reset()  { count.value = 0 }
</script>

<template>
  <div class="counter">
    <button @click="minus">-</button>
    <span class="number">{{ count }}</span>
    <button @click="add">+</button>
    <br/>
    <button @click="reset">重置</button>
  </div>
</template>

<style scoped>
.counter { text-align: center; padding: 20px; }
.number { font-size: 32px; margin: 0 16px; font-weight: bold; }
button { margin: 4px; padding: 8px 16px; cursor: pointer; }
</style>
```

## 🛠 三、ref 支持的数据类型

`ref()` **不只是给基本类型用的**——它也能包装对象和数组：

```js
// 基本类型
const name = ref('张三')
const age = ref(20)
const isLogin = ref(false)

// 对象
const user = ref({ name: '张三', age: 20 })
// 改属性：user.value.name = '李四'

// 数组
const list = ref([1, 2, 3])
// 操作数组：list.value.push(4)
```

⚠️ 注意：ref 包对象时，读写嵌套属性仍然是 `ref.value.xxx`。

## ⚠️ 四、常见陷阱

> 🎬 **小剧场：小新又双叒忘了 `.value`**
>
> **小新**：我明明写了 `count++`，页面为什么一动不动？
> **报错君**：因为 Vue 没收到通知。而且它**也不会报错**——这才是最坑的地方。
> **小新**：那我怎么知道什么时候该写 `.value`？
> **报错君**：看你在哪儿写。**脚本里**要，**模板里**不要。
> **小新**：凭什么模板里可以不写？
> **报错君**：因为 Vue 在编译模板时帮你拆了壳——它知道你要的是值，不是那个盒子。
>
> 记住这句话，下面两个坑都能躲开。

### 陷阱 1：JS 代码里忘了 .value

```js
function add() {
  count++        // ❌ 永远不会触发更新
  count.value++  // ✅ 这才是对的
}
```

> 记一个口诀：**模板里光杆司令，脚本里 `.value` 护身**。

### 陷阱 2：把 ref 当普通变量解构

```js
const state = ref({ a: 1, b: 2 })
const { a } = state        // ❌ a 是普通数字，不是响应式的
const { a } = state.value  // ❌ 也是普通数字 1
```

> 📦 **ES6 小灶：`const { a } = state` 这是什么写法？**
>
> 这叫**解构赋值**（ES6 新增）。它按"形状"从对象里把字段取出来：
>
>     const obj = { a: 1, b: 2 }
>     const { a, b } = obj          // 等价于 const a = obj.a; const b = obj.b
>     const { b: renamed } = obj    // 取出 b 并改名为 renamed
>
> 它让代码短了不少，但也正是它，把 `state.value` 里的响应式"掰断"了——因为解构拿到的是**某个瞬间的值**（一个普通数字），不再是那个被 Proxy 盯着的盒子。

解构会丢失响应式——这点后面 3.2 和 3.9 会详细讲。

### 陷阱 3：ref 包 ref（没必要）

```js
const a = ref(ref(0))  // ❌ 不要这样写，Vue 会自动解包
```

`ref()` 已经够用了，不需要套娃。

## 🧠 本节小结

- **为什么普通变量不行**：赋值后 Vue 收不到通知，页面不会自动更新
- **ref() 是什么**：把值包进一个带 `.value` 的响应式容器，读写会被 Vue 拦截
- **怎么用**：JS 里读改写都要写 `ref.value`；模板里自动解包，直接写 ref 名字
- **能包什么**：基本类型、对象、数组都能包（包对象时嵌套属性仍要 `.value.xxx`）
- **两个大坑**：忘了 `.value`、把 ref 解构出来（解构会丢响应式，3.2 和 3.9 会展开）
