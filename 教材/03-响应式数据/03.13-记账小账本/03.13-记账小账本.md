## 🎯 项目需求（一句话）

做一个"闲置交易记账本"：记录每笔"卖出 / 买入"流水（物品、金额、方向），能增删流水，并实时算出总收入、总支出、结余——全程只用第 3 章已学的 `ref` / `reactive`、计算属性、响应式更新姿势，不引入任何新库。

> **小新**：我算了算，宿舍里那几本闲置书和台灯卖出去能回血两百多……但每次算完就忘，还要翻聊天记录对半天。

> **报错君**：对。你现在写的这三十行逻辑，就是后面购物车的发动机。

## 🛠 分步提示（3~5 步，含关键代码锚点）

> 以下只给路线和关键锚点，**不贴全量答案**。卡住时回头翻 3.1 / 3.2 / 3.9 / 3.3 对应小节。

### Step 1：定义流水数据结构

```js
const records = ref([
  { id: 1, item: '九成新《高等数学》', amount: 15, direction: 'income' },
  { id: 2, item: '购入二手台灯', amount: 20, direction: 'expense' }
])
```

表单字段用 `reactive` 管理（回顾 3.2 对象/数组倾向 `reactive`；这里先用 `ref` 包对象也行，注意别混用踩坑）。

### Step 2：新增流水——先想"能不能原地 push"

新增用 `records.value.push({ id: nextId++, ... })` 即可触发更新（回顾 3.3：数组用 `push` 没问题）。**按下标改也能触发**（`records.value[i] = x` 在 Vue 3 完全有效），但当你要"按 id 定位再改"时，`splice` 语义更清楚，所以下面统一用会改原数组的方法。整体换新数组 `records.value = newArray` 在 `ref` 下也能触发更新，但要手动拼新数组，不如 `splice` 直观。

```js
function addRecord() {
  if (!form.item.trim() || !(form.amount > 0)) return
  records.value.push({
    id: ++nextId,
    item: form.item.trim(),
    amount: Number(form.amount),
    direction: form.direction
  })
  form.item = ''
  form.amount = ''
}
```

### Step 3：用计算属性推导汇总（回顾 2.8 方案一）

总金额不手动存，全部由列表推导：

```js
const totalIncome = computed(() =>
  records.value.filter((r) => r.direction === 'income').reduce((s, r) => s + r.amount, 0)
)
const totalExpense = computed(() =>
  records.value.filter((r) => r.direction === 'expense').reduce((s, r) => s + r.amount, 0)
)
const balance = computed(() => totalIncome.value - totalExpense.value)
```

> 🎯 **类比一下：手写余额小票 vs 银行自动结账**
>
> 手动维护"总金额"变量，就像在便利贴上自己写余额——每加一笔都要记得擦掉重写，擦漏一次就对不上账；用计算属性从流水列表推导，就像**银行对账单**——你存多少取多少，银行按每笔流水自动算出余额，永远和流水对得上。所以"总金额"不自己存，改流水汇总自动跟着变。

> 锚点检查：在计算属性里只依赖 `records`，删/加流水后汇总自动变——这就是"状态单一来源"的甜头。

<details>
<summary>🔍 卡住了点这里：本节引用的三个"前人章节"在哪</summary>

- **2.8 方案一（computed 过滤）**：`filter` + `reduce` 求和的标准写法在第 2 章 2.8 节；忘了 `reduce` 第二个参数（初始值）干什么用的，回去扫一眼那节示例。
- **3.3 更新数组的姿势**：`push` / `splice` / 按下标赋值**都能触发更新**（Vue 3 的 Proxy 优势）。真正要小心的是 `filter` / `map` 这类**返回新数组、不改原数组**的方法——返回值必须赋回去，原因见 3.3。
- **3.9 不可变原则**：为什么"整体换一个新数组"在 `ref` 下生效、在 `reactive` 下却会断链？这条铁律 3.9 讲得最透。

三处都是学过的内容，不用重学，回去**只找对应那一段**。这也是真实开发的常态：不靠背，靠知道去哪儿查。

</details>

### Step 4：删除流水——按 id 过滤出新数组

删除用"过滤出新数组再整体赋值"还是 `splice`？两种都要注意响应式（回顾 3.3）。推荐 `splice` 原地改：

```js
function removeRecord(id) {
  const idx = records.value.findIndex((r) => r.id === id)
  if (idx > -1) records.value.splice(idx, 1)
}
```

### Step 5：给界面加一点"账本感"

用 `v-for` 渲染流水列表，每条显示物品名 / 方向徽章（收入绿 / 支出红）/ 金额 / 删除按钮；顶部放三张汇总卡片。思考题：为什么把"收支统计"做成计算属性而不是在 `addRecord` 里手动 `total += amount`？

```vue
<script setup>
import { ref, reactive, computed } from 'vue'

// ========== 状态：流水列表 ==========
// 用 ref 包数组：后续整体替换（如 loadFromStorage）也能触发更新
const records = ref([
  { id: 1, item: '九成新《高等数学》', amount: 15, direction: 'income' },
  { id: 2, item: '购入二手台灯', amount: 20, direction: 'expense' }
])

let nextId = records.value.length

// ========== 状态：表单（用 reactive 管理对象） ==========
const form = reactive({
  item: '',
  amount: '',
  direction: 'income'      // income 收入 / expense 支出
})

// ========== 计算属性：汇总全部由列表推导，不手动维护 ==========
const totalIncome = computed(() =>
  records.value
    .filter((r) => r.direction === 'income')
    .reduce((sum, r) => sum + r.amount, 0)
)

const totalExpense = computed(() =>
  records.value
    .filter((r) => r.direction === 'expense')
    .reduce((sum, r) => sum + r.amount, 0)
)

const balance = computed(() => totalIncome.value - totalExpense.value)

// ========== 方法 ==========
function addRecord() {
  // 校验：物品名非空、金额为正数
  if (!form.item.trim() || !(Number(form.amount) > 0)) return

  // 新增用 push（回顾 3.3：数组用 push 没问题）
  records.value.push({
    id: ++nextId,
    item: form.item.trim(),
    amount: Number(form.amount),
    direction: form.direction
  })

  // 清空表单（方向保持不变，省得用户每笔都重选）
  form.item = ''
  form.amount = ''
}

function removeRecord(id) {
  const idx = records.value.findIndex((r) => r.id === id)
  if (idx > -1) records.value.splice(idx, 1)
}

// 格式化金额：固定两位小数 + 千分位
function formatMoney(n) {
  return n.toLocaleString('zh-CN', { minimumFractionDigits: 2 })
}
</script>

<template>
  <div class="ledger">
    <h2 class="title">💰 记账小账本</h2>

    <!-- 汇总卡片：数字直接绑定计算属性 -->
    <div class="cards">
      <div class="card income">
        <div class="card-label">总收入</div>
        <div class="card-value">￥{{ formatMoney(totalIncome) }}</div>
      </div>
      <div class="card expense">
        <div class="card-label">总支出</div>
        <div class="card-value">￥{{ formatMoney(totalExpense) }}</div>
      </div>
      <div class="card balance" :class="{ negative: balance < 0 }">
        <div class="card-label">结余</div>
        <div class="card-value">￥{{ formatMoney(balance) }}</div>
      </div>
    </div>

    <!-- 新增表单 -->
    <form class="add-form" @submit.prevent="addRecord">
      <input v-model="form.item" class="input item" placeholder="物品名，如：九成新《高等数学》" />
      <input
        v-model="form.amount"
        class="input amount"
        type="number"
        step="0.01"
        min="0"
        placeholder="金额"
      />
      <select v-model="form.direction" class="input direction">
        <option value="income">卖出 · 收入</option>
        <option value="expense">买入 · 支出</option>
      </select>
      <button class="btn" type="submit">添加</button>
    </form>

    <!-- 流水列表 -->

    <p v-else class="empty">还没有流水，点上面添加第一笔吧</p>
  </div>
</template>
```

**照着做完可以顺手验证的 4 个知识点**：

| 验证动作 | 观察到什么 | 对应小节 |
|---|---|---|
| 点"添加"但不填金额，直接提交 | 列表没变化（`addRecord` 的 `if` 拦住了） | 3.4 条件 |
| 删掉一笔"支出"流水 | 三张卡片**同时**跟着变，一个都没手动改 | 3.6 computed |
| 把 `form.item` 改成 `form.name` | 控制台报 `form.name is not defined` | 3.3 读取路径 |
| 在 `removeRecord` 里换成 `records.value = records.value.filter(...)` | 结果相同——两种更新姿势都对 | 3.3 / 3.9 |

> 💬 **老师备注：这个成品里藏了一个"意外正确"**
> `let nextId = records.value.length` ——如果学生先删掉一条再新增，`nextId` 可能与已有 id 重复，导致 `v-for` 的 `key` 冲突（列表渲染异常）。
> **正确写法是用自增最大值而不是长度**：改用 `Date.now()`，或每次新增前 `Math.max(...ids) + 1`。
> 这个 bug 在演示时不一定出现，但**它恰好说明了为什么 `key` 不能随便写**（回顾 2.7）。你可以留作"找茬"练习，也可以直接用 `Date.now()` 规避。

## 🚀 延伸挑战（1~2 个加分项）

1. **加一个"单价 × 数量"的明细**：每条流水带数量，汇总金额 = Σ(单价 × 数量)。你会发现"金额由数据推导"在复杂场景更省心。
2. **试试 `customRef` 做个金额输入**：参考 3.11，让金额输入带 2 位小数格式化 / 防抖——这是响应式自定义能力的第一次实战。

<details>
<summary>🏆 成就挑战：财务自由徽章 + 一处"找茬"</summary>

**徽章 1｜🧮 账房先生**：记满 5 笔流水（3 收 2 支），三张汇总卡片的数字和手算完全一致——结余 = 总收入 − 总支出，一分不差。

**徽章 2｜💰 财务自由**：随便删掉一笔流水，汇总数字**立刻**跟着变。如果列表变了、卡片没动，说明还有一处总金额在手动维护（`total += amount` 那种写法），回去把它换成计算属性。

**找茬模式**：小新写了下面这个"清空账本"的函数，点按钮后页面纹丝不动，控制台还飘了红。错在哪？

    function resetAll() {
      records = []          // 想把流水全部清空
    }

提示：`records` 是 `ref`（见 Step 1）。想想 3.1 那句口诀——"模板里光杆司令，脚本里 `.value` 护身"。

</details>
