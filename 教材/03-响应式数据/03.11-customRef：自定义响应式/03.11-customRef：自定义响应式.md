用 `ref` 顺手后，你可能嫌它"太老实"：用户疯狂输入搜索框，每次击键都触发更新，请求快被打爆；想顺手存历史记录，却没地方挂钩子。默认 ref 的"一改就触发"不够灵活，Vue 留了后门：`customRef` 让你接管依赖收集和触发时机，实现防抖、异步校验、历史记录等玩法。本节用两个实战例子带你上手。

## 🤔 一、为什么要学 customRef？

前面用 `ref()` 时，Vue 帮我们搞定了 track 和 trigger——你只管 `.value++`，剩下的 Vue 全包。

但生活中有些场景，Vue 默认的"一改就触发"不太合适：

- **搜索输入框**：用户每敲一个字母就发一次请求，太浪费了。应该等用户停手 500ms 再发。
- **表单草稿**：用户填了一半刷新页面，数据没了。应该自动存 localStorage，刷新后恢复。
- **编辑器**：用户改了一段文字，想撤销回去。应该有撤销/重做功能。

这些需求都有个共同点：**想在 `set value` 和 `trigger` 之间加点自定义逻辑**。

这就是 `customRef` 的用武之地——它把 `track` 和 `trigger` 的控制权交给你。

---

## 💡 二、customRef 基础语法

```js
import { customRef } from 'vue'

function myRef(initialValue) {
  return customRef((track, trigger) => {
    let value = initialValue

    return {
      get() {
        track()   // 🔑 告诉 Vue："有人在读我，记下他"
        return value
      },
      set(newVal) {
        value = newVal
        trigger() // 🔑 告诉 Vue："我变了，通知所有读我的人"
      }
    }
  })
}
```

> **`track` 和 `trigger` 是 customRef 工厂函数的参数**，不是从别处 import 的。

要点速记：
- `get()` 里先调 `track()` 再 return——告诉 Vue "我被读了"
- `set()` 里改值后调 `trigger()`——告诉 Vue "我变了，重新渲染"
- `track()` 和 `trigger()` 之间就是你可以"加料"的地方

一句话总结 `ref` 和 `customRef` 的分工：

| 对比维度 | 普通 `ref` | `customRef` |
|---|---|---|
| track 时机 | Vue 自动收集 | 你在 `get()` 里手动调 `track()` |
| trigger 时机 | Vue 自动触发 | 你在 `set()` 里手动调 `trigger()` |
| 可定制点 | 无（开箱即用） | set 前后可插入防抖、持久化、历史记录等逻辑 |
| 上手难度 | 低 | 中（需要理解 track / trigger） |
| 适用场景 | 绝大多数日常状态 | 延迟更新、副作用同步、额外状态管理 |

## 🛠 三、实战 1：防抖 ref（debounceRef）

### 场景

搜索输入框：用户打字时不应每次按键都发请求，而应等用户停下来再发。

### 实现

```js
// composables/useDebounceRef.js
import { customRef } from 'vue'

export function debounceRef(value, delay = 500) {
  let timer = null

  return customRef((track, trigger) => {
    return {
      get() {
        track()            // 读的时候正常收集依赖
        return value
      },
      set(newVal) {
        value = newVal     // 先存新值（输入框实时显示）
        clearTimeout(timer)
        timer = setTimeout(() => {
          trigger()        // 🔑 延迟后才触发视图更新
        }, delay)
      }
    }
  })
}
```

### 使用示例

```vue
<script setup>
import { debounceRef } from './composables/useDebounceRef'

const keyword = debounceRef('', 500)

// 用 watch 监听 keyword——只有当 trigger() 被调用时才会触发
// （也就是用户停止输入 500ms 后）
import { watch } from 'vue'
watch(keyword, (val) => {
  console.log('发起搜索请求：', val)
  // 在这里调用 API：fetch(`/api/search?q=${val}`)
})
</script>

<template>
  <input v-model="keyword" placeholder="输入搜索关键词..." />
  <p>当前输入：{{ keyword }}</p>
  <!-- 注意：keyword 的显示会延迟 500ms 才更新，
       如果你希望输入框实时显示，需要用两个 ref：
       一个 debounceRef 给请求，一个普通 ref 给 v-model -->
</template>
```

### 改进版：输入框实时显示 + 搜索防抖

```js
export function debounceRef(value, delay = 500) {
  let timer = null
  let displayValue = value  // 立即显示的值

  return customRef((track, trigger) => {
    return {
      get() {
        track()
        return displayValue   // 读的时候返回最新值，输入框实时显示
      },
      set(newVal) {
        displayValue = newVal
        trigger()             // 🔑 立即 trigger！让输入框实时显示

        clearTimeout(timer)
        timer = setTimeout(() => {
          value = newVal       // 延迟后才真正"确认"这个值
          trigger()            // 再 trigger 一次，watch 触发请求
        }, delay)
      }
    }
  })
}
```

## 🛠 四、实战 2：自动持久化 ref（localRef）

### 场景

表单填了一半，刷新页面或关掉浏览器，数据没了。希望自动存到 `localStorage`。

### 实现

```js
// composables/useLocalRef.js
import { customRef } from 'vue'

export function localRef(key, initialValue) {
  // 初始化：尝试从 localStorage 读，读不到用 initialValue
  let value = initialValue
  try {
    const stored = localStorage.getItem(key)
    if (stored !== null) {
      value = JSON.parse(stored)
    }
  } catch {
    // 解析失败，用默认值
  }

  return customRef((track, trigger) => {
    return {
      get() {
        track()
        return value
      },
      set(newVal) {
        value = newVal
        // 🔑 每次修改自动存 localStorage
        try {
          localStorage.setItem(key, JSON.stringify(newVal))
        } catch (e) {
          console.warn('localStorage 写入失败：', e)
        }
        trigger()
      }
    }
  })
}
```

### 使用示例

```
<script setup>
import { localRef } from './composables/useLocalRef'

// 表单数据自动持久化，刷新页面不丢
const username = localRef('form_username', '')
const email = localRef('form_email', '')
const bio = localRef('form_bio', '')
</script>

<template>
  <form>
    <input v-model="username" placeholder="用户名" />
    <input v-model="email" placeholder="邮箱" type="email" />
    <textarea v-model="bio" placeholder="简介"></textarea>
    <p class="hint">数据自动保存到本地，刷新页面也不会丢失</p>
  </form>
</template>

<style scoped>
.hint { color: #999; font-size: 0.85em; }
</style>
```

> 💬 **老师备注**：`localStorage` 有 5-10MB 的容量限制，别存太大的数据。能用 IndexedDB 更好但太重了——localStorage 够用。

## 🛠 五、实战 3：带历史记录的 ref（historyRef）

### 场景

做一个简易画板或文本编辑器，支持撤销（Ctrl+Z）和重做（Ctrl+Y）。

### 实现

```js
// composables/useHistoryRef.js
import { customRef } from 'vue'

export function historyRef(initialValue, maxHistory = 50) {
  let value = initialValue
  let history = []         // 历史记录栈
  let future = []          // 重做栈
  let isUndoing = false    // 防止撤销时重复入栈

  function pushHistory(val) {
    if (isUndoing) return
    history.push(JSON.parse(JSON.stringify(val)))  // 深拷贝
    if (history.length > maxHistory) {
      history.shift()  // 超出上限，删最早的
    }
    future = []  // 新操作清空重做栈
  }

  const result = customRef((track, trigger) => {
    return {
      get() {
        track()
        return value
      },
      set(newVal) {
        pushHistory(value)  // 🔑 改之前把旧值存进历史
        value = newVal
        trigger()
      }
    }
  })

  // 附加 undo / redo 方法
  result.undo = function() {
    if (history.length === 0) return
    isUndoing = true
    future.push(JSON.parse(JSON.stringify(value)))
    value = history.pop()
    isUndoing = false
    trigger()  // 这里需要拿到 factory 里的 trigger → 
  }

  // ... 由于 trigger 在 factory 闭包里，需要改造一下
  // 完整写法见下方改进版
  return result
}
```

### 改进版（完整可运行）

```js
// composables/useHistoryRef.js
import { customRef } from 'vue'

export function useHistoryRef(initialValue, maxHistory = 50) {
  let value = initialValue
  let history = []
  let future = []
  let isUndoing = false
  let _trigger = null

  const clone = (v) => JSON.parse(JSON.stringify(v))

  function pushHistory() {
    if (isUndoing) return
    history.push(clone(value))
    if (history.length > maxHistory) history.shift()
    future = []
  }

  const state = customRef((track, trigger) => {
    _trigger = trigger
    return {
      get() { track(); return value },
      set(newVal) {
        pushHistory()
        value = newVal
        trigger()
      }
    }
  })

  // 附加方法
  state.undo = function() {
    if (history.length === 0) return
    isUndoing = true
    future.push(clone(value))
    value = history.pop()
    isUndoing = false
    _trigger()
  }

  state.redo = function() {
    if (future.length === 0) return
    isUndoing = true
    history.push(clone(value))
    value = future.pop()
    isUndoing = false
    _trigger()
  }

  state.canUndo = () => history.length > 0
  state.canRedo = () => future.length > 0

  return state
}
```

### 使用示例

```vue
<script setup>
import { useHistoryRef } from './composables/useHistoryRef'

const text = useHistoryRef('Hello', 100)
</script>

<template>
  <div>
    <textarea v-model="text" rows="5" cols="50"></textarea>
    <div class="toolbar">
      <button @click="text.undo()" :disabled="!text.canUndo()">撤销（Ctrl+Z）</button>
      <button @click="text.redo()" :disabled="!text.canRedo()">重做（Ctrl+Y）</button>
    </div>
  </div>
</template>

<style scoped>
.toolbar { margin-top: 8px; display: flex; gap: 8px; }
button:disabled { opacity: 0.4; cursor: not-allowed; }
</style>
```

## 🔬 六、customRef 的本质

回到 5.3 节 `RefImpl` 的简化版。`customRef` 让你直接注入自定义的 `get` / `set` 逻辑，替代默认的 `track()` 和 `trigger()` 位置。

```text
          读 .value
              │
              ▼
    ┌─────────────────┐
    │  get()           │
    │  track() ← 你控制 │    ← customRef 插手的地方
    │  return value    │
    └─────────────────┘

          写 .value = X
              │
              ▼
    ┌─────────────────┐
    │  set(newVal)     │
    │  你的自定义逻辑... │   ← customRef 主要战场
    │  trigger() ← 你控制│
    └─────────────────┘
```

## ⚠️ 七、常见陷阱

### 陷阱 1：get 里忘了 track

```js
get() {
  return value   // ❌ 忘了 track() → 视图永远不会更新
}
```

### 陷阱 2：track / trigger 多调或少调

```js
set(newVal) {
  value = newVal
  trigger()
  trigger()  // ❌ 调两次没意义，浪费性能
}
```

### 陷阱 3：set 里不调 trigger 却期望视图更新

```js
set(newVal) {
  value = newVal
  // ❌ 没调 trigger → 视图不会更新
}
```

### 陷阱 4：track 和 trigger 只能在 customRef 内部使用

```js
// ❌ 不能从 vue 直接 import track / trigger
import { track, trigger } from 'vue'  // 不存在！
```

## 🧠 本节小结

- **customRef 是什么**：让你自定义 ref 的 get/set 行为，接管 `track`（收集依赖）和 `trigger`（触发更新）时机
- **基本结构**：`customRef((track, trigger) => ({ get() {...}, set(v) {...} }))`，get 里必须 track、set 里改完值记得 trigger
- **防抖实现**：set 里用 setTimeout 延迟 trigger，实现"停止输入一段时间后才更新"
- **适用场景**：防抖/节流、数据持久化与埋点同步、历史记录与脏检测
- **注意**：`track`/`trigger` 不能直接 import，只能在 customRef 工厂参数里使用
