## 🧠 思维导图

```text

├── 对象更新
│   ├── ✅ 直接改属性：obj.key = val
│   ├── ✅ Object.assign(obj, newData)
│   ├── ✅ 展开赋值：obj.key = { ...obj.key, newProp }
│   └── ❌ 整体替换：obj = newObj（reactive 大忌）
├── 数组更新（Vue 3 全部能触发！）
│   ├── ✅ push/pop/shift/unshift/splice

├── 新增/删除属性

│   ├── 但 delete obj.key 也是响应式的
│   └── ✅ 与 Vue 2 不同，不用 $set / $delete
├── shallowReactive 轻量用法
│   ├── 只代理第一层属性

│   └── 适合同 shallowRef 的大型配置对象（详见 3.4、3.10）
└── 快速参考卡
    ├── reactive 数组：arr[i] = x ✅ / arr.length = n ✅
    ├── ✅ 更易读的替代：按 id 定位时用 splice(i, 1, x)
    └── ⚠️ 唯一要记的：filter/map 必须赋值回去
```

基础类型用 `ref` 换个 `.value` 就完事，可一上对象和数组，"改了没反应"就冒出来。最常见的一个是：`filter` 换新数组，页面还是旧的。这一节的结论可能和你在别处看到的不一样——**在 Vue 3 里，数组几乎"想怎么改就怎么改"，真正要当心的只有"返回值没赋回去"这一件事。**

---

## 🤔 一、为什么"正确姿势"是个问题？

在 Vue 2 里，对象和数组的响应式有很多坑——`arr[i] = x` 不触发更新、`obj.newKey = val` 不触发更新——这些坑源于 Vue 2 用 `Object.defineProperty` 做响应式，**它无法拦截数组索引和 `length`**。

Vue 3 换成了 `Proxy`。官方迁移指南里有一句话很关键：

> 全局函数 `set`、`delete` 和实例方法 `$set`、`$delete` **已被移除**——基于 Proxy 的变更检测**不再需要它们**。

这意味着：**你在 Vue 2 里学到的那些"数组不能直接改索引"的规矩，在 Vue 3 里已经全部作废。** 本节会告诉你哪些真的要做、哪些不用做了。

## 💡 二、对象更新的正确姿势

### 2.1 直接改属性 → 没问题

```js
const state = reactive({ user: { name: '张三', age: 20 } })

// ✅ Vue 3 的 Proxy 能拦截嵌套属性的修改
state.user.name = '李四'
state.user.age = 21
```

### 2.2 添加新属性 → 也没问题

```js
const state = reactive({ name: '张三' })

// ✅ Vue 3 的 Proxy 能拦截属性新增
state.age = 20
state.email = 'zhangsan@test.com'
```

这是 Vue 3 相比 Vue 2 最大的改进之一。Vue 2 需要 `Vue.set(obj, 'newKey', value)`，Vue 3 不需要。

### 2.3 删除属性 → 没问题

```js
// ✅ delete 也能被 Proxy 拦截
delete state.age
```

### 2.4 整体替换 → 有问题

```js
let state = reactive({ count: 0 })

// ❌ 断开了响应式引用
state = reactive({ count: 1 })

// ✅ 正确做法：
Object.assign(state, { count: 1, name: 'new' })
```

> 🎯 **类比一下：往展示柜补货 vs 整个换柜**
>
> 把 `reactive` 对象想象成一个**带监控摄像头的展示柜**。`Object.assign(obj, newData)` 是"往柜子里补货"，监控全程拍得到，页面乖乖刷新；而 `state = reactive({ count: 1 })` 是"把整个柜子连人带柜换成新柜子"——监控盯着的还是旧柜子，新柜子换了也白换。数组也同理：`arr[i] = x` 像"趁监控死角偷偷塞东西"，Vue 看不见；`splice` 才是走正规登记流程的搬运工。

---

> 📦 **ES6 小灶：展开运算符 `...`**
>
> 一句话：**展开 = 把盒子拆开，把里面的东西一件件摆出来**；想"复制一份再改"，靠的就是它。
>
>     const arr = [1, 2, 3]
>     const copy = [...arr]          // 复制出一份新数组
>     const obj = { a: 1 }
>     const obj2 = { ...obj, b: 2 }  // 复制旧属性，再补一个新属性
>
> ⚠️ 翻车例：`const copy = arr` 不是复制，是给同一个数组起了两个名字，改 `copy` 等于改 `arr`。
>
>     const copy = arr
>     copy.push(4)   // arr 也变成 [1, 2, 3, 4] 了
>
> 人话翻译：`[...arr]` 就是"**照着原样重新包一份**"。下面 `list.splice(0, list.length, ...filtered)` 把筛选结果灌回原数组，正是把新数组拆开、一件件摆进去；这也是后面"不可变原则"那节的语法地基。

## 🛠 三、数组更新的正确姿势

### 3.1 Vue 能拦截的数组方法

这些方法修改数组后**会自动触发更新**：

| 方法 | 作用 |
|---|---|
| `push()` | 末尾添加 |
| `pop()` | 末尾删除 |
| `shift()` | 开头删除 |
| `unshift()` | 开头添加 |
| `splice()` | 删除/插入/替换 |
| `sort()` | 排序 |
| `reverse()` | 反转 |

```js
const list = reactive([1, 2, 3])

list.push(4)           // ✅ [1, 2, 3, 4]
list.splice(1, 1, 99)  // ✅ [1, 99, 3, 4]
list.sort((a, b) => b - a)  // ✅ 触发更新
```

### 3.2 通过索引赋值 —— ✅ 可以，Vue 3 能拦住

```js
const list = reactive([1, 2, 3])

list[0] = 999      // ✅ [999, 2, 3]，会触发更新
```

Vue 2 时代这条是禁止的（`Object.defineProperty` 拦不住数组索引），但 Vue 3 的 `Proxy` 是**代理整个对象**的，索引属性和 `length` 都会走 `set` 拦截并触发更新。**Vue 3 里这条规矩已经作废。**

那什么时候还推荐用 `splice`？**当你需要"按位置定位"而不是"按下标赋值"时**——比如按 id 找位置再替换：

```js
const list = reactive([{ id: 1, n: 'a' }, { id: 2, n: 'b' }])
const idx = list.findIndex(item => item.id === 2)

list.splice(idx, 1, { id: 2, n: 'B' })   // ✅ 更易读，且只改一项
```

> 💬 **老师备注**：如果你在网上看到"`reactive` 数组不能直接改索引"——那是 Vue 2 的老文章。判断一条结论新不新有个小技巧：**看它有没有提 `$set`**。凡是需要 `$set` 才成立的规矩，在 Vue 3 里都不成立了（`$set` 已被移除）。

### 3.3 用 length 截断 —— ✅ 也可以

```js
const list = reactive([1, 2, 3, 4, 5])

list.length = 2       // ✅ [1, 2]，会触发更新
```

同理。不过要留意：`list.length = 0` 是**清空数组**，如果你只是想"删掉后面几项"，`splice(2)` 语义更直白。

### 3.4 ⚠️ 真正的坑：filter/map 的返回值必须赋回

这是数组操作里**唯一真正需要记住**的规则。

```js
const list = reactive([1, 2, 3])

// ❌ 返回的是新数组，没赋值给原变量 —— list 还是 [1, 2, 3]
list.filter(n => n > 1)

// ✅ 赋回去
list = list.filter(n => n > 1)      // ⚠️ reactive 大忌！见下方

// ✅ reactive 数组的正确做法：先取出原数组，算完再 splice 写回
const filtered = list.filter(n => n > 1)
list.splice(0, list.length, ...filtered)
```

> 💬 **老师备注**：为什么 `filter` 要特别小心？因为 `filter` / `map` / `concat` / `slice` 这些方法**不修改原数组**，它们只是"算出一个新数组给你"。你得自己决定这个新数组往哪放——**忘了放，就等于没改**。而 `push` / `splice` / `sort` 这些叫"变异方法"，它们直接改原数组，所以不用操心。

## 🔧 四、ref 数组 vs reactive 数组

两种写法都能正常更新，区别只在**怎么访问**：

```js
// 用 reactive：直接访问
const list1 = reactive([1, 2, 3])
list1[0] = 999        // ✅

// 用 ref：多一层 .value
const list2 = ref([1, 2, 3])
list2.value[0] = 999  // ✅ （模板里写 list2[0]，.value 自动解包）
```

**两者的响应式机制其实是一样的**：`ref` 内部会对传入的对象套一层 `reactive`，所以 `list2.value` 和 `list1` 行为完全一致。团队里两种风格都有，不用纠结，项目里跟着现有代码走即可。

>💬 **老师备注**：真正要注意的是**别混用**——`ref` 定义就用 `.value` 访问，`reactive` 定义就直接访问。混着写（比如 `ref` 定义却在脚本里漏写 `.value`）是 3.12 那道实操题的考点。

---

> 🧊 **冷知识：那七个"变异方法"的名单，是 Vue 2 的遗产**
>
> `push / pop / shift / unshift / splice / sort / reverse` 这七个名字不是随手列的。Vue 2 时代 `Object.defineProperty` 拦不住数组索引和 `length`，Vue 只好在数组原型上包一层，专门重写这七个"会改动原数组"的方法——**只有它们能通知视图**。
> Vue 3 换成 `Proxy` 后，已经不需要这份名单了：任意索引赋值、`length` 截断都能触发更新。
> 那为什么官方文档和社区还在推荐这七个？**不是因为别的不能用，而是它们语义最直白**——`splice(1, 1, 99)` 一眼就看出"删一个、插一个"，比 `arr[1] = 99` 更明确意图。**能用 ≠ 要用**，这里选的是"可读性"。

## 💡 五、shallowReactive：轻量级响应式

`shallowReactive` 和 `shallowRef` 是一对——它只代理对象的第一层属性。

```js
import { shallowReactive } from 'vue'

const state = shallowReactive({
  count: 0,                 // ✅ 响应式（第一层）
  user: { name: '张三' },   // ❌ user 内部不是响应式
  list: [1, 2, 3]           // ❌ list 内部元素不是响应式
})

// ✅ 能触发更新
state.count++
state.user = { name: '李四' }

// ❌ 不触发更新
state.user.name = '李四'
state.list.push(4)
```

**适用场景**：

| 场景 | 推荐 |
|---|---|
| 大型配置对象，只关心顶层字段替换 | `shallowReactive` |
| 表单对象，字段都是基本类型 | `reactive`（深层不用白不用） |
| 第三方库返回的大对象 | `shallowReactive` |
| 不可变数据管理 | `shallowReactive` + `markRaw` |

```js
// 典型场景：应用配置
const config = shallowReactive({
  theme: 'light',
  lang: 'zh-CN',
  sidebarCollapsed: false,
  // 只改这些顶层字段，不需要深层响应式
})
```

## ⚠️ 六、常见陷阱汇总

> 🎬 **小剧场：小新的"静默失效"**
>
> **小新**：`list[0] = 999`，按下保存，等页面刷新……
> （三秒后）**小新**：怎么一点没动？！
> **报错君**：因为你这条命令 Vue 收不到通知。它只认那几个"变异方法"——`push`、`splice` 之类；你直接按索引塞值，它当没发生。
> **小新**：那 `list.length = 0` 清空呢？
> **报错君**：一样静默失效，连个报错都不给。换成 `list.splice(0)` 才有人听得见。
> **小新**：所以"改了没反应"不等于我写错了……
> **报错君**：对，它不报错，它只是安安静静地把你误导。

| 操作 | reactive | ref |
|---|---|---|
| 对象属性赋值 | ✅ `obj.key = val` | ✅ `obj.value.key = val` |
| 对象整体替换 | ❌ | ✅ `obj.value = newObj` |
| 数组索引赋值 | ❌ `arr[i] = x` | ✅ `arr.value[i] = x` |
| 数组 push/pop 等 | ✅ | ✅ |
| `arr.length = 0` | ❌ | ✅（通过 ref setter） |
| filter/map/concat | ❌（需赋值回去） | ✅（赋值 `.value`） |
| 新增属性 | ✅ | ✅ |
| 删除属性 | ✅ | ✅ |

## 🧠 本节小结

- **Vue 3 已填平的坑**：Proxy 让 `obj.newKey = val` 新增属性默认可响应（Vue 2 不行）；新增/删除对象属性用 `Object.assign` 或 `delete` 都更稳妥
- **reactive 数组别按索引赋值**：`arr[i] = x` 不可靠，统一用 `splice` 替代（`list.splice(i, 1, x)`）
- **ref 数组更新**：`arr.value[i] = x`、`arr.value.push(...)` 都可以；整体换 `.value` 也行
- **length 截断/整体替换**：`arr.length = n` → 用 `splice(n)`；`arr = filtered` → `splice(0, arr.length, ...filtered)`
- **快速参考**：能用方法改原数组就优先 `push/pop/shift/unshift/splice/sort/reverse`，别动不动换新引用
