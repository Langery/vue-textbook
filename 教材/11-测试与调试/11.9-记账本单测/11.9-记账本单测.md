### Step 2：把"算钱"抽成纯函数（回顾 12.1 的可测试设计）

新建 `src/lib/ledger.js`，把记账本里所有计算逻辑搬进去，做成不依赖 Vue 的纯函数：

```js
// src/lib/ledger.js
export function totalIncome(records) { /* 累加 direction === 'income' 的 amount */ }
export function totalExpense(records) { /* 累加 direction === 'expense' 的 amount */ }
export function balance(records) { return totalIncome(records) - totalExpense(records) }
```

> 锚点检查：组件里不再直接手算汇总，而是 `computed(() => balance(records.value))`——改一个函数，全项目（包括测试）同步生效。

### Step 3：写纯函数单测（回顾 12.4）

新建 `src/lib/ledger.test.js`，用 `describe / test / expect` 覆盖关键路径：

```js
import { describe, test, expect } from 'vitest'
import { totalIncome, totalExpense, balance } from './ledger'

describe('ledger 汇总逻辑', () => {
  test('空列表收支结余都为 0', () => { ... })
  test('只有收入时 totalIncome 正确、balance 等于收入', () => { ... })
  test('删除一条支出后 balance 随之变化', () => { ... })
})
```

锚点检查：刻意先写一个"错误期望"（比如期望 0）跑一次，确认测试真的会红；改回正确期望后全绿——先见红再见绿，才是有效测试。

### Step 4：组件测试（回顾 12.3）

新建 `src/App.test.js`（或组件同名测试）：用 `mount` 挂载记账组件，断言初始渲染出汇总卡片与空列表提示；找到输入框 `setValue('卖旧书')`、金额 `setValue('15')`、选方向后点击"记账"按钮，断言列表里新增了这一行、汇总数字更新。注意用 `nextTick` / `await` 等待 DOM 更新（12.3 教的异步断言姿势）。

### Step 5：埋 Bug → DevTools 揪出来（回顾 12.5 / 12.6）

在 `ledger.js` 里**故意**把 `totalExpense` 写成也累加 income（模拟"统计逻辑写反"），跑测试看它挂在哪几个用例；再开 `npm run dev`，用 Vue DevTools 的 Components 面板观察"支出合计"的 computed 值来源，结合 12.6 的排查思路找到根因、修复、重跑测试全绿。这一步请向同学演示：**测试如何先于肉眼发现问题**。
