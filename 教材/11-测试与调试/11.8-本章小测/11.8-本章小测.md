## 📊 参考答案

### 选择题

| 题号 | 答案 | 解析 |
|------|------|------|
| 1 | **C** | 单元测试是金字塔基石，数量最多、速度最快、成本最低。A 错在"真实"；B 错在 E2E 最慢；D 错在单元测试应占 60%~70%。 |
| 2 | **B** | Vue 的 DOM 更新是异步的，trigger 后必须 await 等更新完成。 |
| 3 | **B** | `return false` 阻止错误继续向上冒泡。 |
| 4 | **C** | `console.table()` 将数组或对象以表格形式输出，直观易读。 |

### 填空题

| 题号 | 答案 | 解析 |
|------|------|------|
| 5 | `vitest` `@vue/test-utils` | 三个包各司其职，**一个都不能少**：`vitest` 是测试运行器（提供 `describe` / `test` / `expect` / `vi` 等 API）；`@vue/test-utils` 是 Vue 官方的组件测试工具（提供 `mount` / `shallowMount` / `wrapper`）；`happy-dom` 是模拟的浏览器 DOM 环境——测试跑在 Node 里，而 Node **没有 `document`**，不装它 `mount` 起来就报错。<br>⚠️ 完整命令是 `npm install -D vitest @vue/test-utils happy-dom`，`-D` 表示装成**开发依赖**（测试代码不进生产包）。`happy-dom` 换成 `jsdom` 也行，二选一即可 |
| 6 | emit 可以带多个参数，所以每次事件参数都包在数组里 | `wrapper.emitted('update')` 返回的是"**该事件被触发了多少次**"的二维数组——外层每一项代表一次触发，内层那项才是**这次触发时传入的参数**。<br>所以第 1 次触发的参数要写 `emitted('update')[0][0]`（第 0 次触发、第 0 个参数）。<br>⚠️ **这正是第 15 题要考的坑**：断言时容易漏写一层下标，把 `[1]` 当成答案直接去比 `toBe(1)`，结果永远失败 |
| 7 | `value` | 在 `<script setup>` 里，`ref` 创建的变量**在脚本中**必须用 `.value` 读写：`count.value++`。<br>⚠️ **关键区分——同一个 `ref` 在两个地方写法不同**：<br>**模板里**写 `{{ count }}` 即可，**不用**加 `.value`——编译器会自动帮你解包（unref）；<br>**JS 逻辑里**必须写 `count.value`——这里没有编译器介入，写 `count++` 改的是 ref 对象本身，那个操作既不会改到真正的值，视图也不会更新。<br>这一条在测试里同样容易踩：`<script setup>` 里定义的 `ref` 暴露到 `wrapper.vm` 上时**拿到的仍是 ref 对象**，判断值得写 `wrapper.vm.count.value`；更稳妥的做法是直接断言渲染结果（`wrapper.text()`），既不用管 ref 有没有解包，也不怕绑定改动后测试挂掉 |
| 8 | `errorHandler` | `app.config.errorHandler` 是挂在**应用实例**上的兜底错误处理器，用来捕获所有**没有被组件级 `onErrorCaptured` 处理掉**的错误。<br>📌 **两级边界的分工**：`onErrorCaptured` 属于单个组件、可以 `return false` 就地拦截（常配合降级 UI，第 14 题考的就是它）；`errorHandler` 是全局兜底、拦到这里说明已经没人处理了，通常用来**打日志 + 上报监控**。<br>⚠️ 它**不会阻止** Vue 打印到控制台的错误——想静默控制台输出需要额外处理，但线上排查问题恰恰要保留这个输出，所以通常不动它 |

### 判断题

| 题号 | 答案 | 解析 |
|------|------|------|
| 9 | **×** | shallowMount 只渲染一层，子组件用占位符替代，适合单元测试。 |
| 10 | **×** | vi.mock() 必须放在文件最顶层，Vitest 会自动"提升"执行顺序。 |
| 11 | **×** | computed 应该是纯函数，副作用（异步请求等）应放在 watch 或方法中。 |
| 12 | **×** | 空函数虽然用户看不到报错，但开发者也看不到——线上出 bug 完全不知道。应该静默用户侧 + 上报开发侧。 |

### 简答题

**13.** 参考答案：

`data-test` 属性是专门为测试设计的标记，与样式和结构解耦。用 `class` 或标签名查找元素的问题是：改样式（比如 `class="btn"` 改成 `class="button"`）或改结构（比如 `<button>` 换成 `<a>`）会导致测试挂掉，即使功能完全没变。`data-test` 属性的命名约定明确表达了"这是给测试用的"，团队成员不会因为改样式而误改它。

**14.** 参考答案：

在设置页面中，用自定义的 `ErrorBoundary` 组件包裹"修改头像"模块。`ErrorBoundary` 内部使用 `onErrorCaptured` 钩子捕获子组件抛出的错误并 `return false` 阻止向上传播。当图片裁剪库崩溃时，`ErrorBoundary` 显示降级 UI（如"头像编辑功能暂时不可用，请稍后重试"），但设置页面的其他功能（修改昵称、修改密码等）不受影响，正常可用。

### 编程题

**15.** 参考答案：

```vue
<!-- TodoItem.vue -->
<script setup>
defineProps({
  text: { type: String, required: true },
  done: { type: Boolean, default: false }
})
const emit = defineEmits(['toggle', 'delete'])
</script>

<template>
  <div class="todo-item">
    <span
      data-test="text"
      :class="{ done }"
      @click="emit('toggle')"
    >
      {{ text }}
    </span>
    <button data-test="delete-btn" @click="emit('delete')">删除</button>
  </div>
</template>

<style scoped>
.done { text-decoration: line-through; color: #999; }
</style>
```

```js
// __tests__/TodoItem.test.js
import { mount } from '@vue/test-utils'
import TodoItem from '../TodoItem.vue'

describe('TodoItem', () => {
  test('渲染 text', () => {
    const wrapper = mount(TodoItem, {
      props: { text: '学 Vue 3' }
    })
    expect(wrapper.find('[data-test="text"]').text()).toBe('学 Vue 3')
  })

  test('done 默认 false，无 .done 类', () => {
    const wrapper = mount(TodoItem, {
      props: { text: '学 Vue 3' }
    })
    expect(wrapper.find('[data-test="text"]').classes()).not.toContain('done')
  })

  test('done 为 true 时有 .done 类', () => {
    const wrapper = mount(TodoItem, {
      props: { text: '学 Vue 3', done: true }
    })
    expect(wrapper.find('[data-test="text"]').classes()).toContain('done')
  })

  test('点击文字触发 toggle', async () => {
    const wrapper = mount(TodoItem, {
      props: { text: '学 Vue 3' }
    })
    await wrapper.find('[data-test="text"]').trigger('click')
    expect(wrapper.emitted('toggle')).toHaveLength(1)
  })

  test('点击删除按钮触发 delete', async () => {
    const wrapper = mount(TodoItem, {
      props: { text: '学 Vue 3' }
    })
    await wrapper.find('[data-test="delete-btn"]').trigger('click')
    expect(wrapper.emitted('delete')).toHaveLength(1)
  })
})
```
