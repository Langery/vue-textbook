## 🤔 一、环境搭建：从零开始

先在一个已有的 Vite + Vue 3 项目中安装测试依赖：

```bash
npm install -D vitest @vue/test-utils happy-dom
```

> 💬 **老师备注**：`happy-dom` 是一个轻量的浏览器 DOM 模拟器。测试在 Node.js 环境跑，没有真实的浏览器，`happy-dom` 负责提供一个假的 DOM 环境让 Vue 组件能"渲染"。

### 配置 vite.config.ts

```ts
// vite.config.ts
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'

export default defineConfig({
  plugins: [vue()],
  test: {
    // 使用 happy-dom 模拟浏览器环境
    environment: 'happy-dom',
    // 全局引入 describe / it / expect（不用每个文件 import）
    globals: true,
  },
})
```

如果你的 TypeScript 报错 `test` 字段不存在，需要从 `vitest/config` 导入 `defineConfig`：

```ts
/// <reference types="vitest" />
import { defineConfig } from 'vitest/config'
import vue from '@vitejs/plugin-vue'

export default defineConfig({
  plugins: [vue()],
  test: {
    environment: 'happy-dom',
    globals: true,
  },
})
```

### 添加 npm 脚本

```json
// package.json
{
  "scripts": {
    "test": "vitest",
    "test:ui": "vitest --ui",
    "test:run": "vitest run"
  }
}
```

- `npm test`：启动 Vitest 的 watch 模式（改了代码自动重跑）
- `npm run test:run`：跑一次就退出（CI/CD 用）
- `npm run test:ui`：打开 Vitest 的图形界面（需要先装 `@vitest/ui`）

## 💡 二、第一个测试：挂载组件

假设你有一个最简单的组件：

```vue
<!-- src/components/Greeting.vue -->
<script setup>
defineProps({
  name: { type: String, default: '同学' }
})
</script>

<template>
  <h1>你好，{{ name }}！</h1>
</template>
```

写它的测试：

```js
// src/components/__tests__/Greeting.test.js
import { mount } from '@vue/test-utils'
import Greeting from '../Greeting.vue'

test('默认显示"你好，同学！"', () => {
  const wrapper = mount(Greeting)
  expect(wrapper.text()).toBe('你好，同学！')
})

test('传入 name 属性后正确渲染', () => {
  const wrapper = mount(Greeting, {
    props: { name: '小明' }
  })
  expect(wrapper.text()).toBe('你好，小明！')
})
```

### 代码解读

- `mount(组件)`：把组件"挂载"到虚拟 DOM 中，返回一个 `wrapper`
- `wrapper`：可以理解成组件的"遥控器"，你可以通过它读取渲染结果、触发事件
- `wrapper.text()`：组件渲染后的纯文本
- `props`：跟模板里用 `:name="xxx"` 效果一样

### mount vs shallowMount

| 方法 | 行为 | 何时用 |
|------|------|--------|
| `mount` | 完整渲染，包含所有子组件 | 集成测试 |
| `shallowMount` | 只渲染一层，子组件用占位符替代 | 单元测试（隔离被测组件） |

```js
import { shallowMount } from '@vue/test-utils'

// 子组件不会被真正渲染，只显示 <child-stub>
const wrapper = shallowMount(ParentComp)
console.log(wrapper.html())
// <div><child-stub></child-stub></div>
```

> 💬 **老师备注**：初学时统一用 `mount` 就行，等你的组件嵌套越来越深、需要隔离测试时再用 `shallowMount`。

## 🔑 三、查找元素：wrapper.find()

`find()` 是 Vue Test Utils 中最常用的 API 之一，用来在渲染结果中查找元素。

### 3.1 基本查找

```js
const wrapper = mount(MyComponent)

// CSS 选择器
wrapper.find('button')            // 找第一个 button
wrapper.find('.submit-btn')       // 找 class 为 submit-btn 的元素
wrapper.find('#email')            // 找 id 为 email 的元素
wrapper.find('input[type="text"]') // 属性选择器

// 找所有匹配
wrapper.findAll('li')             // 返回 WrapperArray，类似数组
wrapper.findAll('li').length      // 获取数量
```

### 3.2 推荐做法：data-test 属性

用 class 或标签名查找有个问题：改样式或结构时测试就挂了。推荐加专门的 `data-test` 属性：

```
<template>
  <button data-test="submit-btn">提交</button>
  <input data-test="email-input" v-model="email" />
</template>
```

```js
// 测试代码
wrapper.find('[data-test="submit-btn"]')
wrapper.find('[data-test="email-input"]')
```

这样 CSS 怎么改都不影响测试。

### 3.3 查找子组件

```js
import ChildComp from './ChildComp.vue'

const wrapper = mount(ParentComp)
wrapper.findComponent(ChildComp)  // 找某个子组件实例
```

### 3.4 判断元素是否存在

```js
wrapper.find('.error-msg').exists()  // true 或 false
```

## 🛠 四、获取组件内容

### 4.1 text() vs html()

```vue
<template>
  <div class="card">
    <h1>标题</h1>
    <p>内容文字</p>
  </div>
</template>
```

```js
const wrapper = mount(Card)

wrapper.text()
// "标题内容文字"  （纯文本，去掉所有标签）

wrapper.html()
// "<div class="card"><h1>标题</h1><p>内容文字</p></div>"  （完整 HTML）
```

### 4.2 访问组件内部数据（vm）

```js
const wrapper = mount(Counter)

// 通过 vm 直接读组件内部的响应式数据
console.log(wrapper.vm.count)        // ref 自动解包
console.log(wrapper.vm.doubleCount)  // computed 自动解包

// 也可以直接调组件的方法
wrapper.vm.reset()
```

> 💬 **老师备注**：`wrapper.vm` 虽然方便，但尽量少用。好的测试应该通过组件的"公共接口"（模板渲染结果、触发的事件）来验证，而不是直接扒组件内部数据。

### 4.3 常用断言速查

```js
// 文本包含
expect(wrapper.text()).toContain('你好')

// 元素存在
expect(wrapper.find('.error').exists()).toBe(true)

// 属性值
expect(wrapper.find('input').attributes('type')).toBe('text')

// class
expect(wrapper.find('button').classes()).toContain('primary')

// 是否可见
expect(wrapper.find('.modal').isVisible()).toBe(true)
```

## ⚠️ 五、常见陷阱

### 陷阱 1：忘记 await 异步操作

Vue 的 DOM 更新是异步的，触发事件后需要 `await`：

```js
// ❌ 错误：没有 await
test('点击后文本更新', () => {
  const wrapper = mount(Counter)
  wrapper.find('button').trigger('click')
  expect(wrapper.text()).toContain('1')  // 可能还是旧值！
})

// ✅ 正确：加 await
test('点击后文本更新', async () => {
  const wrapper = mount(Counter)
  await wrapper.find('button').trigger('click')
  expect(wrapper.text()).toContain('1')
})
```

### 陷阱 2：测试文件路径不对

Vitest 默认查找：
- `**/*.test.js`（或 `.ts`）
- `**/*.spec.js`（或 `.ts`）
- `**/__tests__/**`

推荐把测试文件放在组件同目录下的 `__tests__/` 文件夹中。

### 陷阱 3：全局组件/插件没注册

如果你的组件用了 Pinia、Vue Router 或全局组件，测试时需要手动注入：

```js
import { createPinia } from 'pinia'

const wrapper = mount(MyComponent, {
  global: {
    plugins: [createPinia()]  // 注入 Pinia
  }
})
```

## 🧠 本节小结

- **环境搭建**：`npm i -D vitest @vue/test-utils happy-dom`；`vite.config` 加 `test.environment: 'happy-dom'` + `globals: true`；TypeScript 报错时从 `vitest/config` 导入 `defineConfig`
- **mount vs shallowMount**：完整渲染（集成测试）vs 只渲染一层、子组件变 stub（隔离单元测试）
- **wrapper 是"遥控器"**：`find` / `findAll` 查元素、`text()` / `html()` 取渲染结果、`vm` 访问组件实例（尽量少用，优先验证公共接口）
- **查找推荐 `data-test`**：用 class / 标签名改样式就挂测试，加 `data-test="submit-btn"` 属性更稳；`findComponent` 找子组件、`exists()` 判存在
- **断言速查**：`toContain` 文本、`exists()`、`attributes('type')`、`classes()`、`isVisible()`
- **三大坑**：触发事件后必须 `await`（DOM 异步更新）；测试文件放 `__tests__/` 或用 `.test.js` 后缀；组件依赖 Pinia / Router 时用 `global.plugins` 注入
