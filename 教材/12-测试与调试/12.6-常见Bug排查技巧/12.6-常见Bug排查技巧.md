## 🤔 一、Bug 排查的思路框架

遇到 Bug，不要慌，按这个流程走：

1. **定位**：Bug 发生在哪个文件、哪个函数？
2. **复现**：什么操作能稳定触发这个 Bug？
3. **假设**：可能的原因是什么？
4. **验证**：用调试工具验证假设
5. **修复**：改代码，跑测试，确认修好

最怕的是**盲目改代码**——看见报错就随便改一行，改完不报错了但引入新 Bug。有章法地排查，效率高得多。

## 💡 二、Console 高级用法

大多数同学只会 `console.log(xxx)`，其实 Console 有更强大的姿势。

### 2.1 console.table()：数据一目了然

```js
const users = [
  { id: 1, name: '张三', age: 20 },
  { id: 2, name: '李四', age: 22 },
  { id: 3, name: '王五', age: 19 },
]

console.table(users)
```

控制台会以表格形式展示：

```text
┌─────┬────┬──────┬─────┐
│ idx │ id │ name │ age │
├─────┼────┼──────┼─────┤
│  0  │ 1  │ 张三 │ 20  │
│  1  │ 2  │ 李四 │ 22  │
│  2  │ 3  │ 王五 │ 19  │
└─────┴────┴──────┴─────┘
```

比 `console.log` 密密麻麻的 `[{...}, {...}]` 清楚一百倍。

### 2.2 console.time() / timeEnd()：精确计时

```js
console.time('大列表渲染')
// 渲染 10000 条数据...
console.timeEnd('大列表渲染')
// 输出：大列表渲染: 234.56ms
```

性能排查利器，不用手动 `Date.now()` 相减。

### 2.3 console.group()：日志分组

```js
console.group('用户信息')
console.log('姓名：张三')
console.log('年龄：20')
console.groupEnd()
```

复杂逻辑调试时，把相关日志折叠成分组，控制台不会乱成一锅粥。

### 2.4 console.trace()：调用栈追踪

```js
function c() {
  console.trace('谁调了我？')
}
function b() { c() }
function a() { b() }
a()

// 输出：
// 谁调了我？
//   at c (app.js:2)
//   at b (app.js:5)
//   at a (app.js:6)
```

当你不知道某个函数是被谁调用的，`console.trace()` 直接告诉你完整调用链。

### 2.5 console.assert()：条件断言

```js
console.assert(user.age >= 0, '年龄不能为负！', user)
// 只有 age < 0 时才打印，正常情况不显示
```

相当于"如果条件为假，就打印警告"，不会污染正常流程的日志。

## 🔑 三、断点调试

有时 `console.log` 不够用——你想在某个时刻"冻结"代码执行，一步步看变量怎么变化的。

### 3.1 代码中断点：debugger

最简单粗暴的方法：在代码里写一行 `debugger`：

```vue
<script setup>
function handleSubmit() {
  const formData = { name: '', email: '' }
  debugger  // ← 代码跑到这里会自动暂停
  validateForm(formData)
}
</script>
```

刷新页面，触发 `handleSubmit`，浏览器自动停在 `debugger` 这行。你可以：

- 鼠标悬停在变量上，看当前值
- 按 F10：单步执行（Step Over），一行一行往下走
- 按 F11：进入函数内部（Step Into）
- 按 F8：继续执行到下一个断点

> 💬 **老师备注**：调试完记得删掉 `debugger`！提交代码前全局搜一下，别把断点带上线。

### 3.2 浏览器 Sources 面板断点

不用改代码，直接在浏览器里打断点：

1. F12 → **Sources** 面板
2. 左侧文件树找到你的 `.vue` 文件
3. 点击行号打上蓝色断点标记
4. 刷新页面，代码执行到那行自动暂停

Sources 面板还支持**条件断点**：右键行号 → "Add conditional breakpoint" → 输入条件如 `count > 10`。只有满足条件时才暂停，非常适合在循环中调试。

### 3.3 Watch：监控变量

Sources 面板右侧的 Watch 区域，你可以添加表达式：

```js
user.name
cartItems.length
```

这些表达式会在每次断点暂停时重新计算并显示当前值，帮你持续追踪关键变量。

## 🛠 四、Network 面板排查 API 问题

前端开发 80% 的 Bug 跟接口有关："数据怎么没出来？"

F12 → **Network** 面板，刷新页面后你会看到所有网络请求。

### 4.1 三秒定位法

找到你怀疑有问题的请求，看三样东西：

| 看什么 | 在哪看 | 问题 |
|--------|--------|------|
| **状态码** | Status 列 | 200=正常，404=找不到，500=服务器炸了 |
| **请求参数** | Payload 标签 | 参数名对不对？值对不对？ |
| **响应数据** | Response 标签 | 数据格式是你期望的吗？字段名对不对？ |

### 4.2 常见状态码

```text
200  → 一切正常
301/302 → 重定向了
400  → 请求参数有误（前端的问题）
401  → 没登录或 token 过期
403  → 没权限
404  → 接口地址写错了
500  → 服务器内部错误（后端的问题）
CORS error → 跨域问题（找后端加 CORS 头，或 Vite 配代理）
```

### 4.3 Vite 代理解决跨域

```ts
// vite.config.ts
export default defineConfig({
  server: {
    proxy: {
      '/api': {
        target: 'http://localhost:3000',  // 后端地址
        changeOrigin: true,
      }
    }
  }
})
```

配好后，前端请求 `/api/users`，Vite 自动代理到 `http://localhost:3000/api/users`，不跨域。

## ⚠️ 五、Vue 高频 Bug 速查

### Bug 1：「xxx is not defined」

```js
// ❌ 忘了 import
const count = ref(0)  // ReferenceError: ref is not defined

// ✅ import
import { ref } from 'vue'
```

### Bug 2：ref 忘加 .value

```js
const count = ref(0)
count++           // ❌ 无效！count 是对象而不是数值
count.value++     // ✅
```

> 💬 **老师备注**：模板里自动解包不用 `.value`，但 `<script>` 里必须加。这是新手最高频的 Bug，没有之一。

### Bug 3：v-if 和 v-for 同时用

```
<!-- ❌ v-if 和 v-for 在同级，v-if 先执行，拿不到 item -->
<li v-for="item in list" v-if="item.active">{{ item.name }}</li>

<!-- ✅ 用 computed 过滤 -->
<li v-for="item in activeList">{{ item.name }}</li>
```

### Bug 4：响应式丢失

```js
const state = reactive({ count: 0 })
const { count } = state  // ❌ count 现在是普通数字，不再响应式
count++                   // 不会触发视图更新

// ✅ 用 toRefs
const { count } = toRefs(state)
```

### Bug 5：直接修改 Props

```vue
<script setup>
const props = defineProps({ count: Number })
props.count++  // ❌ 警告：props 是只读的
</script>
```

### Bug 6：watch 没加 { immediate: true }

```js
// ❌ 页面首次渲染时 watch 不执行
watch(dataSource, (val) => { fetchData(val) })

// ✅ 首次渲染也执行
watch(dataSource, (val) => { fetchData(val) }, { immediate: true })
```

### Bug 7：异步数据还没到就渲染

```
<!-- ❌ data 为 null 时 data.name 报错 -->
<p>{{ data.name }}</p>

<!-- ✅ 加 v-if 守卫 -->
<p v-if="data">{{ data.name }}</p>
<!-- 或用可选链 -->
<p>{{ data?.name }}</p>
```

### Bug 8：组件名大小写问题

```vue
<script setup>
import MyComponent from './MyComponent.vue'
</script>

<template>
  <MyComponent />   <!-- ✅ PascalCase -->
  <my-component />  <!-- ✅ kebab-case 也行 -->
</template>
```

### Bug 9：onMounted 里获取 DOM 失败

```
<script setup>
import { ref } from 'vue'

const divRef = ref(null)
console.log(divRef.value)  // ❌ null！setup 阶段 DOM 还没渲染

import { onMounted } from 'vue'
onMounted(() => {
  console.log(divRef.value)  // ✅ 拿到真实 DOM
})
</script>
```

### Bug 10：computed 里写副作用

```js
// ❌ computed 是纯函数，不应该做副作用
const total = computed(() => {
  fetch('/api/report')     // 副作用！
  localStorage.set('total', sum)  // 副作用！
  return price.value * count.value
})
```

## 🧠 本节小结

- **排查五步法**：定位 → 复现 → 假设 → 验证 → 修复；最忌看见报错就盲改，改好旧错引入新坑
- **Console 进阶**：`table()` 表格化数据、`time/timeEnd()` 精确计时、`group()` 折叠日志、`trace()` 打印调用栈、`assert()` 条件打印——按场景选对姿势
- **断点调试**：`debugger` 代码暂停 + Sources 面板行号断点，F10/F11/F8 单步走；条件断点（`count > 10`）专治循环；Watch 面板持续追踪关键表达式；上线前记得删 `debugger`
- **Network 三秒定位**：看状态码（404 地址错、401/403 权限、500 后端问题、CORS 跨域）、看 Payload 参数、看 Response 数据格式；跨域用 Vite proxy 代理
- **Bug 1-3**：忘 import、ref 忘 `.value`（script 内必加）、`v-if`/`v-for` 同级（用 computed 过滤）
- **Bug 4-6**：解构 reactive 丢响应性（用 `toRefs`）、直接改 props（只读）、watch 首轮不触发（补 `{ immediate: true }`）
- **Bug 7-10**：异步数据加 `v-if`/可选链守卫、组件名大小写与文件一致、`onMounted` 里才拿 DOM、computed 保持纯函数别写副作用
