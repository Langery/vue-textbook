
10.8 把注册表单的 `<script setup>` 逻辑写得差不多了——`values`、`errors`、异步查重、提交都在。可光有逻辑页面还是空壳，用户真正看到、点到的全是 `<template>` 里的东西。这节干两件事：一是把模板补齐——字段绑定、校验图标、密码可见切换、提交按钮全对上号；二是把这些逻辑抽成 `useRegister` composable，让组件只剩 UI，以后换表单、加校验都不用动模板结构。

> 🎯 **类比一下：逻辑抽离成 composable ≈ 把"后厨"和"前台"分开**
> 8 节的模板像前台（用户看到的一切），script 像后厨（逻辑）。一开始后厨忙乱：验菜、记账、传菜都堆在一起。抽成 `useRegister` 相当于**开一个独立中央厨房**：所有逻辑（values/errors/onSubmit）都在后厨完成，前台只负责"上菜"（渲染）。以后换菜谱（换表单）不动前台，加新菜（加字段）也只改后厨。

> 🧑 **小白**：逻辑抽离听起来高大上，实际好处是啥？
> 🤖 **Vue 君**：①组件模板变干净，只留 UI；②逻辑可复用（别的页面也能用）；③可测试（composable 脱离组件单独测）。项目一大，这个习惯直接决定代码能活多久。
> 👨🏫 **老湿**：**组合式函数（composable）是 Vue 3 的"模块化答案"**。面试聊"逻辑复用"，能说出 composable 与 mixin 的区别（数据来源清晰、无命名冲突），比背 API 更有说服力。

## 🛠 一、模板部分（RegisterForm.vue）

上一节的 `<script setup>` 管逻辑，这一节的 `<template>` 管界面。两者通过 `values`、`errors`、`submitting` 等变量对接：

```vue
<!-- views/RegisterForm.vue（模板部分） -->
<template>
  <div class="register-page">
    <h2>用户注册</h2>

    <!-- 成功提示 -->
    <div v-if="submitSuccess" class="success-banner">
      ✅ 注册成功！即将跳转到登录页...
    </div>

    <form @submit="onSubmit" class="register-form">
      <!-- ===== 用户名 ===== -->
      <div class="field">
        <label>用户名</label>
        <div class="input-wrapper">
          <input
            v-model="values.username"
            name="username"
            placeholder="至少 3 个字符"
            class="input"
          />
          <!-- 异步校验状态图标 -->
          <span v-if="checkingUsername" class="icon">⏳</span>
          <span v-else-if="usernameAvailable === true" class="icon ok">✅</span>
          <span v-else-if="usernameAvailable === false" class="icon fail">❌</span>
        </div>
        <span v-if="errors.username" class="error">{{ errors.username }}</span>
        <span
          v-else-if="usernameAvailable === false"
          class="error"
        >该用户名已被注册</span>
      </div>

      <!-- ===== 手机号 ===== -->
      <div class="field">
        <label>手机号</label>
        <div class="input-wrapper">
          <input
            v-model="values.phone"
            name="phone"
            placeholder="11 位手机号"
            class="input"
          />
          <span v-if="checkingPhone" class="icon">⏳</span>
          <span v-else-if="phoneAvailable === true" class="icon ok">✅</span>
          <span v-else-if="phoneAvailable === false" class="icon fail">❌</span>
        </div>
        <span v-if="errors.phone" class="error">{{ errors.phone }}</span>
        <span
          v-else-if="phoneAvailable === false"
          class="error"
        >该手机号已被注册</span>
      </div>

      <!-- ===== 邮箱 ===== -->
      <div class="field">
        <label>邮箱</label>
        <input
          v-model="values.email"
          name="email"
          placeholder="example@mail.com"
          class="input"
        />
        <span v-if="errors.email" class="error">{{ errors.email }}</span>
      </div>

      <!-- ===== 密码 ===== -->
      <div class="field">
        <label>密码</label>
        <div class="input-wrapper">
          <input
            v-model="values.password"
            name="password"
            :type="showPassword ? 'text' : 'password'"
            placeholder="至少 8 位，含数字和字母"
            class="input"
          />
          <button
            type="button"
            class="toggle-pwd"
            @click="showPassword = !showPassword"
          >
            {{ showPassword ? '🙈' : '👁' }}
          </button>
        </div>
        <!-- 密码强度 -->
        <PasswordStrength :password="values.password" />
        <span v-if="errors.password" class="error">{{ errors.password }}</span>
      </div>

      <!-- ===== 确认密码 ===== -->
      <div class="field">
        <label>确认密码</label>
        <input
          v-model="values.confirmPassword"
          name="confirmPassword"
          type="password"
          placeholder="再次输入密码"
          class="input"
        />
        <span v-if="errors.confirmPassword" class="error">{{ errors.confirmPassword }}</span>
      </div>

      <!-- ===== 同意协议 ===== -->
      <div class="field-checkbox">
        <label class="checkbox-label">
          <input type="checkbox" v-model="agreed" />
          我已阅读并同意 <a href="#">《用户协议》</a> 和 <a href="#">《隐私政策》</a>
        </label>
        <span v-if="errors.agreed" class="error">{{ errors.agreed }}</span>
      </div>

      <!-- ===== 提交按钮 ===== -->
      <button
        type="submit"
        class="submit-btn"
        :disabled="submitting || !agreed"
      >
        {{ submitting ? '提交中...' : '注册' }}
      </button>
    </form>
  </div>
</template>
```

> 💬 **老师备注**：注意用户名/手机号字段的"三态图标"——`⏳` 校验中、`✅` 可用、`❌` 不可用，这是异步校验 UI 的标准做法。

## 💡 三、为什么密码强度组件单独抽出来？

回顾 10.7 节的 `PasswordStrength.vue`，它被主表单引用：

- **单一职责**：它只负责"展示"，不关心密码是怎么来的
- **可复用**：以后登录页、修改密码页都能用
- **可测试**：独立组件更容易写单元测试

这就是"组件拆分"的意义——把重复出现、职责单一的 UI 片段独立成组件。

## 🛠 四、进阶：抽成 Composable

上面的代码已经可以运行了，但 `RegisterForm.vue` 的 `<script>` 部分太长了。我们可以把注册逻辑抽成一个 composable：

```js
// composables/useRegister.js
import { useForm } from 'vee-validate'
import { ref, watch } from 'vue'
import { useDebounceFn } from '@vueuse/core'
import { checkUsername, checkPhone } from '../utils/validators'

export function useRegister() {
  const { handleSubmit, errors, values, resetForm } = useForm({
    validationSchema: {
      username: { required: true, min: 3 },
      phone: { required: true, phone: true },
      email: { required: true, email: true },
      password: { required: true, passwordStrength: true },
      confirmPassword: { required: true, confirmed: '@password' },
      agreed: { required: true }
    }
  })

  const submitting = ref(false)
  const submitSuccess = ref(false)

  // 异步校验（同上面的逻辑）
  const checkingUsername = ref(false)
  const usernameAvailable = ref(null)
  const checkingPhone = ref(false)
  const phoneAvailable = ref(null)

  const debouncedCheckUsername = useDebounceFn(async () => {
    const name = values.username
    if (!name || name.length < 3) { usernameAvailable.value = null; return }
    checkingUsername.value = true
    usernameAvailable.value = null
    try {
      usernameAvailable.value = await checkUsername(name)
    } catch { usernameAvailable.value = null }
    finally { checkingUsername.value = false }
  }, 500)

  const debouncedCheckPhone = useDebounceFn(async () => {
    const phone = values.phone
    if (!phone || !/^1[3-9]\d{9}$/.test(phone)) { phoneAvailable.value = null; return }
    checkingPhone.value = true
    phoneAvailable.value = null
    try {
      phoneAvailable.value = await checkPhone(phone)
    } catch { phoneAvailable.value = null }
    finally { checkingPhone.value = false }
  }, 500)

  watch(() => values.username, () => { usernameAvailable.value = null; debouncedCheckUsername() })
  watch(() => values.phone, () => { phoneAvailable.value = null; debouncedCheckPhone() })

  // 提交
  const onSubmit = handleSubmit(async (formValues) => {
    if (usernameAvailable.value === false) { alert('用户名已被占用'); return }
    if (phoneAvailable.value === false) { alert('手机号已被注册'); return }
    if (submitting.value) return
    submitting.value = true
    submitSuccess.value = false
    try {
      await new Promise(r => setTimeout(r, 1500))
      console.log('✅ 注册成功：', formValues)
      submitSuccess.value = true
      resetForm()
      setTimeout(() => { submitSuccess.value = false }, 5000)
    } catch (err) {
      alert('注册失败：' + err.message)
    } finally {
      submitting.value = false
    }
  })

  return {
    // 表单
    values, errors, onSubmit, resetForm,
    // 提交状态
    submitting, submitSuccess,
    // 异步校验
    checkingUsername, usernameAvailable,
    checkingPhone, phoneAvailable
  }
}
```

然后在组件里只需要：

```vue
<script setup>
import { ref } from 'vue'
import { useRegister } from '../composables/useRegister'
import PasswordStrength from '../components/PasswordStrength.vue'

const {
  values, errors, onSubmit,
  submitting, submitSuccess,
  checkingUsername, usernameAvailable,
  checkingPhone, phoneAvailable
} = useRegister()

const agreed = ref(false)
const showPassword = ref(false)
</script>
```

组件一下子瘦身了 80%，逻辑清晰、可测试、可复用。

> 💬 **老师备注**：这就是组合式 API 的真正威力。把"注册表单的业务逻辑"完整抽成一个 composable，和 UI 解耦。以后改业务逻辑只改 `useRegister.js`，改 UI 只改 `RegisterForm.vue`，互不影响。

## ⚠️ 五、常见陷阱

### 陷阱 1：`resetForm` 不能重置组件自己的 ref

`resetForm()` 只能重置 `useForm` 内部的值（`values.xxx`），不会重置你手动声明的 `agreed`、`showPassword` 等 ref。这些需要手动重置：

```js
resetForm()
agreed.value = false   // 手动重置
```

### 陷阱 2：抽 composable 时把 UI 状态也带走了

像 `agreed`（是否勾选协议）、`showPassword`（是否显示明文）这种纯 UI 状态，应该留在组件里，不需要进 composable。判断标准：**换一个 UI 就不需要的状态，留在组件；业务规则需要的状态，进 composable**。

## 🧠 本节小结

- **模板 ↔ 逻辑对接**：`<template>` 通过 `values.xxx` 双向绑定、`errors.xxx` 显示错误、`submitting` / `submitSuccess` 控制按钮与横幅，与 `<script setup>` 一一对应
- **异步校验三态 UI**：字段右侧图标 `⏳`（校验中）/ `✅`（可用）/ `❌`（不可用），错误文案与同步错误 `v-else-if` 错开渲染
- **纯 UI 组件拆分**：`PasswordStrength` 等只展示不碰数据的小组件独立成文件，可复用（登录页/改密页）、可测试
- **Composable 抽离**：把 `useForm` 全家桶 + 查重 watch + 提交逻辑收进 `useRegister()`，返回 `values / errors / onSubmit / submitting / 校验状态`，组件 script 只留 UI 相关 ref
- **UI 状态留组件**：`agreed`、`showPassword` 这类"换 UI 就不需要"的状态别进 composable——判断标准是业务相关还是展示相关
- **resetForm 的边界**：它只清 `useForm` 内部字段值，`agreed` 等手动 ref 要自己 `agreed.value = false` 手动重置

> 🧊 **冷知识**：composable 不是 Vue 独有的概念，React 的 `Hooks`（useState/useEffect）、Svelte 的 stores 都是同一种"逻辑复用"思路。Vue 3 的组合式函数和 React Hooks 最大的区别：**Vue composable 不需要遵守"调用顺序"规则**（可以在条件分支里调用），因为响应式系统靠依赖追踪而不是靠调用顺序对齐。这也是从 Vue 2 选项式切到 Vue 3 组合式后，心智负担反而更小的原因之一。

<details><summary>🔍 想深究再看：`useRegister` 里返回的对象为什么能保持响应式？</summary>

`useForm` 内部用 `reactive` / `ref` 创建了响应式状态，`useRegister()` 返回的 `values`、`errors` 就是这些响应式对象的引用——组件解构使用时，**只要不 `toRefs` 打散**，模板里 `values.username` 依然能触发更新。反过来说，如果你在组件里 `const { values } = useRegister()` 后直接解构 `const { username } = values`，就会丢掉响应式（解构出的是普通值）。正确姿势：模板里始终用 `values.xxx` 访问，或需要解构时用 `toRefs(values)`。这个"响应式引用 vs 普通值"的区别，是组合式 API 最常见的翻车点。

</details>
