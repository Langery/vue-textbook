## 📊 参考答案

### 选择题（每题 5 分，共 40 分）

| 题号 | 答案 | 解析 |
|---|---|---|
| 1 | **C** | `onMounted` 在组件**挂载完成之后**触发——此时 DOM 已经渲染好，可以安全地操作元素、初始化依赖 DOM 的第三方库。A `setup()` 是"准备阶段"，B `onBeforeMount` 是"挂载前"，D `onUpdated` 是"更新后"，都不是首次挂载的时机 |
| 2 | **C** | `fetch('/api/user')` 会发起网络请求、修改外部状态——这就是副作用。A/B/D 都只是**由输入算出输出**的纯计算（computed 虽然会缓存，但它的"缓存"是内部实现，不算对外产生副作用） |
| 3 | **C** | `watchEffect` **自动收集**你在回调里读过的响应式数据（读`count` 就订阅 `count`），`watch` 需要**手动指定**监听源。A 说反了（`watch` 才有 `oldVal`），B 也说反了（`watchEffect` 立即执行，`watch` 默认惰性），D 显然不对 |
| 4 | **C** | Vue 3 的 `ref` 数组**默认就是深层响应式**——`list.value[0] = 9` 能触发 watch 回调，不需要 `deep: true`。<br>⚠️ **这是 Vue 2 时代的老记忆**：Vue 2 的 `Vue.set` 时代数组索引赋值确实不触发，需要 `Vue.set` 或 `splice`；**Vue 3 用 Proxy，索引赋值、`length` 截断都能拦截**。<br>那 `deep: true` 什么时候要加？当你的监听源是**一个对象**（而不是 ref 包裹的响应式对象）时，比如 `watch(() => obj.a, cb)` 想监听 `obj` 的深层变化 |
| 5 | **C** | `onWatcherCleanup` 是 Vue 3.5 引入的官方 API，在 watcher 回调里注册"下次重跑前要执行的清理函数"。A `onCleanup` 是 3.5 之前 watcher 回调的**第三个参数**（现在仍兼容，但不推荐新代码用）。B `onBeforeUnmount` 是组件卸载钩子，粒度不对。D `onScopeDispose` 属于第 7 章 `effectScope`，**本章没讲过**，选了说明你在偷看后面 |
| 6 | **B** | "用户点击按钮"是**明确的用户意图**，不是"数据变了"——这种场景用 `@click` 直接调函数最直接，套一层 `watch` 是把简单事复杂化。<br>A/C/D 都是"数据变了 → 触发副作用"的典型场景，用 watch 正合适 |
| 7 | **B** | `flush: 'pre'`（默认）在组件 DOM 更新**之前**执行，`flush: 'post'` 在更新**之后**执行。<br>所以：需要读取更新后的 DOM（测量高度、聚焦新输入框、调用依赖 DOM 的第三方库）→ 用 `'post'`；只是想在数据变化时做点事、不关心 DOM 时序 → 用默认的 `'pre'`（它能更早执行，副作用也启动得更早） |

### 填空题（每题 5 分，共 25 分）

| 题号 | 答案 | 解析 |
|---|---|---|
| 8 | 创建、挂载、更新、卸载 | Vue 3 组件生命周期四阶段。顺序不能颠倒：**创建 → 挂载 → 更新 → 卸载**。挂载前后的钩子（`onBeforeMount`/`onMounted`）只在首次挂载时触发一次，而更新钩子每次组件更新都会触发 |
| 9 | **前** | `watchEffect` 默认 `flush: 'pre'`，即在组件 DOM 更新**之前**执行。想在 DOM 更新后操作元素，改成 `flush: 'post'` |
| 10 | **deep** | 监听 `ref` 包装的数组时，如果要感知**内部元素的变化**（如 `arr.push`、改对象属性），需要 `{ deep: true }`。<br>⚠️ 注意区分：第 4 题说的"数组索引赋值能触发"，是**监听数组本身**（`watch(list, cb)`）；本题是"要感知数组**内容**变化"——`push` 改变了数组内容，`watch(list, cb)` 默认只比较引用，所以要 `deep` |
| 11 | **onWatcherCleanup** | Vue 3.5+ 用 `onWatcherCleanup(() => clearTimeout(timer))` 注册清理函数。Vue 3.2~3.4 则用 watcher 回调的第三个参数 `onCleanup` |
| 12 | 新值（newVal）、旧值（oldVal） | `watch(source, (newVal, oldVal) => {})`。这两个值只在**值真的变了**时才有意义；如果是 `immediate: true` 首次执行，`oldVal` 是 `undefined` |

### 代码题

**13. 代码补全**：

```javascript
import { ref, watch, onWatcherCleanup } from 'vue'

watch(keyword, (newVal) => {
  const timer = setTimeout(() => {
    result.value = `搜索「${newVal}」的结果`
  }, 500)

  onWatcherCleanup(() => {
    clearTimeout(timer)
  })
})
```

**14. 实战题参考**：

```vue
<script setup>
import { ref, onMounted, onUnmounted } from 'vue'

const seconds = ref(0)
let timer = null

onMounted(() => {
  timer = setInterval(() => {
    seconds.value++
  }, 1000)
})

onUnmounted(() => {
  clearInterval(timer)
  console.log(`用户停留了 ${seconds.value} 秒`)
})
</script>

<template>
  <p>已停留：{{ seconds }} 秒</p>
</template>
```

**15. 分析题参考**：

问题 1：**竞态条件**——用户快速点击，旧请求可能覆盖新请求。
问题 2：**没有清理**——组件卸载时请求可能还在进行。

修复：

```vue
<script setup>
import { ref, watch, onWatcherCleanup } from 'vue'

const userId = ref(1)
const userData = ref(null)
const loading = ref(false)

watch(userId, async (newId) => {
  loading.value = true
  const controller = new AbortController()

  onWatcherCleanup(() => {
    controller.abort()
  })

  try {
    const res = await fetch(`/api/user/${newId}`, {
      signal: controller.signal
    })
    userData.value = await res.json()
  } catch (err) {
    if (err.name !== 'AbortError') {
      console.error(err)
    }
  } finally {
    loading.value = false
  }
})
</script>
```
