刚学会 `watch` 的人容易得"锤子病"：看到什么都想 watch。结果组件里堆五六个 watch，回调只做简单赋值、甚至改了被监听数据造成循环。其实 Vue 给每个需求都配了更合适的工具：要计算值用 `computed`、用户操作走事件、组件通信用 props/emit。本节帮你建立"该不该用 watch"的直觉。

## 🤔 一、`watch` 不是万能胶

学完前几节，你可能觉得 `watch` 很好用——数据变了就自动干活，省心！但**好用的东西最容易滥用**。

> 💬 **老师备注**：有句话叫"当你手里拿着锤子，看什么都像钉子"。`watch` 就是那把锤子——但很多场景其实不需要它。用 `watch` 解决的问题，可能用更简单的 API 就能搞定，而且代码更清晰、性能更好。

## 💡 二、4 种不该用 watch 的场景

### 场景 1：纯计算 → 用 `computed`

```javascript
// ❌ 滥用 watch：监听 price 和 quantity，手动算 total
const total = ref(0)
watch([price, quantity], ([p, q]) => {
  total.value = p * q   // 这只是个计算！
})

// ✅ 用 computed：更简洁，有缓存，性能更好
const total = computed(() => price.value * quantity.value)
```

**判断标准**：如果你 watch 回调里的逻辑是"**根据某些数据算出另一个数据**"，直接用 `computed`。

### 场景 2：用户主动操作 → 用 `@event`

```vue
<script setup>
// ❌ 滥用 watch：监听 keyword，用户点了搜索按钮才发请求
const keyword = ref('')
watch(keyword, () => {
  // 但用户只想在点"搜索"按钮时才发请求！
})
</script>

<template>
  <!-- ✅ 直接用 @click 事件处理 -->
  <input v-model="keyword" />
  <button @click="doSearch">搜索</button>
</template>
```

**判断标准**：如果操作是**用户点击、按键、鼠标拖拽等主动行为触发的**，用事件处理（`@click`、`@submit` 等），不要用 `watch`。

### 场景 3：组件通信 → 用 `props` + `emit`

```
<script setup>
// ❌ 滥用 watch：子组件监听某个全局变量来"接收"父组件传值
//   用 watch 监听 props 来实现"父组件的值变了我就更新"
const props = defineProps({ userId: Number })
watch(() => props.userId, (newId) => {
  fetchData(newId)  // 这种场景 watch 可以接受，但不是唯一选择
})
</script>
```

> 💬 **老师备注**：监听 `props` 用 `watch` 本身没错——这是 watch 的合法使用场景。但注意区分：**如果只是要把数据传给子组件展示**，直接 `{{ props.userId }}` 就行，不需要 watch。

### 场景 4：常量 / 一次性配置 → 直接写

```javascript
// ❌ 滥用 watchEffect：监听一个永远不会变的值
const API_URL = 'https://api.example.com'
watchEffect(() => {
  console.log(API_URL)  // 这个值永远不变，watchEffect 只执行一次
})

// ✅ 直接写
console.log('https://api.example.com')
```

## 🔍 三、判断口诀

背下这个表就够了：

| 你想干什么 | 用什么 | 一句话 |
|---|---|---|
| "根据已有数据，**算一个新值**" | `computed` | "算"不是"做" |
| "用户**点击/输入/拖拽**了某些东西" | `@event` | 用户主动 = 事件 |
| "某个数据变了，要**干外部的事**（请求、存储）" | `watch` / `watchEffect` | 数据变了要做额外的事 = watch |
| "组件挂载时**开始做一件事**" | `onMounted` | 启动 = onMounted |
| "父组件传进来的值**变了**，我要反应" | `watch` 监听 props | 被动响应父组件变化 |

## 🛠 四、完整对比示例

```vue
<script setup>
import { ref, computed, watch, onMounted } from 'vue'

const price = ref(100)
const quantity = ref(1)
const searchKeyword = ref('')
const username = ref('')

// ✅ computed：纯计算，有缓存
const total = computed(() => price.value * quantity.value)

// ✅ watch：数据变了，要发请求（副作用）
watch(searchKeyword, (val) => {
  if (val.trim()) fetchSearchResults(val)
})

// ✅ onMounted：组件启动时初始化
onMounted(() => {
  loadUserData()
})

// ✅ @event：用户主动触发（见 template）
function handleLogin() {
  login(username.value)
}
</script>

<template>
  <!-- ✅ @event：用户点击登录按钮 -->
  <input v-model="username" placeholder="用户名" />
  <button @click="handleLogin">登录</button>

  <!-- ✅ computed 自动计算 -->
  <p>单价：{{ price }} × 数量：{{ quantity }} = 总价：{{ total }}</p>

  <!-- ✅ watch 监听输入 -->
  <input v-model="searchKeyword" placeholder="搜索（自动请求）" />
</template>
```

## ⚠️ 五、过度使用 watch 的典型症状

### 症状 1：一个组件里有 5+ 个 watch

```javascript
// 这种代码说明设计有问题
watch(a, () => { /* ... */ })
watch(b, () => { /* ... */ })
watch(c, () => { /* ... */ })
watch(d, () => { /* ... */ })
watch(e, () => { /* ... */ })
// 太多了！考虑用 computed / @event 替代
```

**修复方向**：
- 如果是"根据 A+B+C 算一个新值" → `computed`
- 如果是"用户操作 A/B/C" → `@event`
- 如果真的是多个数据变化都要做不同的事 → 考虑拆分成独立 composable

### 症状 2：watch 里只做了"赋值"

```javascript
// ❌ 这种 watch 完全是多余的
watch(source, (val) => {
  target.value = val  // 只是传值？直接用 computed！
})

// ✅ 等价于
const target = computed(() => source.value)
```

### 症状 3：watch 链

```javascript
// ❌ watch 触发 watch
watch(a, (val) => { b.value = val })
watch(b, (val) => { c.value = val })
watch(c, (val) => { doSomething(val) })
// 数据流混乱，调试困难。考虑用 computed 链
```

## 🧠 本节小结

- **判断口诀**："我要一个值"→ computed；"用户点了什么"→ @event；"数据变了要干活"→ watch/watchEffect；"组件启动要干活"→ onMounted
- **纯计算别用 watch**：watch 里只做 `ref.value = 计算` 的赋值，基本都可以改成 computed
- **用户主动操作别用 watch**：点击/输入直接用事件处理，不需要 watch 监听数据兜一圈
- **组件通信别用 watch**：父子通信优先 props + emit，watch 只会让数据流更难追踪
- **过度使用症状**：组件里 5+ 个 watch、回调里再改被监听数据、只做简单赋值——都要警惕
- **watch 回调改数据要设防**：防止"改了→触发→再改"的循环
