第六章回答了 Vue 里"什么时候、做什么事"：生命周期钩子管时机，`watchEffect` / `watch` 管响应，清理函数管善后。这一节我们用它们做一个**真正靠"时间副作用"跑起来**的应用——「番茄钟 + 学习记录器」。它和大项目 Campus2Hand 的关联很直接：拍卖/抢购倒计时、订单状态轮询，底层都是"定时副作用 + 生命周期清理"这套写法。先在番茄钟上把它练熟。

> 🎯 **类比一下：番茄钟 ≈ 电子厨房定时器**
> 旋钮一拧（running 状态变了），齿轮开始转（watchEffect 建定时器）；拧停或时间到（状态变化），齿轮自动停（清理函数）。整个应用就是"状态变化 → 定时副作用 → 清理"的循环——和拍卖倒计时、订单轮询是同一套底层逻辑。

> 🤖 **Vue 君**：八成是旧定时器没被清理，叠了好几个在跑——看 6.6 的"退房打扫"。

## 🎯 项目需求（一句话）

做一个"番茄钟 + 学习记录器"：25 分钟专注倒计时，结束后自动进入 5 分钟休息并记录一个"完成番茄"；支持开始 / 暂停 / 重置，界面剩余秒数实时刷新——全程只用第 6 章已学的生命周期、`watchEffect` / `watch`、定时副作用与清理，不引入任何新库。

### ✅ 验收标准（能跑、能展示）

- [ ] 项目能 `npm run dev` 启动，能看到一个大大的倒计时和"专注 / 休息"状态

- [ ] 点"暂停"能停住计时，"重置"能回到初始 25:00
- [ ] 每完成一个完整专注周期，右上角"今日完成番茄" +1
- [ ] 页面标题（`document.title`）能跟着显示当前剩余时间（用副作用实现）
- [ ] 能向同学讲清：定时器放在哪个钩子里创建、为什么必须在卸载时清理（切走页面后时间不能再跑）

## 🛠 分步提示（3~5 步，含关键代码锚点）

> 以下只给路线和关键锚点，**不贴全量答案**。卡住时回头翻 6.1 / 6.4 / 6.5 / 6.6 / 6.3 对应小节。

### Step 1：设计"状态机"

番茄钟有两种模式：`focus`（25 分钟）与 `break`（5 分钟）。用 `reactive`（或 `ref`）存 `mode`、`remainSeconds`、`running`、`finishedCount` 四个状态。

### Step 2：开始/暂停——用 `watchEffect` 管理定时器（回顾 6.4 / 6.6）

关键思路：让定时器的创建/清理**跟着 `running` 状态走**，用 `watchEffect` 在副作用里开停：

```js
// ⚠️ watchEffect 不支持"return 清理函数"！
// 清理函数要通过 onWatcherCleanup 注册（Vue 3.5+），
// 详见 6.6 节。
import { watchEffect, onWatcherCleanup } from 'vue'

watchEffect(() => {
  if (!state.running) return
  const timer = setInterval(() => {
    if (state.remainSeconds > 0) {
      state.remainSeconds--
    }
  }, 1000)
  onWatcherCleanup(() => clearInterval(timer))   // 重跑前自动清理旧定时器
})
```

> 锚点检查：点"开始"后每秒递减；点"暂停"后立即停住；再次"开始"能续跑——注意 `watchEffect` 重跑时旧定时器被 `onWatcherCleanup` 自动清掉了，不会叠出多个计时器。

### Step 3：到 0 切换模式 + 计数（回顾 6.5 watch）

用 `watch` 监听 `remainSeconds` 归零的那一刻，而不是在定时器里到处判断：

```js
watch(
  () => state.remainSeconds,
  (val) => {
    if (val !== 0) return
    if (state.mode === 'focus') {
      state.finishedCount++
      state.mode = 'break'
      state.remainSeconds = BREAK_SECONDS
    } else {
      state.mode = 'focus'
      state.remainSeconds = FOCUS_SECONDS
    }
    state.running = false   // 一轮结束，等用户再点开始
  }
)
```

### Step 4：同步页面标题——用副作用改"外部世界"（回顾 6.2 / 6.4）

把剩余时间同步到 `document.title`，这正是副作用的典型场景（改的是 Vue 之外的东西）：

```js
watchEffect(() => {
  const mm = String(Math.floor(state.remainSeconds / 60)).padStart(2, '0')
  const ss = String(state.remainSeconds % 60).padStart(2, '0')
  document.title = `${state.running ? '⏳' : '⏸'} ${mm}:${ss} · ${state.mode === 'focus' ? '专注中' : '休息中'}`
})
```

### Step 5：卸载时兜底清理 + 界面完善

即使 `watchEffect` 已负责清理，也建议在卸载钩子里显式把计时状态归零，形成"双保险"习惯（回顾 6.3）：

```js
onUnmounted(() => {
  state.running = false   // 触发 watchEffect 重跑 → 定时器被清理
})
```

界面用 `v-if / v-else` 显示专注/休息配色，把按钮（开始/暂停/重置）与"今日完成番茄"统计摆好。

```vue
<script setup>
import { computed, onUnmounted, ref, watch, watchEffect, onWatcherCleanup } from 'vue'

// ====== 可配置时长：演示版 0.1 分钟 = 6 秒，方便你 6 秒看完一轮 ======
// 真正用的时候，把这两个数字改回 25 / 5 就行，其余代码一个字都不用动
const FOCUS_MINUTES = 0.1
const BREAK_MINUTES = 0.05
// Math.round 是必须的：浮点数不精确，比如 8.2 * 60 会得到 491.99999999999994
const FOCUS_SECONDS = Math.round(FOCUS_MINUTES * 60)
const BREAK_SECONDS = Math.round(BREAK_MINUTES * 60)

// ====== 状态：一个模式 + 一个秒数 + 一个开关 + 一个计数 ======
const mode = ref('focus')            // 'focus' 专注 | 'break' 休息
const remaining = ref(FOCUS_SECONDS) // 剩余秒数
const running = ref(false)           // 是否在跑表
const finishedCount = ref(0)         // 已完成的番茄数

// ====== 派生状态：用 computed，别用 const 存快照 ======
const isFocus = computed(() => mode.value === 'focus')
const display = computed(() => {
  const mm = String(Math.floor(remaining.value / 60)).padStart(2, '0')
  const ss = String(remaining.value % 60).padStart(2, '0')
  return `${mm}:${ss}`
})

// ====== 定时副作用：watchEffect 负责"开表"，onWatcherCleanup 负责"收表" ======
// 这个 effect 只同步读了 running，所以它只在 running 变化时重跑
watchEffect(() => {
  if (!running.value) return

  const timer = setInterval(() => {
    // 注意：这里是回调里读 remaining，不在 effect 主体里同步读，所以不会被追踪
    if (remaining.value > 0) remaining.value -= 1
  }, 1000)

  // ⭐ Vue 3.5 的官方姿势：用 onWatcherCleanup 注册清理函数
  // 效果重跑前（比如 running 变成 false）和组件卸载时，Vue 会自动调用它
  onWatcherCleanup(() => clearInterval(timer))
})

// ====== 归零处理：用 watch 精准监听"秒数归零"这一刻 ======
watch(remaining, (val) => {
  if (val > 0) return

  if (mode.value === 'focus') {
    // 专注结束：记一个番茄，然后进入休息
    finishedCount.value += 1
    mode.value = 'break'
    remaining.value = BREAK_SECONDS
    // running 保持 true：休息自动接着走
  } else {
    // 休息结束：回到专注，但要等人点开始
    mode.value = 'focus'
    remaining.value = FOCUS_SECONDS
    running.value = false
  }
})

// ====== 另一个副作用：把剩余时间同步到浏览器标签页标题 ======
// ⚠️ 必须写成独立的 watchEffect：如果和上面的定时器合并成一个，
// remaining 就变成了被追踪的依赖，秒数每跳一次这个 effect 就重跑一次
watchEffect(() => {
  const mm = String(Math.floor(remaining.value / 60)).padStart(2, '0')
  const ss = String(remaining.value % 60).padStart(2, '0')
  document.title = `${running.value ? '⏳' : '⏸'} ${mm}:${ss} · ${mode.value === 'focus' ? '专注中' : '休息中'}`
})

// ====== 卸载兜底：把"外部世界"还原 ======
onUnmounted(() => {
  // 组件卸载时 Vue 会停掉本组件的 watchEffect，
  // onWatcherCleanup 注册的 clearInterval 会被自动调用，定时器不会泄漏
  running.value = false
  document.title = '🍅 番茄钟'
})

// ====== 行为 ======
function start() {
  running.value = true
}
function pause() {
  running.value = false
}
function reset() {
  running.value = false
  mode.value = 'focus'
  remaining.value = FOCUS_SECONDS
}
</script>

<template>
  <div class="timer" :class="mode">
    <div class="mode">{{ isFocus ? '🍅 专注中' : '☕ 休息中' }}</div>

    <div class="digits">{{ display }}</div>

    <div class="actions">
      <button v-if="!running" class="btn primary" @click="start">开始</button>
      <button v-else class="btn" @click="pause">暂停</button>
      <button class="btn" @click="reset">重置</button>
```

<details>
<summary>💬 老师备注：这个成品里有三处"故意的非标准写法"，值得你找出来</summary>

**① 定时器写在 `watchEffect` 里，而不是 `onMounted` 里。**
很多人写定时器第一反应是 `onMounted(() => setInterval(...))`。但那样你只有"开"没有"收"——组件卸载了定时器还在跑，而且"暂停"这个功能根本没法实现（你得自己再搞一个 `timerId` 变量来 `clearInterval`）。

写成 `watchEffect` 之后，"什么时候该有定时器"就变成了**一个响应式问题**：`running` 是 `true` 才有定时器，`running` 一变 `false`，effect 重跑、`onWatcherCleanup` 先把旧定时器清掉、新的一次因为 `running` 是 `false` 直接 `return`——**"暂停"其实是白送的**。

**② 清理函数用的是 `onWatcherCleanup`，不是 `return () => clearInterval(timer)`。**
这一条我专门实测过（用 Vue 3.5.44 跑了一遍）：把 `onWatcherCleanup(() => clearInterval(timer))` 换成 `return () => clearInterval(timer)`，**那个 `clearInterval` 一次都不会被调用**。

原因是：Vue 3.5 的 `watchEffect` 压根不读 effect 函数的返回值。返回清理函数是 Vue 2 时代 `watch` 的老写法（以及 3.2–3.4 时代 `onCleanup` 参数的老写法），到了 3.5 已经被 `onWatcherCleanup()` 这个独立 API 取代了。所以本章 Step 2 里那句注释——"⚠️ watchEffect 不支持 return 清理函数！"——是**必须当真的**。

> 📌 顺手纠正一下本章末尾"冷知识"里的一句话：那里说 `watchEffect` **返回的**清理函数"会被 Vue 当作该次副作用执行前要调用的清理"。这句话在 Vue 3.5 里**不成立**——返回值会被直接丢弃。真正会被调用的是 `onWatcherCleanup` 注册的、以及 `onCleanup` 参数传进来的那两种。读到这里如果你正好试了 `return` 写法，会发现秒数停不下来，别怀疑自己。

**③ 两个 `watchEffect` 必须分开写，不能合并。**
这是本章最容易踩、也最难自查的坑。定时器那个 effect 里，我们**只在 `setInterval` 的回调内部**读 `remaining`（回调是异步执行的，不在 effect 的同步执行期，所以不会被收集成依赖）；而标题那个 effect 里，我们**同步读了** `remaining`。

一旦把两段合到一起，标题那段同步读的 `remaining` 就变成了同一个 effect 的依赖——于是 `remaining` 每变一次，这个 effect 就重跑一次，**定时器被反复重建**。我实测过：合并之后 3 秒内 `setInterval` 被调用了 4 次（正确写法只调 1 次）。

后果是：计时会"看起来还行但一直在抖"，而且你永远查不出为什么——因为语法完全合法，编译也不会报错。**`watchEffect` 收集依赖的规则是"effect 函数体同步执行期间读到的一切"**，这个规则只有你真正理解它，才能预判哪些代码会互相影响。

**④ 顺带说说 `Math.round`。**
我们把时长配成 `FOCUS_MINUTES = 0.1`，而 `0.1 * 60` 恰好等于 `6`（IEEE 754 下正好是 6，所以这段没出问题）。但**换个数字就可能翻车**：`8.2 * 60` 在浮点数里是 `491.99999999999994`，`Math.floor` 一下就变成 **491** 秒——**倒计时凭空少了一秒**。`0.29 * 60` 同理是 `17.399999999999998`。

这种 bug 极难查（页面不会报错，只是"时间对不上"），所以**分钟转秒一定要取整**：`Math.round(FOCUS_MINUTES * 60)`。

最后留个思考题：为什么"专注结束进入休息"之后，我们让 `running` **保持** `true`（休息自动接着走），而"休息结束回到专注"却把 `running` 置为 `false`（等你手动点开始）？（提示：想想这两种"结束"对用户来说分别意味着什么——专注结束是"任务告一段落"，还是"该轮换班了"？）

## 🔮 它在最后的大项目里长成什么

这一节的"番茄钟"，就是大项目 **Campus2Hand 校园二手集市**的**倒计时与状态同步**雏形：拍卖/抢购的"距结束 xx:xx"就是这里的 `remainSeconds` 倒计时，订单"等待支付/已超时"的状态流转就是这里的模式切换；第 12 章把 25 分钟换成拍卖截止时间，把专注计数换成订单状态轮询，你会觉得"这套写法我熟"。

---

> 🧊 **冷知识**：本节的"暂停即清定时器"不是额外加的逻辑，而是 `watchEffect` 内置的"换房先退房"机制在工作——6.6 学的 `onWatcherCleanup` 会在 effect **重跑前**（`running` 从 `true` 变 `false`）和**组件卸载时**自动执行，把上一个 `setInterval` 清掉。
>
> ⚠️ 顺便澄清一个常见误解：**Vue 3.5 的 `watchEffect` 不认 `return` 出去的清理函数**。写成 `return () => clearInterval(timer)` 的话，那个函数**一次都不会被调用**，定时器会彻底泄漏。真正会被调用的只有两种：`onWatcherCleanup(() => clearInterval(timer))`（3.5+ 推荐）和 `onCleanup` 回调参数（3.2–3.4 的老写法）。本章成品统一用 `onWatcherCleanup`。

<details><summary>🔍 想深究再看：为什么 Step 5 还要"双保险"？</summary>

理论上 `watchEffect` 已经负责清理定时器，组件卸载时 effect 停止也会触发清理，似乎不用再写 `onUnmounted`。但"双保险"防的不是定时器，而是**状态残留**：组件可能被缓存（如 keep-alive）、或卸载后外部模块仍引用了 `state`，不清零 `running` 的话，再次进入页面会从"暂停中"起步，体验割裂。工程上"副作用靠机制清、状态靠显式归位"是一对固定搭档——机制兜底、显式保预期，两条腿走路才稳。

</details>
