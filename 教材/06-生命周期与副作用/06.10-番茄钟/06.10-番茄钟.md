## 🛠 分步提示（3~5 步，含关键代码锚点）

> 以下只给路线和关键锚点，**不贴全量答案**。卡住时回头翻 6.1 / 6.4 / 6.5 / 6.6 / 6.3 对应小节。

### Step 1：设计"状态机"

番茄钟有两种模式：`focus`（25 分钟）与 `break`（5 分钟）。用 `reactive`（或 `ref`）存 `mode`、`remainSeconds`、`running`、`finishedCount` 四个状态。

### Step 2：开始/暂停——用 `watchEffect` 管理定时器（回顾 6.4 / 6.6）

关键思路：让定时器的创建/清理**跟着 `running` 状态走**，用 `watchEffect` 在副作用里开停：

```js
watchEffect(() => {
  if (!state.running) return
  const timer = setInterval(() => {
    if (state.remainSeconds > 0) {
      state.remainSeconds--
    }
  }, 1000)
  return () => clearInterval(timer)   // watchEffect 里返回清理函数，重跑前自动清理
})
```

> 锚点检查：点"开始"后每秒递减；点"暂停"后立即停住；再次"开始"能续跑——注意 watchEffect 重跑时旧定时器被自动清掉了，不会叠出多个计时器。

### Step 3：到 0 切换模式 + 计数（回顾 6.5 watch）

用 `watch` 监听 `remainSeconds` 归零的那一刻，而不是在定时器里到处判断：

```js
watch(
  () => state.remainSeconds,
  (val) => {
    if (val !== 0) return
    if (state.mode === 'focus') {
      state.finishedCount++
      state.mode = 'break'
      state.remainSeconds = BREAK_SECONDS
    } else {
      state.mode = 'focus'
      state.remainSeconds = FOCUS_SECONDS
    }
    state.running = false   // 一轮结束，等用户再点开始
  }
)
```

### Step 4：同步页面标题——用副作用改"外部世界"（回顾 6.2 / 6.4）

把剩余时间同步到 `document.title`，这正是副作用的典型场景（改的是 Vue 之外的东西）：

```js
watchEffect(() => {
  const mm = String(Math.floor(state.remainSeconds / 60)).padStart(2, '0')
  const ss = String(state.remainSeconds % 60).padStart(2, '0')
  document.title = `${state.running ? '⏳' : '⏸'} ${mm}:${ss} · ${state.mode === 'focus' ? '专注中' : '休息中'}`
})
```

### Step 5：卸载时兜底清理 + 界面完善

即使 `watchEffect` 已负责清理，也建议在卸载钩子里显式把计时状态归零，形成"双保险"习惯（回顾 6.3）：

```js
onUnmounted(() => {
  state.running = false   // 触发 watchEffect 重跑 → 定时器被清理
})
```

界面用 `v-if / v-else` 显示专注/休息配色，把按钮（开始/暂停/重置）与"今日完成番茄"统计摆好。

> 🧊 **冷知识**：Step 2 里 `watchEffect` 返回的清理函数，正是 6.6 学的 `onWatcherCleanup` 的"语法糖前身"——Vue 会把它当作该次副作用执行前要调用的清理。所以番茄钟里"暂停即清定时器"不是额外加的逻辑，而是 watchEffect 内置的"换房先退房"机制在工作。

<details><summary>🔍 想深究再看：为什么 Step 5 还要"双保险"？</summary>

理论上 `watchEffect` 已经负责清理定时器，组件卸载时 effect 停止也会触发清理，似乎不用再写 `onUnmounted`。但"双保险"防的不是定时器，而是**状态残留**：组件可能被缓存（如 keep-alive）、或卸载后外部模块仍引用了 `state`，不清零 `running` 的话，再次进入页面会从"暂停中"起步，体验割裂。工程上"副作用靠机制清、状态靠显式归位"是一对固定搭档——机制兜底、显式保预期，两条腿走路才稳。

</details>
