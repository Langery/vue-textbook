## 🎯 本章目标

学完这章，你将能够：

- ✅ 理解**前后端分离架构**：API 是什么、前端怎么和后端"说话"
- ✅ 熟练使用 **Axios** 发送 GET / POST 请求
- ✅ 掌握**全局配置与拦截器**：独立实例、baseURL、token 注入、统一错误处理
- ✅ 掌握**错误处理与重试**：区分网络错误 / 超时错误 / 业务错误
- ✅ 用 **Composable 封装请求状态**（loading / error / data 三态）
- ✅ 用 **AbortController** 取消请求，防止内存泄漏

## 🤔 这章讲什么、为什么、学完能干什么

**这章讲什么？**

从第 8 章开始，你已经能搭出"长得像应用"的前端了。但一个正经的 Vue 项目，数据不是写死在组件里的——它来自后端服务器。本章教你**前端如何与后端通信**：HTTP 协议基础、Axios 请求库、请求拦截器、错误处理与请求状态管理，一条链路打通。

**为什么必须有这章？**

没有服务端通信，前端只是"静态页面"；有了它，你才能做登录注册、商品列表、订单管理这些真实业务。第 12 章综合项目的所有数据请求，全部依赖本章的 Axios 封装能力。

**学完能干什么？**

- 独立编写项目的 API 请求层（`api/index.js` + 各模块接口函数）
- 自动携带 token、统一弹错误提示，代码不再到处重复 try-catch
- 处理超时、断网、业务失败的场景，页面体验不崩

> 🧑 **小白**：目前我的页面数据都是写死的，怎么才能拿到后端数据库里的"真数据"？

> 🤖 **Vue 君**：通过 HTTP 接口！我用 Axios 帮你发请求、收响应，你只管把数据显示出来。

> 👨🏫 **老湿**：登录、列表、下单……真实业务全靠这一章。第 12 章综合项目的数据请求，也会复用这里的 Axios 封装。

> 💬 **老师备注**：第 9 章 + 第 12 章是"从会调接口到会做项目"的完整链路——本章把请求能力练扎实，综合项目就能直接复用。

## 🛠 本章实战

1. 用 Axios 写一个"新闻列表"页面：进入自动加载、下拉刷新重新请求
2. 封装 `api/index.js`：创建独立实例 + 请求/响应拦截器
3. 给所有请求自动注入 token，并在 401 时跳转登录页
4. 写一个 `useRequest` composable，组件里三行代码完成请求
5. 给请求加"失败自动重试 3 次"，并对 4xx 业务错误单独提示

## ⚠️ 学习提示

- **先理解再封装**：先学会裸写 `axios.get`，再学拦截器，最后才封装 `useRequest`——不要跳过基础直接抄封装代码。
- **关注拦截器的收益**：token 注入和统一错误处理放在拦截器里，是所有真实项目的标准姿势。
- **错误处理是加分项**：能区分"网络断、超时、业务失败"的工程师，写出的页面才叫"可用"。

## 📖 本章术语表

下表收录本章 9.1~9.9 正文实际讲到的核心术语，按首次出现的节号排序，方便随时回查。

| 术语 | 一句话解释 | 首现节号 |
|---|---|---|
| `前后端分离` | 把前端展示与后端数据处理拆成独立两部分，通过 HTTP 接口通信，各自独立部署。 | 9.1 |
| `HTTP 协议` | 浏览器与服务器通信的请求-响应协议，包含方法、状态码、请求头与请求体等约定。 | 9.1 |
| `API` | 应用编程接口，这里指后端暴露给前端调用的 URL 端点，按约定返回 JSON 数据。 | 9.1 |
| `RESTful` | 以资源为中心、用 HTTP 方法表达操作（GET 查、POST 增）的 API 设计风格。 | 9.1 |
| `跨域` | 浏览器同源策略限制不同源（协议/域名/端口）请求，开发期用代理或 CORS 解决。 | 9.1 |
| `Mock 数据` | 用本地模拟数据替代真实接口返回，方便前端在接口未就绪时先行开发调试。 | 9.1 |
| `Axios` | 基于 Promise 的 HTTP 客户端库，提供请求/响应拦截器、取消请求等丰富能力。 | 9.2 |
| `axios.get` | Axios 发 GET 请求的方法，参数放 URL 或 params 配置中，返回 Promise。 | 9.2 |
| `axios.post` | Axios 发 POST 请求的方法，数据放请求体中，常用于新增资源。 | 9.2 |
| `response.data` | Axios 响应对象上存放服务端实际返回数据的属性，默认已解析为 JSON。 | 9.2 |
| `async/await` | 让异步代码看起来像同步的语法糖，配合 Promise 简化 axios 请求的读写。 | 9.2 |
| `幂等性` | 同一请求重复执行结果一致的性质，GET 幂等、POST 不幂等（重复提交会重复创建）。 | 9.4 |
| `axios.create` | 创建独立 Axios 实例的方法，可为不同后端配置各自的 baseURL 与拦截器。 | 9.5 |
| `baseURL` | Axios 实例配置的基础 URL，请求路径会与其拼接，便于统一管理接口地址。 | 9.5 |
| `请求拦截器` | 请求发出前统一加工配置，如注入 token、加公共请求头、统一日志记录。 | 9.5 |
| `响应拦截器` | 响应返回后统一处理结果，如剥离 data、统一错误提示、401 跳转登录。 | 9.5 |
| `网络错误` | 请求未到达服务器或响应异常（断网、超时）引发的错误，需单独捕获处理。 | 9.6 |
| `业务错误` | 服务端正常返回但业务逻辑失败（如库存不足），用状态码或 code 字段区分。 | 9.6 |
| `指数退避` | 重试策略：失败后等待时间按 2 的幂次增长（1s、2s、4s…），减轻服务压力。 | 9.6 |
| `AbortController` | Web 标准 API，通过 signal 通知浏览器取消进行中的请求，避免竞态浪费。 | 9.7 |
