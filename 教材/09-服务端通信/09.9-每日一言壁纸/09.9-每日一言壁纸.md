
# 9.9 章末实战：每日一言壁纸（P9）

> 章节：第 9 章 服务端通信
> 课时：1 课时
> 类型：章末实战 · 独立小项目 P9

---

第九章打通了"前端 ↔ 后端"：9.2~9.4 是 Axios 裸请求，9.5 教独立实例与拦截器，9.6 教错误分类与重试，9.7 教 `useRequest` 三态封装与 `AbortController` 取消。这一节把它们串成一个**看得到的网络请求应用**——「每日一言壁纸」：每次打开随机加载一句话 + 一张壁纸，点按钮换内容，加载中、失败、重试、取消全套体验都有。它和大项目 Campus2Hand 的关联是结构性的：大项目所有接口请求都走本章封装的 Axios（实例 + token 注入 + 401 处理 + 统一错误），本实战的"api 层 + 三态"就是那套结构的迷你版。

> 🎯 **类比一下：本章实战 ≈ 用"标准零件"组装一台小机器**
> 9.5 的实例 + 拦截器是"标准电源模块"，9.6 的错误分类重试是"保险丝"，9.7 的 useRequest 是"总控开关"。这台「每日一言壁纸」小机器，就是用标准零件拼出来的：你不在组件里裸写 axios，就像不自己拉电线——**所有请求走封装通道，才是大项目的正确姿势**。

> 🧑 **小白**：为啥不能图省事直接在组件里 `axios.get` 一把梭？
> 🤖 **Vue 君**：能跑，但 token 注入、错误提示、取消请求全得每个组件自己写一遍——大项目里几十个页面就崩了。这节练的就是"先把通道修好，再往通道上接东西"。
> 👨🏫 **老湿**：**验收标准的最后一条"能向同学讲清"，其实就是大项目面试题**：token 为什么放拦截器？防连点靠什么？把这两问答顺，这节才算真学会。

## 🎯 项目需求（一句话）

做一个"每日一言壁纸"页面：进入页面自动请求两条公开接口——一句话（文本）与一张壁纸（图片），展示出来；按钮"换一言 / 换壁纸"各自重新请求；全程带 loading / 错误提示 / 可重试——API 调用必须经过自己封装的 `api` 层 + `useRequest`，不允许在组件里裸写 `axios.get`。

### ✅ 验收标准（能跑、能展示）

- [ ] 项目能 `npm run dev` 启动，页面能看到一句中文名言/语录 + 一张全屏壁纸
- [ ] 首次加载时展示 loading（转圈或占位图），数据返回后淡入正文
- [ ] 请求失败时显示错误文案与"重试"按钮，点重试能重新请求（用 9.6 的错误分类处理）
- [ ] 点"换一言"只换句子不重新拉壁纸，点"换壁纸"只换图不换句子
- [ ] 组件里找不到裸 `axios.get`——所有请求都从 `api/` 模块导入，页面只用 `useRequest` 的结果
- [ ] 能向同学讲清：token 注入和统一错误提示为什么放在拦截器而不是每个组件里？"换壁纸"连续快速点击时怎么防止旧请求覆盖新结果？

## 🛠 分步提示（3~5 步，含关键代码锚点）

> 以下只给路线和关键锚点，**不贴全量答案**。卡住时回头翻 9.5 / 9.6 / 9.7 对应小节。

### Step 1：建 api 层：实例 + 拦截器（回顾 9.5）

新建 `src/api/http.js`：`axios.create({ timeout: 8000 })` 建独立实例（两个公开接口不同源，**不要写死 baseURL**）；请求拦截器里从 `localStorage` 取 fake token 注入 `Authorization` 头；响应拦截器把"非 2xx 的响应"统一 reject 并弹一句错误提示。再从该实例导出默认 `http`。

### Step 2：写接口模块（回顾 9.2 / 9.5 的模块化）

新建 `src/api/quote.js` 与 `src/api/wallpaper.js`，各导出一个返回 Promise 的函数：

```js
// api/quote.js
import http from './http'
export function getQuote() {
  return http.get('https://v1.hitokoto.cn/')   // 中文一言接口
}
```

壁纸接口可用 `https://picsum.photos/seed/{随机种子}/1600/900`——它直接返回图片，页面里用 `<img :src>` 引用即可（要"换一张"只需换 seed）。

### Step 3：页面用 `useRequest` 接三态（回顾 9.7）

复用课堂的 `useRequest(fetcher)`：内部维护 `data / loading / error` 并执行 `fetcher`。组件里：

```js
const { data: quote, loading: quoteLoading, error: quoteError, run: loadQuote } = useRequest(getQuote)
const { data: imgSeed, loading: imgLoading, error: imgError, run: loadImg } = useRequest(() => randomSeed())
```

`onMounted` 时同时 `loadQuote()` 与 `loadImg()`；模板按 `loading / error / data` 三态渲染：loading 显占位、error 显"加载失败 + 重试按钮（`@click="loadQuote()"`）"、成功显正文。

### Step 4：换一言 / 换壁纸 + 防连点

"换一言"按钮 `@click="loadQuote()"`——成功就更新 `data`，`useRequest` 内部自动把 `loading` 开关一遍。按钮在 `loading` 时禁用（回顾 9.6 防重复请求的思路），文案可换成"加载中…"。

### Step 5：取消请求与竞态（回顾 9.7）

给 `useRequest` 集成 `AbortController`：每次 `run()` 前先 `abort()` 上一个请求，`onUnmounted` 时也 `abort()`。锚点检查：快速连点"换一言"5 次，只应看到最后一次的结果；切走页面后 Network 面板里不再有"在飞"的请求。

## 🚀 延伸挑战（1~2 个加分项）

1. **失败自动重试**：给"换一言"加 9.6 教的自动重试逻辑——网络类错误最多自动重试 2 次，4xx 业务错误不重试并直接展示后端 message。
2. **收藏语录**：把喜欢的句子"收藏"到本地列表（可复用第 7 章的 `useLocalStorage`，若已完成 P7 直接搬过来），做个"我的收藏"抽屉。

> 🧊 **冷知识**：一言接口（hitokoto）返回的句子本身就是"接口设计样板"：一个 JSON 里有 `hitokoto`（正文）、`from`（出处）、`from_who`（作者）、`creator`（投稿人）等字段。如果你认真看过它，会发现"API 返回结构"正是 9.1 说的"JSON 是菜本身"——拿到对象后该取哪个字段渲染，全看后端怎么定义。**看一个公开接口的返回，是学后端思维最快的捷径**。

<details><summary>🔍 想深究再看：为什么实战反复强调"所有请求走 api 层、组件不碰 axios"？</summary>

因为大项目里"接口通道"会持续演进：今天后端地址是 `http://test.com`，明天上线要换 `https://prod.com`；今天 token 存 localStorage，明天改存 cookie；今天 401 只弹框，明天要自动跳登录并刷新 token。这些变化如果散落在每个组件里，就是几十个文件的连锁改动；收进 `api/http.js` 一个文件，通常只改几行。9.5~9.7 教的"实例 + 拦截器 + 三态"，本质是把**请求的生命周期管理权**从组件手里收归到统一层——组件永远只跟"业务数据"打交道，这是工程化最重要的分工。

</details>

## 🔮 它在最后的大项目里长成什么

这一节的"每日一言壁纸"，就是大项目 **Campus2Hand 校园二手集市**的**api 层模板**：`http.js` 里的独立实例会升级为带 `baseURL` 的后端地址；fake token 换成真实登录后的 token 并在 401 时自动跳登录页；`getQuote` 这样的单接口函数会扩展成 `api/goods.js`、`api/order.js` 等一整套模块。第 12 章里所有页面拉商品、下订单，都不会再碰裸 Axios——请求全走这节练熟的"实例 + 拦截器 + 三态"通道。
