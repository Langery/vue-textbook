# 4.9 章末实战：点赞投票器（P4）

> 章节：第 4 章 Props 和事件
> 课时：1 课时
> 类型：章末实战 · 独立小项目 P4

---

第四章解决了组件间"怎么说话"的问题：数据从父到子靠 **Props**，子通知父靠 **emit**，双向绑定靠 **v-model**。这一节把它们拼成一个**能用的互动组件**——「点赞投票器」。设想校园二手集市里每件商品都有一排"👍 有用 / 👎 不推荐 / ⭐ 收藏"，这正是大项目 Campus2Hand 商品详情页「收藏 / 留言」交互组件与表单控件双向绑定的模型，先把单条交互做熟。

---

## 🎯 项目需求（一句话）

做一个"商品口碑投票器"：一条商品信息旁边有 👍 / 👎 两个按钮和一个 ⭐ 收藏开关——点赞数、点踩数、收藏状态都实时反馈在界面上——全程只用第 4 章已学的 props 传值、emit 事件、v-model，不引入任何新库。

### ✅ 验收标准（能跑、能展示）

- [ ] 项目能 `npm run dev` 启动，能看到一条或多条商品及其投票区域
- [ ] 商品的标题、初始票数通过 **props** 从父组件传入，子组件不私自改 props（回顾 4.3 只读性）
- [ ] 点 👍 会触发子组件 **emit** 事件，父组件更新票数，界面上数字 +1
- [ ] 同一用户不能无限刷票：同一件商品点赞后再次点击可"取消赞"（或已赞状态置灰）
- [ ] 收藏按钮用 **v-model** 双向绑定实现（父组件持有收藏状态，子组件通过 `defineModel` 同步）
- [ ] 展示页里至少复用同一个投票组件 3 次，各条数据互不影响

## 🛠 分步提示（3~5 步，含关键代码锚点）

> 以下只给路线和关键锚点，**不贴全量答案**。卡住时回头翻 4.1 / 4.5 / 4.6 / 4.7 对应小节。

### Step 1：定义好"一条商品"的数据结构

在父组件准备本地数据，字段固定为 `id / title / price / likes / dislikes`，另外维护每件商品的"我的态度"（未投 / 赞 / 踩）与"是否收藏"，方便做防刷票和收藏回显。

### Step 2：写子组件 `VotePanel`——props 只读 + emit 上报（回顾 4.1 / 4.6）

```vue
<script setup>
const props = defineProps({
  id: Number,
  title: String,
  likes: Number,
  dislikes: Number
})
const emit = defineEmits(['vote', 'collect'])
</script>
<template>
  <div class="vote-panel">
    <h4>{{ title }}</h4>
    <button @click="emit('vote', { id, type: 'like' })">👍 {{ likes }}</button>
    <button @click="emit('vote', { id, type: 'dislike' })">👎 {{ dislikes }}</button>
    <!-- 收藏按钮用 v-model 语法糖，见 Step 4 -->
  </div>
</template>
```

> 锚点检查：组件内部**绝不**写 `props.likes++`（只读，回顾 4.3）——所有改动都通过 emit 请父组件完成，父子各管一摊。

### Step 3：父组件接住事件、统一改状态（回顾 4.6 传参）

父组件写一个 `handleVote(payload)`，`payload` 里带着 `id` 和 `type`。用最朴素的写法：先按 `id` 找到对应商品，再修改它的 `likes / dislikes`（对象字段的直接增减在这一步是可行的，更讲究的"不可变更新姿势"到第 5 章再系统学）：

```js
function handleVote({ id, type }) {
  const target = goods.value.find((item) => item.id === id)
  if (!target) return
  if (myAttitude.value[id] === type) {          // 取消赞/踩
    type === 'like' ? target.likes-- : target.dislikes--
    delete myAttitude.value[id]                 // 置回未投
  } else {
    if (myAttitude.value[id] === 'like') target.likes--
    if (myAttitude.value[id] === 'dislike') target.dislikes--
    type === 'like' ? target.likes++ : target.dislikes++
    myAttitude.value[id] = type                 // 记录当前态度
  }
}
```

> 锚点检查：父组件 `goods` 用 `ref` 声明，模板里 `@vote="handleVote"` 绑定后，点按钮数字能正确增/减——事件链路（子 → 父）就通了。

### Step 4：收藏按钮换成 v-model（回顾 4.7）

把收藏单独抽成小组件 `FavoriteStar`，内部用 `defineModel` 暴露一个布尔状态，自身只管"点击取反"：

```vue
<script setup>
const collected = defineModel('collected', { type: Boolean, default: false })
</script>
<template>
  <button :class="{ collected }" @click="collected = !collected">⭐ 收藏</button>
</template>
```

父组件使用：`<FavoriteStar v-model:collected="favorites[id]" />`——父组件只维护 `favorites` 状态，子组件点一下，父组件数据自动同步。

### Step 5：加一点"真实感"的界面

标题显示"口碑得分"、切换商品、已收藏的按钮高亮……把投票组件复用 3 次以上，每条数据独立验证。想一想：为什么这条链路上，props 向下、emit 向上、v-model 双向，各自只干自己那一件事？
