`props.xxx` 写多了嫌烦？很多人顺手解构：`const { name } = defineProps(...)`。可一旦在 `<script>` 里用解构后的变量做逻辑，父组件把 `name` 从"张三"改成"李四"，你拿到的还是旧值——响应式"断线"了。为什么模板解构没事、脚本却丢更新？本节讲透普通解构和 Vue 3.5 响应式解构的区别。

## 🤔 一、为什么要解构？

在 4.1 节我们学了：`<script>` 里访问 props 要写 `props.xxx`。

```vue
<script setup>
const props = defineProps(['name', 'age', 'role', 'avatar'])

// 每次用都要写 props. —— 烦不烦？
console.log(props.name)
console.log(props.age)
const displayName = props.name + ' (' + props.role + ')'
</script>
```

能不能像模板里一样直接写变量名？

```
<script setup>
defineProps(['name', 'age'])

// 我想要这样直接用
console.log(name)   // ❌ 不行，会报 undefined
</script>
```

模板里可以直接写，是因为 Vue 编译器帮你做了自动处理。但在 `<script>` 里，你得用 **ES6 解构** 来简化。

## 💡 二、普通解构 vs toRefs 解构

### 普通解构（会丢响应式）

```vue
<script setup>
import { ref } from 'vue'
const props = defineProps(['name'])

// ❌ 普通解构：name 变成普通字符串，跟 props 断开连接
const { name } = props
// 之后父组件改了 name，这里的 name 不会更新
</script>
```

**为什么？** ES6 解构本质是"取值然后赋值给新变量"——`const { name } = props` 等价于 `const name = props.name`。基础类型的值被复制了一份，新变量跟原对象无关。

### toRefs 解构（保持响应式）

```
<script setup>
import { toRefs } from 'vue'
const props = defineProps(['name', 'age'])

// ✅ toRefs 解构：每个变量变成 ref，跟 props 保持响应式连接
const { name, age } = toRefs(props)

// 现在可以像 ref 一样用 —— 但注意要 .value！
console.log(name.value)
console.log(age.value)
</script>
```

`toRefs(props)` 把 props 对象里的每个属性都转成一个独立的 `ref`，并且这些 ref **跟原 props 保持同步**——父组件改了 prop，这里的 ref 自动更新。

> 💬 **老师备注**：解构后变量变成 ref 了，所以在 `<script>` 里要用 `.value`，在 `<template>` 里不用（模板自动解包）。如果觉得又要写 `.value` 跟没解构差不多——确实，所以不是所有场景都推荐解构，后面会讲什么时候用。

### 🆕 Vue 3.5 响应式 Props 解构（推荐）

Vue 3.5 起，**响应式 Props 解构默认开启**——你可以直接用 JS 原生解构语法，同时保留响应式，而且默认值也用原生写法：

```vue
<script setup>
// ✅ Vue 3.5+：解构保持响应式，默认值用原生 JS 语法
const { count = 0, name = '匿名' } = defineProps({
  count: Number,
  name: String
})

// count 和 name 现在是响应式的，修改父组件传的值会自动同步到这里
// 不需要 toRefs、不需要 .value、不需要 import 任何东西
watchEffect(() => {
  console.log(`count 变为 ${count}, name 变为 ${name}`)  // 依赖自动追踪
})
</script>
```

**与老写法对比：**

| | Vue 3.4 及以前（toRefs） | Vue 3.5+（响应式解构） |
|---|---|---|
| 写法 | `const { count } = toRefs(props)` | `const { count = 0 } = defineProps({...})` |
| 访问值 | `count.value` | `count`（直接访问） |
| 默认值 | 只能在 `defineProps` 对象里写 `default` | 原生 JS：`count = 0` |
| 需要 import | `import { toRefs } from 'vue'` | 不需要 |

> 💬 **老师备注**：这是 Vue 3.5 的重要升级——终于不用在 `toRefs` 和 `.value` 之间纠结了。本书后续章节默认使用这种写法。如果你的项目还是 3.4.x，升级到 3.5+ 即可使用，所有 3.4 代码完全兼容。

## 💡 三、defineProps 的对象语法

学到了第 4 章，该给你的 props 加点"规矩"了。数组写法只能声明名字，对象写法可以做更多事：

```
<script setup>
const props = defineProps({
  // 基础：只指定类型
  name: String,

  // 带默认值
  age: {
    type: Number,
    default: 18
  },

  // 必填
  email: {
    type: String,
    required: true
  },

  // 自定义校验
  role: {
    type: String,
    validator(value) {
      return ['admin', 'user', 'guest'].includes(value)
    }
  }
})
</script>
```

**对象语法支持的配置项**：

| 配置项 | 作用 | 示例 |
|---|---|---|
| `type` | 类型校验 | `String`、`Number`、`Boolean`、`Array`、`Object`、`Function` |
| `default` | 默认值 | `default: 18` 或 `default: () => []`（数组/对象必须用工厂函数） |
| `required` | 是否必填 | `required: true` |
| `validator` | 自定义校验函数 | `validator: (v) => v > 0` |

> 💬 **老师备注**：数组和对象的 `default` 必须用**工厂函数**——`default: () => []` 而不是 `default: []`。因为 Vue 需要为每个组件实例创建独立的数据副本，直接写 `[]` 会让所有实例共享同一个数组。

## 🛠 四、完整可运行示例：用户资料表单

```vue
<!-- ProfileCard.vue -->
<script setup>
import { computed } from 'vue'

// 🆕 Vue 3.5+ 响应式解构：直接用原生解构 + 原生默认值
const {
  username,
  level = 1,
  tags = [],
  bio = '这个人很懒，什么都没写...'
} = defineProps({
  username: {
    type: String,
    required: true
  },
  level: {
    type: Number,
    default: 1
  },
  tags: {
    type: Array,
    default: () => []    // 数组必须用工厂函数
  },
  bio: {
    type: String,
    default: '这个人很懒，什么都没写...'
  }
})

// 派生值：根据等级显示不同的徽章（直接访问，不需要 .value）
const badge = computed(() => {
  if (level >= 50) return '🏆 大神'
  if (level >= 20) return '⭐ 活跃'
  return '🌱 新手'
})

// 派生值：标签列表
const tagList = computed(() => {
  return tags.length > 0
    ? tags.join(' · ')
    : '暂无标签'
})
</script>

<template>
  <div class="profile-card">
    <h2>{{ username }} <span class="badge">{{ badge }}</span></h2>
    <p class="level">Lv.{{ level }}</p>
    <p class="tags">{{ tagList }}</p>
    <p class="bio">{{ bio }}</p>
  </div>
</template>
```

## ⚠️ 五、常见陷阱

### 陷阱 1：解构后忘了 `.value`（仅限 Vue 3.4 及以前的老写法）

```vue
<script setup>
import { toRefs } from 'vue'
const props = defineProps(['name'])
const { name } = toRefs(props)

// ❌ 错误：打印的是 Ref 对象，不是值
console.log(name)

// ✅ 正确
console.log(name.value)
</script>
```

> 💬 **Vue 3.5+ 已解决**：响应式解构默认开启，直接访问变量即可，不需要 `.value`。如果你还在用 `toRefs`，建议升级到 3.5+。

### 陷阱 2：数组/对象的 default 没用工厂函数

```
<!-- ❌ 所有实例共享同一个数组 -->
defineProps({
  tags: { type: Array, default: [] }
})

<!-- ✅ 每个实例独立创建 -->
defineProps({
  tags: { type: Array, default: () => [] }
})
```

### 陷阱 3：不需要响应式时还用 toRefs（仅限老写法）

如果你只是读一次 props 值（比如在 `console.log` 里打印），直接解构就行，不需要 toRefs：

```vue
const props = defineProps(['name'])
// 只读一次，可以不解构或直接解构
console.log(props.name)
const { name } = props   // 不响应也没关系，反正只读一次
```

> 💬 **Vue 3.5+ 已解决**：响应式解构统一处理，不需要区分场景——直接 `const { name } = defineProps(['name'])` 就是响应式的。

## 🧠 本节小结

- **解构能省代码**：`const { name } = defineProps(...)` 后脚本里不用再写 `props.` 前缀
- **普通解构会丢响应式**：基础类型被"快照"，父组件更新后拿到的还是旧值
- **保持响应式的老写法**：`toRefs(props)` 把每个属性转成独立 ref，解构后仍是响应式连接（Vue 3.4 及以前）
- **Vue 3.5+ 新写法**：响应式 Props 解构默认开启，`const { count = 0 } = defineProps({...})` 原生支持默认值，不需要 toRefs、不需要 `.value`
- **defineProps 对象语法**：用 `type`/`default`/`required`/`validator` 声明类型、默认值与校验规则
