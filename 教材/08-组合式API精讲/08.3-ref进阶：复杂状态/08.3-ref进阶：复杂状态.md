## 🤔 一、ref 包对象：深层响应式的代价

前几章已经知道：`ref` 包对象时，Vue 内部会调用 `reactive` 处理对象，实现**深层响应式**：

```js
const user = ref({
  name: '张三',
  address: { city: '北京', district: '海淀' }
})

// 深层修改也会触发更新
user.value.address.city = '上海'  // ✅ 页面会更新
```

这对大多数场景是好事——你怎么改都能感知到。但有一个代价：**Vue 要对整个对象树做 Proxy 代理**。如果对象很大（比如一个包含 10000 条数据的列表），初始化时会有明显的性能开销。

---

## 💡 二、shallowRef：浅层响应式

当你有一个很大的数据对象，**只需要关心"整个对象是否被替换"而不关心内部属性变化**时，就用 `shallowRef`：

```js
import { shallowRef } from 'vue'

const bigList = shallowRef([
  { id: 1, name: '张三' },
  { id: 2, name: '李四' },
  // ... 还有 9998 条
])

// ✅ 会触发更新：整个 .value 被换掉了
bigList.value = newDataFromServer

// ❌ 不会触发更新：只改了内部某个元素的属性
bigList.value[0].name = '王五'  // 页面不变！
```

`shallowRef` 的核心逻辑：**只追踪 `.value` 本身被替换的情况，不追踪 `.value` 内部属性的变化**。

### 什么时候用 shallowRef？

| 场景 | 原因 |
|---|---|
| **大数据量列表** | 避免深层 Proxy 开销 |
| **第三方库的对象** | 你不需要 Vue 去代理别人的对象 |
| **只做整体替换** | 数据每次从服务端拿新数据，直接 `.value = 新数据` |

## 🔑 三、triggerRef：手动触发更新

如果用了 `shallowRef`，改了内部属性后想手动通知视图更新，用 `triggerRef`：

```vue
<script setup>
import { shallowRef, triggerRef } from 'vue'

const list = shallowRef([
  { id: 1, done: false },
  { id: 2, done: false }
])

function toggleDone(index) {
  // 直接改内部属性
  list.value[index].done = !list.value[index].done
  // 手动通知 Vue："这个 shallowRef 的内部变了，重新渲染！"
  triggerRef(list)
}
</script>

<template>
  <div v-for="(item, i) in list" :key="item.id">
    <span :class="{ done: item.done }">{{ item.id }}</span>
    <button @click="toggleDone(i)">切换</button>
  </div>
</template>
```

> 💬 **老师备注**：`triggerRef` 是一种"手动挡"操作，大多数时候你不需要它。知道有这个东西就行——当你遇到 "shallowRef 改了数据但页面不更新" 又不想转 ref 时，用它。

## 🛠 四、toRef 和 toRefs：在 ref 体系中解构

### 4.1 toRef：给 reactive 对象的某个属性"绑一个 ref"

```js
import { reactive, toRef } from 'vue'

const state = reactive({ count: 0, name: 'Vue' })

// 给 state.count 挂一个 ref 引用
const countRef = toRef(state, 'count')

// 改 countRef.value 等于改 state.count
countRef.value++
console.log(state.count)  // 1

// 反过来也成立
state.count++
console.log(countRef.value)  // 2
```

`toRef` 创建的是一个**双向绑定**：你改 ref，原对象跟着变；你改原对象，ref 也跟着变。它不是复制，而是引用。

### 4.2 toRefs：一键全转

```js
import { reactive, toRefs } from 'vue'

const state = reactive({ count: 0, name: 'Vue' })

// 把 state 的所有属性转成 ref
const { count, name } = toRefs(state)
// 等价于：
// const count = toRef(state, 'count')
// const name = toRef(state, 'name')

// 解构后安全使用
count.value++  // state.count 同步更新
```

这是在 composable 中返回 reactive 对象时的标准做法：

```js
// useUser.js
export function useUser() {
  const state = reactive({ name: '张三', age: 20 })
  // 返回 toRefs 后的结果，调用方安全解构
  return { ...toRefs(state) }
}
```

## ⚠️ 五、常见陷阱

### 陷阱 1：shallowRef 改成 .value 整个替换时触发两次更新

```js
const obj = shallowRef({ a: 1 })
obj.value = { a: 1 }  // ✅ 触发更新（整个对象换了）
obj.value = obj.value  // ❌ 不会触发（引用没变）
obj.value = { ...obj.value }  // ✅ 触发（新对象）
```

### 陷阱 2：toRef 只在 reactive 对象上有意义

```js
const plain = { count: 0 }
const r = toRef(plain, 'count')  // ❌ 不会响应式
```

`toRef` 依赖原对象已经是响应式的。普通对象传进去，返回的 ref 改了也不会触发视图更新。

### 陷阱 3：toRef 不等于 ref 复制

```js
const state = reactive({ count: 0 })
const copy = ref(state.count)   // 复制：值断开连接
const link = toRef(state, 'count')  // 引用：双向绑定
```

- `ref(state.count)`：创建了一个独立的 ref，初始值是 0，和 `state.count` 不再有关系
- `toRef(state, 'count')`：创建了一个指向 `state.count` 的引用，它们永远同步

## 🧠 本节小结

- **ref 包对象默认深层响应**：对象里任意层级属性修改都能触发更新，代价是每个嵌套属性都走 Proxy
- **读写姿势**：JS 里 `ref.value.user.name` 逐层取值；模板中对象 ref 只自动解包到 `.value` 一层
- **整体替换最稳**：给 `ref.value` 赋新对象/新数组是标准姿势，直接替换不会丢响应
- **解构有坑**：`const { name } = ref.value` 会丢响应，用 `toRef`/`toRefs` 保住引用关系
- **toRef vs 新建**：`ref(state.count)` 是独立副本；`toRef(state, 'count')` 与原属性永远同步
