## 📝 一、即时练习

3 个练习覆盖了交易订单模块最常用的三个能力：**文件下载、状态变更、条件查询**。每个都附「需求拆解 → 参考骨架 → 验收清单」。

### 练习 1：导出交易订单 Excel

**需求拆解**：
1. 在交易订单列表页顶栏加"导出"按钮，点击后调用后端接口 `/orders/export`；
2. Axios 请求设置 `responseType: 'blob'`——后端返回的是二进制流，不是 JSON，不设置会得到一堆乱码文本；
3. 拿到 blob 后用 `URL.createObjectURL` 创建临时链接、`a.click()` 触发下载、最后 `URL.revokeObjectURL` 释放内存；
4. 处理好"导出当前筛选条件"和"导出为空"两种场景。

**参考实现骨架**：

```js
// src/api/order.js
export const exportOrders = (params) => {
  return request({
    url: '/orders/export',
    method: 'get',
    params,
    responseType: 'blob'   // ✅ 关键：告诉 Axios 按二进制流接收
  })
}
```

```js
// api/order.js —— 导出接口要单独设置 responseType
// ⚠️ 文件下载必须用 responseType: 'blob'，否则拿到的还是 JSON
export const exportOrders = (params) => {
  return request.get('/orders/export', {
    params,
    responseType: 'blob'      // ← 关键：告诉 Axios 这是二进制
  })
}
```

```js
// OrderList.vue 中的导出逻辑
import { exportOrders } from '@/api/order'

const handleExport = async () => {
  try {
    const res = await exportOrders(currentQuery)   // 带上当前筛选条件

    // ⚠️ 关键：res 是「完整的响应对象」还是「被剥壳的 data」？
    // 取决于你的响应拦截器做了什么（见下方说明）：
    //   - 拦截器 return response.data        → res 就是 data（Blob），没有 headers
    //   - 拦截器 return response（不剥壳）    → res.headers 和 res.data 都在
    // 本书 12.7 的封装是 return response.data，所以下面这样拿：
    const blob = res instanceof Blob ? res : new Blob([res])

    // ① 文件名：Blob 下载时前端拿不到后端定的名字，用自己的即可
    // （想读后端的名字，得用「不剥壳」的 response，复杂度不值当）
    const filename = `交易订单导出_${new Date().toISOString().slice(0, 10)}.xlsx`

    // ② 创建临时链接触发下载
    const url = URL.createObjectURL(blob)
    const link = document.createElement('a')
    link.href = url
    link.download = filename
    link.click()

    // ③ 释放内存（不释放会累积内存泄漏）
    URL.revokeObjectURL(url)
    ElMessage.success('导出成功')
  } catch (e) {
    ElMessage.error('导出失败')
  }
}
```

> ⚠️ **老师备注：文件下载是"拦截器剥壳"最容易翻车的地方**
>
> 本书 12.7 的响应拦截器统一 `return response.data`，意思是"把响应壳剥掉，只给业务数据"。这对普通 JSON 接口很方便，但**文件下载需要两个东西**：`res.data`（文件内容）和 `res.headers`（文件名）。剥了壳之后 `res.headers` 就是 `undefined`。
>
> 三种处理方式：
> 1. **简单做法（推荐初学者）**：像上面这样，在拦截器里给 `responseType === 'blob'` 开个特例，返回完整 response
> 2. **绕过拦截器**：用 `axios.get(url, { responseType:'blob' })` 直接调，不走封装实例
> 3. **不读后端文件名**：直接自己起名（上面的写法），这样就完全不需要 headers
>
> 另外记得：**接口要设 `responseType: 'blob'`**，否则后端返回的二进制会被当成字符串解析，得到一堆乱码。

**验收清单**：

- [ ] 点击"导出"能下载到一份 Excel 文件，且内容与当前列表一致
- [ ] 文件能正常打开，不是乱码（说明 `responseType: 'blob'` 设置成功）
- [ ] 文件名来自后端 `content-disposition`（拿不到时回退到默认名）
- [ ] 筛选了日期/状态后导出，导出内容也按相同条件过滤
- [ ] 导出为空数据时不报错，能给用户"暂无数据可导出"的提示（进阶）
- [ ] 导出按钮有 loading 状态，防止重复点击

### 练习 2：详情弹窗内修改状态

**需求拆解**：
1. 在 `OrderDetailDialog.vue` 的状态展示处，把只读的 `el-tag` 换成 `el-select`（或保留 Tag、另加一个下拉框）；
2. 选项来自 12.14 定义的 `ORDER_STATUS_OPTIONS`（如 待付款/已付款/已发货/已完成/已取消）；
3. 选中新状态后调用 `updateOrderStatus(id, status)`；
4. 成功后：更新本地状态、`ElMessage.success` 提示、`emit` 事件通知父组件刷新列表。

**参考实现骨架**：

```vue
<!-- OrderDetailDialog.vue -->
<el-descriptions-item label="交易订单状态">
  <el-select
    :model-value="orderDetail.status"
    placeholder="请选择状态"
    @change="handleStatusChange"
  >
    <el-option
      v-for="opt in ORDER_STATUS_OPTIONS"
      :key="opt.value"
      :label="opt.label"
      :value="opt.value"
    />
  </el-select>
</el-descriptions-item>
```

```js
import { updateOrderStatus } from '@/api/order'
import { ORDER_STATUS_OPTIONS } from '@/constants/orderStatus'

const emit = defineEmits(['refresh'])

const handleStatusChange = async (newStatus) => {
  const oldStatus = orderDetail.value.status
  try {
    await updateOrderStatus(orderDetail.value.id, newStatus)
    orderDetail.value.status = newStatus      // 本地立即更新
    ElMessage.success(`状态已从「${getStatusLabel(oldStatus)}」改为「${getStatusLabel(newStatus)}」`)
    emit('refresh')                            // 通知父组件刷新列表
  } catch {
    // 失败：保持原状态，el-select 通过 model-value 自动回显
    ElMessage.error('状态修改失败')
  }
}
```

**验收清单**：

- [ ] 详情弹窗里能打开状态下拉框，选项与 12.14 定义一致
- [ ] 选择新状态后调用接口，成功才更新本地状态
- [ ] 成功后弹提示，并通知父组件刷新列表（列表里的状态同步变化）
- [ ] 接口失败时下拉框回显原状态，不产生"前端改了、后端没改"的假象
- [ ] 修改状态期间按钮/下拉框有防重复提交处理（loading 或禁用）

### 练习 3：按日期范围筛选

**需求拆解**：
1. 在交易订单列表筛选区加 `el-date-picker`，类型 `daterange`，绑定 `dateRange` 数组；
2. 选择范围后，拆成 `startDate` / `endDate` 传给后端（或直接传 `startDate`/`endDate` 两个参数）；
3. 参考 12.14 的筛选逻辑：**日期变化时重置 `pagination.pageNum` 为 1**；
4. 值为空时不传参数给后端（后端拿 `''` 做过滤会查不出数据）。

**参考实现骨架**：

```vue
<el-date-picker
  v-model="dateRange"
  type="daterange"
  range-separator="至"
  start-placeholder="开始日期"
  end-placeholder="结束日期"
  value-format="YYYY-MM-DD"
  @change="handleDateChange"
/>
```

```js
const dateRange = ref([])

const handleDateChange = () => {
  pagination.pageNum = 1// 筛选条件变化 → 回到第一页
  fetchList()
}

// fetchList 组装参数：空值不传
const fetchList = async () => {
  const params = {
    pageNum: pagination.pageNum,
    pageSize: pagination.pageSize
  }
  if (dateRange.value?.length === 2) {
    params.startDate = dateRange.value[0]
    params.endDate = dateRange.value[1]
  }
  // 其他筛选条件（keyword / status）同理...
  const res = await getOrderList(params)
  tableData.value = res.data.list
  pagination.total = res.data.total
}
```

> 📌 **命名沿用 12.14**：`tableData` 存列表、`pagination` 是 `{ pageNum, pageSize, total }` 这个 `reactive` 对象。**每个筛选器（关键词 / 状态 / 日期）都要重置 `pagination.pageNum = 1`**，这是本章反复强调的那条纪律。

**验收清单**：

- [ ] 能选择起止日期，选择后列表按日期范围过滤
- [ ] 选择日期后页码重置为 1（从第 5 页筛选后不会停留在空页）
- [ ] 清空日期范围后恢复全部交易订单
- [ ] 参数以 `YYYY-MM-DD` 格式传给后端，空值不传
- [ ] 与状态筛选、关键词搜索能组合使用

## 🚀 二、进阶挑战

**挑战 1：导出文件名带日期 + 空数据拦截**

升级练习 1：导出时自动把导出日期拼进文件名（如 `交易订单导出_2026-08-28.xlsx`）；后端返回的 blob 为空时，用 `res.data.size === 0` 拦截并提示"暂无数据可导出"，避免下载一个打不开的空文件。

提示：`new Blob([res.data]).size` 可以判断 blob 是否为空；文件名里不要带 `:` 等非法字符。

**挑战 2：状态流转合法性校验**

交易订单状态不是随便改的——"已发货"不能改回"已付款"，"已完成"不能改回"已发货"。请为 12.15 的 `handleShip` 和练习 2 的下拉框加一层**状态机校验**：定义每个状态允许流转到哪些状态（如 `已付款 → [已发货, 已取消]`），不允许的流转直接提示"当前状态不能直接变更为 X"。

提示：在 `orderStatus.js` 里维护一张 `ORDER_STATUS_TRANSITIONS` 映射表；前端校验拦截后，后端接口最好也做同样的校验（前端校验是体验，后端校验才是安全）。

验收：从"已发货"尝试改回"已付款"会被拦截并给出明确提示；合法流转（已付款→已发货）正常通过。

<details>
<summary>💡 深究一下：blob 下载的完整姿势</summary>

练习里用 `responseType: 'blob'` 下载文件，标准流程是：

```js
const res = await downloadOrderFile(id)   // responseType: 'blob'
const url = URL.createObjectURL(res.data)
const a = document.createElement('a')
a.href = url
a.download = '订单导出.xlsx'               // 指定文件名
a.click()
URL.revokeObjectURL(url)                   // 用完释放
```

两个坑：**文件名别硬编码**（后端常在 `Content-Disposition` 里返回，解析出来再用）；**blob URL 用完必须 revoke**，否则内存泄漏。这和 12.9 图片预览的 `createObjectURL` 是同一套 API——"临时 URL 用完即焚"是前端基本功。
