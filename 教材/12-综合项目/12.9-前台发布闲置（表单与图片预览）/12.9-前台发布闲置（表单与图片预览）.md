## 🎯 学习目标

## 🧠 思维导图

```text
12.9 前台发布闲置（表单与图片预览）
├── 页面位置
│   └── views/front/PublishView.vue（路由 /publish，需要登录）
├── 表单数据
│   └── form 对象：title / category / price / condition / desc / images[]
├── 校验（第 10 章）
│   ├── el-form :model + :rules
│   └── 提交前 await formRef.validate()
├── 图片预览（不上传）
│   ├── input[type=file] / el-upload 拦截
│   ├── URL.createObjectURL(file) → 预览地址
│   └── 关闭 / 组件卸载时 revokeObjectURL 释放
└── 提交
    ├── 校验通过 → 组装新对象、生成 id
    ├── 本地 unshift 到列表（普通数组，无 .value）→ router.push('/home') 可见
    └── 12.11 接口就绪后替换为 POST /goods
```

12.4 到 12.8 走完了"逛 → 看 → 登录"这条主线，但集市里不能只有买家——**人人都是卖家**，校园二手集市的灵魂就在"发布"两个字上。这节我们把第 10 章的表单处理与验证，落到一个真实业务页上：发布闲置。它要能收集字段、拦得住空标题和负数价格、能选图并立刻看到预览，提交后回到首页还能马上看到自己刚发的东西。

> 🎯 **类比一下：发布闲置 ≈ 闲鱼摆摊的第一课**
> 摆摊的"门面"三件套：**摊位信息写清楚**（标题/分类/价格/成色，对应表单校验）、**商品图拍好看**（本地预览，对应 `URL.createObjectURL`）、**收摊前清点**（关闭预览释放内存，对应 `revokeObjectURL`）。这节就是教你"把摊摆起来"——不真的上传图片，是因为课程没有后端，先把前端该干的活干漂亮。

> 🧑 **小白**：`URL.createObjectURL(file)` 生成的预览地址用完为什么要 `revokeObjectURL` 释放？
> 🤖 **Vue 君**：因为每调用一次 `createObjectURL` 都会**占用一块浏览器内存**，不释放的话发 100 次图就白占 100 块内存，页面会越来越卡。**用完即释放**是这类 API 的纪律。
> 👨🏫 **老湿**：**发布页 = 表单验证的"毕业考"**：必填、长度、价格 >0、最多两位小数、图片数量上限——把第 10 章的校验规则用到真实业务里。**空标题和负数价格拦不住，这个功能就是摆设**。

## 🤔 一、先把"发布闲置"要收的东西列清楚

一个闲置要挂到集市上，最少要交代五件事，再加图片：

| 字段 | 类型 | 校验要求 |
|---|---|---|
| `title` | 字符串 | 必填，3~30 字 |
| `category` | 字符串 | 必选（数码电子 / 教材书籍 / 生活用品 / 运动户外 / 其他） |
| `price` | 数字 | 必填，大于 0，最多两位小数 |
| `condition` | 字符串 | 必选（全新 / 九成新 / 八成新 / 有使用痕迹） |
| `desc` | 字符串 | 选填，最多 200 字 |
| `images` | 数组 | 最多 3 张，本地预览 |

### 1.1 为什么这节的图片"不真的上传"？

真实的图片上传要配后端（对象存储、上传接口、回传 URL），而本课程全程没有真实后端。所以这里把重点放在**前端职责**上：选文件 → 校验体积与格式 → 生成预览地址给用户看。等你有后端时，只需在"确认提交"那一步把 `File` 对象塞进 `FormData` 发出去，预览逻辑一行都不用改。

> 💬 **老师备注**：面试问"图片上传怎么做的"，答"选择即本地预览、提交时才上传、用 `URL.createObjectURL` 不占内存读文件"，比背 `el-upload` 属性表更打动人。

## 💡 二、用 `v-model` 把表单数据收进一个对象

先建页面骨架。注意：发布页是"要登录才能进"的页面，12.3 的守卫已经会给 `/publish` 加 `meta.requiresAuth`，这里不用重复判断。

```vue
<!-- src/views/front/PublishView.vue -->
<script setup>
import { reactive, ref } from 'vue'
import { useRouter } from 'vue-router'

const router = useRouter()

// 1. 一个对象装下所有字段，模板里 v-model 直接绑到字段上
const form = reactive({
  title: '',
  category: '',
  price: null,
  condition: '九成新',
  desc: '',
  images: []      // 存放 { file, url } 预览项
})

const formRef = ref(null)   // 拿 el-form 实例，用于 validate / resetFields
</script>
```

```vue
<template>
  <div class="publish-page">
    <h2>发布闲置</h2>

    <el-form ref="formRef" :model="form" :rules="rules" label-width="80px">
      <el-form-item label="标题" prop="title">
        <el-input v-model="form.title" placeholder="例如：九成新《C语言程序设计》" />
      </el-form-item>

      <el-form-item label="分类" prop="category">
        <el-select v-model="form.category" placeholder="请选择分类">
          <el-option v-for="c in categories" :key="c" :label="c" :value="c" />
        </el-select>
      </el-form-item>

      <el-form-item label="价格" prop="price">
        <el-input-number v-model="form.price" :min="0.01" :precision="2" />
      </el-form-item>

      <el-form-item label="成色" prop="condition">
        <el-radio-group v-model="form.condition">
          <el-radio v-for="c in conditions" :key="c" :value="c">{{ c }}</el-radio>
        </el-radio-group>
      </el-form-item>

      <el-form-item label="描述" prop="desc">
        <el-input v-model="form.desc" type="textarea" :rows="4" maxlength="200" show-word-limit />
      </el-form-item>

      <el-form-item label="图片">
        <!-- 图片预览部分下一节讲 -->
      </el-form-item>

      <el-form-item>
        <el-button type="primary" @click="handleSubmit">确认发布</el-button>
        <el-button @click="formRef.resetFields()">重置</el-button>
      </el-form-item>
    </el-form>
  </div>
</template>
```

要点：

- `form` 用 `reactive` 而不是一堆 `ref`——字段多的时候，模板里 `v-model="form.title"` 比 `v-model="title"` 更好读，提交时也能整体拿走。
- `el-form` 必须同时给 `:model="form"` 和 `:rules="rules"`，`el-form-item` 上用 `prop` 指明"这一项校验哪个字段"，三者缺一校验就是摆设（第 10 章踩过的坑）。

## 🛠 三、校验规则：把第 10 章搬进业务

```js
const categories = ['数码电子', '教材书籍', '生活用品', '运动户外', '其他']
const conditions = ['全新', '九成新', '八成新', '有使用痕迹']

const rules = {
  title: [
    { required: true, message: '标题不能为空', trigger: 'blur' },
    { min: 3, max: 30, message: '标题 3~30 字', trigger: 'blur' }
  ],
  category: [{ required: true, message: '请选择分类', trigger: 'change' }],
  price: [
    { required: true, message: '价格不能为空', trigger: 'change' },
    { type: 'number', min: 0.01, message: '价格必须大于 0', trigger: 'change' }
  ],
  condition: [{ required: true, message: '请选择成色', trigger: 'change' }]
}
```

> 💬 **老师备注**：`trigger` 按控件类型选——输入框用 `blur`（失焦才提示，别边打字边报红），选择器、数字框用 `change`。把两者写反，用户会在还没选就被提示"请选择分类"。

### 3.1 提交时再校验一次

`validate()` 返回 Promise，**校验不通过会 reject**，所以要 `try/catch` 或者用回调写法：

```js
async function handleSubmit() {
  try {
    await formRef.value.validate()          // 不通过就抛错，直接进 catch
  } catch {
    return                                   // 页面已经标红了，什么都不做
  }

  const newGoods = {
    id: Date.now(),                          // 本地临时 id
    ...form,                                 // title/category/price/condition/desc
    cover: form.images[0]?.url || '',        // 第一张图当封面
    seller: '我',
    createdAt: new Date().toLocaleDateString()
  }

  // ⚠️ goodsList 是 12.4 导出的「普通数组」（不是 ref），所以没有 .value
  // 普通数组是可以直接 unshift 的 —— 这正是 3.3 讲的：Vue 3 数组随便改都触发
  goodsList.unshift(newGoods)                // 先塞进本地列表（见第四节）
  ElMessage.success('发布成功！')
  router.push('/home')                // 回首页（路由见 12.3 终版路由表）
}
```

## 🔑 四、图片预览：选完就能看，看完要"还"

用原生 `input[type=file]` 也能做，但既然项目已经用了 Element Plus，就用 `el-upload` 的"手动模式"——**拦截自动上传**，只拿文件对象：

```vue
<script setup>
// 选文件 → 校验 → 生成预览地址
function handleFileChange(uploadFile) {
  const file = uploadFile.raw

  if (!file.type.startsWith('image/')) {
    ElMessage.error('只能选择图片')
    return
  }
  if (file.size > 5 * 1024 * 1024) {
    ElMessage.error('单张图片不能超过 5MB')
    return
  }
  if (form.images.length >= 3) {
    ElMessage.warning('最多 3 张图片')
    return
  }

  // 关键一行：把 File 变成浏览器能显示的 blob URL
  form.images.push({ file, url: URL.createObjectURL(file) })
}

// 删除预览：既要从数组移除，也要释放地址
function removeImage(index) {
  URL.revokeObjectURL(form.images[index].url)
  form.images.splice(index, 1)
}

// 组件卸载时兜底释放所有未释放的地址
onBeforeUnmount(() => {
  form.images.forEach(img => URL.revokeObjectURL(img.url))
})
</script>
```

```vue
<template>
  <el-upload
    :auto-upload="false"                  <!-- 核心：不自动发请求 -->
    :show-file-list="false"
    accept="image/*"
    :on-change="handleFileChange"
  >
    <el-button>选择图片</el-button>
  </el-upload>

  <div class="preview-list">
    <div v-for="(img, i) in form.images" :key="img.url" class="preview-item">
      <img :src="img.url" alt="预览图" />
      <el-button size="small" text type="danger" @click="removeImage(i)">删除</el-button>
    </div>
  </div>
</template>
```

三句话记住这段：

1. **`auto-upload=false`**：`el-upload` 默认选完就 POST，我们没后端，必须关掉，改成"只交文件"。
2. **`URL.createObjectURL(file)`**：把大图片"映射"成一个 `blob:` 开头的临时地址，浏览器直接能渲染，**不读进内存、不转 base64**，比 `FileReader` 快得多。
3. **必须 `revokeObjectURL`**：临时地址会一直占着内存直到页面关闭。用户删图、切页面时手动释放，是这个 API 唯一的纪律。

> 💬 **老师备注**：别用 base64 预览——一张 4MB 的图转成 base64 变 5.3MB 字符串塞进 `src`，页面立刻卡。这是学生作品最常见的性能问题第一名。

## ⚠️ 五、常见陷阱

### 陷阱 1：只在按钮上写校验，直接回车就绕过去了

```js
// ❌ 只靠点击校验，用户按回车表单就提交了
<el-button @click="submit">提交</el-button>

// ✅ el-form 上用 @submit.prevent="handleSubmit" 兜住回车，且校验统一走 validate()
<el-form @submit.prevent="handleSubmit" ...>
```

### 陷阱 2：预览地址用完不释放

```js
// ❌ 删了图，blob URL 还在内存里躺着
form.images.splice(i, 1)

// ✅ 先释放，再移除
URL.revokeObjectURL(form.images[i].url)
form.images.splice(i, 1)
```

### 陷阱 3：发布后首页看不到新商品

**先看两种典型报错**：

| 你会看到的 | 真实原因 |
|---|---|
| `TypeError: Cannot read properties of undefined (reading 'unshift')` | `goodsList` 是 12.4 导出的**普通数组**，不是 `ref`，所以**不能写 `.value`** |
| 发布成功了，跳首页却没看到 | 两个页面各自 `import` 了**不同的数据副本** |

**正确做法：数据源必须唯一。** 12.4 的 mock 数据已经抽到 `src/data/goods.js` 里，发布页和首页 `import` 的必须是**同一个数组**：

```js
// src/data/goods.js —— 单一数据源
export const goodsList = [ /* ... */ ]
export const GOODS_CATEGORIES = [...]
export const PRICE_RANGES = [...]
```

```js
// 12.4 首页 和 12.9 发布页 —— 都这样 import，拿到的是同一个数组引用
import { goodsList } from '@/data/goods'
```

因为是同一个数组对象，发布页 `unshift` 之后，首页读到的也是最新的数据。

> 💬 **老师备注**：这就是"先本地、后接口"的代价与解法——**数据源必须唯一**。等12.11 接口就绪，把这段替换成"提交成功后重新拉取列表"就彻底解决了，这也是企业里的标准做法（提交 → 让列表缓存失效 → 重新请求）。

> ⚠️ **另一个容易忽略的坑**：`unshift` 改的是**同一个数组**，但如果首页是用 `computed(() => goodsList.filter(...))` 派生的，它确实会跟着重算（`filter` 读取了 `goodsList` 的内容）。可如果你在首页写了 `const sorted = computed(() => goodsList.slice(0, 10))` 之类**只在初始化时读一次**的逻辑，就又看不到了。**记住判断标准：computed 内部有没有真的读到那个数组。**

## 🧠 本节小结

- **发布页就是个"表单 + 校验 + 预览"的组合**：字段收进一个 `reactive` 对象，模板 `v-model` 绑定，提交前统一 `await formRef.validate()`
- **校验三件套缺一不可**：`el-form :model` + `:rules` + `el-form-item prop`，`trigger` 按控件类型选
- **图片预览的关键三句**：`auto-upload=false` 只收文件、`URL.createObjectURL` 生成预览、`revokeObjectURL` 及时释放
- **数据源唯一原则**：发布页和首页必须读写同一份数据，否则"发完看不见"；接口就绪后改为提交成功再重新拉取
- **发布是集市的生命线**：没有发布功能的二手平台，只是个展示柜

## 🔥 冷知识 / 小灶

- **`URL.createObjectURL` 生成的是 `blob:` 开头的临时地址**，只在当前页面会话内有效，刷新就失效——所以它只适合"本地预览"，不适合当永久图片链接存进数据库。

<details>
<summary>💡 深究一下：预览图片还有别的方案吗？</summary>

除了 `createObjectURL`，老方案是 `FileReader.readAsDataURL`：

```js
// FileReader 方案：把文件读成 base64 字符串
const reader = new FileReader()
reader.onload = (e) => { preview.value = e.target.result }  // data:image/png;base64,...
reader.readAsDataURL(file)
```

对比：

| 方案 | 内存占用 | 适用 |
|---|---|---|
| `URL.createObjectURL` | 轻（引用原文件） | 预览大图、频繁操作（推荐） |
| `FileReader` base64 | 重（体积膨胀约 33%） | 小图、需要把内容真正读进内存 |

两者都要"用完释放"（`revokeObjectURL` / 主动清空），本节的预览方案已经是**性能更优**的那条路了。

</details>
