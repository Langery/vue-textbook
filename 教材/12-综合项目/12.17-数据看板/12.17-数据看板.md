交易订单模块教会你"管数据"，登录后的第一屏却要"看数据"——看板把这些数字变成一眼能读懂的卡片和图表。这节用 ECharts 集成打开第三个技术面：`onMounted` 里 init、数据变化 `watch` 后 setOption、卸载前 `dispose`；同屏 6 个互不依赖的接口用 `Promise.all` 并发拉取，再分发到 StatCard / 图表子组件。

> 🎯 **类比一下：数据看板 ≈ 驾驶舱的仪表盘**
> 飞行员不会盯着几十份原始报告，仪表盘把速度、油量、高度**浓缩成一眼能扫完的指针与数字**；老板也不看数据库，看板把"今日销售额、闲置物品总数、交易订单量"**拍在脸上**。本节训练的本质不是画图表，而是**把一堆接口的原始数据，整理成人能秒懂的信息层级**——这正是前端工程师在真实项目里的日常。

> 🧑 **小白**：四个统计卡片 + 两个图表，要请求 6 个接口，挨个 `await` 会不会太慢？
> 🤖 **Vue 君**：会！串行等待 6 个接口 = 慢 6 倍。用 `Promise.all` **并发请求**，6 个一起发、最快那个先回，整体只花"最慢接口"的时间——这是多接口页面的标准优化。
> 👨🏫 **老湿**：**ECharts 三步走别记反**：`onMounted` 里 `init`（图表挂载后才有 DOM）、数据变化 `watch` 后 `setOption`（别在 init 前 set）、卸载前 `dispose`（否则内存泄漏、页面越切越卡）。组件拆分 `StatCard / SalesChart / OrderChart` 也是"数据分发"的经典练习。

## 🤔 一、看板的作用：一眼看清全局

登录管理后台后，用户看到的第一个页面就是看板（Dashboard）。它不像闲置物品管理那样做精细操作，而是用卡片和图表把最关键的数据"拍在脸上"——**一眼看清今天发生了什么**。

典型的数据看板包含两类元素：

| 元素类型 | 示例 | 特点 |
|---|---|---|
| 统计卡片 | 闲置物品总数、今日交易订单、今日销售额 | 一个数字 + 标签，一目了然 |
| 趋势图表 | 近 7 天销售额折线图、交易订单量柱状图 | 展示变化趋势，帮助决策 |

对我们课程来说，看板的训练价值在于：**在同一个页面中并发请求多个接口、将数据分发给不同子组件、集成第三方图表库**——这是真实项目中每天都在做的事。

## 💡 二、ECharts 的 Vue 3 集成方案

### 2.1 安装与引入

```bash
npm install echarts
```

在组件中按需引入：

```js
import * as echarts from 'echarts'
```

注意不要用 `import echarts from 'echarts'`（默认导出可能导致 Tree Shaking 失效、打包体积偏大），`import * as` 是官方推荐方式。

### 2.2 核心模式：ref 获取 DOM → init → setOption

ECharts 需要绑定到一个真实的 DOM 容器上，这意味着你必须等组件挂载完成（`onMounted`）后再初始化：

```vue
<template>
  <div ref="chartRef" style="width:100%; height:400px"></div>
</template>

<script setup>
import { ref, onMounted, watch } from 'vue'
import * as echarts from 'echarts'

const props = defineProps({ data: Array })
const chartRef = ref(null)
let chart = null

onMounted(() => {
  chart = echarts.init(chartRef.value)
  renderChart()
  window.addEventListener('resize', () => chart?.resize())
})

watch(() => props.data, () => renderChart())

function renderChart() {
  if (!props.data) return
  chart.setOption({
    xAxis: { type: 'category', data: props.data.map(d => d.date) },
    yAxis: { type: 'value' },
    series: [{ data: props.data.map(d => d.value), type: 'line' }]
  })
}
</script>
```

### 2.3 三个易错点

| 问题 | 原因 | 解决 |
|---|---|---|
| 图表不显示 | `ref` 还未绑定 | 确保在 `onMounted` 中 `init` |
| 数据变了图表不动 | `setOption` 没调用 | 用 `watch` 监听数据变化后重新调用 |
| 窗口缩放后图表错位 | 没监听 resize | `window.addEventListener('resize', chart.resize)` |
| 组件卸载后内存泄漏 | 图表实例没销毁 | `onBeforeUnmount` 中 `chart.dispose()` |

## 🔑 三、看板页面的完整骨架

### 3.1 页面组件 DashboardView.vue（完整代码）

```vue
<template>
  <div class="dashboard" v-loading="loading">
    <!-- 统计卡片行 -->
    <el-row :gutter="20">
      <el-col :span="6" v-for="card in cards" :key="card.label">
        <StatCard :title="card.label" :value="card.value" :icon="card.icon" />
      </el-col>
    </el-row>

    <!-- 图表行 -->
    <el-row :gutter="20" style="margin-top:20px">
      <el-col :span="12">
        <el-card><div ref="salesChartRef" style="height:350px"></div></el-card>
      </el-col>
      <el-col :span="12">
        <el-card><div ref="orderChartRef" style="height:350px"></div></el-card>
      </el-col>
    </el-row>
  </div>
</template>

<script setup>
import { ref, onMounted, onBeforeUnmount, nextTick } from 'vue'
import * as echarts from 'echarts'
import StatCard from './StatCard.vue'
import { getStats, getSalesTrend, getOrderStats } from '@/api/dashboard'

// ========== 状态 ==========
const loading = ref(true)
const cards = ref([])
const salesData = ref([])
const orderData = ref([])

// ========== 模板引用 ==========
const salesChartRef = ref(null)
const orderChartRef = ref(null)

// ========== ECharts 实例（必须用普通变量持有，不能放ref） ==========
let salesChart = null
let orderChart = null

// ========== 渲染两个图表 ==========
const renderCharts = () => {
  // ① 销售额折线图
  salesChart = echarts.init(salesChartRef.value)
  salesChart.setOption({
    title: { text: '近 7 天销售额', left: 'center' },
    tooltip: { trigger: 'axis' },
    xAxis: { type: 'category', data: salesData.value.map(d => d.date) },
    yAxis: { type: 'value', axisLabel: { formatter: '¥{value}' } },
    series: [{
      data: salesData.value.map(d => d.value),
      type: 'line',
      smooth: true,
      areaStyle: { color: 'rgba(64,158,255,0.15)' }
    }]
  })

  // ② 订单状态饼图
  orderChart = echarts.init(orderChartRef.value)
  orderChart.setOption({
    title: { text: '订单状态分布', left: 'center' },
    tooltip: { trigger: 'item' },
    legend: { bottom: 0 },
    series: [{
      type: 'pie',
      radius: ['40%', '65%'],
      data: orderData.value.map(d => ({ name: d.name, value: d.value })),
      label: { formatter: '{b}: {c}' }
    }]
  })
}

// ========== 监听窗口变化：让图表跟着容器自适应 ==========
const handleResize = () => {
  salesChart?.resize()
  orderChart?.resize()
}

// ========== 生命周期 ==========
onMounted(async () => {
  try {
    // 三个请求互不依赖，并发执行，总耗时 = 最慢那个
    const [stats, sales, orders] = await Promise.all([
      getStats(),        // 返回 { goods, orders, users, todaySales }
      getSalesTrend(),   // 返回 [{ date, value }, ...]
      getOrderStats()    // 返回 [{ name, value }, ...]
    ])

    cards.value = [
      { label: '闲置物品总数', value: stats.goods, icon: 'Goods' },
      { label: '交易订单总数', value: stats.orders, icon: 'Document' },
      { label: '用户总数', value: stats.users, icon: 'User' },
      { label: '今日销售额', value: `¥${stats.todaySales}`, icon: 'Money' }
    ]
    salesData.value = sales
    orderData.value = orders

    // ⚠️ 必须等 DOM 更新完，ref 才拿得到真实元素，否则 init 会报
    //    "Initialize failed: invalid dom"
    await nextTick()
    renderCharts()
  } catch (e) {
    ElMessage.error('看板数据加载失败')
  } finally {
    loading.value = false
  }

  window.addEventListener('resize', handleResize)
})

onBeforeUnmount(() => {
  window.removeEventListener('resize', handleResize)
  // ⚠️ 必须 dispose：不销毁会内存泄漏（ECharts 实例持有大量 canvas 资源）
  salesChart?.dispose()
  orderChart?.dispose()
  salesChart = null
  orderChart = null
})
</script>

<style scoped>
.dashboard { padding: 20px; }
</style>
```

> ⚠️ **老师备注：图表空白九成出在这三个地方**
>
> **① 忘了 `echarts.init()`** —— 只写 `setOption` 是不会出图的，`chart` 这个变量根本不存在。
> **② 忘了 `await nextTick()`** —— `onMounted` 里 `ref` 已经能拿到元素，但如果你是在 `await 请求` 之后才 init，必须再 `nextTick` 一次，否则容器还没渲染，init 报 `invalid dom`。
> **③ 忘了 `dispose()`** —— 组件切走后 ECharts 实例还活着，监听器一直绑在 window 上。用户来回切十次页面，内存就翻十倍。
>
> 记住 ECharts 三件套：**`onMounted` 里 init → 数据变了 setOption → `onBeforeUnmount` 里 dispose**。

> **为什么用 Promise.all？** 三个请求互不依赖，并发执行的总耗时是「最慢那个」，串行则是「所有耗时之和」。对看板页来说，可能把 2 秒的等待压到 0.4 秒。

## 🛠 四、图表配置详解

3.1 已经给出了可运行的完整代码，这里挑几个**最容易写错的配置项**讲清楚。

### 4.1 两个常见配置项的含义

| 配置 | 作用 | 不写会怎样 |
|---|---|---|
| `smooth: true` | 折线平滑（不写是折线段） | 看起来生硬，但不算错 |
| `yAxis.axisLabel.formatter` | y 轴刻度加前缀，如 `'¥{value}'` | 销售额显示成纯数字，看不出单位 |
| `yAxis.minInterval: 1` | y 轴刻度强制取整数 | 订单数可能出现 2.5 这种"半个订单" |
| `tooltip.trigger` | `'axis'`（轴触发）或 `'item'`（点触发） | 饼图必须用 `'item'`，折线图用 `'axis'` |

### 4.2 数据变了怎么更新？

三种方式，按场景选：

```js
// ① 一次性渲染：数据只取一次（3.1 就是这种，简单场景够用）
chart.setOption(option)

// ② watch 响应式更新：接口刷新后重新 setOption（推荐）
import { watch } from 'vue'
watch(salesData, (val) => {
  salesChart.setOption({
    xAxis: { data: val.map(d => d.date) },
    series: [{ data: val.map(d => d.value) }]
  })
}, { deep: true })

// ③ 直接用 option 引用（echarts 官方推荐，可省内存）
const option = reactive({ xAxis: { data: [] }, series: [{ data: [] }] })
watch(salesData, () => {
  option.xAxis.data = salesData.value.map(d => d.date)
  option.series[0].data = salesData.value.map(d => d.value)
}, { deep: true })
```

> 💬 **老师备注**：看板页面通常有「刷新」「切换时间范围」按钮，这时数据会反复变，用 ② 或 ③ 更合适。**注意 `deep: true`**——`salesData` 是 `ref([])`，替换数组时必须深度监听才能触发。

## ⚠️ 五、常见陷阱

### 陷阱 1：在 `setup` 顶层获取 DOM 引用

`<script setup>` 中直接用 `chartRef.value` 拿不到 DOM——此时模板还没渲染。必须等 `onMounted`。

### 陷阱 2：忘记清理 ECharts 实例

组件切换（路由跳走）后，ECharts 实例还挂在内存中。`onBeforeUnmount` 中调用 `chart.dispose()` 是必须的。

```js
onBeforeUnmount(() => {
  chart?.dispose()
  window.removeEventListener('resize', handleResize) // 也要解绑
})
```

### 陷阱 3：用 `v-if` 包裹图表容器

如果用 `v-if="!loading"` 包裹图表容器，则 `onMounted` 时容器还不存在，`echarts.init` 会失败。**始终用 `v-show` 或让容器始终存在、通过 Loading 遮罩覆盖**。

## 🧠 本节小结

- **看板 = 卡片 + 图表**：卡片给"一个数字"（闲置物品总数、今日销售额），图表给"一段趋势"（近 7 天折线/柱状）；登录后第一屏的核心诉求是一眼看全局
- **ECharts 三件套生命周期**：`onMounted` 中 `echarts.init(chartRef.value)` → 数据变化时 `watch` 后 `setOption` → `onBeforeUnmount` 里 `chart.dispose()` 并 `removeEventListener`
- **引入方式用 `import * as echarts`**：不用默认导出，避免 Tree Shaking 失效、打包体积变大
- **6 个接口用 `Promise.all` 并发**：互不依赖的请求并发总耗时 = 最慢那个；配合 `try/finally` 把 `loading` 置 false，必要时 catch 后提示错误
- **组件拆分思路**：StatCard（props: title/value/icon）、图表组件（props: data）各司其职，父组件只负责并发取数与分发
- **三个易错点**：`setup` 顶层拿不到 DOM（等 onMounted）；忘了 dispose 会内存泄漏；图表容器别用 `v-if` 包（init 时容器不存在），用 `v-show` 或 Loading 遮罩

<details>
<summary>💡 深究一下：窗口缩放时图表为什么需要 resize？</summary>

```js
onMounted(() => {
  chart = echarts.init(chartRef.value)
  window.addEventListener('resize', onResize)
})
const onResize = () => chart?.resize()

onBeforeUnmount(() => {
  window.removeEventListener('resize', onResize)  // 解绑，防内存泄漏
  chart?.dispose()                                // 销毁实例
})
```

三点注意：**`resize` 事件要解绑**（否则组件销毁后还在监听窗口）；**高频触发可节流**（`lodash.debounce` 或手动 rAF）；**`dispose` 与 `removeEventListener` 都要做**。这三行是 ECharts 生命周期最容易漏的部分，漏了就是"页面越切越卡"的元凶。
