## 🤔 一、前台首页要做什么？

管理后台列表页的思路是"给人管"：表格、条件查询、批量操作，每一列都是字段。前台首页的思路是"给人逛"：

```text
┌────────────────────────────────────────────────┐
│  Campus2Hand   [🔍 搜你想找的闲置……]            │  ← 顶栏（搜索）
├────────────────────────────────────────────────┤
│  分类：[全部 ▾]   价格：[全部 ▾]   共 12 件闲置  │  ← 筛选栏
├────────────────────────────────────────────────┤
│  ┌────────┐ ┌────────┐ ┌────────┐              │
│  │  卡片  │ │  卡片  │ │  卡片  │              │  ← 闲置卡片（响应式栅格）
│  └────────┘ └────────┘ └────────┘              │
│  （筛选无结果时 → el-empty 空态）               │
└────────────────────────────────────────────────┘
```

和管理后台一样，页面由"数据 → 视图"驱动；但前台多了一层**筛选派生**：用户改任意一个条件，列表立刻重算。这正是 `computed` 的主场。

### 1.1 为什么这节先不调接口？

前台首页的重点是**筛选逻辑与列表渲染**，一旦掺进 Axios、loading、错误处理（13.10 才集中讲），注意力会被分散。所以先用一份本地数据把"视图 + 筛选"跑通，等管理后台接口就绪（13.11），只需把 `goodsList` 从"本地导入"换成"接口返回"，**视图层一行不用改**。

> 💬 **老师备注**：这种"先本地后接口"的开发顺序在企业里很常见——前端不等后端，先用 mock 并行开发，接口好了再切数据源。第 10 章的章末实战 P10「每日一言壁纸」你已经用过这招。

## 🛠 三、抽出卡片组件 GoodsCard.vue

首页会重复渲染 N 张卡片，**重复的结构就该抽成组件**（第 3 章的心法）。新建 `src/components/GoodsCard.vue`：


卡片只做一件事：**把 `goods` 渲染出来**，不关心筛选、不关心数据从哪来。这样 13.5 详情页、后续"我的闲置"都能复用它。

> 💬 **老师备注**：这里用 `defineProps` 声明 `goods` 是**必填对象**（`required: true`）。初学者常把"组件要用的数据"写成"组件自己去导数据"——那样组件就绑死了数据源。**让父组件把数据传进来**，组件才可复用。

## 🔑 四、HomeView.vue：筛选与渲染

新建 `src/views/front/HomeView.vue`。三个筛选条件各用一个 `ref`，再用一个 `computed` 汇总：

```vue
<!-- src/views/front/HomeView.vue -->
<script setup>
import { ref, computed } from 'vue'
import GoodsCard from '@/components/GoodsCard.vue'
import { goodsList, GOODS_CATEGORIES, PRICE_RANGES } from '@/data/goods'

const keyword = ref('')
const category = ref('')
const priceRange = ref('')

// 核心：把三个条件组合成一条筛选流水线
const filteredGoods = computed(() => {
  const kw = keyword.value.trim().toLowerCase()

  return goodsList.filter((item) => {
    // 1. 关键词：标题或描述包含
    const hitKeyword =
      !kw ||
      item.title.toLowerCase().includes(kw) ||
      item.desc.toLowerCase().includes(kw)

    // 2. 分类
    const hitCategory = !category.value || item.category === category.value

    // 3. 价格区间（'0-50' / '50-200' / '200-'）
    let hitPrice = true
    if (priceRange.value) {
      const [min, max] = priceRange.value.split('-')
      hitPrice = item.price >= Number(min) && (max === '' || item.price < Number(max))
    }

    return hitKeyword && hitCategory && hitPrice
  })
})

function resetFilters() {
  keyword.value = ''
  category.value = ''
  priceRange.value = ''
}
</script>

<template>
  <div class="home">
    <!-- 顶栏搜索 -->
    <div class="topbar">
      <h2>Campus2Hand 校园二手集市</h2>
      <el-input
        v-model="keyword"
        placeholder="搜你想找的闲置（标题 / 描述）"
        clearable
        style="max-width: 360px"
      />
    </div>

    <!-- 筛选栏 -->
    <div class="filters">
      <el-select v-model="category" placeholder="全部分类" clearable style="width: 160px">
        <el-option v-for="c in GOODS_CATEGORIES" :key="c" :label="c" :value="c" />
      </el-select>

      <el-select v-model="priceRange" placeholder="全部价格" clearable style="width: 160px">
        <el-option v-for="p in PRICE_RANGES" :key="p.label" :label="p.label" :value="p.value" />
      </el-select>

      <span class="count">共 {{ filteredGoods.length }} 件闲置</span>
      <el-button v-if="keyword || category || priceRange" link type="primary" @click="resetFilters">
        清空筛选
      </el-button>
    </div>

    <!-- 列表 / 空态 -->
    <el-row v-if="filteredGoods.length" :gutter="16">
      <el-col v-for="item in filteredGoods" :key="item.id" :xs="24" :sm="12" :md="8" :lg="6">
        <GoodsCard :goods="item" />
      </el-col>
    </el-row>

    <el-empty v-else description="没有找到符合条件的闲置，换个词试试？">
      <el-button type="primary" @click="resetFilters">看看全部闲置</el-button>
    </el-empty>
  </div>
</template>

<style scoped>
.home { max-width: 1100px; margin: 0 auto; padding: 16px; }
.topbar { display: flex; justify-content: space-between; align-items: center; margin-bottom: 16px; }
.filters { display: flex; align-items: center; gap: 12px; margin-bottom: 16px; }
.count { color: #909399; font-size: 13px; }
</style>
```

### 4.1 这段代码的三个关键点

| 关键点 | 说明 |
|---|---|
| `computed` 而非方法 | 筛选结果随三个 `ref` 自动重算并缓存；若写成普通函数，每次渲染都重跑一遍 |
| `filter` 不修改原数组 | `filter` 返回新数组，`goodsList` 始终完整——切条件时才不会"越筛越少" |
| `:key="item.id"` | 用业务 id 而非 `index`，列表更新时 DOM 复用才正确（见陷阱 1） |

---

## ⚠️ 五、常见陷阱

### 陷阱 1：`v-for` 的 key 用 `index`

```html
<!-- ❌ 筛选后列表长度变化，index 会错位复用 DOM，出现"图片和标题对不上" -->
<GoodsCard v-for="(item, index) in filteredGoods" :key="index" :goods="item" />

<!-- ✅ 用业务唯一 id -->
<GoodsCard v-for="item in filteredGoods" :key="item.id" :goods="item" />
```

### 陷阱 2：在 `computed` 里直接 `sort` 原数组

```js
// ❌ sort 会就地修改 goodsList，原始数据被永久打乱
const sorted = computed(() => goodsList.sort((a, b) => a.price - b.price))

// ✅ 先复制再排
const sorted = computed(() => [...goodsList].sort((a, b) => a.price - b.price))
```

### 陷阱 3：把"筛选"写成"循环里发请求"

初学者容易把每张卡片做成"自己请求详情"，结果 12 张卡片发 12 个请求。**列表数据一次拿全，筛选在本地用 `computed` 完成**；等 13.11 接后端分页时，再改成"筛选参数变化 → 请求一次"。

## 🧠 本节小结

- **前台首页是"给人逛"的**：搜索 + 分类 + 价格三条件，`computed` 派生筛选结果，改任一条件列表即时重算
- **数据先本地、后接口**：`src/data/goods.js` 提供 mock，等 13.11 接口就绪只需替换数据来源，视图层不动
- **组件化**：重复的卡片抽成 `GoodsCard.vue`，通过 `props` 接收 `goods`——组件不自己找数据，父组件传进来
- **三条红线**：`v-for` 的 `key` 用 `item.id`；`computed` 里排/倒序要先 `[...arr]` 复制；列表数据一次拿全、别在卡片里发请求
- **体验细节**：结果计数 + 一键清空筛选 + `el-empty` 空态，让人"筛不到"时也有路可走
