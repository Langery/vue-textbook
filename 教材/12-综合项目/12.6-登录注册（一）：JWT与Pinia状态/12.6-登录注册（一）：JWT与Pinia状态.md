## 🤔 一、JWT token 是什么？为什么不用 session？

### 1.1 传统 session 方式的问题

传统 Web 应用登录后，服务器在内存里存一个 `session`，浏览器存一个 `sessionId`（cookie）。下次请求时，浏览器自动带上 cookie，服务器查 session 确认身份。

这种方式在**单台服务器**上没问题，但一旦有多台服务器（负载均衡），session 就需要在服务器之间共享，很麻烦。

### 1.2 JWT 方式

JWT（JSON Web Token）把用户信息**加密后存在客户端**（localStorage 或 cookie），服务器不需要存任何状态。

```text
登录流程（JWT 方式）：
1. 用户输入账号密码 → 点击登录
2. 前端发 POST /api/login
3. 后端验证账号密码正确 → 返回 token（字符串）
4. 前端把 token 存到 localStorage + Pinia
5. 后续所有请求，在 Header 里带 token：
   Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...
6. 后端解密 token，确认身份
```

> 💬 **老师备注**：JWT token 是有过期时间的（比如 7 天）。过期后需要重新登录。真实项目中还会用"refresh token"机制自动刷新，但课设级别不要求，登录过期直接跳回登录页即可。

## 💡 二、Pinia 用户状态——token 的"家"

token 不能只存在组件里（组件销毁就没了），也不能只存在 localStorage 里（组件读不到）。正确做法是：**Pinia 存状态 + localStorage 做持久化**。

```js
// src/stores/user.js
import { defineStore } from 'pinia'
import { ref } from 'vue'
import { login as loginApi, logout as logoutApi } from '@/api/auth'

export const useUserStore = defineStore('user', () => {
  // ==================== state ====================
  const token = ref(localStorage.getItem('token') || '')
  const userInfo = ref(JSON.parse(localStorage.getItem('userInfo') || 'null'))

  // ==================== actions ====================
  // 登录
  const login = async (credentials) => {
    const res = await loginApi(credentials)
    token.value = res.data.token
    userInfo.value = res.data.user

    // 持久化到 localStorage
    localStorage.setItem('token', res.data.token)
    localStorage.setItem('userInfo', JSON.stringify(res.data.user))

    return res
  }

  // 退出登录
  const logout = async () => {
    try {
      await logoutApi()
    } catch (e) {
      // 退出接口失败也不影响前端清除状态
    }
    token.value = ''
    userInfo.value = null
    localStorage.removeItem('token')
    localStorage.removeItem('userInfo')
  }

  // 从 localStorage 恢复状态（页面刷新时调用）
  const restoreToken = () => {
    const savedToken = localStorage.getItem('token')
    const savedUser = localStorage.getItem('userInfo')
    if (savedToken) {
      token.value = savedToken
      userInfo.value = JSON.parse(savedUser || 'null')
    }
  }

  return {
    token,
    userInfo,
    login,
    logout,
    restoreToken
  }
})
```

### 关键点说明

| 代码 | 作用 |
|---|---|
| `ref(localStorage.getItem('token') \|\| '')` | 初始化时从 localStorage 读取，刷新页面不丢 |
| `localStorage.setItem` | 登录成功后持久化 |
| `localStorage.removeItem` | 退出时清除 |
| `restoreToken()` | 在 `main.js` 里调用，确保刷新后状态恢复 |

在 `main.js` 里恢复状态：

```js
// src/main.js
import { createApp } from 'vue'
import { createPinia } from 'pinia'
import App from './App.vue'
import router from './router'
import { useUserStore } from './stores/user'

const app = createApp(App)
const pinia = createPinia()

app.use(pinia)
// 在挂载之前恢复 token
const userStore = useUserStore()
userStore.restoreToken()

app.use(router)
app.mount('#app')
```

> 💬 **老师备注**：为什么既要存 Pinia 又要存 localStorage？Pinia 是"内存状态"，组件响应式读取；localStorage 是"持久化备份"，刷新页面后恢复。两者配合，才能做到"刷新不丢登录态"。

## 🧠 本节小结

- **为什么用 JWT**：用户信息加密后存在客户端，服务器无状态；多台服务器（负载均衡）无需共享 session，天然好扩展
- **JWT 链路**：登录 POST → 后端验证返回 token → 存 localStorage + Pinia → 后续请求带 `Authorization: Bearer <token>` → 后端解密确认身份；token 有过期时间（课设不做 refresh token，过期回登录页）
- **Pinia 是"家"、localStorage 是"备份"**：组件读 Pinia 拿响应式状态，刷新页面靠 localStorage 恢复——二者配合才能"刷新不丢登录态"
- **store 三个动作**：`login()` 存 token/userInfo + `setItem` 持久化；`logout()` 清状态 + `removeItem`（即使退出接口失败也清）；`restoreToken()` 从 localStorage 回填
- **恢复时机**：`main.js` 中 `app.use(pinia)` 之后、`app.mount` 之前调用 `restoreToken()`，确保刷新后守卫一进来就能读到 token
