## 🤔 一、跨组件共享状态有多痛苦？

假设一个电商 App，有三个组件都需要"购物车商品数量"：

```text
<Navbar>        ← 显示购物车角标数字
<CartPanel>     ← 展示购物车里的商品
<ProductPage>   ← 点击"加入购物车"
```

这三个组件是兄弟/表亲关系，光靠 Props 根本没法传。早期 Vue 2 的解决方案是 EventBus（全局事件总线），但这样做很脆弱——数据改了不知道谁改的、排查 bug 全靠 `console.log` 大海捞针。

你需要一个**集中式的数据仓库**：所有组件都从同一个地方读取数据、通过同一个渠道修改数据。

---

## 💡 二、Vuex 的五大核心概念

Vuex 把这个"数据仓库"拆成了五个概念：

```text
┌─────────────────────────────────────────┐
│                  Vuex Store              │
│                                          │
│  State ────→ Getter ────→ 组件（读）     │
│    ↑                                    │
│    │ commit                             │
│  Mutation（同步修改 state）              │
│    ↑                                    │
│    │ dispatch                           │
│  Action（异步操作 + 调 mutation）         │
└─────────────────────────────────────────┘
```

### 2.1 State：单一数据源

```js
// store/index.js
import { createStore } from 'vuex'

const store = createStore({
  state: {
    count: 0,
    user: null,
    cart: [],
  }
})
```

所有组件共享这一个 `state` 对象。在组件里读取：

```js
// 选项式 API
this.$store.state.count

// 组合式 API（需要 useStore）
import { useStore } from 'vuex'
const store = useStore()
console.log(store.state.count)
```

### 2.2 Getter：派生状态（类似 computed）

```js
const store = createStore({
  state: {
    cart: [
      { name: '键盘', price: 299, quantity: 1 },
      { name: '鼠标', price: 99, quantity: 2 },
    ]
  },
  getters: {
    // 购物车总价
    cartTotal(state) {
      return state.cart.reduce((sum, item) => sum + item.price * item.quantity, 0)
    },
    // 购物车商品数量
    cartCount(state) {
      return state.cart.reduce((sum, item) => sum + item.quantity, 0)
    }
  }
})
```

组件里用：`store.getters.cartTotal`。

## 🔑 三、Mutation：修改 state 的唯一方式

Vuex 要求 state 只能通过 **mutation** 来修改。这样做的好处是：所有修改都有迹可循，Devtools 能追踪每一次状态变化。

```js
const store = createStore({
  state: {
    count: 0
  },
  mutations: {
    // mutation 接收 state 作为第一个参数
    increment(state) {
      state.count++
    },
    incrementBy(state, payload) {
      state.count += payload
    }
  }
})

// 组件里调用（不是直接调 mutation，而是 commit）
store.commit('increment')
store.commit('incrementBy', 5)
```

> ⚠️ **mutation 必须是同步函数**。因为 Devtools 需要快照状态变化，如果 mutation 里有异步，快照会不准确。

## 🛠 四、Action：处理异步 + 调用 mutation

异步操作（API 请求、定时器）必须放在 **action** 里。action 不直接改 state，而是通过 `commit` 调用 mutation：

```js
const store = createStore({
  state: {
    user: null,
    loading: false,
  },
  mutations: {
    setUser(state, user) {
      state.user = user
    },
    setLoading(state, loading) {
      state.loading = loading
    }
  },
  actions: {
    // action 接收 context（包含 commit、state、getters 等）
    async login({ commit }, { username, password }) {
      commit('setLoading', true)
      try {
        const user = await fakeLoginAPI(username, password)
        commit('setUser', user)
      } finally {
        commit('setLoading', false)
      }
    }
  }
})

// 组件里调用（dispatch）
store.dispatch('login', { username: 'admin', password: '123456' })
```

## 🛠 五、Module：拆分 store

一个电商 App 的 store 可能有几百行，全写在一起太难维护。Vuex 用 **Module** 拆分：

```js
// store/modules/cart.js
export default {
  namespaced: true,  // 开启命名空间
  state: { items: [] },
  mutations: { /* ... */ },
  actions: { /* ... */ },
  getters: { /* ... */ },
}

// store/modules/user.js
export default {
  namespaced: true,
  state: { profile: null },
  mutations: { /* ... */ },
  actions: { /* ... */ },
}

// store/index.js
import { createStore } from 'vuex'
import cart from './modules/cart'
import user from './modules/user'

export default createStore({
  modules: { cart, user }
})
```

开启命名空间后，调用时需带模块名：

```js
store.dispatch('cart/addItem', item)
store.commit('user/setProfile', profile)
```

## ⚠️ 六、为什么 Pinia 取代了 Vuex？

Vuex 功能很完备，但有一些明显的痛点：

| 痛点 | Vuex | Pinia |
|---|---|---|
| **TypeScript 支持** | 需要额外类型声明，体验差 | 原生完美支持 |
| **Mutation 冗余** | 必须写 mutation，哪怕逻辑只有一行 | 没有 mutation，action 直接改 state |
| **模块嵌套** | `namespaced` 写起来繁琐 | 天然的扁平 store，每个 store 独立 |
| **API 直觉性** | `store.commit('xxx')` + `store.dispatch('xxx')` | 直接 `store.xxx()`，像调普通函数 |
| **体积** | ~15KB | ~5KB |

Vue 官方现在**推荐 Pinia 作为默认状态管理方案**。Vuex 仍在维护，但新项目应该用 Pinia。

> 💬 **老师备注**：如果你接手的是老项目（Vue 2 + Vuex），本节的知识够你读懂和维护。但**新项目全部用 Pinia**，9.8 开始全讲 Pinia。

## 🧠 本节小结

- **历史方案定位**：Vuex 是 Vue 2/3 时代的状态管理方案，本节学会它能读懂老项目；**新项目直接用 Pinia（9.8）**
- **集中式仓库**：单一状态树 + 单向数据流 `dispatch → action → commit → mutation → state`
- **五大核心**：State（数据）、Getter（派生）、Mutation（同步改）、Action（异步+调 mutation）、Module（拆分）
- **为什么要这套流程**：数据从哪来、被谁改都留痕可查；缺点就是啰嗦——这也是 Pinia 诞生的原因
- **何时需要状态管理**：多组件共享、跨页面保持、复杂联动才值得上；单页局部数据别杀鸡用牛刀
