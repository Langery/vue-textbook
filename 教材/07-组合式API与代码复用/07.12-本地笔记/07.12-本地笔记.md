### Step 1：把课堂写过的持久化 composable 拿进项目

真正体现 7.6 组合式设计：一个 composable 管一块完整逻辑，内部只依赖上一步的 `useLocalStorage`：

```js
export function useNotes() {
  const notes = useLocalStorage('campus-notes', [])
  const addNote = () => { /* 生成 id + 空笔记，push 进 notes.value */ }
  const removeNote = (id) => { /* 用 filter 生成新数组替换（回顾 5.8 更新姿势） */ }
  const updateNote = (id, patch) => { /* map 出新数组，合并 patch */ }
  return { notes, addNote, removeNote, updateNote }

```

> 锚点检查：组件里 `const { notes, addNote, removeNote, updateNote } = useNotes()` 后，模板能直接 `v-for` 出列表——"存"这件事已经被 composable 藏起来了。

### Step 3：搜索过滤——`useDebounce` + `computed`

搜索不该每敲一个字符都过滤（以后接后端就是每敲一个字符发请求）。用 7.7 的 `useDebounce` 包一层：

```js
const keyword = ref('')
const debouncedKeyword = useDebounce(keyword, 300)   // 停笔 300ms 后才更新

const filteredNotes = computed(() => {
  const kw = debouncedKeyword.value.trim()
  if (!kw) return notes.value
  return notes.value.filter(n =>
    n.title.includes(kw) || n.content.includes(kw)
  )
})
```

> 锚点检查：快速连续敲 "vue 教材" 六个字，`debouncedKeyword` 只在停笔后才变成完整词——在输入框下方显示 `keyword` 与 `debouncedKeyword` 两个值即可肉眼验证。

### Step 4：编辑与"自动保存"

编辑区用 `v-model` 绑定当前选中笔记的 `title` / `content`，改动经 `updateNote` 写回 `notes.value`——由于 `useLocalStorage` 内部有 `deep watch`，**保存自动发生**，无需任何手动代码。可选：右上角放一个"最近保存时间"小字，用 `watch` 监听选中笔记内容变化更新时间，让"自动保存"看得见。

### Step 5：界面收尾

左侧列表显示每条的标题与预览（`content.slice(0, 20)` 之类），右侧编辑选中项；"新建"生成新笔记并选中；删除按钮带一个 `confirm` 确认。空列表时给一句引导文案。把搜索框放到顶部，让整页像"极简备忘录"。

**`src/composables/useLocalStorage.js`** —— 手写持久化：读的时候从 localStorage 初始化，写的时候自动回写：

```js
import { ref, watch } from 'vue'
import { useDebounce } from './useDebounce'

/**
 * 把一个 ref 和 localStorage 绑在一起：读的时候从 localStorage 初始化，
 * 写的时候自动回写。
 *
 * ⭐ 本文件本身就是"逻辑复用"的示范：写盘太频繁（每敲一个字存一次）
 * 会拖慢页面，所以这里直接复用了同一层的 useDebounce。
 *
 * @param {string} key localStorage 的键名
 * @param {*} defaultValue localStorage 里没有（或数据损坏）时的默认值
 * @param {number} delay 写盘防抖毫秒数，默认 300
 * @returns {import('vue').Ref} 和 localStorage 双向同步的 ref
 */
export function useLocalStorage(key, defaultValue, delay = 300) {
  // ====== 1. 初始化：优先读 localStorage ======
  const raw = localStorage.getItem(key)
  let initial = defaultValue

  if (raw !== null) {
    try {
      initial = JSON.parse(raw)
    } catch (err) {
      // 脏数据兜底：解析失败就退回默认值，别让整个应用崩掉
      console.warn(`[useLocalStorage] "${key}" 里的数据不是合法 JSON，已回退默认值`, err)
      initial = defaultValue
    }
  }

  const data = ref(initial)

  // ====== 2. 算出「要写成什么样」的字符串 ======
  // 存进 localStorage 的永远是字符串，所以先序列化。
  // null 表示「还没发生过任何变化」，所以不会一上来就往 localStorage 里写一笔
  const snapshot = ref(null)

  watch(
    data,
    (val) => {
      snapshot.value = JSON.stringify(val)
    },
    { deep: true } // deep：数组里对象的字段被原地改了，也要能被发现
  )

  // ====== 3. 写回 localStorage（复用 useDebounce） ======
  const readyToWrite = useDebounce(snapshot, delay)

  watch(readyToWrite, (text) => {
    if (text === null) return
    localStorage.setItem(key, text)
  })

  return data
}
```

**`src/composables/useDebounce.js`** —— 手写防抖：停手 N 毫秒才输出最后一次的值：

```js
import { ref, watch } from 'vue'

/**
 * 防抖：源数据连续变化时，只在"停下来"delay 毫秒后输出最后一次的值。
 *
 * @param {import('vue').Ref} source 源 ref
 * @param {number} delay 延迟毫秒数，默认 300
 * @returns {import('vue').Ref} 防抖后的 ref
 */
export function useDebounce(source, delay = 300) {
  // 初始值先同步一份，避免刚挂载时读到 undefined
  const debounced = ref(source.value)

  let timer = null

  watch(source, (newVal) => {
    // 每次变化都先清掉上一个待触发的定时器 —— 不清的话会"排队爆炸"，
    // 而且旧的值可能覆盖新值
    if (timer) clearTimeout(timer)

    timer = setTimeout(() => {
      debounced.value = newVal
    }, delay)
  })

  return debounced
}
```

**`src/composables/useNotes.js`** —— 业务组合：把上面两个拼起来，对外只暴露状态和方法：

```js
import { computed, ref } from 'vue'
import { useDebounce } from './useDebounce'
import { useLocalStorage } from './useLocalStorage'

/**
 * 笔记业务的组合式函数：把「数据存哪」「怎么过滤」「怎么增删改」都收在一处。
 * 组件只管渲染和派发意图，逻辑全在这里 —— 这就是 composable 的意义。
 */
export function useNotes(storageKey = 'campus-notes') {
  // ====== 1. 数据：useLocalStorage 负责持久化，刷新不丢 ======
  const notes = useLocalStorage(storageKey, [], 300)

  // ====== 2. 搜索：keyword 立即变化，debouncedKeyword 停手 300ms 后才变 ======
  const keyword = ref('')
  const debouncedKeyword = useDebounce(keyword, 300)

  // ====== 3. 当前选中的笔记 id ======
  const activeId = ref(null)

  // ====== 4. 派生数据：过滤后的列表 / 当前笔记 ======
  // ⚠️ 必须用 computed：keyword 一变它就重新算；写成 const 就成了死值
  const filteredNotes = computed(() => {
    const kw = debouncedKeyword.value.trim()
    if (!kw) return notes.value
    return notes.value.filter(
      (n) => n.title.includes(kw) || n.content.includes(kw)
    )
  })

  const activeNote = computed(
    () => notes.value.find((n) => n.id === activeId.value) || null
  )

  // ====== 5. 行为：增 / 删 / 改 ======
  function createNote() {
    const note = {
      id: `n${Date.now()}${Math.random().toString(36).slice(2, 6)}`,
      title: '新笔记',
      content: '',
      updatedAt: Date.now()
    }
    // 用新数组替换，而不是 push —— 后者对「存快照」的思路不友好
    notes.value = [note, ...notes.value]
    activeId.value = note.id
    return note.id
  }

  function removeNote(id) {
    notes.value = notes.value.filter((n) => n.id !== id)
    if (activeId.value === id) {
      activeId.value = notes.value[0]?.id ?? null
    }
  }

  function updateNote(id, patch) {
    notes.value = notes.value.map((n) =>
      n.id === id ? { ...n, ...patch, updatedAt: Date.now() } : n
    )
  }

  return {
    notes,
    keyword,
    debouncedKeyword,
    activeId,
    activeNote,
    filteredNotes,
    createNote,
    removeNote,
    updateNote
  }
}
```

<details>
<summary>💬 老师备注：这个成品里有三处"故意的非标准写法"，值得你找出来</summary>

**① `useLocalStorage` 内部复用了 `useDebounce`——这就是"逻辑复用"。**
本章标题是"组合式API与代码复用"，而复用的关键**不在于把代码抽成函数，而在于抽出来的东西能不能被别人直接拿去用**。这里 `useLocalStorage` 没有自己再写一遍 `setTimeout` + `clearTimeout`，而是直接 `import { useDebounce } from './useDebounce'`，把"防抖"这件事完全外包出去了。

所以你会看到一个有点反直觉的写法：写盘**不是**在 `watch` 的回调里直接 `localStorage.setItem`，而是先序列化成字符串、经过防抖、再写。中间多绕了一层，换来的是"连续敲 10 个字只写一次盘"。

代价也要认：**最后 300ms 内的输入，在页面被强刷的瞬间可能丢**。真实项目里通常会再补一个 `beforeunload` 兜底，但那就超出本章范围了。

**② `useLocalStorage` 里多了一个 `snapshot` 中间层。**
为什么不能直接 `watch(data, () => localStorage.setItem(key, JSON.stringify(data.value)))`？因为那样每次变化都要**重新序列化一遍当前值**；而我们想要的是"**停手 300ms 后，把那一刻的值写下去**"。加了 `snapshot` 之后，`watch` 回调只负责"拍一张照"（算出字符串），真正的写盘交给 `useDebounce` 去排队——**"拍照"和"冲洗"分给了两个各自负责一件事的 composable**。

顺带注意 `snapshot` 的初值是 `null` 而不是 `''`：它代表"**还没发生过任何变化**"，所以组件一挂载不会莫名其妙往 localStorage 里写一笔。

**③ `useNotes` 里所有会变的派生数据都用了 `computed`。**
`filteredNotes`（过滤后的列表）和 `activeNote`（当前笔记）都是"由别的数据算出来的"，所以必须是 `computed`。如果你写成 `const filteredNotes = notes.value.filter(...)`，它**只在组件创建那一刻算一次**，之后 `notes` 怎么变它都不动——搜索会彻底失灵。

这正是 7.3 讲 `computed` 时反复强调的那件事：**`computed` 不是"更方便的 filter"，而是"会自己重算的缓存"**。`computed` 内部确实有缓存，但它靠的是**依赖追踪**——`notes.value` 或 `debouncedKeyword.value` 变了，缓存自动作废并重算。

**④ 最后说说 `deep: true` 这个开关。**
把它删掉，你会发现**保存居然还正常**！因为我们的 `updateNote` 是"整个数组替换"（`notes.value.map(...)`），浅监听也能看见数组引用变了。

那 `deep: true` 是干嘛的？它是给"**原地改字段**"留的保险。上面知识点表里那条"删掉 `deep: true`"之所以让你意外，正是因为我们**恰好**用了不可变更新（每次都造新数组）。如果哪天有人图省事改成 `note.title = 'x'` 直接改字段，没有 `deep` 就写不进盘了。

**所以 `deep: true` 不是"必须加的语法糖"，而是"给未来的自己留的保险"**——这恰恰是写 composable 时该有的心态：composable 要对**使用者怎么改数据**保持宽容。

最后留个思考题：搜索框的 `keyword` 和写盘的 `snapshot` 都用了防抖，但它们防的是**完全不同**的问题——搜索防的是"每敲一个字就重算一次列表"，写盘防的是"每敲一个字就写一次 localStorage"。如果给这两个防抖**共用同一个 delay 参数**，将来想只调其中一个，该怎么办？（提示：想想 composable 的参数化。）

</details>
