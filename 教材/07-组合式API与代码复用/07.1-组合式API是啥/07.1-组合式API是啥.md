听到"组合式 API"这个词，很多人第一反应是"又双叒要学新写法了？"其实你早就在用了——从第 4 章起写的 `setup`、`ref`、`watch`，全是组合式 API 的地盘。它和选项式 API 不是替代关系，而是同一种 Vue 的两种组织代码的方式。本节先带你把选项式写法完整过一遍，才好对比出组合式到底解决了什么。

> 🎯 **类比一下：选项式 ≈ 一栋"按楼层分类"的公寓，组合式 ≈ 一栋"按家庭分类"的公寓**
> 选项式：所有"数据"住 1 楼、"方法"住 2 楼、"监听"住 3 楼——可一家人（一个功能）被拆散在不同楼层，串门要上下跑。组合式：一家人住一层，数据、方法、监听都在同一个房间里，找起来一步到位。

> 🧑 **小白**：我前几章一直用 `<script setup>` 写，是不是已经会组合式了？
> 🤖 **Vue 君**：对，你早就用上了！本节只是帮你补上"选项式"这张旧地图做对照。
> 👨🏫 **老湿**：重点不是背语法，是体会"按功能聚拢"这个组织思想——它决定你以后写大组件是清爽还是灾难。

## 🤔 一、先复习：选项式 API 长啥样？

你在前 7 章已经写的所有代码，其实用的就是**组合式 API** 的 `<script setup>` 语法。但我们来回顾一下传统的**选项式 API**，这样才能真正理解"组合式"好在哪。

```vue
<script>
export default {
  // 数据
  data() {
    return {
      count: 0,
      message: 'Hello'
    }
  },
  // 计算属性
  computed: {
    doubleCount() {
      return this.count * 2
    }
  },
  // 方法
  methods: {
    add() {
      this.count++
    }
  },
  // 监听器
  watch: {
    count(newVal) {
      console.log('count 变了：' + newVal)
    }
  },
  // 生命周期
  mounted() {
    console.log('组件挂载了')
  }
}
</script>
```

这种写法的特点是：**按"类型"分块**。所有数据放 `data` 里，所有方法放 `methods` 里，所有计算属性放 `computed` 里。

小组件还好，一旦组件变复杂，就会出现一个问题：**同一个功能的代码散落在不同选项里**。比如一个"搜索功能"：

- 搜索关键词在 `data` 里
- 搜索结果在 `data` 里
- 搜索方法在 `methods` 里
- 防抖逻辑在 `watch` 里
- 请求发送在 `mounted` 里

你在 `data` 块和 `methods` 块之间反复横跳，改一个功能要在文件里上下翻好几屏。

## 💡 二、组合式 API 长啥样？

组合式 API 换个思路：**按"功能"组织代码**。同一个功能的数据、方法、监听、生命周期，全部写在一起。

```vue
<script setup>
import { ref, computed, watch, onMounted } from 'vue'

// ========== 计数功能 ==========
const count = ref(0)
const doubleCount = computed(() => count.value * 2)

function add() { count.value++ }

watch(count, (newVal) => {
  console.log('count 变了：' + newVal)
})

// ========== 消息功能 ==========
const message = ref('Hello')

onMounted(() => {
  console.log('组件挂载了')
})
</script>
```

一眼就能看出来：

- **不需要** `this` 了，变量直接用
- **不需要** `data()` / `methods` 这些选项，一切都在 `<script setup>` 里自由写
- `ref`、`computed`、`watch` 都是从 `vue` 按需导入，想用哪个 import 哪个

## 🔄 三、同一个功能，两种写法对比

假设有一个"用户登录"功能：用户名、密码、登录按钮、登录状态。

### 选项式写法

```vue
<script>
export default {
  data() {
    return {
      username: '',
      password: '',
      loading: false,
      errorMsg: ''
    }
  },
  methods: {
    async login() {
      this.loading = true
      this.errorMsg = ''
      try {
        await fakeLogin(this.username, this.password)
      } catch(e) {
        this.errorMsg = e.message
      } finally {
        this.loading = false
      }
    }
  }
}
</script>
```

### 组合式写法

```vue
<script setup>
import { ref } from 'vue'

// 登录功能 —— 所有相关代码都在这一块
const username = ref('')
const password = ref('')
const loading = ref(false)
const errorMsg = ref('')

async function login() {
  loading.value = true
  errorMsg.value = ''
  try {
    await fakeLogin(username.value, password.value)
  } catch(e) {
    errorMsg.value = e.message
  } finally {
    loading.value = false
  }
}
</script>
```

组合式版本里，登录相关的四个状态 + 一个方法**全写在一起**，你一眼就能看到"登录功能用了哪些数据、有哪些逻辑"。而且将来如果你想把这个登录逻辑抽成独立的 composable，直接剪切出去就行——几乎零成本。

两种 API 的差异可以浓缩成一张表：

| 对比维度 | 选项式 API | 组合式 API |
|---|---|---|
| 代码组织 | 按"类型"分块（data / methods / computed / watch） | 按"功能"分块（功能 A → B → C） |
| 核心写法 | `export default { data() {...}, methods: {...} }` | `<script setup>` + 按需 import |
| `this` | 必须用 `this.xxx` | 不需要，变量直接用 |
| 逻辑复用 | 靠 mixins（易冲突、来源不明） | 抽 composable，零成本剪切复用 |
| TypeScript 支持 | 较弱（类型推断困难） | 强（变量天然有类型） |
| 适合场景 | 小组件、Vue 2 老项目 | 中大型组件、新项目推荐 |

## 🛠 四、`<script setup>` 到底做了啥？

`<script setup>` 是 Vue 3 给组合式 API 开的语法糖。它在编译时做的事：

1. **自动 `export default`** —— 你不需要手动写 `export default { ... setup() { ... } }`
2. **自动注册组件** —— import 进来的组件直接能在模板里用，不用在 `components` 里注册
3. **自动暴露顶层变量** —— `<script setup>` 里的顶层变量自动暴露给模板
4. **支持 `defineProps` / `defineEmits`** —— 这两个 API 在 `<script setup>` 里可以直接用，不需要 import

```vue
<script setup>
import { ref } from 'vue'
import ChildComp from './ChildComp.vue'  // 自动注册

const name = ref('Vue')   // 模板里直接用 name
defineProps(['title'])     // 自动可用
</script>

<template>
  <h1>{{ title }}</h1>
  <p>{{ name }}</p>
  <ChildComp />   <!-- 自动可用 -->
</template>
```

> 💬 **老师备注**：全书从第 1 章开始就在用 `<script setup>`，你可能已经习惯了。但要知道，在 Vue 2 时代没有这个东西，得写一堆 `export default` 和 `setup()` 函数。`<script setup>` 让组合式 API 写起来比选项式还简洁。

## ⚠️ 五、常见误区

### 误区 1：「组合式 API 很难，选项式更简单」

正好相反。对于简单组件，两者差不多；一旦组件复杂起来，组合式 API **显著更简单**，因为代码按功能聚在一起，不用跳来跳去。

### 误区 2：「用了组合式就不能用选项式了」

Vue 3 完全兼容两种写法，甚至可以在同一个组件里混用（但不推荐）。你完全可以用组合式写新功能，老代码的选项式不禁不动。

### 误区 3：「<script setup> 里不能写 import 以外的代码」

`<script setup>` 里可以写任何 JS 代码——条件判断、循环、函数声明、直接调用 API……它本质就是在 `setup()` 函数里运行。

## 🧠 本节小结

- **两种写法是一套 Vue**：选项式与组合式共享同一响应式系统，不是替代关系
- **选项式特点**：按 `data`/`methods`/`computed`/`watch` 等"选项"分块，适合小组件、直观清晰
- **组合式特点**：按"一个功能"把状态、方法、监听收拢到一起，逻辑聚集
- **`<script setup>` 是组合式的地盘**：可以写任意 JS，`setup()` 返回值的语法糖版本
- **怎么选**：项目默认推荐组合式；读老代码时两种都要看得懂

> 🧊 **冷知识**：`<script setup>` 不是新语言，它本质是**编译器语法糖**——Vue SFC 编译器会把 `setup` 顶层代码"包"进一个 `setup()` 函数里执行，并自动处理导出。这也是为什么里面能直接 `import`、能写任意 JS，却不需要 `return`——编译器替你按需生成了返回值。

<details><summary>🔍 想深究再看：为什么说"组合式"是逻辑复用的地基？</summary>

选项式里逻辑复用的主要工具是 Mixin 和自定义指令，但组件一多，"这段逻辑来自哪个 Mixin"就变成谜。组合式的关键升级在于：把"数据 + 方法 + 监听 + 生命周期"打包成**普通函数**，组件里 `const { count, add } = useCounter()` 就能按需取用。复用的对象从"代码片段"变成了"有清晰输入输出的函数"——可测试、可推导、可组合。后面 7.6 节的自定义组合式函数，就是这个思想的正式落地，本节先记住"函数即零件"即可。

</details>
