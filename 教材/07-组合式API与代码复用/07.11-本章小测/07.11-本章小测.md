## ✅ 参考答案

**一、单选题**

| 题号 | 答案 | 解析 |
|---|---|---|
| 1 | B | 组合式 API 的核心价值是逻辑组合与复用 |
| 2 | C | `triggerRef` 只对 `shallowRef` 有效，`reactive` 不需要手动触发 |
| 3 | B | computed 有缓存，依赖不变直接返回缓存 |
| 4 | C | 跨路由全局状态应该用 Pinia |
| 5 | B | `vFocus` → `v-focus` 是 Vue 的自动映射规则 |
| 6 | B | composable 必须在 setup 顶层同步调用 |
| 7 | B | `effectScope` 的核心价值：批量管理副作用 + `scope.stop()` 一次性停止（7.10 节） |

**二、判断题**

| 题号 | 答案 | 解析 |
|---|---|---|
| 8 | ✅ 正确 | `shallowRef` 只对"**重新赋值 `.value`**"敏感，**不管**你在 `.value` 对象内部怎么改——因为 Vue 只在 `.value` 被 `set` 时触发依赖，内部属性的读写根本没走 Proxy 的追踪逻辑。<br>所以 `state.value.count++` 之后视图不会更新，必须**手动调 `triggerRef(state)`** 强行"踢"一下依赖系统，通知所有依赖它的副作用重跑。<br>⚠️ **什么时候该用 `shallowRef` + `triggerRef`？** 当内部对象**不适合被深度代理**时——比如一个很大的第三方实例（地图、图表库、编辑器实例），`reactive` 会递归代理它的每一个属性，既慢又可能因为 Proxy 破坏内部 `this` 而出 bug。此时用 `shallowRef` 只追踪"换了对象"这一层，内部的更新由你自己掌控时机 |
| 9 | ❌ 错误 | **写入会被拦截且不生效**——`readonly` 是**深度只读**：`readonly(reactiveObj)` 会把对象（包括所有嵌套属性）递归包成只读代理，任何写入尝试都被 Proxy 的 `set` 拦截，开发环境下额外打印一条警告。<br>⚠️ 别和 `shallowReadonly` 搞混：`shallowReadonly` **只保护第一层**，`obj.a.b = 1` 这种嵌套写入是能成功的。而 `readonly` 连嵌套也一起锁死。<br>它最典型的用途正是本章第 15 题：`provide` 出去的数据套一层 `readonly`，防止子组件反过来改祖先的状态，把单向数据流搞崩 |
| 10 | ❌ 错误 | `computed` 的设计是**纯函数**：给定同样的输入，必须算出同样的输出，不产生任何副作用。所以 Vue 会放心地**缓存**它的结果——一旦算过，依赖不变就直接返回缓存，根本不再执行。<br>如果你在 `computed` 里改别的响应式数据，就等于把"算值"和"做事情"混在了一起：① 可能和依赖关系形成**循环引用**（A 依赖 B，B 又被 A 的计算修改），直接报错或陷入死循环；② 破坏缓存的正确性，让别的组件读到"半成品"状态。<br>📌 **分家口诀**：`computed` = **"算出一个值"**（纯、缓存、惰性求值）；`watch` / `watchEffect` = **"值变了做件事"**（副作用，默认惰性，`immediate: true` 才立即跑）。副作用永远不要放进 `computed` |
| 11 | ✅ 正确 | `toRefs(reactiveObj)` 会把对象的**每个属性**转成与原属性**双向绑定**的 ref——改 `ref` 会写回原对象，改原对象也会更新 `ref`。<br>⚠️ 为什么要它？因为**解构会丢失响应性**：`const { count } = reactiveObj` 拿到的只是一个普通数字快照，从此和原对象再无关系；而 `const { count } = toRefs(reactiveObj)` 拿到的是 ref，模板和脚本里都能跟着变。<br>（注意 `toRefs` 只接受 `reactive` 对象；`ref` 对象不用拆——`ref` 本身就是深度响应式，直接 `obj.value.count` 就是响应式的。至于从 store 里解构要用 `storeToRefs`，那是第 8 章 Pinia 的内容） |
| 12 | ❌ 错误 | VueUse 是**独立的社区库**，不属于 Vue 官方核心，必须自己装：`npm install @vueuse/core`。<br>⚠️ **别和"官方出品"搞混**：Vue 官方维护的东西很多（vue-router、Pinia、Vite、Vitest……），但它们**每一个都是独立安装的**，不随 `vue` 一起装。`import` 时不写 `'vue'` 的，就说明它不在核心里。<br>VueUse 提供的是一大堆开箱即用的 composable：`useDebounceFn`、`useLocalStorage`、`useMouse`、`useIntersectionObserver` 等，写法约定是 `use` 开头 |
| 13 | ✅ 正确 | `effectScope` 内部用 `onScopeDispose` 注册"**作用域停止时要执行的清理回调**"，`scope.stop()` 一触发，注册在里面的回调就会全部执行。<br>对比记忆：组件里的清理用 `onUnmounted`，watcher 里的清理用 `onWatcherCleanup`，**作用域里的清理用 `onScopeDispose`**——三个 API 各自对应一种"生命周期终点"，别用混 |

**三、简答题**

**14.** 参考答案：
- **computed**：基于已有数据算出一个新值，有缓存。例：`const total = computed(() => price.value * quantity.value)`
- **watch**：监听某个数据变化后"做一件事"（副作用）。例：`watch(keyword, (v) => fetch('/api?q=' + v))`
- **methods**：用户触发时执行。例：`function handleSubmit() { ... }`

**15.** 参考答案：
- Prop Drilling：祖先的数据需要通过 Props 一层层传给深层后代，中间组件被迫转发不关心的数据。
- provide/inject 让祖先直接注入数据，后代直接接收，跳过中间层。
- 搭配 `readonly` 是防止后代组件直接修改祖先数据，破坏单向数据流。代码：`provide('state', readonly(reactiveState))`。

**16.** 三个问题：
1. 在 composable 顶层使用 `if` 语句发请求 —— composable 不应该在非响应式的条件中执行副作用，应该用 `watch` 监听 url 变化。
2. 没有用 `onMounted` 或 `watch` 包裹 fetch —— fetch 会立即执行，不利于控制时机。
3. 没有错误处理 —— 应加 `try/catch` 或 `.catch`，并暴露 `error` 状态。

修正版本：
```js
import { ref, watch } from 'vue'

export function useFetch(url) {
  const data = ref(null)
  const loading = ref(false)
  const error = ref(null)

  watch(() => url, async (newUrl) => {
    if (!newUrl) return
    loading.value = true
    error.value = null
    try {
      const res = await fetch(newUrl)
      data.value = await res.json()
    } catch (e) {
      error.value = e.message
    } finally {
      loading.value = false
    }
  }, { immediate: true })

  return { data, loading, error }
}
```

**四、编程题**

**15.** `v-lazy` 参考实现：

```js
export const vLazy = {
  mounted(el, binding) {
    const observer = new IntersectionObserver(([entry]) => {
      if (entry.isIntersecting) {
        el.src = binding.value   // 进入可视区，加载真实 src
        observer.unobserve(el)   // 加载后停止观察
      }
    })
    observer.observe(el)
    el._lazyObserver = observer  // 存下来以便清理
  },
  unmounted(el) {
    el._lazyObserver?.disconnect()
  }
}
```

> 🧊 **冷知识**：第 6 题和第 14 题其实是"同一枚硬币的两面"——composable 必须在 `setup` 顶层**同步**调用，本质是因为生命周期钩子和响应式副作用都要"挂"到当前组件实例上，而 Vue 的"当前实例"只在同步执行栈里有效。你在 `if` 里或异步回调里调用 `useXxx()`，钩子就找不到家了，这正是 Vue 官方 lint 规则禁止这种写法的原因。
