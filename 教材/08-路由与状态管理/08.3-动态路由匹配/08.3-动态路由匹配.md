---

## 🤔 一、场景：用户详情页

一个博客应用有 100 个用户，你不能为每个用户都写一个路由：

```js
// ❌ 不可能
{ path: '/user/1', component: User },
{ path: '/user/2', component: User },
// ... 写 100 条？
```

你需要一个**动态路由**：一条规则匹配一类 URL。

---

## 💡 二、动态路由参数 `:param`

### 2.1 定义

```js
// router/index.js
const routes = [
  {
    path: '/user/:id',       // :id 是动态部分
    component: UserDetail,
  }
]
```

`/user/:id` 能匹配：`/user/1`、`/user/abc`、`/user/hello-world`。冒号 `:` 后面的 `id` 是参数的**名字**。

多个参数也支持：

```js
{ path: '/user/:userId/post/:postId', component: PostDetail }
// 匹配 /user/42/post/101 → params = { userId: '42', postId: '101' }
```

### 2.2 在组件里获取参数

Vue Router 提供了 `useRoute()` composable，返回当前路由的信息：

```vue
<!-- src/views/UserDetail.vue -->
<script setup>
import { useRoute } from 'vue-router'

const route = useRoute()

// route.params.id 就是 URL 里 :id 的值
console.log('当前用户 ID：', route.params.id)
</script>

<template>
  <h1>用户详情</h1>
  <p>用户 ID：{{ route.params.id }}</p>
</template>
```

> 💬 **老师备注**：`route.params` 里的值都是**字符串**。`/user/123` 拿到的是 `"123"`（字符串），不是数字 123。需要数字时记得 `Number(route.params.id)` 或者用 Props 传参自动转换。

## 🔑 三、query 查询参数

除了动态路径参数，还有一种更灵活的传参方式：**query 查询参数**。

```text
/search?keyword=vue&page=2
```

query 参数不需要在路由表里声明，直接用：

```js
// 跳转时带 query
router.push({ path: '/search', query: { keyword: 'vue', page: '2' } })
```

```
<script setup>
import { useRoute } from 'vue-router'

const route = useRoute()
// route.query.keyword → 'vue'
// route.query.page → '2'
</script>
```

### params vs query：什么时候用哪个？

| | params（动态参数） | query（查询参数） |
|---|---|---|
| **写法** | `/user/:id` | 不声明，直接传 |
| **URL 示例** | `/user/123` | `/search?q=vue&page=2` |
| **是否必填** | 是（不匹配则 404） | 否（可选） |
| **适用场景** | 资源标识（用户 ID、文章 ID） | 筛选/排序/分页 |

一个简单判断：**这个东西是"标识某个资源"还是"描述怎么找资源"？** 前者用 params，后者用 query。

## 🛠 四、进阶：Props 传参（推荐写法）

用 `useRoute()` 获取参数意味着组件和路由**强耦合**——这个组件只能在路由里用。更好的做法是把路由参数通过 Props 传进去：

```js
// router/index.js
const routes = [
  {
    path: '/user/:id',
    component: UserDetail,
    props: true,  // ← 关键：把 route.params 作为 Props 传给组件
  }
]
```

```vue
<!-- UserDetail.vue -->
<script setup>
// 直接用 Props 接收，不依赖 useRoute
defineProps({
  id: {
    type: String,
    required: true
  }
})
</script>

<template>
  <h1>用户详情</h1>
  <p>用户 ID：{{ id }}</p>
</template>
```

这样做的好处：`UserDetail` 组件不依赖 Vue Router，你可以在测试里直接传 `<UserDetail id="123" />`，也可以在别的页面里直接用它。

### Props 函数模式（更灵活）

```js
{
  path: '/user/:id',
  component: UserDetail,
  props: (route) => ({
    id: Number(route.params.id),  // 自动转数字
    from: route.query.from,       // 把 query 也映射进来
  })
}
```

## ⚠️ 五、常见陷阱

### 陷阱 1：路由参数变化，组件不重新创建

从 `/user/1` 跳转到 `/user/2`，组件是同一个，Vue Router 不会销毁再重建（节能）。这意味着 `onMounted` 不会再次触发。如果你想在参数变化时重新请求数据，必须 watch `route.params`：

```js
import { watch } from 'vue'
import { useRoute } from 'vue-router'

const route = useRoute()

watch(() => route.params.id, (newId) => {
  // 重新加载用户数据
  fetchUser(newId)
})
```

### 陷阱 2：params 是字符串

```js
// route.params.id 永远是字符串
if (route.params.id === 1) { ... } // ❌ 永远不会 true
if (Number(route.params.id) === 1) { ... } // ✅
```

### 陷阱 3：query 参数是可选的

用户可能直接访问 `/search` 不带任何 query 参数，访问 `route.query.keyword` 时它是 `undefined`，记得做空值判断。

## 🧠 本节小结

- **动态段语法**：`path: '/users/:id'`，`/users/1001`、`/users/1002` 都命中同一条路由
- **取参数**：`route.params.id`；不同 id 复用同一组件，别忘了在 `watch` 里监听 `params` 变化刷新数据
- **404 兜底**：`path: '/:pathMatch(.*)*'` 捕获一切未匹配路径，渲染 NotFound 组件
- **props 解耦**：`:props: true` 把 params 作为 props 传给组件，组件不再依赖 `$route`，更好测试复用
- **可省略 params 语义**：正则/可选段按需使用，别一上来就把路由写复杂
