## 🧠 思维导图

```text
8.6 导航守卫：路由保安
├── 什么是导航守卫？
│   ├── 导航 = 路由跳转
│   ├── 守卫 = 跳转前后的"拦截点"
│   └── 可以在这些点检查权限、保存数据、取消导航
├── 全局守卫
│   ├── beforeEach：每次导航前触发（最常用）
│   ├── beforeResolve：导航确认前触发
│   └── afterEach：导航完成后触发（没有 next）
├── 路由独享守卫
│   └── beforeEnter：写在路由配置里的守卫
├── 组件内守卫
│   ├── onBeforeRouteLeave：离开当前页时触发
│   ├── onBeforeRouteUpdate：路由参数变化时触发
│   └── beforeRouteEnter（选项式 API）
└── 守卫的返回值
    ├── false / undefined：取消导航
    ├── true / 不返回：放行
    └── 返回路径字符串：重定向
```

路由能跳了、参数能传了，但你先别急着欢呼。想想真实项目最常遇到的场景：用户没登录，手抖输入了 `/admin` 的网址，页面居然直接进去了？下单页、后台页全都裸奔可不行。这节讲导航守卫——在路由跳转的必经之路上设卡检查，拦住没资格的人。

> 🎯 **类比一下：导航守卫 ≈ 地铁站的"安检闸机"**
> 每个乘客（导航）进站（路由跳转）都必须过闸机（守卫）：没票（未登录）→ 被拦去补票（重定向登录页）；票没问题 → 放行。闸机设在进站口（全局守卫 beforeEach），也可以设在特定站台（路由独享 beforeEnter）、甚至车厢门口（组件内守卫）。

> 🧑 **小白**：守卫里 return 一个路径，就是"重定向"吗？
> 🤖 **Vue 君**：对，返回路径 = 改道去别的站；返回 false = 关门不放行（取消导航）。
> 👨🏫 **老湿**：**Vue Router 5 记住一条：守卫靠"返回值"说话**，不用再纠结 next() 那套老写法。

## 🤔 一、导航守卫要解决什么问题？

想象这些场景：

- 用户没登录，想直接访问 `/dashboard` → 踢到登录页
- 用户正在编辑表单，不小心点了后退 → 弹窗确认"有未保存的修改"
- 页面跳转后，自动把页面标题改成新页面的标题

这些都是导航守卫的用武之地。导航守卫就像**路由的安检通道**：每次路由跳转都要经过它，由它决定"放行"、"重定向"还是"禁止通行"。

---

## 💡 二、全局前置守卫 `beforeEach`

`beforeEach` 最常用，**每次导航都会触发**，适合做权限验证、登录拦截。

```js
// src/router/index.js
import { createRouter, createWebHistory } from 'vue-router'

const router = createRouter({ /* ... */ })

// 全局前置守卫
router.beforeEach((to, from, next) => {
  // to：要去的路由（Route 对象）
  // from：当前的路由（Route 对象）
  // next：控制放行/重定向的函数（Vue Router 5 中 next 是可选的）
})
```

Vue Router 5 推荐用**返回值**来控制导航（而不是调 `next`）：

```js
// ✅ Vue Router 5 推荐写法：返回值
router.beforeEach((to, from) => {
  const isLoggedIn = !!localStorage.getItem('token')

  // 要去需要登录的页面，但没登录
  if (to.meta.requiresAuth && !isLoggedIn) {
    // 返回路径 → 重定向到登录页
    return { path: '/login', query: { redirect: to.fullPath } }
  }

  // 已登录用户访问登录页 → 重定向到首页
  if (to.path === '/login' && isLoggedIn) {
    return '/'
  }

  // 返回 true 或什么都不返回 → 放行
  return true
})
```

## 🔑 三、在路由配置中标记"需要登录"

通过路由元信息 `meta` 标记需要登录的页面：

```js
const routes = [
  {
    path: '/dashboard',
    component: () => import('../views/Dashboard.vue'),
    meta: { requiresAuth: true }  // ← 需要登录
  },
  {
    path: '/profile',
    component: () => import('../views/Profile.vue'),
    meta: { requiresAuth: true }
  },
  {
    path: '/login',
    component: () => import('../views/Login.vue'),
    meta: { requiresAuth: false }
  },
  {
    path: '/',
    component: () => import('../views/Home.vue'),
    meta: { requiresAuth: false }
  },
]
```

守卫里统一判断：`to.meta.requiresAuth`。

## 🛠 四、路由独享守卫 `beforeEnter`

如果某个守卫逻辑只适用于特定路由，可以直接写在路由配置里：

```js
const routes = [
  {
    path: '/admin',
    component: AdminPanel,
    beforeEnter: (to, from) => {
      // 只对 /admin 生效的守卫
      const user = getUserFromStore()
      if (user.role !== 'admin') {
        return '/403'  // 权限不足
      }
      return true
    }
  }
]
```

`beforeEnter` 只在进入该路由时触发，离开或参数变化时不触发。

## 🛠 五、组件内守卫

如果你只想在某个特定组件里做守卫（比如编辑页的"未保存离开确认"），可以用组件内守卫：

### 5.1 `onBeforeRouteLeave`：离开页面前

```vue
<script setup>
import { ref } from 'vue'
import { onBeforeRouteLeave } from 'vue-router'

const hasChanges = ref(false)

onBeforeRouteLeave((to, from) => {
  if (hasChanges.value) {
    // 返回 false 取消导航
    const answer = window.confirm('你还有未保存的修改，确定离开吗？')
    if (!answer) return false
  }
  return true
})
</script>
```

### 5.2 `onBeforeRouteUpdate`：路由参数变化

```vue
<script setup>
import { onBeforeRouteUpdate } from 'vue-router'

onBeforeRouteUpdate((to, from) => {
  // 从 /user/1 跳转到 /user/2 时触发
  // 组件没有重新创建，但参数变了
  console.log('用户 ID 变了：', to.params.id)
})
</script>
```

## ⚠️ 六、完整的导航解析流程

理解守卫的执行顺序对调试很重要：

```text
1. 导航被触发
2. 在失活的组件里调用 onBeforeRouteLeave
3. 调用全局 beforeEach 守卫
4. 在重用组件里调用 onBeforeRouteUpdate
5. 在路由配置里调用 beforeEnter
6. 解析异步路由组件
7. 在被激活的组件里调用 beforeRouteEnter（选项式 API）
8. 调用全局 beforeResolve 守卫
9. 导航被确认
10. 调用全局 afterEach 钩子
11. DOM 更新
```

> 💬 **老师备注**：记住最关键的两个就行——`beforeEach`（全局，最常用）和 `onBeforeRouteLeave`（组件级，处理"未保存离开"）。其他守卫在需要时查文档即可。

## ⚠️ 七、常见陷阱

### 陷阱 1：以为"不写 return"会挂起导航

这是一个**流传很广的误解**，先纠正认知：

```js
// ✅ 这样写完全没问题——不 return 等于 return undefined，undefined 就是「放行」
router.beforeEach((to, from) => {
  if (to.meta.requiresAuth && !isLoggedIn) {
    return '/login'
  }
  // 走到这里不写 return → undefined → 导航被「验证通过」，正常进行
})
```

Vue Router 官方文档的原文是：

> 如果没有返回值、`undefined` 或 `true`，**导航将被验证通过**（the navigation is validated）。

也就是说：**返回值模式根本没有"漏调就卡死"的问题**，这正是它比老的 `next()` 写法更省心的原因。

> 💬 **老师备注**：那为什么很多项目还坚持每个分支都写 `return true`？**纯为了可读性**——让看代码的人一眼知道"这里显式放行"，而不是"忘了写"。这是风格选择，不是必需。

那真正的陷阱是什么？**是返回了错误的值**：

```js
// ❌ 真正的 bug：把「放行」写成了「重定向到当前页」
router.beforeEach((to, from) => {
  if (to.meta.requiresAuth && !isLoggedIn) {
    return '/login'
  }
  return from          // ← 返回 from 会触发一次「重定向回来源页」
})

// ❌ 更常见的坑：需要返回 false 时写成了 falsy 的其他值
router.beforeEach((to, from) => {
  if (to.meta.requiresAuth && !isLoggedIn) {
    return false       // ✅ 只有 false 是「取消导航」
  }
  return ''            // ← 空的字符串不是 false，是「重定向到空路径」，行为诡异
})
```

**记住三种返回值**：`false` = 取消导航、`'路径'` 或 `{ name: 'x' }` = 重定向、`true` / `undefined` / 不返回 = 放行。

### 陷阱 2：守卫里做了异步操作但没正确处理

```js
// ❌ 守卫不等待异步操作
router.beforeEach(async (to, from) => {
  const user = await fetchUser()  // 这里会等，但逻辑要完整
  if (!user && to.meta.requiresAuth) {
    return '/login'
  }
  return true
})
```

异步守卫是可以的，但要确保所有分支都有返回值。

### 陷阱 3：`next` 调用多次

```js
// ❌ 调了 next() 又 return
router.beforeEach((to, from, next) => {
  if (isLoggedIn) {
    next()
  }
  next('/login')  // ← 可能调用两次
})

// ✅ Vue Router 5 推荐不用 next，直接用 return
router.beforeEach((to, from) => {
  if (isLoggedIn) return true
  return '/login'
})
```

## 🧠 本节小结

- **守卫本质**：导航发生前后挂上"关卡"，可以放行、拦下、重定向到别的页
- **全局守卫**：`beforeEach` 最常用；`return false` 中止导航，返回路径字符串则重定向
- **路由独享守卫**：`beforeEnter` 只保护某一条路由；**组件内守卫**：`onBeforeRouteLeave` 等写在组件里
- **读元信息**：`to.meta.requiresAuth` 这类字段配合守卫实现权限拦截，别把权限判断散落各组件
- **写法纪律**：**Vue Router 4 起官方推荐用返回值代替 `next()`**；`next()` 在 Vue Router 5 中**仍然受支持**（官方文档标注为"可选的第三个参数"），只是不再是首选。**两种写法不要混用**——同一个守卫里既 `next()` 又 `return` 会导致导航被处理两次

> 🧊 **冷知识**：守卫的执行顺序是固定的：**全局 beforeEach → 路由独享 beforeEnter → 组件内 onBeforeRouteUpdate / beforeRouteEnter → 全局 beforeResolve → 导航确认 → 全局 afterEach**。想给页面加"标题更新"就放 afterEach（导航已确定），想加"权限校验"就放 beforeEach（最早、最前置）。顺序记牢，写守卫心里有谱。

<details><summary>🔍 想深究再看：为什么官方推荐用返回值而不是 next()？</summary>

Vue Router **3** 时代，守卫必须调 `next()` 显式放行——漏调会导致导航"卡死"（既不放行也不取消，页面白等）。这个设计既容易忘、又容易重复调用。

Vue Router **4** 起改用**返回值说话**：返回 `true` / 不返回 = 放行，返回 `false` = 取消，返回路径或对象 = 重定向。返回值模式没有"漏调"问题——没写 return 就是默认放行。

**关于 Vue Router 5**：官方迁移指南明确写了，如果你在用 Vue Router 4（且没装 `unplugin-vue-router`），**升级到 5 没有破坏性变更**；导航守卫文档也把 `next` 标注为"可选的第三个参数"，并说明它**仍然受支持**。所以 `next()` **没有被弃用**，只是不再是首选。

**给新代码的建议**：一律用返回值。理由不是"旧写法不能用"，而是返回值模式的心智负担更小——你不需要在每个分支都记得调一次 `next`。

**如果你在维护老项目**：`next()` 继续用即可，只要遵守一条纪律——**同一个守卫里要么全用 `next()`，要么全用返回值，不要混用**。混用会导致导航被处理两次，出现诡异的跳转行为。

</details>
