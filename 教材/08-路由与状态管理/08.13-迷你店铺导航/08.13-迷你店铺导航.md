## 🎯 项目需求（一句话）

做一个"迷你二手店铺"：首页商品列表 → 点进商品详情（动态路由）→ 加购进购物车（Pinia，刷新后购物车还在）→ 结算时未登录先跳登录页（路由守卫 + Store）——全程只用第 8 章已学的 Router 与 Pinia 能力，不引入新库。

### ✅ 验收标准（能跑、能展示）

- [ ] 项目能 `npm run dev` 启动，导航栏能切换"商品列表 / 购物车 / 登录"三个页面
- [ ] 列表页点某件商品，URL 变成 `/goods/:id` 且详情页展示对应商品
- [ ] 商品详情页点"加入购物车"，购物车角标数字 +1；商品可再次加购、可删除
- [ ] 购物车数据用 Pinia 管理并持久化到 `localStorage`：**刷新页面购物车不丢**
- [ ] 未登录时直接访问 `/cart`（或结算按钮）会被守卫拦下并跳到登录页；"登录"后能回到原目标页
- [ ] 能向同学讲清：为什么"购物车"放 Pinia 而不是每个页面自己 `ref`？守卫为什么要在 `beforeEach` 里读 Store？

## 🛠 分步提示（3~5 步，含关键代码锚点）

> 以下只给路线和关键锚点，**不贴全量答案**。卡住时回头翻 8.2 / 8.3 / 8.6 / 8.9 / 8.10 / 8.11 对应小节。

### Step 1：搭路由骨架（回顾 8.2）

建 `router/index.js`：三条一级路由 `/`（列表）、`/goods/:id`（详情，动态路由回顾 8.3）、`/cart`（购物车），App 顶部用 `router-link` 做导航、页面出口放 `<RouterView />`。商品数据先写死在页面里，先把"三个页面能互相跳"跑通。

### Step 2：商品数据进 Store（回顾 8.9 的 product store）

仿照课堂 `stores/product.js` 建 `stores/product.js`：`defineStore` + Setup Store 风格，state 放 6~8 件二手商品（名称、价格、图片可用 emoji/色块占位、描述），提供"按 id 取商品"的 getter。列表页用 `storeToRefs` 解出商品数组渲染成卡片。

### Step 3：详情页走动态路由（回顾 8.3）

详情页用 `useRoute()` 拿 `route.params.id`，再调 product store 的 getter 取商品。可选把 `:id` 声明为 props 后直接用 `defineProps` 接收（8.3 的 Props 传参模式）。卡片上"加入购物车"按钮先留空壳。

### Step 4：购物车 Store + 持久化（回顾 8.8 / 8.9 / 8.10）

建 `stores/cart.js`：state 存 `items`（商品 id + 数量）、actions 提供 `add(itemId)` / `remove(itemId)` / `clear()`，`totalAmount` 用 `computed` 在 store 内实时汇总（回顾 8.9 跨 Store 协作：需要商品单价时在 cart 里 import `useProductStore` 查价格）。按 8.10 教的 localStorage 持久化姿势，让 `items` 刷新不丢。购物车页展示行明细 + 总价 + "去结算"按钮（暂时跳 `/cart` 自己或占位）。

### Step 5：登录守卫 + Store 权限（回顾 8.6 / 8.11）

建 `stores/user.js`（或 `auth.js`）：`isLoggedIn` + `login()` + `logout()`。用 8.11 的姿势在 `router.beforeEach` 里拦截未登录访问 `/cart`：

```js
router.beforeEach((to) => {
  const user = useUserStore()   // 9.11 强调：在守卫里调用 Pinia 是安全的
  if (to.path === '/cart' && !user.isLoggedIn) {
    return { path: '/login', query: { redirect: to.fullPath } }
  }
})
```

登录页点"模拟登录"后调 `user.login()` 并 `router.push(route.query.redirect || '/')` 回跳（回顾 8.5 编程式导航）。此时再验证：未登录访问 `/cart` 被拦、登录后能回到购物车。

**`src/stores/cart.js`** —— 含跨 Store 协作与持久化：

```js
import { defineStore } from 'pinia'
import { computed, ref, watch } from 'vue'
import { useProductStore } from './product'

const STORAGE_KEY = 'mini-shop-cart'

export const useCartStore = defineStore('cart', () => {
  // state：只存"商品 id + 数量"，不存商品详情
  // 原因：商品价格会变，存快照会导致购物车里显示过期价格
  const items = ref([])

  // 冷备份：从 localStorage 恢复
  function load() {
    try {
      const raw = localStorage.getItem(STORAGE_KEY)
      if (raw) items.value = JSON.parse(raw)
    } catch (e) {
      console.warn('购物车数据解析失败，已重置', e)
      items.value = []
    }
  }

  // 活状态 → 冷备份：数据一变就写回 localStorage
  watch(items, (val) => {
    localStorage.setItem(STORAGE_KEY, JSON.stringify(val))
  }, { deep: true })

  // actions
  function add(itemId, count = 1) {
    const exist = items.value.find((i) => i.itemId === itemId)
    if (exist) {
      exist.count += count          // 已在车里 → 加数量
    } else {
      items.value.push({ itemId, count })
    }
  }

  function remove(itemId) {
    items.value = items.value.filter((i) => i.itemId !== itemId)
  }

  function setCount(itemId, count) {
    const target = items.value.find((i) => i.itemId === itemId)
    if (target) target.count = Math.max(0, count)
  }

  function clear() {
    items.value = []
  }

  // ====== 跨 Store 协作：需要价格时去 product store 查 ======
  const productStore = useProductStore()

  // 明细：把 id 展开成完整商品信息
  const detailedItems = computed(() =>
    items.value
      .map((i) => {
        const p = productStore.getById(i.itemId)
        return p ? { ...p, count: i.count, subtotal: p.price * i.count } : null
      })
      .filter(Boolean)
  )

  // 总价：全部由明细推导，不手动维护
  const totalAmount = computed(() =>
    detailedItems.value.reduce((sum, i) => sum + i.subtotal, 0)
  )

  const totalCount = computed(() =>
    items.value.reduce((sum, i) => sum + i.count, 0)
  )

  return {
    items, load, add, remove, setCount, clear,
    detailedItems, totalAmount, totalCount
  }
})
```

**`src/stores/user.js`**：

import { defineStore } from 'pinia'
import { ref } from 'vue'

export const useUserStore = defineStore('user', () => {
  const isLoggedIn = ref(false)
  const nickname = ref('')

  function login(name = '小新') {
    isLoggedIn.value = true
    nickname.value = name
  }

  function logout() {
    isLoggedIn.value = false
    nickname.value = ''
  }

  return { isLoggedIn, nickname, login, logout }
})

**`src/router/index.js`** —— 路由表 + 守卫：

```js
import { createRouter, createWebHistory } from 'vue-router'
import { useUserStore } from '@/stores/user'
import HomeView from '@/views/HomeView.vue'

const router = createRouter({
  history: createWebHistory(),
  routes: [
    { path: '/', name: 'home', component: HomeView },
    // 动态路由：/goods/3 → GoodsDetailView，id 从 params 拿
    {
      path: '/goods/:id',
      name: 'goods-detail',
      component: () => import('@/views/GoodsDetailView.vue')
    },
    { path: '/cart', name: 'cart', component: () => import('@/views/CartView.vue') },
    { path: '/login', name: 'login', component: () => import('@/views/LoginView.vue') },
    // 兜底：放最后
    { path: '/:pathMatch(.*)*', name: 'not-found', component: () => import('@/views/NotFoundView.vue') }
  ]
})

// ====== 导航守卫：未登录访问 /cart 拦到 /login ======
router.beforeEach((to) => {
  // 在守卫里调 useStore 是安全的——此时 Pinia 已挂载
  const user = useUserStore()

  if (to.path === '/cart' && !user.isLoggedIn) {
    // 返回路径对象，Vue Router 5 会自动导航；带上来源，登录后回跳
    return { path: '/login', query: { redirect: to.fullPath } }
  }
})

export default router
```

> 💬 **老师备注：这个成品里有三处"故意踩的坑"，值得你找出来**
>
> **① `cart.js` 里只存 id 不存商品快照。**
> 很多教程会把整个商品对象塞进购物车：`items.push({ ...product, count: 1 })`。这样一旦商品涨价，购物车里还显示旧价格——**因为那是快照**。正确做法是只存 `itemId`，要价格时去 `productStore` 查（就是上面 `detailedItems` 做的跨 Store 协作）。**购物车是"引用"，不是"拷贝"。**
>
> **② `watch(items, ...)` 为什么要加 `{ deep: true }`？**
> 因为 `items` 是数组，数组本身被替换时（`items.value = [...]`）浅层 watch 能触发；但 `exist.count += 1` **改的是数组里某个对象的属性**，数组引用没变，浅层 watch 收不到。加 `deep: true` 才能监听到内部变化。
>
> **③ 守卫里为什么用 `return { path: '/login', query: {...} }` 而不是 `next('/login')`？**
> Vue Router 4+ 推荐直接 `return` 目标位置，**不需要 `next()`**。而且 `return` 的写法能避免 `next()` 被调用两次的经典 bug。回顾 8.6：两种写法都对，但 `return` 更不容易出错。

</details>

> 🧊 **冷知识**：你在这个实战里写的"`router.beforeEach` 里 `useUserStore()` 读登录态"，正是第 8 章最难也最常考的联合姿势。很多新手在这里翻车是因为忘记 `app.use(pinia)` 要**先于** `app.use(router)`——守卫在路由安装时就可能被触发，Pinia 还没挂上，`useStore()` 直接报错。装插件顺序：**先 Pinia，后 Router**。

<details><summary>🔍 想深究再看：为什么"迷你店铺"不把购物车直接放 localStorage？</summary>

如果购物车只存 localStorage，页面 A 加了商品，页面 B 的角标**不会自动 +1**——localStorage 不会通知界面。Pinia 的价值恰恰在这：它是**响应式的活状态**，任何组件读了 store 都会自动跟随更新；localStorage 只是"冷备份"，负责刷新后恢复。这个实战要求"购物车 Pinia + 持久化"双管齐下，就是要你体会"活状态 + 冷备份"的分工。第 12 章大项目里，这套组合会原样放大成正式架构。

</details>
