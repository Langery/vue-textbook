## 💡 一、原则 3：低耦合（Low Coupling）

### 定义

> **组件之间的依赖尽量少、尽量松散。删掉一个组件，其他组件应当还能正常运行。**

### 反例：组件之间"直接操作"

```
<!-- ❌ OrderList.vue：直接操作兄弟组件的数据 -->
<script setup>
import { cartItems } from './CartBadge.vue' // ❌ 直接引入兄弟组件的变量
import { addToCart } from './CartBadge.vue' // ❌ 直接调用兄弟组件的函数

function handleBuy(item) {
  cartItems.value.push(item)  // ❌ 直接改兄弟的数据
  showToast('已加入购物车')
}
</script>
```

**问题**：
- OrderList 和 CartBadge **强绑定**——改 CartBadge 的内部变量名，OrderList 也得改
- 无法独立测试 OrderList——测试它必须同时引入 CartBadge
- 如果哪天不用 CartBadge 了，OrderList 直接炸

### 正例：通过事件通信

```
<!-- ✅ OrderList.vue：通过 emit 通知父组件 -->
<script setup>
const emit = defineEmits(['add-to-cart'])

function handleBuy(item) {
  emit('add-to-cart', item) // ✅ 只是通知父组件，父组件决定怎么处理
}
</script>
```

```vue
<!-- ✅ 父组件：负责协调 -->
<script setup>
import { ref } from 'vue'
import OrderList from './OrderList.vue'
import CartBadge from './CartBadge.vue'

const cartItems = ref([])

function handleAddToCart(item) {
  cartItems.value.push(item)
}
</script>

<template>
  <OrderList @add-to-cart="handleAddToCart" />
  <CartBadge :count="cartItems.length" />
</template>
```

<img src="../00-公共资源/图/03-组件化思想/图3-3.svg" alt="高耦合 vs 低耦合的数据流对比">

**OrderList 不知道 CartBadge 的存在**——它只负责通知父组件"有人点了购买"。父组件作为"调度中心"来协调两个子组件。

> 💬 **老师备注**：Vue 的组件通信有一个**黄金规则**——**数据向下（Props），事件向上（emit）**。父子之间遵守这条规则，兄弟之间通过父组件做中转，你的组件树就永远是"低耦合"的。第 4 章会全面讲 Props 和事件。

### 低耦合的检查标准

问自己一个问题：**"删掉这个组件，其他组件还能跑吗？"**

- 如果答案是"能"——恭喜，你的组件耦合度很低
- 如果答案是"不能，因为 X 组件直接用了它的数据"——说明耦合太紧，需要重构

## 🛠 二、综合实战：基于三大原则重构一个组件

场景：做一个"课程卡片"，显示课程名、讲师、价格、标签、购买按钮。

### 违反三大原则的写法（❌）

```vue
<!-- ❌ 一个组件管全部，数据写死，无法复用 -->
<script setup>
import { ref } from 'vue'

// 所有数据写死在组件里
const courseName = ref('Vue 3 全栈实战')
const teacher = ref('张老师')
const price = ref(299)
const tag = ref('热门')
const bought = ref(false)

function buy() {
  bought.value = true
  alert('购买成功！')
}
</script>

<template>
  <div class="course-card">
    <span class="tag">{{ tag }}</span>
    <h3>{{ courseName }}</h3>
    <p>讲师：{{ teacher }}</p>
    <p class="price">¥{{ price }}</p>
    <button @click="buy" :disabled="bought">
      {{ bought ? '已购买' : '立即购买' }}
    </button>
  </div>
</template>
```

**它违反了哪条原则？** 全违反了：

- ❌ 数据写死 → 违反**开闭原则**（无法扩展）
- ❌ 标签、按钮逻辑全塞在一个组件 → 违反**单一职责**
- ❌ 购买逻辑和展示逻辑耦合 → 违反**低耦合**

### 按三大原则重构（✅）

先拆分：CourseCard（卡片主体）+ CourseTag（标签）+ BuyButton（购买按钮）

```
<!-- CourseTag.vue —— 标签组件（单一职责 + 开闭原则） -->
<script setup>
defineProps({
  text: { type: String, required: true },
  type: {
    type: String,
    default: 'default',
    validator: (v) => ['default', 'hot', 'new'].includes(v)
  }
})
</script>

<template>
  <span class="tag" :class="`tag--${type}`">{{ text }}</span>
</template>

<style scoped>
.tag {
  display: inline-block;
  padding: 2px 8px;
  border-radius: 4px;
  font-size: 12px;
  color: #fff;
}
.tag--default { background: #718096; }
.tag--hot     { background: #e53e3e; }
.tag--new     { background: #38a169; }
</style>
```

```
<!-- BuyButton.vue —— 购买按钮组件（单一职责 + 低耦合） -->
<script setup>
const props = defineProps({
  price: { type: Number, required: true },
  disabled: { type: Boolean, default: false }
})
const emit = defineEmits(['buy'])

function handleClick() {
  emit('buy', props.price)
}
</script>

<template>
  <button
    class="buy-btn"
    :disabled="disabled"
    @click="handleClick"
  >
    {{ disabled ? '已购买' : `¥${price} 立即购买` }}
  </button>
</template>

<style scoped>
.buy-btn {
  width: 100%;
  padding: 12px;
  border: none;
  border-radius: 8px;
  background: linear-gradient(135deg, #42b883, #38a06c);
  color: #fff;
  font-size: 16px;
  font-weight: 600;
  cursor: pointer;
  transition: opacity 0.2s;
}
.buy-btn:disabled {
  background: #cbd5e0;
  cursor: not-allowed;
}
.buy-btn:not(:disabled):hover {
  opacity: 0.9;
}
</style>
```

```vue
<!-- CourseCard.vue —— 卡片主体（组合上面两个子组件） -->
<script setup>
import { ref } from 'vue'
import CourseTag from './CourseTag.vue'
import BuyButton from './BuyButton.vue'

const props = defineProps({
  course: { type: Object, required: true }
})

const bought = ref(false)

function handleBuy(price) {
  bought.value = true
  alert(`购买成功！支付 ¥${price}`)
}
</script>

<template>
  <div class="course-card">
    <CourseTag
      :text="course.tag"
      :type="course.tagType"
    />
    <h3>{{ course.name }}</h3>
    <p class="teacher">讲师：{{ course.teacher }}</p>
    <BuyButton
      :price="course.price"
      :disabled="bought"
      @buy="handleBuy"
    />
  </div>
</template>

<style scoped>
.course-card {
  border: 1px solid #e2e8f0;
  border-radius: 12px;
  padding: 20px;
  max-width: 300px;
  background: #fff;
}
.course-card h3 {
  margin: 12px 0 8px 0;
  font-size: 18px;
}
.teacher {
  color: #718096;
  font-size: 14px;
  margin-bottom: 16px;
}
</style>
```

**使用方式**：

```vue
<script setup>
import CourseCard from './CourseCard.vue'

const courses = [
  { name: 'Vue 3 全栈实战', teacher: '张老师', price: 299, tag: '热门', tagType: 'hot' },
  { name: 'React 18 精讲',   teacher: '李老师', price: 199, tag: '新课', tagType: 'new' },
  { name: 'Node.js 基础',    teacher: '王老师', price: 99,  tag: '基础', tagType: 'default' }
]
</script>

<template>
  <div class="course-list">
    <CourseCard
      v-for="item in courses"
      :key="item.name"
      :course="item"
    />
  </div>
</template>
```

> 💬 **老师备注**：重构后，每个组件职责清晰，CourseTag 和 BuyButton 可以在其他页面复用，CourseCard 只需关心"组合"。改标签样式？只改 CourseTag 一个文件——其他组件完全不受影响。

## ⚠️ 三、常见陷阱

### 陷阱 1：为了"解耦"把所有通信都走全局状态

```
<!-- ❌ 两个毫不相干的组件，非要通过 Pinia 共享 -->
const store = useCartStore()
store.addToCart(item)   // 明明用 emit 就够
```

全局状态（Pinia / Vuex）是"最后的手段"，不是"默认手段"。局部通信（Props + emit）能解决的，不要升级到全局状态，否则组件一多，状态管理就变成"一团乱麻"。

### 陷阱 2：emit 事件名起得太泛

```
<!-- ❌ 事件名太泛，父组件不知道什么时候触发 -->
<button @click="$emit('change', ...)">

<!-- ✅ 事件名说明业务语义 -->
<button @click="$emit('add-to-cart', item)">
```

事件名建议用"动词 + 宾语"的格式，让别人一眼看出这个事件是干什么的。

### 陷阱 3：组件内部直接 import 兄弟组件的状态

这在前面"反例"里已经见过。记住：**兄弟组件之间永远不要互相 import 数据**，一律通过父组件中转。

## 🧠 本节小结

- **原则 3 低耦合**：组件之间尽量"只通过 Props 进、事件出"通信，不互相操作内部状态
- **反例与正例**：A 直接操作 B 的状态 → 一改全崩；改为子组件 emit 事件、父组件统一处理 → 各自独立可测
- **检查标准**：把组件单独拎出来还能不能跑？内部实现换了会不会影响别人？
- **综合重构套路**：先识别"神组件 + 高耦合"，再按职责拆、用事件解耦、用 Props 开放扩展
- **别矫枉过正**：为"解耦"把所有通信都塞进全局状态（Pinia），耦合没少、反而更难追踪
