## 🤔 一、两种 API，两种组织方式

Vue 3 支持**两种写 Vue 组件的方式**：选项式 API 和组合式 API。

**它们不是"替代关系"，而是"两种不同的代码组织哲学"**。

### 选项式 API：按"选项类型"分类

```
<script>
export default {
  // 数据
  data() {
    return {
      count: 0,
      message: 'Hello'
    }
  },

  // 计算属性
  computed: {
    doubleCount() {
      return this.count * 2
    }
  },

  // 方法
  methods: {
    increment() {
      this.count++
    }
  },

  // 侦听器
  watch: {
    count(newVal) {
      console.log('count 变了:', newVal)
    }
  },

  // 生命周期
  mounted() {
    console.log('组件挂载好了')
  }
}
</script>
```

<img src="../00-公共资源/图/03-组件化思想/图3-11.svg" alt="选项式 API vs 组合式 API 的代码组织对比">


**组织方式**：把代码按"类型"分到不同的"选项框"里——数据放 `data`，函数放 `methods`，计算属性放 `computed`。

### 组合式 API：按"逻辑功能"分类

```vue
<script setup>
import { ref, computed, watch, onMounted } from 'vue'

// 计数器相关逻辑（在一个"逻辑块"里）
const count = ref(0)
const doubleCount = computed(() => count.value * 2)
function increment() { count.value++ }
watch(count, (newVal) => { console.log('count 变了:', newVal) })

// 消息相关逻辑（另一个"逻辑块"）
const message = ref('Hello')

// 生命周期
onMounted(() => { console.log('组件挂载好了') })
</script>
```

**组织方式**：把跟"计数器"相关的**所有代码**（数据 + 计算 + 方法 + 侦听）写在一坨，跟"消息"相关的写在另一坨。

<img src="../00-公共资源/图/03-组件化思想/图3-11.svg" alt="选项式 API 和组合式 API 的代码组织对比">

> 💬 **老师备注**：这个对比是理解 Vue 3 的关键。**选项式 API = 按"代码类型"分类；组合式 API = 按"逻辑功能"分类。** 后者让同一个功能的代码内聚在一起，阅读和维护都更直观。

## 💡 二、同一功能的两种写法对比

### 场景：一个计数器组件

**选项式 API 写法**：

```vue
<script>
export default {
  data() {
    return {
      count: 0
    }
  },
  computed: {
    doubleCount() {
      return this.count * 2
    },
    isPositive() {
      return this.count > 0
    }
  },
  methods: {
    increment() {
      this.count++
    },
    decrement() {
      this.count--
    },
    reset() {
      this.count = 0
    }
  },
  mounted() {
    console.log('计数器组件已挂载，初始值：', this.count)
  }
}
</script>

<template>
  <div>
    <p>计数：{{ count }}</p>
    <p>双倍：{{ doubleCount }}</p>
    <button @click="increment">+1</button>
    <button @click="decrement">-1</button>
    <button @click="reset">重置</button>
  </div>
</template>
```

**组合式 API 写法（`<script setup>`）**：

```
<script setup>
import { ref, computed, onMounted } from 'vue'

// —— 计数器相关的全部代码在一坨 ——
const count = ref(0)
const doubleCount = computed(() => count.value * 2)
const isPositive = computed(() => count.value > 0)

function increment() { count.value++ }
function decrement() { count.value-- }
function reset() { count.value = 0 }

onMounted(() => {
  console.log('计数器组件已挂载，初始值：', count.value)
})
</script>

<template>
  <div>
    <p>计数：{{ count }}</p>
    <p>双倍：{{ doubleCount }}</p>
    <button @click="increment">+1</button>
    <button @click="decrement">-1</button>
    <button @click="reset">重置</button>
  </div>
</template>
```

### 看出区别了吗？

| 维度 | 选项式 API | 组合式 API |
|---|---|---|
| **代码组织** | 按类型分区（data/methods/computed） | 按功能内聚（计数器的一坨、表单的一坨） |
| **this** | 到处用 `this` | 不需要 `this` |
| **类型推导** | 需要额外配置 | 原生支持，TS 友好 |
| **逻辑复用** | Mixins（容易冲突） | Composables（函数式、无冲突） |
| **心智负担** | 记住选项名 | 记住 API 函数名 |
| **模板部分** | **完全一样** | **完全一样** |

> 💬 **老师备注**：注意模板部分（`<template>` 标签里的内容）**两种写法完全一样**！选项式和组合式的区别只在 `<script>` 里。你的 HTML/CSS 完全不受影响。

## 💡 三、`<script setup>`：组合式 API 的终极形态

Vue 3.2 引入了 `<script setup>` 语法糖，进一步简化组合式 API。

```
<script setup>
import { ref } from 'vue'

// 顶级变量自动暴露给模板
const count = ref(0)

// defineProps / defineEmits 不需要 import，编译器全局可用
const props = defineProps({
  title: String
})

const emit = defineEmits(['update'])
</script>
```

**`<script setup>` 的好处**：

| 好处 | 说明 |
|---|---|
| **不需要 `return`** | 顶级变量和函数自动暴露给模板 |
| **不需要手动注册组件** | import 进来的组件直接在模板里用 |
| **编译时优化** | 更小的打包体积，更好的性能 |
| **更少的样板代码** | 少了 `export default`、`components`、`setup()` 等模板代码 |

> 💬 **老师备注**：Vue 3.8 引入了 `useTemplateRef()` 来替代传统的 `ref` 获取模板引用（DOM 元素或组件实例）。传统写法 `const inputRef = ref(null)` 然后在模板里 `ref="inputRef"` 仍然能用，但 `useTemplateRef('inputRef')` 更语义化、类型推导更精准。本书第 4 章讲 ref 时会对比两种写法，现在你先知道有这个新 API 就行。

## 💡 四、该用哪个？

### 答案很明确

| 场景 | 推荐 | 理由 |
|---|---|---|
| **新项目** | 组合式 API + `<script setup>` | Vue 官方主推，生态工具倾向 |
| **Vue 2 老项目** | 选项式 API | 不动老代码，渐进迁移 |
| **团队有 Vue 2 经验** | 选项式 → 逐步引入组合式 | 降低迁移摩擦 |
| **学习** | 两种都了解，**主学组合式** | 面试两种都会问，但日常写组合式 |

> 💬 **老师备注**：本书 100% 使用组合式 API（`<script setup>`）。如果你将来接手 Vue 2 老项目需要选项式，花 30 分钟看[官方迁移指南](https://v3-migration.vuejs.org/)就够了。

### 为什么本书主推组合式 API？

1. **逻辑内聚**：同一功能的代码在一起，改需求不用跨 section
2. **复用简单**：抽离成 composable 函数（第 8-9 章重点），比 Mixins 清晰 10 倍
3. **TS 友好**：TypeScript 原生支持，不需要额外装饰器
4. **Vue 的未来**：官方主推，新特性优先支持组合式

## ⚠️ 五、常见陷阱

### 陷阱 1：在组合式 API 里用 `this`

```vue
<script setup>
import { ref } from 'vue'
const count = ref(0)

function log() {
  console.log(this.count) // ❌ 组合式 API 里没有 this！
}
</script>
```

**正确**：直接用变量名 `count.value`。

### 陷阱 2：混用选项式和组合式

虽然 Vue 3 允许一个组件里同时用两种 API，但**强烈不建议**。选了组合式就全用组合式代码。

### 陷阱 3：以为"组合式 API"就是"把代码打乱"

新手写组合式 API 时，把所有 `ref` 堆在一起，所有 `function` 堆在一起——变成选项式 API 的拙劣模仿。记住核心：**按逻辑功能分组**。

```vue
<script setup>
// ✅ 好的分组：相关代码在一起
// —— 用户信息 ——
const user = ref(null)
const isLoading = ref(false)
async function fetchUser() { /* ... */ }

// —— 商品列表 ——
const products = ref([])
function addToCart(id) { /* ... */ }
</script>
```

## 🧠 本节小结

- **两种 API 是"组织代码"的两套思路**：选项式按类型（data/methods/computed）分类，组合式按"逻辑功能"聚合
- **同功能两种写法**：计数器例子说明——选项式把相关代码拆散，组合式把相关代码聚到一起
- **`<script setup>`**：组合式 API 的终极形态，少一层 `setup()` 包裹，本书默认写法
- **该用哪个**：新项目主推组合式 API（逻辑复用、TypeScript 友好、可读性随规模提升）；能看懂选项式用于维护老项目
- **别踩的坑**：组合式里用 `this`、选项式组合式混用、以为组合式 = 把代码打乱
