## 🤔 一、什么是 Composable？

**Composable（组合式函数）** 就是把一段"独立完整的功能"封装成一个以 `use` 开头的函数。

回顾 8.2 的鼠标追踪例子：

```js
// composables/useMouse.js
import { ref, onMounted, onUnmounted } from 'vue'

export function useMouse() {
  const x = ref(0)
  const y = ref(0)

  function update(e) {
    x.value = e.pageX
    y.value = e.pageY
  }

  onMounted(() => window.addEventListener('mousemove', update))
  onUnmounted(() => window.removeEventListener('mousemove', update))

  return { x, y }
}
```

使用：

```vue
<script setup>
import { useMouse } from './composables/useMouse'

const { x, y } = useMouse()
</script>

<template>
  <p>鼠标位置：{{ x }}, {{ y }}</p>
</template>
```

## 💡 二、Composable 的命名规范

| 项目 | 规范 | 示例 |
|---|---|---|
| 函数名 | `use` + 大写开头名词/动词 | `useMouse`、`useFetch`、`useLocalStorage` |
| 文件名 | 和函数名一致 | `useMouse.js`、`useFetch.js` |
| 目录 | 放在 `src/composables/` 下 | 集中管理可复用逻辑 |
| 返回值 | 对象 `{ ref1, ref2, fn1 }` | 方便解构 |

> 💬 **老师备注**：为什么一定是 `use` 开头？因为 Vue 官方约定如此，而且 VS Code 的 Volar 插件会识别 `use` 开头的函数，提供自动补全和类型检查。

## 🛠 三、Composable 的结构模板

```js
// composables/useCounter.js
import { ref, computed } from 'vue'

/**
 * 计数器的组合式函数
 * @param {number} initialValue - 初始值，默认 0
 */
export function useCounter(initialValue = 0) {
  // 1. 状态（响应式数据）
  const count = ref(initialValue)

  // 2. 计算属性
  const doubleCount = computed(() => count.value * 2)

  // 3. 方法
  function increment() { count.value++ }
  function decrement() { count.value-- }
  function reset() { count.value = initialValue }

  // 4. 返回值：暴露状态 + 方法
  return {
    count,        // ref
    doubleCount,  // computed ref
    increment,
    decrement,
    reset
  }
}
```

使用：

```
<script setup>
import { useCounter } from './composables/useCounter'

const { count, doubleCount, increment, reset } = useCounter(10)
</script>

<template>
  <p>{{ count }} × 2 = {{ doubleCount }}</p>
  <button @click="increment">+1</button>
  <button @click="reset">重置</button>
</template>
```

## 🔑 四、返回值设计：ref vs reactive

### 方案 A：返回 ref 对象（推荐）

```js
export function useCounter() {
  const count = ref(0)
  return { count, increment: () => count.value++ }
}

// 使用：安全解构
const { count, increment } = useCounter()
count.value++  // ✅ ref 解构不丢响应式
```

### 方案 B：返回 reactive（需 toRefs）

```js
export function useCounter() {
  const state = reactive({ count: 0 })
  return toRefs(state)  // 或 { ...toRefs(state) }
}
```

**推荐方案 A**。因为方案 A 的返回值全是 ref，调用方解构安全，没有心智负担。

## 🔄 五、生命周期在 Composable 中的行为

Composable 里的生命周期钩子和组件生命周期是**绑定**的：

```js
// composables/useEventListener.js
import { onMounted, onUnmounted } from 'vue'

export function useEventListener(target, event, callback) {
  onMounted(() => target.addEventListener(event, callback))
  onUnmounted(() => target.removeEventListener(event, callback))
}
```

```vue
<script setup>
import { useEventListener } from './composables/useEventListener'

// 这个 listener 的生命周期和当前组件绑定
useEventListener(window, 'resize', () => {
  console.log('窗口大小变了')
})
// 组件销毁时自动移除监听器，无需手动清理
</script>
```

**关键点**：谁调用 `useXxx()`，里面的 `onMounted` / `onUnmounted` 就挂在谁身上。每个组件调用都是独立实例。

## ⚠️ 六、常见陷阱

### 陷阱 1：在条件或异步中调用

```js
// ❌ 不要在 if / for / async 里调用 composable
if (someCondition) {
  const { x, y } = useMouse()  // 可能导致响应式错乱
}
```

Composable 必须在 `<script setup>` 或 `setup()` 的**顶层同步调用**。

### 陷阱 2：在 composable 外创建共享状态

```js
// ❌ 模块级变量会被所有调用者共享
const sharedCount = ref(0)  // 这是一个全局单例

export function useCounter() {
  return { count: sharedCount }  // 所有组件共享同一个 count！
}
```

除非你**明确需要**全局共享（如全局 loading 状态），否则每个 composable 的状态应该在函数内部创建。

### 陷阱 3：忘记清理副作用

```js
// ❌ 没有在 onUnmounted 中清理
export function useInterval(fn, ms) {
  const timer = setInterval(fn, ms)
  // 组件销毁后 timer 还在跑！
  return { timer }
}

// ✅ 正确清理
export function useInterval(fn, ms) {
  const timer = ref(null)
  onMounted(() => { timer.value = setInterval(fn, ms) })
  onUnmounted(() => { clearInterval(timer.value) })
  return { timer }
}
```

## 🧠 本节小结

- **Composable 是什么**：以 `use` 开头、内部可用 ref/computed/watch/生命周期钩子的普通函数，把可复用逻辑抽出组件
- **命名与返回**：`useXxx` 前缀是铁律；返回对象/数组包 ref，调用方解构后仍保持响应式
- **只做一件事**：每个 composable 职责单一，方便组合、测试与替换
- **可自由组合**：composable 之间可以互相调用，像搭积木一样拼功能
- **生命周期限制**：`onMounted` 等钩子只能在 setup 执行上下文中调用，所以 composable 也必须在组件 setup 阶段同步调用
- **对比 mixin**：无命名冲突、来源清晰、天然 TS 友好——这是组合式 API 的复用底座
