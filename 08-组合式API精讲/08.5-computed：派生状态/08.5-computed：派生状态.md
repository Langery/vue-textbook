## 🤔 一、什么是"派生状态"？

假设你的组件里有 `firstName` 和 `lastName` 两个数据，你需要显示全名 `firstName + ' ' + lastName`。这个全名不是独立存储的新数据，而是**由已有数据"算"出来的**——这就是"派生状态"。

你当然可以在模板里直接写：

```vue
<p>{{ firstName + ' ' + lastName }}</p>
```

但有两个问题：

1. **逻辑散落**：如果多处用到全名，你需要在模板里重复这段拼接逻辑
2. **无法利用缓存**：Vue 不知道这个表达式依赖了哪些数据，每次渲染都得重新计算

`computed` 就是用来解决这个问题的——**把派生逻辑封装起来，并且自动缓存**。

---

## 💡 二、computed 基本用法

```
<script setup>
import { ref, computed } from 'vue'

const firstName = ref('张')
const lastName = ref('三')

// 计算属性：只读
const fullName = computed(() => {
  return firstName.value + ' ' + lastName.value
})
</script>

<template>
  <p>姓名：{{ fullName }}</p>  <!-- "张三" -->
</template>
```

`computed` 接收一个函数，返回一个**只读的 ref**。模板里直接用 `fullName`（自动解包），JS 代码里用 `fullName.value`。

### 核心特性：自动依赖追踪

```js
const fullName = computed(() => {
  console.log('computed 重新计算了！')
  return firstName.value + ' ' + lastName.value
})
```

当你改 `firstName.value` 时：
- Vue 检测到 `firstName` 变了
- 发现 `fullName` 依赖 `firstName`
- 自动重新计算 `fullName`，控制台打印"computed 重新计算了！"

当你改完全不相关的其他变量时：
- `fullName` 的依赖没有变化
- 直接返回缓存值，不重新计算
- 控制台不打印

## 🔑 三、缓存机制（这是重点）

### 3.1 computed vs methods：本质区别

很多同学会问："computed 不就是一个函数吗？我用 methods 不是一样？"

看这个例子：

```vue
<script setup>
import { ref, computed } from 'vue'

const count = ref(0)
const countB = ref(0)

// computed 版本
const doubleComputed = computed(() => {
  console.log('computed 计算了')
  return count.value * 2
})

// methods 版本
function doubleMethod() {
  console.log('method 执行了')
  return count.value * 2
}
</script>

<template>
  <!-- computed：只计算一次 -->
  <p>{{ doubleComputed }}</p>
  <p>{{ doubleComputed }}</p>
  <p>{{ doubleComputed }}</p>

  <!-- methods：每次渲染都执行三次 -->
  <p>{{ doubleMethod() }}</p>
  <p>{{ doubleMethod() }}</p>
  <p>{{ doubleMethod() }}</p>

  <button @click="countB++">改 countB</button>
</template>
```

你点"改 countB"按钮时：
- `doubleComputed`：控制台**不打印**。因为 `count` 没变，缓存命中，直接返回旧值
- `doubleMethod()`：控制台**打印三次**。methods 每次都重新执行

> 💬 **老师备注**：这就是 computed 的核心价值——**缓存**。如果你的计算很昂贵（比如要遍历一个大数组做过滤），用 computed 能避免不必要的重复计算。用 methods 的话，每次组件重新渲染都会跑一遍。

### 3.2 什么情况下缓存"失效"？

只有**计算属性依赖的响应式数据变化**时，才会重新计算。其他任何情况都不会。

```js
const a = ref(1)
const b = ref(2)
const sum = computed(() => a.value + b.value)

a.value = 3   // ✅ 缓存失效，重新计算 → 5
b.value = 4   // ✅ 缓存失效，重新计算 → 7
// 任何不是 a 和 b 的变化都不会触发重新计算
```

## 🛠 四、可写计算属性（get + set）

默认情况下 `computed` 是只读的。如果你需要既能读又能写，用带 `get` 和 `set` 的形式：

```
<script setup>
import { ref, computed } from 'vue'

const firstName = ref('张')
const lastName = ref('三')

const fullName = computed({
  get() {
    // 读取时：拼接返回
    return firstName.value + ' ' + lastName.value
  },
  set(newValue) {
    // 写入时：反向拆解
    const parts = newValue.split(' ')
    firstName.value = parts[0]
    lastName.value = parts[1] || ''
  }
})
</script>

<template>
  <input v-model="fullName" />  <!-- v-model 会触发 set -->
  <p>firstName: {{ firstName }}</p>
  <p>lastName: {{ lastName }}</p>
</template>
```

用户输入 "李四" → `set('李四')` → 自动把 `firstName` 设为 `'李'`，`lastName` 设为 `'四'`。

> 💬 **老师备注**：可写计算属性最常见的场景就是 `v-model` 绑定——你希望组件对外暴露一个字段，但内部实际维护的是多个字段，计算属性作为"翻译层"负责来回转换。比如你在 Pinia 里封装一个 store，把内部 `cents` 转换成对外的 `yuan`。

### 可写计算属性的典型场景

| 场景 | get（读） | set（写） |
|---|---|---|
| 全名 ↔ 姓+名 | 拼接 | 拆分 |
| 元 ↔ 分（金额） | 分 ÷ 100 | 元 × 100 |
| 日期字符串 ↔ Date 对象 | 格式化 | 解析 |
| v-model 绑定 | 返回内部值 | 更新内部值 |

## ⚠️ 五、常见陷阱

### 陷阱 1：在 computed 里做副作用

```js
// ❌ 不要这样写！
const bad = computed(() => {
  fetch('/api/data')           // 异步请求
  document.title = 'xxx'       // DOM 操作
  localStorage.setItem('k', 'v') // 副作用
  return count.value * 2
})
```

computed 应该是**纯函数**——只做计算，不改任何外部状态。副作用（异步、DOM、存储）应放在 `watch` 或方法里。

### 陷阱 2：直接修改只读计算属性

```js
const double = computed(() => count.value * 2)
double.value = 10  // ❌ 控制台警告：computed value is readonly
```

要可写，必须用 `get` + `set` 模式。

### 陷阱 3：依赖不稳定的数据

```js
const now = computed(() => Date.now())  // ❌ 永远不会更新
```

`Date.now()` 不是响应式的，Vue 追踪不到它。这个 computed 计算一次后永远返回同一个值。

## 🧠 本节小结

- **派生状态**：由现有数据计算出来的值，模板里写复杂表达式时应抽出来
- **computed 带缓存**：只有依赖变化才重算；同一次渲染多次引用只算一遍
- **自动追踪依赖**：getter 里读了哪些响应式数据，它们一变 computed 就失效重算
- **默认只读**：computed 返回只读 ref，直接赋值会警告；要可写需 get/set 双写
- **必须"纯"**：computed 里别发请求、改别的数据（副作用），否则推导不可控
- **别指望追踪非响应式**：如 `Date.now()`、`Math.random()` 不是响应式的，computed 不会因它们重算
