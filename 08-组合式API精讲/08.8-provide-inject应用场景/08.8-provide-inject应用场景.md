## 💡 一、什么时候用 provide / inject？

**记忆口诀**：数据是"祖传"的，不只是"父子"的。

根据"数据流转"选择方案：

| 场景 | 方案 | 原因 |
|---|---|---|
| 父 → 子（一层） | Props | 最简单、最明确 |
| 子 → 父（一层） | Emits | 事件通知 |
| 祖 → 任意后代 | provide/inject | 跳过中间层 |
| 任意组件 → 任意组件 | Pinia | 全局共享 |
| URL 参数 | Router | 地址栏传递 |

## 🛠 二、场景实战

### 场景 1：全局主题切换

```vue
<!-- App.vue -->
<script setup>
import { reactive, readonly, provide } from 'vue'

const themeConfig = reactive({
  mode: 'light',
  primaryColor: '#1890ff',
  borderRadius: '6px'
})

provide('theme', readonly(themeConfig))
provide('switchMode', () => {
  themeConfig.mode = themeConfig.mode === 'light' ? 'dark' : 'light'
})
</script>
```

```
<!-- 任意深层组件 -->
<script setup>
import { inject } from 'vue'

const theme = inject('theme')
const switchMode = inject('switchMode')
</script>

<template>
  <div :style="{
    background: theme.mode === 'dark' ? '#141414' : '#fff',
    color: theme.mode === 'dark' ? '#fff' : '#333',
    borderRadius: theme.borderRadius
  }">
    <button @click="switchMode">
      切换到{{ theme.mode === 'light' ? '深色' : '浅色' }}模式
    </button>
  </div>
</template>
```

### 场景 2：表单组件（组件库内部通信）

这是组件库的经典模式。以 Element Plus 的 `el-form` + `el-form-item` 为例：

```vue
<!-- SuperForm.vue（表单容器） -->
<script setup>
import { reactive, readonly, provide } from 'vue'

const props = defineProps({
  model: Object,    // 表单数据对象
  rules: Object     // 校验规则
})

const formState = reactive({
  errors: {}        // 各字段的错误信息
})

function validateField(field) {
  // 校验逻辑...
}

// 向所有 FormItem 后代提供表单上下文
provide('formContext', readonly({
  model: props.model,
  errors: formState.errors,
  rules: props.rules,
  validateField
}))
</script>
```

```
<!-- SuperFormItem.vue（表单项） -->
<script setup>
import { inject } from 'vue'

const props = defineProps({ prop: String })

// Inject 表单上下文
const formContext = inject('formContext')

// 拿到本字段的值和错误信息
const fieldValue = computed(() => formContext.model[props.prop])
const fieldError = computed(() => formContext.errors[props.prop])
</script>

<template>
  <div class="form-item">
    <label>{{ props.prop }}</label>
    <input v-model="formContext.model[props.prop]"
           @blur="formContext.validateField(props.prop)" />
    <span class="error">{{ fieldError }}</span>
  </div>
</template>
```

用户使用时完全不需要感知内部 provide/inject：

```vue
<SuperForm :model="loginForm" :rules="rules">
  <SuperFormItem prop="username" />
  <SuperFormItem prop="password" />
</SuperForm>
```

> 💬 **老师备注**：这就是组件库的"黑盒设计"——组件内部用 provide/inject 自由通信，对外只暴露简洁的 API。

### 场景 3：面包屑导航

```
<!-- App.vue -->
<script setup>
import { ref, provide } from 'vue'

const breadcrumbs = ref([
  { label: '首页', path: '/' }
])

provide('breadcrumbs', breadcrumbs)
provide('addBreadcrumb', (crumb) => { breadcrumbs.value.push(crumb) })
</script>
```

```vue
<!-- 任意深层页面组件 -->
<script setup>
import { inject, onMounted } from 'vue'

const addBreadcrumb = inject('addBreadcrumb')

onMounted(() => {
  addBreadcrumb({ label: '用户管理', path: '/users' })
  addBreadcrumb({ label: '编辑用户', path: '' })
})
</script>
```

### 场景 4：权限控制

```
<!-- App.vue -->
<script setup>
import { reactive, readonly, provide } from 'vue'

const permissions = reactive({
  canEdit: true,
  canDelete: false,
  canViewReport: true
})

provide('permissions', readonly(permissions))
</script>
```

```vue
<!-- 深层子组件 -->
<script setup>
import { inject } from 'vue'

const permissions = inject('permissions')
</script>

<template>
  <button v-if="permissions.canEdit">编辑</button>
  <button v-if="permissions.canDelete">删除</button>
</template>
```

## 🔑 三、进阶：用 Symbol 做 Key

直接用字符串 `'theme'` 作为 key，如果多个模块都 provide 了 `'theme'`，后一个会覆盖前一个。解决方案：用 `Symbol` 作为唯一 key。

```js
// keys.js（统一管理 Injection Key）
export const THEME_KEY = Symbol('theme')
export const FORM_KEY = Symbol('form')
export const PERMISSION_KEY = Symbol('permission')
```

```
<!-- 祖先 -->
<script setup>
import { provide } from 'vue'
import { THEME_KEY } from './keys'

provide(THEME_KEY, themeData)
</script>
```

```vue
<!-- 后代 -->
<script setup>
import { inject } from 'vue'
import { THEME_KEY } from './keys'

const theme = inject(THEME_KEY)
</script>
```

`Symbol('theme')` 每次创建都是独一无二的，即使描述文字相同也不会冲突。

## ⚠️ 四、provide / inject 的边界

**不适合 provide / inject 的场景**：

| 场景 | 为什么不适合 | 应该用什么 |
|---|---|---|
| 父传子一层 | 杀鸡用牛刀，数据来源不透明 | Props |
| 跨路由共享状态 | 路由切换后代关系断了 | Pinia |
| 大量全局状态 | 难以追踪数据流 | Pinia |
| 需要持久化 | provide 的数据组件销毁就没了 | Pinia + localStorage |

**适用场景总结**：
- ✅ 全局配置（主题、语言、权限）
- ✅ 组件库内部通信（Form/FormItem、Tab/TabPane）
- ✅ 深层嵌套且中间层不关心的数据

---

## 🧠 本节小结

- **适合上 provide/inject**：全局配置（主题/语言/权限）、组件库内部通信（Form/FormItem、Tab/TabPane）、深层嵌套且中间层不关心的数据
- **配套模式**：提供方给默认值 + 响应式状态 + readonly 保护，消费方 inject 后只读使用
- **别滥用**：能父子 Props 传的就别跨层；滥用会让组件依赖"看不见的全局"，难以测试复用
- **跨组件封装利器**：组件库/复杂表单里，provide/inject 能显著减少逐层透传的样板代码
- **组合式写法**：可把 provide 逻辑收进 composable，`inject` 侧配好默认值更健壮
