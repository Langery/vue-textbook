## 🧠 思维导图

```text
8.6 computed vs watch vs methods
├── computed（计算属性）
│   ├── 有缓存，依赖不变不重新算
│   ├── 同步返回结果
│   ├── 不能有副作用
│   └── 适合：派生数据（总价、过滤、格式化）
├── watch（侦听器）
│   ├── 无缓存，每次触发都执行
│   ├── 可以异步、可以有副作用
│   └── 适合：数据变化后"做某事"（请求、存储、DOM 操作）
├── methods（方法）
│   ├── 无缓存，调用才执行
│   ├── 可以传参
│   └── 适合：事件处理、命令式操作
├── 三句话区分
│   ├── computed：基于数据 "算" 出新值
│   ├── watch：数据变了 "做" 某事
│   └── methods：用户触发了 "执行" 某事
└── 常见选型错误
    ├── 用 watch 实现"同步拼接" → 应该用 computed
    ├── 用 computed 发请求 → 应该用 watch 或方法
    └── 用 watch 监听多个来源做同一件事 → 应该用 watchEffect
```

computed 会缓存、watch 能拿新旧值、methods 最简单直接——可项目里真遇到"数据变化要做什么"时，你到底该用哪个？选错的结果不是报错，而是代码越来越绕：该缓存的反复计算、该派生的堆了一堆 watch、该手动调用的塞进 computed 里产生副作用。本节不教你新 API，只帮你把三个工具的分工焊死在脑子里。

## 🤔 一、三句话说清楚

很多同学学完这三个 API 后还是容易搞混。记住这三句话：

| API | 一句话 |
|---|---|
| **computed** | "基于已有数据**算出**一个新值" |
| **watch** | "盯着某个数据，一旦变了就**做**点事" |
| **methods** | "用户点了按钮、触发了事件，**执行**一段逻辑" |

核心区别：
- `computed` 关注的是**结果**（返回值）
- `watch` 关注的是**副作用**（数据变了之后干什么）
- `methods` 关注的是**执行**（主动触发）

---

## 💡 二、computed 该做的事

computed 应该做的：
- 格式化显示（日期格式化、货币格式化）
- 列表过滤（根据搜索关键词过滤列表）
- 列表排序（根据排序条件重排列表）
- 布尔判断（是否登录、是否全选、是否满减）
- 数学计算（总计、折扣价、平均值）

computed 不该做的：
- ❌ 发送网络请求
- ❌ 修改 DOM
- ❌ 写 localStorage
- ❌ 修改其他响应式数据

```vue
<script setup>
import { ref, computed } from 'vue'

const keyword = ref('')
const list = ref([
  { name: '苹果', price: 5 },
  { name: '香蕉', price: 3 },
  { name: '橘子', price: 4 }
])

// ✅ 好的 computed：纯计算
const filteredList = computed(() => {
  return list.value.filter(item => item.name.includes(keyword.value))
})

const totalPrice = computed(() => {
  return filteredList.value.reduce((sum, item) => sum + item.price, 0)
})
</script>
```

## 🔍 三、watch 该做的事

watch 应该做的：
- 数据变化后发网络请求
- 数据变化后写 localStorage
- 数据变化后操作 DOM（如滚动到某个位置）
- 监听路由参数变化

watch 不该做的：
- ❌ 用它来"计算"一个新值（应该用 computed）
- ❌ 在 callback 里直接修改正在监听的数据（小心死循环）

```
<script setup>
import { ref, watch } from 'vue'

const keyword = ref('')
const results = ref([])

// ✅ 好的 watch：数据变了发请求
watch(keyword, async (newKeyword) => {
  if (newKeyword.length < 2) return
  const res = await fetch(`/api/search?q=${newKeyword}`)
  results.value = await res.json()
})
</script>
```

### watch 和 computed 的典型对比：搜索过滤

**computed 版（本地过滤）**：
```js
const keyword = ref('')
const list = ref([...])  // 全部数据已在本地

const filtered = computed(() =>
  list.value.filter(item => item.name.includes(keyword.value))
)
```

**watch 版（远程搜索）**：
```js
const keyword = ref('')
const results = ref([])  // 从服务端拿

watch(keyword, async (kw) => {
  results.value = await fetch(`/api/search?q=${kw}`).then(r => r.json())
})
```

同一个"搜索"功能，本地过滤用 computed，远程搜索用 watch。选错会出问题：

- 如果你用 computed 发请求：每次依赖变化都会触发请求，而且 computed 不能是 async 的
- 如果你用 watch 做本地过滤：完全没必要，computed 有缓存性能更好

## 🛠 四、methods 该做的事

methods 适合：
- 事件处理函数（`@click`、`@submit`、`@input`）
- 需要传参的逻辑（computed 不能传参）
- "命令式"操作（手动触发、不依赖响应式追踪）

```vue
<script setup>
import { ref } from 'vue'

const count = ref(0)
const list = ref([])
const inputValue = ref('')

// ✅ 好的 methods：用户触发的行为
function add() { count.value++ }
function removeItem(index) { list.value.splice(index, 1) }
function handleSubmit() { /* 表单提交逻辑 */ }

// methods 可以传参，computed 不行
function multiplyBy(n) { return count.value * n }
</script>

<template>
  <button @click="add">+1</button>
  <p>{{ multiplyBy(3) }}</p>  <!-- ✅ 传参，只能用 methods -->
</template>
```

## 📊 五、一表搞懂

| 维度 | computed | watch | methods |
|---|---|---|---|
| **缓存** | ✅ 有缓存 | ❌ 无缓存 | ❌ 无缓存 |
| **返回值** | ✅ 必须返回 | ❌ 不需要 | ❌ 不需要 |
| **副作用** | ❌ 禁止 | ✅ 适合 | ✅ 可以 |
| **异步** | ❌ 不支持 | ✅ 支持 | ✅ 支持 |
| **传参** | ❌ 不支持 | ❌ 不支持 | ✅ 支持 |
| **触发时机** | 依赖变化时自动 | 监听数据变化时自动 | 手动调用 |
| **模板中使用** | ✅ 直接写 | ❌ 不宜 | ✅ 需要加 `()` |

## ⚠️ 六、常见选型错误

### 错误 1：用 watch 做简单计算

```js
// ❌ 不应该用 watch
const firstName = ref('')
const lastName = ref('')
const fullName = ref('')

watch([firstName, lastName], () => {
  fullName.value = firstName.value + ' ' + lastName.value  // 多余！
})

// ✅ 用 computed 一行搞定
const fullName = computed(() => firstName.value + ' ' + lastName.value)
```

### 错误 2：用 computed 发请求

```js
// ❌ computed 不应该有副作用
const userData = computed(() => {
  fetch('/api/user').then(r => r.json())  // 每次依赖变化都发？
  // computed 甚至没法 return 异步结果
})
```

### 错误 3：watch 写回调时忘了处理旧值

```js
// ❌ 可能造成内存泄漏
watch(dataSource, (newVal) => {
  const ws = new WebSocket(newVal.url)  // 每次创建新的，旧的没关
})

// ✅ 清理旧资源
watch(dataSource, (newVal, oldVal) => {
  if (oldVal) { /* 关闭旧连接 */ }
  const ws = new WebSocket(newVal.url)
})
```

### 错误 4：watch 监听 computed 做二次计算

```js
const list = ref([...])
const filtered = computed(() => list.value.filter(...))

// ❌ 对 computed 的结果再 watch —— 多余！
watch(filtered, (val) => {
  count.value = val.length
})

// ✅ 再写一个 computed
const count = computed(() => filtered.value.length)
```

> 💬 **老师备注**：一个实用的判断法：自问一句"这个操作是返回一个值，还是做一件事？"返回值的用 computed，做事的用 watch。

## 🧠 本节小结

- **判断口诀**：返回一个值 → computed；做一件事 → watch/watchEffect；事件里手动调用 → methods
- **computed**：带缓存、自动依赖追踪，适合派生数据；别在里面做副作用
- **watch**：拿到新旧值、可配 immediate/deep，适合"数据变了要干的事"；不要只做简单赋值
- **methods**：函数本身不缓存，每次调用都执行；适合事件处理器、用户主动操作
- **反面信号**：watch 里只 `ref.value = 计算` 应改 computed；computed 里发请求应挪走
- **三个工具可配合**：computed 产出派生值 → watch 观察值变化 → methods 提供操作入口
