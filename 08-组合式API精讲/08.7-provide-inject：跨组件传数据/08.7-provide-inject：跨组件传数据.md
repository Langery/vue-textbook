## 🤔 一、问题：Props 的"逐层传递"之痛

看这个组件树：

```
App (爷爷)
 └─ Layout (爸爸)
     └─ Sidebar (儿子)
         └─ UserMenu (孙子)
             └─ Avatar (曾孙)
```

如果 `App` 里有一个 `theme` 主题色，`Avatar` 需要用。常规做法是用 Props 一层层传：

```vue
<!-- App.vue -->
<Layout :theme="theme" />

<!-- Layout.vue -->
<Sidebar :theme="theme" />   <!-- 我不要 theme，但必须传 -->

<!-- Sidebar.vue -->
<UserMenu :theme="theme" />  <!-- 我也不要 theme，但必须传 -->

<!-- UserMenu.vue -->
<Avatar :theme="theme" />    <!-- 继续传 -->
```

这就是 **Prop Drilling（Props 打孔）**：中间组件不关心这个数据，但被迫接收和转发。

## 💡 二、provide / inject：隔代传

Vue 提供了 `provide` 和 `inject`，让祖先组件可以直接给任意后代组件"注入"数据：

```
<!-- App.vue（祖先） -->
<script setup>
import { ref, provide } from 'vue'

const theme = ref('light')
// 向所有后代组件提供 theme
provide('theme', theme)
// 也提供一个切换方法
provide('toggleTheme', () => {
  theme.value = theme.value === 'light' ? 'dark' : 'light'
})
</script>
```

```vue
<!-- Avatar.vue（曾孙） -->
<script setup>
import { inject } from 'vue'

// 直接拿到爷爷提供的 theme，不需要经过爸爸、儿子
const theme = inject('theme')
const toggleTheme = inject('toggleTheme')
</script>

<template>
  <div :class="theme">
    <img src="avatar.png" />
    <button @click="toggleTheme">切换主题</button>
  </div>
</template>
```

**中间组件完全不需要知道 `theme` 的存在。**

## 🔑 三、响应式数据：怎么传才正确？

### 3.1 传普通值（不响应式）

```js
// 祖先
const theme = 'light'
provide('theme', theme)  // 传的是值 "light"

// 后代
const theme = inject('theme')  // "light" —— 后面改了也不会变
```

如果你传的是一个普通字符串或数字，后代拿到的是**当时的快照**，后续变化不会同步。

### 3.2 传 ref / reactive（响应式）

```js
// 祖先
const theme = ref('light')
provide('theme', theme)  // 传的是 ref 对象本身

// 后代
const theme = inject('theme')
// 模板里：{{ theme }}  ← 自动跟新
// JS 里：theme.value   ← 也能拿到最新值
```

传 ref 对象，后代拿到的就是同一个 ref，两边共享同一个响应式引用。

### 3.3 传 reactive 对象

```js
// 祖先
const state = reactive({ theme: 'light', user: 'admin' })
provide('appState', state)

// 后代
const appState = inject('appState')
// 直接改 appState.theme = 'dark' —— 能改！而且祖先也会变！
```

⚠️ 这带来一个隐患：**后代组件可以直接修改 provide 的数据**，导致数据流混乱——你不知道是谁改的。

## 🛡️ 四、进阶：readonly 防止子组件误改

**最佳实践：provide 数据时用 `readonly` 包装，只给后代读权限。**

```
<!-- App.vue -->
<script setup>
import { reactive, readonly, provide } from 'vue'

const state = reactive({
  theme: 'light',
  sidebarCollapsed: false
})

// ✅ 提供只读版本
provide('appState', readonly(state))

// ✅ 同时提供修改方法（受控修改）
provide('toggleTheme', () => {
  state.theme = state.theme === 'light' ? 'dark' : 'light'
})

provide('toggleSidebar', () => {
  state.sidebarCollapsed = !state.sidebarCollapsed
})
</script>
```

```vue
<!-- 后代组件 -->
<script setup>
import { inject } from 'vue'

const appState = inject('appState')
const toggleTheme = inject('toggleTheme')

// ❌ 开发模式会报警告：Set operation on key "theme" failed: target is readonly
// appState.theme = 'dark'

// ✅ 只能通过暴露的方法修改
function handleToggle() {
  toggleTheme()
}
</script>

<template>
  <div :class="appState.theme">
    <p>当前主题：{{ appState.theme }}</p>
    <button @click="handleToggle">切换主题</button>
  </div>
</template>
```

这个模式非常清晰：
- **只读数据**：`provide('appState', readonly(state))` —— 后代只能看不能改
- **修改方法**：`provide('toggleTheme', fn)` —— 要改？调我给你的方法

> 💬 **老师备注**：这个模式在企业项目中非常常见。就像你去银行办事——柜员可以查看你的账户余额（只读），但你要转账必须通过柜员的操作流程（方法），不能自己翻过柜台直接改数据库。

## 🛠 五、完整示例：主题系统

```
<!-- App.vue -->
<script setup>
import { reactive, readonly, provide } from 'vue'
import Layout from './Layout.vue'

const themeState = reactive({
  mode: 'light',           // 'light' | 'dark'
  fontSize: 'medium',      // 'small' | 'medium' | 'large'
})

provide('theme', readonly(themeState))
provide('setThemeMode', (mode) => { themeState.mode = mode })
provide('setFontSize', (size) => { themeState.fontSize = size })
</script>

<template>
  <div :class="['app', themeState.mode]">
    <Layout />
  </div>
</template>
```

```vue
<!-- ThemePanel.vue（深层嵌套的后代组件） -->
<script setup>
import { inject } from 'vue'

const theme = inject('theme')
const setThemeMode = inject('setThemeMode')
const setFontSize = inject('setFontSize')
</script>

<template>
  <div class="theme-panel">
    <p>当前主题：{{ theme.mode }}</p>
    <p>字体大小：{{ theme.fontSize }}</p>

    <button @click="setThemeMode('light')">浅色</button>
    <button @click="setThemeMode('dark')">深色</button>

    <button @click="setFontSize('small')">小</button>
    <button @click="setFontSize('medium')">中</button>
    <button @click="setFontSize('large')">大</button>
  </div>
</template>
```

## ⚠️ 六、常见陷阱

### 陷阱 1：inject 拿不到值

```js
// ❌ 祖先 provide 了，但后代 inject 不到
// 原因：inject 的组件不是 provide 组件的后代
```

provide/inject 只能在**父子链**上工作。兄弟组件、非后代关系的组件之间不能传。

### 陷阱 2：provide 对象被解构后丢失响应式

```js
// 祖先
provide('config', reactive({ host: 'localhost', port: 3000 }))

// 后代
const config = inject('config')
const { host } = config  // ❌ host 解构出来是普通字符串
```

解决：不解构，直接用 `config.host`，或者用 `toRef(config, 'host')`。

### 陷阱 3：滥用 provide/inject

provide/inject 的缺点是**数据来源不透明**——你看一个组件的代码，`inject('xxx')` 的 `xxx` 是从哪来的？必须去查祖先组件。所以：
- 父子关系用 Props
- 深度嵌套 + 中间层不关心 + 全局性质（主题/语言/用户信息）才用 provide/inject

## 🧠 本节小结

- **用法**：祖先 `provide('key', value)`，任意后代 `inject('key')`，绕过中间层逐级转发
- **响应性靠你自己传**：provide 普通值就是一次性快照；传 ref/reactive 才能响应，要防篡改可包 `readonly`
- **默认值/兜底**：`inject('key', fallback)` 处理祖先未提供的情况
- **优点**：深层传值少写样板、跨层级共享便捷
- **代价**：数据来源不透明——`inject('xxx')` 得回查祖先组件才知道谁提供的
- **判断标准**：能用 Props 就近传就优先 Props；中间层不关心、数据带全局性质才上 provide/inject
